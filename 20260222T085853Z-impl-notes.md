# Implementation Notes

## Persistence-Safe Terminal Transitions

Terminal transitions (`Done` and `Failed`) now follow a strict ordering:

1. **Add terminal label** (`ralph:prd-done` or `ralph:prd-failed`) first
2. **Set in-memory state** to the terminal value
3. **Save state to disk** via `finish_transition`
4. **Remove `ralph:prd-active`** only after save succeeds

If the save fails at step 3, the state is reverted to `AwaitingFeedback` (non-terminal) so the issue remains visible to the poll loop via `ralph:prd-active`. The save failure is routed through retry accounting (`error_count` incremented, `last_error` set). After 3 consecutive failures, `transition_to_failed` is invoked.

`transition_to_failed` itself is persistence-safe: it adds `ralph:prd-failed`, sets state to `Failed`, attempts save, and only removes `ralph:prd-active`/`ralph:prd` after a successful save. On save failure it reverts to `AwaitingFeedback`.

## Bot-Scoped Marker Idempotency

All marker lookup and posting operations now filter by `author_login == bot_login`:

- `find_bot_comment_with_marker()` - scoped lookup (new helper in `github.rs`)
- `post_bot_comment_with_marker()` - scoped idempotent post returning `Option<u64>`
- `post_bot_comment_with_marker_metadata()` - scoped idempotent post returning `Option<IssueComment>`

Callers updated in `interactive_prd.rs`:
- `do_pending_to_awaiting` (questions marker)
- `do_awaiting_answers_to_awaiting_feedback` (draft marker)
- `do_awaiting_feedback` (revision marker)
- `do_approval_transition` (approved marker)
- `extract_questions_text` (questions marker lookup)

The `bot_login` is obtained from the existing `bot_login_cache` (which calls `gh api user`) and threaded through all transition functions. User-authored comments containing the same marker text are ignored.

## Save-Failure Retry Accounting

`finish_transition` now catches save errors and:
1. Reverts terminal state to `AwaitingFeedback` if the transition was terminal
2. Increments `error_count`
3. Sets `last_error` with the save failure message
4. If `error_count >= 3`, calls `transition_to_failed`
5. Otherwise, attempts a recovery save with the reverted state
6. Returns `RalphError::InteractivePrdFailed`

# Decisions Made

1. **Revert target for save failures**: Always revert to `AwaitingFeedback` rather than trying to detect the previous state. This is safe because only `AwaitingFeedback -> Done` and `AwaitingFeedback -> Failed` are terminal transitions, so the previous state is always `AwaitingFeedback`.

2. **Bot-scoped helpers alongside generic helpers**: Added new bot-scoped functions (`find_bot_comment_with_marker`, `post_bot_comment_with_marker`, `post_bot_comment_with_marker_metadata`) rather than modifying existing generic helpers (`find_comment_with_marker`, `post_comment_with_marker`). This preserves backward compatibility for any non-PRD callers.

3. **Unconditional pub for `tests_extract_questions_text`**: Made this wrapper unconditionally `pub` rather than `#[cfg(test)]`-gated because the conformance tests in the validate module are part of the lib target, not the test target. The function is a thin wrapper for test access only.

4. **Label ordering in `do_approval_transition`**: Changed to add `ralph:prd-done` before removing `ralph:prd-active`, ensuring the issue always has at least one terminal label visible even if the daemon crashes mid-transition.

# Spec Deviations

None. All spec requirements were implemented as specified:
- Persistence-safe terminal transitions with save-before-label-remove ordering
- Bot-scoped marker idempotency via `author_login` filtering
- Save-failure retry accounting through existing `error_count`/`last_error` fields
- All required integration and conformance tests added
