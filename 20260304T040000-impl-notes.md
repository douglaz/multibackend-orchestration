# Implementation Notes

## Decisions Made
- Added 6 quick-dev mock script helpers to `src/validate/mock_scripts.rs` rather than a separate file, following the existing pattern where all mock scripts live in the shared module. The helpers include: happy-path implementer/reviewer, always-reject reviewer, reject-once reviewer, final-review-issues-once (for reloop testing), and final-review-always-issues (for force-complete guard testing).
- Used environment variables (`QUICK_DEV_REVIEW_RESULT`, `QUICK_DEV_FINAL_REVIEW_RESULT`, `QUICK_DEV_REVIEW_STATE_FILE`, `QUICK_DEV_FR_STATE_FILE`) in mock scripts to control behavior deterministically without needing separate scripts for every scenario.
- Used `/bin/sh` wrapper scripts around the bash mock scripts for Nix sandbox compatibility, following the `setup_mock_backends_stable` pattern.
- Read `state.json` directly from disk for quick-dev-specific state assertions (`current_phase`, `quick_dev_phase`) because `reconstruct_project_state` (used by `h.load_state()` / `project show --json`) does not propagate `current_phase` from the quick-dev orchestrator's state.json — it reconstructs from artifacts/git which doesn't cover quick-dev phase semantics. This is the correct approach since the quick-dev orchestrator owns its state file.
- Used exit code 2 (not 1) for validation error assertions, matching the `RalphError::Validation` exit code mapping in `error.rs`.
- Configured `claude` as implementer backend and `codex` as reviewer backend in all tests, matching the project's two-backend architecture.

## Spec Deviations
- The spec mentions `src/validate/mock_scripts.rs` as "optional reusable deterministic quick-dev mock script helpers to reduce duplication." I added the helpers directly to the existing `mock_scripts.rs` module rather than creating a separate file, since the module already serves this purpose for all validate tests and a new file would fragment the mock infrastructure unnecessarily.
- Daemon quick-label branching tests (`ralph:quick` fresh/resume dispatch) were already implemented in `src/validate/tests_daemon.rs` in a prior loop. The new `tests_quick_dev.rs` module does not duplicate those; the validate filter `--filter quick_dev` matches both the new tests and the existing daemon dispatch tests (12 total).
