The spec has been revised. Here's a summary of how each review issue was addressed:

**Issue 1 — Quick PRD detection race (SPEC.md deleted after project creation):** Replaced the unreliable `SPEC.md` glob-poll with detection via the project's `prompt.md`. Since `create_project()` copies SPEC.md verbatim into `prompt.md`, the watcher reads that file instead — it persists for the entire child lifetime. The watcher distinguishes pre-review `prompt.md` from post-review by checking that `prompt-review.md` does not yet exist in the same project directory.

**Issue 2 — Stale artifacts from prior runs:** Added an mtime-gating strategy. The watcher records `start_time = SystemTime::now()` at creation and only considers files with mtime strictly after `start_time` as new. This prevents re-posting content from a previous run's leftover `.ralph/projects/` directory. Also documented that `clean_worktree()` preserves `.ralph/` but old files retain their old mtimes.

**Issue 3 — Prompt review completion signal:** Changed from `prompt-original.md` (written before the prompt overwrite) to `prompt-review.md` (the last artifact written by the review step at orchestrator.rs:336–346). This is a true completion signal — if review fails between `prompt-original.md` write and `prompt.md` overwrite, `prompt-review.md` won't exist and no comment is posted.

**Issue 4 — Child lifecycle integration (all exit paths):** Explicitly specified watcher cancellation and join in all three exit paths: `collect_children()`, `kill_aborted_children()`, and `drain_all_children()`. Documented that `complete_task()` (which triggers worktree removal) only runs after the watcher join completes, preventing races with file reads. Also added a dedicated lifecycle test.

**Issue 5 — Acceptance criteria clarity:** Replaced vague "immediately" with concrete, testable guarantees: "within one poll cycle (2 s)" for artifact detection, "before `complete_task()` runs" for ordering, and a "final drain scan" mechanism that guarantees artifacts written moments before child exit are caught. Added explicit criteria for `ralph run --project` resume behavior.

**Issue 6 — Testing completeness:** Added tests for: stale artifact rejection (test 3), `is_resume` skipping Quick PRD (test 4), final drain scan catching late artifacts (test 6), `--skip-prompt-review` path (test 8), watcher cancellation in all exit paths (test 9), and ordering/timing assertion in the integration test (test 10 verifies Quick PRD comment timestamp precedes completion comment).

**Issue 7 — Large comment handling:** Added explicit truncation at 60,000 characters (under GitHub's 65,536 limit) with a clear `_(truncated — full content in worktree artifact)_` suffix. Added a dedicated unit test (test 7) and an acceptance criterion for this behavior.
