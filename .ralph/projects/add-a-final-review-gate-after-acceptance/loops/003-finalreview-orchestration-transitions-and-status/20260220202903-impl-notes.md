# Implementation Notes

## Decisions Made
- Implemented `Completing -> FinalReview` behind `final_review_enabled`, and `FinalReview` exits to either `Planning` (accepted amendments + restarts remaining) or `Completing` with `Completed` status (no amendments or restart cap reached), to match the phase-gate objective.
- Implemented FinalReview as artifact-resumable, fail-closed steps (proposals, planner positions, votes, arbiter) so partial artifacts are reused safely and malformed existing artifacts fail the run.
- Derived restart count only from git checkpoint commits matching `final_review -> planning` for the project; round is computed as `restart_count + 1`.
- Added config snapshot/resume guard via `final-review-config.json`; on mismatch, only current-loop `final-review-*` artifacts and config snapshot are removed before restarting the phase flow.
- Enforced `FinalReview` iteration invariant as `1` in lifecycle/state/history handling.
- Added status/history visibility for FinalReview progress and phase display, plus integration and validate coverage for final-review completion/restart/arbiter/resume/mismatch/cap flows.
