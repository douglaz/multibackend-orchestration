# Feature: FinalReview Orchestration, Transitions, and Status

## Description
Implement the complete `FinalReview` orchestrator flow, phase transitions (`Completing -> FinalReview`, `FinalReview -> Planning`, `FinalReview -> Completing`), consensus computation, artifact-resumable step execution, config mismatch invalidation, restart count derivation from checkpoint history, force-complete behavior, `ralph status` progress output for final review, and all required integration and validate tests.

## Acceptance Criteria
- [ ] `Completing -> FinalReview` transition implemented: when completion verdict is `Complete` and acceptance QA passed, if `final_review_enabled` is true, transition to `Phase::FinalReview` instead of setting `ProjectStatus::Completed`.
- [ ] `FinalReview` iteration is always `1` (set on transition).
- [ ] Restart count derived solely from checkpoint commit messages matching `final_review -> planning` pattern for the current project.
- [ ] Final review round number is `restart_count + 1`.
- [ ] `final-review-config.json` written to current completion loop directory; on resume, compare saved normalized config with current config.
- [ ] Config mismatch invalidation: log warning, delete only current-loop `final-review-*` artifacts and `final-review-config.json`, restart from step 1.
- [ ] Each reviewer invoked with `final_reviewer` template unless proposal artifact already exists (artifact-resume).
- [ ] Each proposal parsed via `parse_final_reviewer_output`; parse failure fails the run.
- [ ] Amendments merged across reviewers; amendment IDs globally unique.
- [ ] If no amendments: write `final-review-exit-approved` artifact and complete project.
- [ ] Planner invoked with planner-position template unless positions artifact exists; parsed via `parse_planner_position_output` (must cover every amendment ID).
- [ ] Each reviewer invoked with vote template unless vote artifact exists per reviewer; parsed via `parse_vote_output` (must cover every amendment ID).
- [ ] Per-amendment consensus computed: `ratio = accepts / total_voters`; accepted if `ratio >= threshold`; rejected if `accepts == 0`; disputed otherwise.
- [ ] Disputed set invokes arbiter (unless arbiter artifact exists); parsed via `parse_arbiter_output` (must cover every disputed ID).
- [ ] Final accepted set = consensus-accepted + arbiter-accepted.
- [ ] If final accepted set empty: write `final-review-exit-approved` artifact and complete.
- [ ] If non-empty and restart limit not reached: write/append `final-review-amendments-applied.md`, write restart-exit artifact, transition to `Planning`.
- [ ] If non-empty and restart limit reached: write `final-review-force-complete.md`, complete project.
- [ ] `ralph status` shows final-review progress: `Final Review: round N`, `Reviewers: M/N complete`, `Disputed amendments: K`, `Restart count: R / max_final_review_restarts`.
- [ ] `src/cli/history.rs` updated to handle `Phase::FinalReview` display.
- [ ] `src/project/lifecycle.rs` enforces FinalReview iteration = 1 if needed.
- [ ] Integration tests in `tests/orchestrator.rs` cover: no amendments -> complete; accepted amendments -> planning restart; disputed amendments -> arbiter invoked only for disputed IDs; partial artifacts resume skips completed steps; config mismatch invalidates and restarts round; restart cap triggers force-complete.
- [ ] Validate tests in new `src/validate/tests_final_review.rs`: full completion flow with final review enabled; restart flow (round 1 amendments, round 2 none). Module registered in `src/validate/mod.rs`.
