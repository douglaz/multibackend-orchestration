# Feature: FinalReview Template and Parser Contracts

## Description
Loop 1 already established `Phase::FinalReview`, config foundations, role models/timeouts, and final-review artifact kinds.  
The next logical feature is to add the missing prompt/template and parser contracts that make FinalReview executable and deterministic: four new role templates, template-path resolution plumbing, fail-closed parsers for proposals/positions/votes/rulings, and planner prompt injection of accepted amendments context.

## Acceptance Criteria
- [ ] Add four default prompt templates in `src/prompts/templates.rs`: `default_final_reviewer_template()`, `default_planner_position_template()`, `default_vote_template()`, and `default_arbiter_template()`.
- [ ] Extend template config models to include these four template paths in global, project override, and effective config resolution (`project > global > default`).
- [ ] Add default template path functions in global config and ensure serde/default behavior is covered by tests.
- [ ] Update `ralph init` template scaffolding to write the four new template files and update dry-run/init assertions accordingly.
- [ ] Implement parser data types and functions in `src/workflow/parser.rs`: `parse_final_reviewer_output`, `parse_planner_position_output`, `parse_vote_output`, `parse_arbiter_output`.
- [ ] Parser behavior is fail-closed: invalid H1, missing required sections, missing required amendment IDs, duplicate amendment IDs, or malformed vote/ruling values return `ParseError`.
- [ ] `parse_planner_position_output`, `parse_vote_output`, and `parse_arbiter_output` accept required-ID inputs and enforce full ID coverage exactly (no silent omissions).
- [ ] Add parser unit tests for success and failure paths, including strict ID coverage checks and duplicate-ID rejection.
- [ ] In `build_planner_prompt`, inject `final-review-amendments-applied.md` (when present) using `append_section_if_missing` under `## Final Review Amendments` with alias key `final_review_amendments`.
- [ ] Add planner prompt tests proving amendment context is included when file exists and omitted when absent.
- [ ] Update config CLI projection/setters for new template keys so `config show/get/set` can surface and modify them.
- [ ] `cargo test` passes with the new parser/template coverage.

## Files to Modify/Create
- `src/prompts/templates.rs` - add the four new default FinalReview templates.
- `src/config/global.rs` - add template path fields/defaults for FinalReview templates and related tests.
- `src/config/project.rs` - add project-level template override fields for FinalReview templates.
- `src/config/mod.rs` - add effective template path resolution for the new fields and coverage tests.
- `src/cli/init.rs` - scaffold FinalReview template files in new workspaces and update init tests.
- `src/cli/config.rs` - expose new template keys in effective output and set/get handlers.
- `src/workflow/parser.rs` - add FinalReview parsers, typed parse outputs, and fail-closed tests.
- `src/workflow/orchestrator.rs` - inject `final-review-amendments-applied.md` into planner prompt and add prompt tests.
- `src/validate/tests_init.rs` - update expected template file list/dry-run output.
- `src/validate/tests_auto_init.rs` - assert new template files are auto-created.

## Dependencies
- Requires: FinalReview Phase, Config, and Role Foundations (Loop 1)
- Blocks: Completing -> FinalReview gate, executable FinalReview orchestrator flow/resume logic, final-review status progress reporting, final-review integration and validate conformance tests
