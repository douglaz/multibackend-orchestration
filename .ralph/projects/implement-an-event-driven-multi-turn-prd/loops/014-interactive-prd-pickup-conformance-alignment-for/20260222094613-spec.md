# Feature: Interactive PRD Pickup Conformance Alignment for Bot Login

## Description
Most interactive PRD requirements are already implemented (state machine, labels, persistence, revision loop, approval paths, failure handling, and amendments). The remaining blocker is conformance drift: `interactive_prd::pickup_and_question_posting` fails in `nix build -L` because its mock `gh` script does not implement `gh api user -q .login`, while `Pending -> AwaitingAnswers` now requires bot-login resolution for bot-scoped marker idempotency.  
This feature aligns conformance/integration mocks with the current runtime contract and adds regression coverage so the test suite remains green and restart-safe behavior is still enforced.

## Acceptance Criteria
- [ ] `interactive_prd::pickup_and_question_posting` passes in Nix checkPhase and still verifies label swap, question comment marker, and persisted `AwaitingAnswers` state.
- [ ] The pickup conformance GH mock returns a non-empty login for `gh api user -q .login` and no longer silently bypasses that dependency.
- [ ] A regression test covers `Pending`-stage bot-login failure retry exhaustion (`error_count` increments, then terminal `Failed` with `ralph:prd-failed` after 3 ticks).
- [ ] `./result/bin/ralph validate --bin ./result/bin/ralph --filter interactive_prd` passes fully.
- [ ] `nix build -L` passes end-to-end, satisfying the master prompt criterion that existing tests pass.
