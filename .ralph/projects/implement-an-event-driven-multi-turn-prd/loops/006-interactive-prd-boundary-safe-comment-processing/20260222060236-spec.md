# Feature: Interactive PRD Boundary-Safe Comment Processing and Restart Hydration

## Description
Loops 1-4 delivered the core interactive PRD state machine, but completion review identified correctness gaps. This feature hardens comment-cursor semantics so `AwaitingFeedback` only consumes feedback posted after the latest draft, fixes restart behavior by hydrating `questions_posted_at` from an existing questions marker comment (instead of `Utc::now()`), and adds the missing transition-path and end-to-end test coverage required for project completion.

## Acceptance Criteria
- [ ] `AwaitingFeedback` only considers non-bot comments posted after the latest draft boundary (`latest_draft_comment_id`/draft timestamp), not just after `last_processed_comment_id`.
- [ ] Pre-draft comments are ignored for both approval detection and revision aggregation, even if they were previously unprocessed.
- [ ] When `questions-v{n}` marker already exists, `Pending -> AwaitingAnswers` persists `questions_posted_at` from the existing comment `created_at`.
- [ ] Restart/retry on the same issue does not skip valid user answers that were posted after the real questions comment time.
- [ ] Unit tests directly cover transition decision paths: Pending pickup/idempotent marker reuse, AwaitingAnswers answer selection, AwaitingFeedback approval path, AwaitingFeedback revision path, and retry exhaustion to Failed.
- [ ] Integration tests include one multi-tick end-to-end `Pending -> AwaitingAnswers -> AwaitingFeedback -> Done` flow from empty state.
- [ ] Conformance tests cover draft-boundary filtering and restart continuity for reused question markers.
- [ ] Existing `ralph:ready` daemon behavior and current test suites continue to pass.

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - enforce post-draft feedback boundary, hydrate question timestamp from marker metadata, and add missing transition-path unit tests.
- `src/daemon/github.rs` - extend marker comment helpers to return/reuse structured comment metadata (`id`, `created_at`) for idempotent transitions.
- `tests/daemon_interactive_prd.rs` - add full Pending-to-Done multi-tick integration scenario and regression coverage for pre-draft comment exclusion.
- `src/validate/tests_interactive_prd.rs` - add/extend conformance cases for marker timestamp hydration and post-draft-only feedback handling.
