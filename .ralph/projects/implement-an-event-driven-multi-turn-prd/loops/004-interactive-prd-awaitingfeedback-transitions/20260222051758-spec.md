# Feature: Interactive PRD AwaitingFeedback Transitions (Revision + Done)

## Description
Loops 1-3 are already complete (state foundation, `Pending -> AwaitingAnswers`, and `AwaitingAnswers -> AwaitingFeedback`). The next missing slice is the `AwaitingFeedback` state behavior: process new feedback comments, generate revised drafts when needed, detect approval (comment or label), and close the workflow to `Done` with correct labels and persisted terminal state.

## Acceptance Criteria
- [ ] `advance_issue()` no longer no-ops in `PrdWorkflowState::AwaitingFeedback`; it dispatches to a dedicated transition handler.
- [ ] The transition fetches issue comments and current issue labels each tick and only considers unprocessed non-bot comments (`author_login != bot login`, `id > last_processed_comment_id`).
- [ ] Approval by label is supported: if `ralph:prd-approved` is present, transition to `Done` even without a new approval comment.
- [ ] Approval by comment is supported: new feedback comments are evaluated with `detect_approval()` (negative phrases take precedence; mixed positive+negative is non-approval).
- [ ] On approval (`comment` or `label`), daemon posts idempotent status marker `<!-- ralph:prd:{issue_number}:status-approved-v{n} -->` referencing the latest draft.
- [ ] On approval, labels are updated to remove `ralph:prd-active` and add `ralph:prd-done` (keep `ralph:prd-approved` if already applied), and state is persisted as terminal `Done`.
- [ ] When new feedback exists without approval, all new feedback comments since `last_processed_comment_id` are aggregated in chronological order for a revision prompt.
- [ ] Revision generation uses current draft + aggregated feedback through the existing writer/reviewer + section-validation flow, honoring `daemon_prd_max_revisions` and `daemon_prd_backend_timeout_secs`.
- [ ] Each revision posts exactly one idempotent draft comment with incremented marker `draft-v{n}` and updates `draft_revision`, `latest_draft_comment_id`, `latest_draft_body`, `last_processed_comment_id`, and `last_advanced_at`.
- [ ] If no new feedback and no approval signal, transition is a no-op (state unchanged, no new comments).
- [ ] Errors in `AwaitingFeedback` follow existing retry accounting (`error_count`, `last_error`); on threshold (`>=3`) issue transitions to `Failed` with `status-failed` comment and `ralph:prd-failed` label.
- [ ] Existing `ralph:ready` workflow behavior and previous PRD transitions remain unchanged.
- [ ] Validate conformance adds coverage for: feedback revision, approval by comment, approval by label, and failure labeling from feedback stage.

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - implement `AwaitingFeedback` transition logic (approval path, revision loop, state/label updates, idempotent status-approved marker, retry/failure wiring) and unit tests for feedback parsing/approval edge cases.
- `src/daemon/github.rs` - extend helpers only if needed for cleaner label/comment lookups in feedback transition (reuse existing helpers where possible).
- `tests/daemon_interactive_prd.rs` - add integration tests for revision loop and both approval paths to `Done`.
- `src/validate/tests_interactive_prd.rs` - add required conformance tests for feedback revision, comment approval, label approval, and feedback-stage failure labeling.
