# Implementation Response (Iteration 2)

## Changes Made
1. **Fixed AwaitingFeedback retry semantics on approval-path errors** (`src/daemon/interactive_prd.rs:681-692`): Moved the `last_processed_comment_id` cursor advancement to **after** `do_approval_transition()` succeeds. Previously, the cursor was advanced before the approval transition call (lines 683-686), meaning that if `do_approval_transition()` failed, the next tick would see no "new comments" and return `Ok(())` — clearing error state via `apply_transition_result` and dropping the retry path. Now, `do_approval_transition()` is called first with `?` propagation. Only on success is the cursor advanced. On failure, the approval comments remain "new" on the next tick, allowing proper retry and eventual exhaustion to `Failed` after 3 errors.

2. **Added multi-tick approval failure exhaustion conformance test** (`src/validate/tests_interactive_prd.rs`): New test `approval_failure_exhaustion_transitions_to_failed` runs 3 successive daemon ticks where each tick finds an approval comment ("LGTM") but the `issue comment` (status-approved posting) always fails. Verifies:
   - Ticks 1-2: state remains `AwaitingFeedback`, `error_count` increments, `last_processed_comment_id` does NOT advance (approval comments remain retry-visible)
   - Tick 3: threshold reached, state transitions to `Failed`, `ralph:prd-failed` label is applied
