# Review: SUGGESTIONS

## Required Changes
1. **PRD state persistence path is wired to the wrong root**
   - Current: `run_prd_phase` passes `repo_root` as `PrdPollConfig.data_dir` (`src/daemon/runtime.rs:596`), while `InteractivePrdState` appends `{owner}/{repo}` again in `state_path` (`src/daemon/interactive_prd.rs:177`). This writes to `<repo_root>/<owner>/<repo>/.ralph/interactive-prd/...` instead of the spec path.
   - Expected: Persist at `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/{issue}.json` exactly once (no duplicated owner/repo segment).
   - Reference: Spec acceptance criteria (persist transition fields atomically) and prompt persistence contract (`prompt.md` persistence section).

2. **Retry semantics are not stage-stable and can double-advance in one tick**
   - Current: `Pending -> AwaitingAnswers` removes/adds labels before backend generation (`src/daemon/interactive_prd.rs:413`), but state remains `Pending` until end-of-transition save (`src/daemon/interactive_prd.rs:381`, `src/daemon/interactive_prd.rs:456`). On backend failure, retries re-run label swap from `Pending`, which can fail because `ralph:prd` was already removed. Also, the same issue can be processed again in the same poll cycle because PRD and PRD-active are polled sequentially without dedupe (`src/daemon/interactive_prd.rs:296`, `src/daemon/interactive_prd.rs:309`).
   - Expected: Make transition retries idempotent for partially-applied side effects and enforce one advance attempt per issue per tick (dedupe processed issue numbers).
   - Reference: Spec AC for "at most one state transition per issue per tick" and "recoverable errors retry next tick; fail after 3 stage failures".

3. **Conformance coverage does not match required runtime behaviors**
   - Current: `src/validate/tests_interactive_prd.rs` only validates pure helpers/state constants and does not cover startup label creation, pickup/question posting, or idempotent reprocessing flow required by this loop.
   - Expected: Add validate tests that exercise daemon behavior with mocked `gh` for: startup PRD label ensure, first pickup with `questions-v{n}` posting, idempotent reprocessing, and `ralph:prd` + `ralph:ready` conflict handling in runtime claim path.
   - Reference: Spec AC "Conformance coverage is added..." and file requirements for `src/validate/tests_interactive_prd.rs`.

4. **Existing conformance tests regress and currently fail**
   - Current: `daemon start` now creates 9 labels (including PRD labels) (`src/cli/daemon.rs:152`), but existing validate tests still assert only `github::REQUIRED_LABELS.len()==4` (`src/validate/tests_daemon.rs:776`, `src/validate/tests_daemon.rs:868`). Verified failure with `./target/debug/ralph validate --bin ./target/debug/ralph --filter daemon::label_ensure_startup`.
   - Expected: Update existing daemon conformance tests to account for PRD lifecycle label preflight (or split assertions to both standard and PRD label sets) so the suite passes.
   - Reference: Acceptance criterion "Existing tests pass".
