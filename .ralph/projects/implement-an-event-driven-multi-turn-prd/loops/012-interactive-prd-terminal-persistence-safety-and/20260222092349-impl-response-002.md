# Implementation Response (Iteration 2)

## Changes Made

1. **Status-failed marker idempotency is now strictly bot-scoped** (Required Change 1)
   - Removed the body-only fallback in `transition_to_failed()` (`src/daemon/interactive_prd.rs:1391-1396`). When `bot_login` is unavailable, instead of falling back to `github::post_comment_with_marker()` (which uses body-only lookup and is vulnerable to user marker spoofing), the code now uses `github::post_raw_issue_comment()` — a non-idempotent post that skips duplicate checking entirely.
   - Added `github::post_raw_issue_comment()` helper (`src/daemon/github.rs:471-502`) that posts a comment without any idempotency check, so a user-spoofed `status-failed` marker can never suppress the bot's status comment.
   - The marker text is still included in the comment body (prepended by the caller), but duplicate detection is deliberately skipped when bot identity is unknown, trading potential duplicate comments for spoof resistance.

2. **Save-failure tests are now deterministic across all environments** (Required Change 2)
   - Added `RALPH_TEST_INJECT_SAVE_FAILURE` env-var check in `InteractivePrdState::save()` (`src/daemon/interactive_prd.rs:81-90`). When set, all saves fail with a `PermissionDenied` error deterministically, regardless of privilege level.
   - Replaced all chmod-based failure forcing (three locations) with env-var injection:
     - Integration test `terminal_save_failure_approval_path_keeps_issue_retryable` (`tests/daemon_interactive_prd.rs:2130-2147`): passes `RALPH_TEST_INJECT_SAVE_FAILURE=1` via `daemon_env()`.
     - Integration test `terminal_save_failure_failed_path_keeps_issue_retryable` (`tests/daemon_interactive_prd.rs:2458-2477`): same approach.
     - Validate test `terminal_save_failure_keeps_retry_visibility` (`src/validate/tests_interactive_prd.rs:2798-2808`): same approach.
     - Validate test `terminal_save_failure_failed_path_keeps_retry_visibility` (`src/validate/tests_interactive_prd.rs:3003-3013`): same approach.
   - Removed all `#[cfg(unix)]` permission-manipulation blocks and permission-restoration cleanup code.
   - The env-var check is unconditional (not `#[cfg(test)]`) since the daemon binary is a child process in integration/validate tests and `#[cfg(test)]` would not be set. The check has zero cost when unset (`var_os` is a cheap syscall).

3. **Skip duplicate save for successful Done transitions** (Recommended Improvement)
   - Added early return in `finish_transition()` (`src/daemon/interactive_prd.rs:1018-1022`) when state is `Done` and the transition result is `Ok(())`. Since `do_approval_transition()` already durably persists the Done state before removing labels, the second save in `finish_transition` was redundant and increased the window for transient I/O failures to cause state/label drift.
