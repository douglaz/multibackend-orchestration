# Review: SUGGESTIONS

## Required Changes
1. **Status-failed marker idempotency is still not strictly bot-scoped**
   - Current: `transition_to_failed` falls back to generic marker posting when `bot_login` is unavailable (`src/daemon/interactive_prd.rs:1392`). That generic helper uses body-only lookup (`src/daemon/github.rs:1263`, `src/daemon/github.rs:1298`), so a user-spoofed `status-failed` marker can still suppress the bot status comment in that path.
   - Expected: remove the body-only fallback for PRD status markers. Ensure status marker idempotency remains bot-scoped (resolve bot login in this path, or use a non-idempotent post fallback rather than body-only idempotency).
   - Reference: Loop 12 spec AC: "PRD marker lookup for idempotency is bot-scoped…", "Questions/draft/status marker hydration and idempotent posting use bot-scoped lookup…"

2. **New save-failure tests are non-deterministic and currently fail in privileged environments**
   - Current: integration and validate tests force save failure via chmod read-only directories (`tests/daemon_interactive_prd.rs:2131`, `tests/daemon_interactive_prd.rs:2470`, `src/validate/tests_interactive_prd.rs:3003`). In this environment they do not fail writes (running as privileged user), and tests fail:
     - `nix develop -c cargo test terminal_save_failure_approval_path_keeps_issue_retryable -- --nocapture` (fails at `tests/daemon_interactive_prd.rs:2165`)
     - `nix develop -c cargo test terminal_save_failure_failed_path_keeps_issue_retryable -- --nocapture` (fails at `tests/daemon_interactive_prd.rs:2505`)
     - `nix develop -c cargo run -- validate --bin target/debug/ralph --filter interactive_prd::terminal_save_failure --verbose` (fails at `src/validate/tests_interactive_prd.rs:3028`)
   - Expected: replace permission-based failure forcing with deterministic mechanisms (for example, path-shape failure like replacing expected directory with a file, or explicit failure injection hooks in harness/mocks) so coverage is reliable across environments.
   - Reference: Loop 12 testing ACs (new integration + validate coverage) and master AC "Existing tests pass."
