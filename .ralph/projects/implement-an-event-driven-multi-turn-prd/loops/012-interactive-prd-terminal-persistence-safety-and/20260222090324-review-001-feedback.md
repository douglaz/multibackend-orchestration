# Review: SUGGESTIONS

## Required Changes
1. **Done transition durability ordering**
   - Current: `ralph:prd-active` is removed inside `do_approval_transition` before durable state save occurs (`src/daemon/interactive_prd.rs:856`), while persistence happens later in `finish_transition` (`src/daemon/interactive_prd.rs:995`). Polling only looks at `ralph:prd` and `ralph:prd-active` (`src/daemon/interactive_prd.rs:322`, `src/daemon/interactive_prd.rs:338`), so a save failure can make the issue non-visible for retries.
   - Expected: save terminal `Done` state before removing `ralph:prd-active`, or explicitly restore `ralph:prd-active` on save failure before returning error.
   - Reference: Feature spec acceptance criteria: terminal persistence safety for `Done`, and retry re-entry after terminal save failure.

2. **Status marker spoof hardening is incomplete**
   - Current: failure status posting still uses generic body-only marker idempotency (`github::post_comment_with_marker`) in `transition_to_failed` (`src/daemon/interactive_prd.rs:1363`), so a user-authored spoof marker can suppress bot status comment emission.
   - Expected: status marker posting should use bot-scoped lookup/posting semantics (or equivalent anti-spoof logic) for status comments as well.
   - Reference: Feature spec acceptance criteria requiring bot-scoped marker idempotency for questions/draft/status flows.

3. **Missing required save-failure coverage on failure terminal path**
   - Current: new tests cover approval-path save failure (`tests/daemon_interactive_prd.rs:2045`, `src/validate/tests_interactive_prd.rs:2719`) but there is no corresponding integration/validate case for save failure during transition to `Failed`.
   - Expected: add integration + validate tests that force save failure in `transition_to_failed` and assert issue remains retry-visible (`ralph:prd`/`ralph:prd-active`) with retry semantics preserved.
   - Reference: Feature spec acceptance criteria and testing requirements calling for terminal save-failure recovery coverage on both approval and failure paths.

## Recommended Improvements
1. Make save-failure tests deterministic without filesystem-permission assumptions; permission-based forcing is environment-sensitive (e.g., privileged users), and can miss the intended branch.
