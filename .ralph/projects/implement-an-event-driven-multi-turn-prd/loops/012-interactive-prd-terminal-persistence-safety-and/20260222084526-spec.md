# Feature: Interactive PRD Terminal Persistence Safety and Bot-Scoped Marker Integrity

## Description
Loops 1, 2, 3, 4, 6, 8, and 10 already implemented the core interactive PRD workflow (state machine transitions, retries, approvals, section completeness, and earlier reliability fixes).  
The next logical feature is to close the remaining Round 3 gaps: make terminal transitions persistence-safe under save failures, and make PRD marker idempotency bot-author scoped so user marker spoofing cannot block or poison workflow control data.

## Acceptance Criteria
- [ ] `Done` transition is persistence-safe: `ralph:prd-active` is not removed until durable state save succeeds, or is explicitly restored on save failure so the issue remains poll-visible.
- [ ] `Failed` transition is persistence-safe: label mutations do not leave the issue unpolled when state save fails (issue remains retry-visible via `ralph:prd`/`ralph:prd-active`).
- [ ] Save failures are included in PRD retry accounting (`error_count`, `last_error`) and can trigger retry exhaustion handling after 3 consecutive failures in the same stage.
- [ ] Terminal transition save failures do not silently bypass retry semantics; they re-enter the normal error/retry path on subsequent daemon ticks.
- [ ] PRD marker lookup for idempotency is bot-scoped (`author_login == daemon bot login`) rather than body-only matching.
- [ ] Questions/draft/status marker hydration and idempotent posting use bot-scoped lookup so user-authored spoof markers are ignored.
- [ ] Existing idempotency behavior remains correct when the bot marker already exists (no duplicate bot comments).
- [ ] New integration tests cover terminal save-failure recovery on both approval and failure paths.
- [ ] New integration tests cover spoofed user marker comments and verify bot marker posting/hydration still works.
- [ ] New validate conformance tests cover retry visibility after terminal save failure and marker spoof resistance.

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - Refactor terminal transition ordering/compensation around persistence; route save failures through retry accounting; pass bot identity through PRD marker idempotency/hydration calls.
- `src/daemon/github.rs` - Add bot-scoped marker lookup/post helpers (structured + metadata variants) and keep existing generic helpers backward-compatible.
- `tests/daemon_interactive_prd.rs` - Add regression tests for terminal save-failure recovery and user marker spoof scenarios.
- `src/validate/tests_interactive_prd.rs` - Add conformance cases for terminal save-failure retry visibility and bot-scoped marker idempotency behavior.

## Dependencies
- Requires: Interactive PRD Round-2 Compliance Hardening (Loop 10) and prior PRD transition hardening loops (8/10)
- Blocks: Project completion for `implement-an-event-driven-multi-turn-prd`
