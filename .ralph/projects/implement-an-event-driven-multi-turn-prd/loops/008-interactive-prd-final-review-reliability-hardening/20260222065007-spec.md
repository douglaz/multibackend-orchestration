# Feature: Interactive PRD Final-Review Reliability Hardening

## Description
Loops 1, 2, 3, 4, and 6 already implemented the full interactive PRD flow (state machine, polling, transitions, persistence, restart hydration, and approval/revision behavior). The remaining gaps are the two accepted final-review amendments: (1) bot-login resolution errors currently bypass transition retry accounting, and (2) approval label mutation order can orphan a non-terminal issue from polling on partial failure. This feature closes those last correctness gaps and adds regression coverage in integration and validate suites.

## Acceptance Criteria
- [ ] `AwaitingAnswers` and `AwaitingFeedback` bot-login lookup failures are handled inside transition wrappers so `finish_transition` always applies retry accounting (`error_count`, `last_error`, persisted state).
- [ ] Repeated bot-login failures (`gh api user`) in `AwaitingAnswers` increment `error_count` per tick and transition to `Failed` on the third consecutive failure.
- [ ] Repeated bot-login failures (`gh api user`) in `AwaitingFeedback` increment `error_count` per tick and transition to `Failed` on the third consecutive failure.
- [ ] Approval transition mutates labels in boundary-safe order: add `ralph:prd-done` first, remove `ralph:prd-active` second.
- [ ] If approval label mutation partially fails, the issue remains poll-visible (`ralph:prd-active` still present), state stays non-terminal, and retry semantics continue on next ticks.
- [ ] `Done` is persisted only after approval comment + label operations complete successfully; no duplicate status comments are posted across retries.
- [ ] New integration tests cover bot-login retry exhaustion (both states) and approval label-swap partial-failure recovery.
- [ ] New validate conformance tests cover bot-login retry exhaustion and approval label ordering recovery behavior end-to-end.
- [ ] Existing `ralph:ready` daemon behavior and current interactive PRD conformance tests remain passing.

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - route bot-login resolution through transition error handling; reorder approval label operations; preserve idempotent retry behavior.
- `tests/daemon_interactive_prd.rs` - add regression tests for bot-login failure exhaustion and partial approval label-swap recovery.
- `src/validate/tests_interactive_prd.rs` - add conformance tests for the same two amendment scenarios.
