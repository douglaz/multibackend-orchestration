# Implementation Notes

## Decisions Made
- **Bot-login resolution moved inside transition wrappers**: Instead of calling `get_or_fetch_bot_login()` in `advance_prd_issue()` where the `?` operator would bypass `finish_transition()`, the bot-login resolution is now performed inside `transition_awaiting_answers_to_awaiting_feedback()` and `transition_awaiting_feedback()` using `.and_then()` chaining. This routes bot-login errors through `finish_transition()` → `apply_transition_result()`, ensuring `error_count` increments on each tick and `Failed` state is reached after 3 consecutive failures.
- **Transition wrapper signatures changed from `&str` to `&mut Option<String>`**: Both wrappers now accept `bot_login_cache: &mut Option<String>` instead of a pre-resolved `bot_login: &str`. Cache semantics preserved: successful lookups cached within a tick; failures leave cache empty for next tick retry.
- **Approval label order reversed to boundary-safe**: Changed from remove-active-then-add-done to add-done-then-remove-active. On partial failure, `ralph:prd-active` remains present so the issue stays poll-visible.
- **No changes to `do_approval_transition` state mutation**: `Done` is already assigned after both label ops succeed, so partial failure naturally prevents terminal state. Approval comment is idempotent via marker, preventing duplicates across retries.
