# Feature: Interactive PRD State Machine Foundation

## Description
Establish the foundational types, persistence layer, configuration fields, error variants, and module structure for the event-driven interactive PRD workflow. This includes the `PrdWorkflowState` enum, `InteractivePrdState` persistence struct with atomic JSON save/load, new `WorkspaceConfig` fields with validation, PRD lifecycle label constants, the `interactive_prd` module export in the daemon, an error variant in `RalphError`, and an approval-detection helper. This feature does **not** include runtime integration or GitHub API calls — it purely defines the data model, config surface, and core helpers that all subsequent features will depend on.

## Acceptance Criteria
- [ ] New file `src/daemon/interactive_prd.rs` exists with module-level doc comment.
- [ ] `PrdWorkflowState` enum with variants `Pending`, `AwaitingAnswers`, `AwaitingFeedback`, `Done`, `Failed` — derives `Serialize`, `Deserialize`, `Debug`, `Clone`, `PartialEq`, `Eq`.
- [ ] `InteractivePrdState` struct with all minimum persisted fields from the prompt: `issue_number`, `owner`, `repo`, `state`, `question_revision`, `draft_revision`, `questions_comment_id`, `questions_posted_at`, `latest_draft_comment_id`, `latest_draft_body`, `user_answers`, `last_processed_comment_id`, `error_count`, `last_error`, `last_advanced_at`.
- [ ] `InteractivePrdState::new(owner, repo, issue_number)` constructor initializes to `Pending` with zeroed counters and `None` optionals.
- [ ] `InteractivePrdState::save(data_dir)` writes atomically (temp file + rename) to `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/{issue_number}.json`, creating parent dirs as needed.
- [ ] `InteractivePrdState::load(data_dir, owner, repo, issue_number)` reads from the same path, returning `Ok(None)` if file does not exist.
- [ ] `InteractivePrdState::is_terminal()` returns `true` for `Done` and `Failed`.
- [ ] Approval detection helper function `detect_approval(text: &str) -> bool` that strips fenced code blocks and inline code, checks negative phrases first, then positive phrases with word boundaries (case-insensitive), returns `false` if both positive and negative are present.
- [ ] Comment marker helper `prd_marker(issue_number: u32, kind: &str, version: u32) -> String` producing `<!-- ralph:prd:{issue_number}:{kind}-v{version} -->`.
- [ ] PRD lifecycle label constants: `PRD_LABELS` array containing `ralph:prd`, `ralph:prd-active`, `ralph:prd-approved`, `ralph:prd-done`, `ralph:prd-failed` with colors and descriptions (matching the pattern in `github.rs` for `REQUIRED_LABELS`).
- [ ] `WorkspaceConfig` gains six new fields: `daemon_prd_enabled` (default `true`), `daemon_prd_question_backends` (default `["claude", "codex"]`), `daemon_prd_writer_backend` (default `"claude"`), `daemon_prd_reviewer_backend` (default `"codex"`), `daemon_prd_max_revisions` (default `3`), `daemon_prd_backend_timeout_secs` (default `120`).
- [ ] Config validation: `daemon_prd_question_backends` must contain exactly 2 elements; all backend specs must parse with the existing backend spec parser; invalid config returns a clear `Validation` error.
- [ ] `RalphError` gains variant `InteractivePrdFailed(String)` with exit code 14.
- [ ] `src/daemon/mod.rs` exports `pub mod interactive_prd;`.
- [ ] Unit tests in `interactive_prd.rs` (`#[cfg(test)] mod tests`): state serialization round-trip for all 5 states, approval detection positive/negative/edge cases (including code-block stripping, mixed signals, word boundaries), marker generation, `is_terminal()`, save/load round-trip using `tempdir`.
