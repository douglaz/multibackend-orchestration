# Implementation Notes

## Decisions Made
- Added a new `AwaitingAnswers -> AwaitingFeedback` transition in `src/daemon/interactive_prd.rs` and wired `advance_issue()` to dispatch it when state is `AwaitingAnswers`.
- Implemented per-poll-cycle bot-login caching using new `github::fetch_authenticated_login()` in `src/daemon/github.rs`; bot comments are filtered by exact `author_login == bot_login`.
- Added answer-comment selection logic (`created_at > questions_posted_at`, non-bot, unprocessed) and no-op behavior when no qualifying user comment exists.
- Reused quick-PRD writer/reviewer utilities (`DRAFT_PROMPT`, `REVIEW_PROMPT`, `REVISION_PROMPT`, `check_spec_sections()`, `run_review_with_retry()`) with a transition-scoped deadline and section-retry loop.
- Added shared transition error accounting (`apply_transition_result` / `finish_transition`) so recoverable errors increment `error_count` and trigger `Failed` on the 3rd consecutive error.
- Persisted all required fields on success: `state`, `draft_revision`, `latest_draft_comment_id`, `latest_draft_body`, `user_answers`, `last_processed_comment_id`, `last_advanced_at`.
- Added tests:
  - Unit coverage in `src/daemon/interactive_prd.rs` for bot filtering/answer detection, prompt rendering, no-op detection path, and error accumulation/failure trigger.
  - Integration coverage in `tests/daemon_interactive_prd.rs` for seeded `AwaitingAnswers` state transitioning to `AwaitingFeedback` with `draft-v1` posting.
  - Conformance coverage in `src/validate/tests_interactive_prd.rs` with new `interactive_prd::answer_to_draft`.
