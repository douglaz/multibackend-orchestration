# Feature: Cache + Lock + Answers

## Description
Implement the persistence layer for the PRD pipeline: the `CacheManager` for reading/writing stage artifacts under `.ralph/prd/<idea_hash>/`, the `AnswerStore` for YAML-based answer persistence with merge and hashing, and the `PrdLock` RAII guard for preventing parallel cache corruption via `fs2` file locking. This is implementation order step 3 from the master prompt, following the now-completed scaffolding (loop 1) and core types (loop 2). All three components are currently empty stubs.

## Acceptance Criteria
- [ ] `src/prd/cache.rs` implements `CacheManager` with `new(workspace_root, idea)` that computes `idea_hash = sha256_hex(&idea)[..12]` and creates the `.ralph/prd/<idea_hash>/` directory
- [ ] `CacheManager::acquire_lock()` acquires an `fs2` exclusive file lock on `.ralph/prd/<idea_hash>/.lock`, returning an RAII `PrdLock` guard (modeled on `src/util/lock.rs` pattern)
- [ ] `CacheManager::read_stage_output(stage)` / `write_stage_output(stage, content)` read and write files named by `Stage::artifact_filename()` (`01_ideation.md`, `02_research.md`, `03_synthesis.md`, `04_prd.md`)
- [ ] `CacheManager::read_meta()` / `write_meta(meta)` serialize and deserialize `PrdMeta` as `meta.json`
- [ ] `CacheManager::write_missing_info_report(report)` writes a `missing_info_report.md` file
- [ ] `CacheManager::should_skip_stage(stage, context)` compares a `stage_input_hash` (sha256 of idea + relevant answers + prior stage outputs) against the stored hash in `context.stage_input_hashes`, returning `true` if they match
- [ ] Resume validation: on `--resume`, `CacheManager` validates that `meta.json` idea matches current idea; returns `RalphError::PrdCacheMismatch` if mismatched
- [ ] `src/prd/answers.rs` implements `AnswerStore` with `new(path)` pointing to `.ralph/prd/<idea_hash>/answers.yaml`
- [ ] `AnswerStore::load()` reads existing YAML answers file (returns empty map if not found)
- [ ] `AnswerStore::save()` writes the current answers as YAML
- [ ] `AnswerStore::merge(new_answers)` merges a `BTreeMap<String, String>` into the existing answers, overwriting duplicates
- [ ] `AnswerStore::hash()` computes `sha256_hex` of the serialized answers for cache invalidation
- [ ] Unit tests for `CacheManager`: roundtrip write/read for stage outputs, meta.json write/read, `should_skip_stage` returns correct bool, resume mismatch detection
- [ ] Unit tests for `AnswerStore`: YAML roundtrip, merge semantics (new keys added, existing keys overwritten), hash stability (same content produces same hash)
- [ ] Unit tests for `PrdLock`: lock acquisition succeeds, RAII guard releases on drop
- [ ] `cargo test` passes with all new tests
