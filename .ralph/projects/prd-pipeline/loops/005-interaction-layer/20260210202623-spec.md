# Feature: Interaction Layer

## Description
Implement the user interaction abstraction for the PRD pipeline: the `UserInteraction` async trait, `PlainInteraction` for stdin/stdout interactive sessions (with `:back`, `:edit`, `:show`, `:save`, `:quit` commands and `tokio::task::spawn_blocking` for synchronous stdin reads), `NonInteractiveInteraction` that always returns `None`, and `MockInteraction` for testing with canned answer sequences. This also includes the `InteractionContext` struct that conveys current stage, question round, and max rounds to interaction implementations. This is implementation order step 5 from the master prompt, and the last remaining stub module before the pipeline driver can be built.

## Acceptance Criteria
- [ ] `src/prd/interaction.rs` defines the `UserInteraction` async trait with methods: `ask_questions(&self, questions: &[Question], ctx: &InteractionContext) -> Result<Option<BTreeMap<String, String>>>`, `fn status(&self, message: &str)`, `fn stage_complete(&self, stage: &Stage, summary: &str)`
- [ ] `InteractionContext` struct is defined with fields: `stage: Stage`, `question_round: u32`, `max_rounds: u32`
- [ ] `PlainInteraction` implements `UserInteraction` using stdin/stdout — displays each question with its `QuestionKind` (free text, choice list, yes/no), reads input via `tokio::task::spawn_blocking`, supports `:back` (re-ask previous question), `:edit` (re-answer current question), `:show` (display current answers so far), `:save` (accept answers collected so far and return them), `:quit` (return `None` to signal user abort)
- [ ] `PlainInteraction` handles `QuestionKind::Choice` by displaying numbered options and accepting a number; handles `QuestionKind::YesNo` by accepting y/n; handles `QuestionKind::FreeText` as free-form input
- [ ] `PlainInteraction` uses `suggested_default` from `Question` — if present, shows it in the prompt and accepts empty input as the default
- [ ] `NonInteractiveInteraction` implements `UserInteraction`, always returning `Ok(None)` from `ask_questions` and no-oping on `status`/`stage_complete`
- [ ] `MockInteraction` implements `UserInteraction`, taking `Vec<Option<BTreeMap<String, String>>>` in its constructor and popping from the front on each `ask_questions` call; `status` and `stage_complete` are recorded for test assertions
- [ ] Unit tests verify `MockInteraction` returns canned answers in sequence and returns `None` when exhausted
- [ ] Unit tests verify `NonInteractiveInteraction` always returns `None`
- [ ] Unit tests verify `PlainInteraction` command parsing logic for `:back`, `:edit`, `:show`, `:save`, `:quit` (test the parsing/dispatch, not actual stdin I/O)
- [ ] `cargo test` passes with all new tests
