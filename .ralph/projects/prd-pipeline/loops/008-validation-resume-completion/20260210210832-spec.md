# Feature: Validation + Resume Completion

## Description
Loops 1–7 are complete (scaffolding through gap-analysis interactive reruns). The remaining unsatisfied scope from `prompt.md` is implementation-order step 8: wire real `ValidatePrd` behavior and make `--resume` actually reuse cached stage artifacts. Right now `PrdPhase::ValidatePrd` short-circuits directly to `Done`, and resume only checks idea mismatch without skipping stage generation.

## Acceptance Criteria
- [ ] `src/prd/pipeline.rs` implements a real `ValidatePrd` phase that builds the validation prompt (`StagePromptBuilder::build_validation_prompt`), calls `backend.execute()`, and parses fenced JSON with shape `{"valid": bool, "issues": [{"field": "...", "description": "..."}]}`.
- [ ] Validation parsing uses fenced-JSON extraction + `serde_json` and retries parse failures up to 3 attempts with a strict reformat prompt (same retry pattern used for gap analysis).
- [ ] If validation returns `valid: true`, pipeline transitions to `Done` and finalizes normally (`meta.json` + `PRD.md`).
- [ ] If validation returns `valid: false`, pipeline writes an actionable markdown report to cache and returns `RalphError::PrdValidationFailed(...)` (exit code 11), with no auto-repair loop in v1.
- [ ] On `--resume`, pipeline hydrates context from cache (stage outputs and persisted stage input hashes) before stage execution.
- [ ] `RunStage` uses resume-aware skip logic: when cached artifact exists and `CacheManager::should_skip_stage(...)` is true, skip backend stage generation and reuse cached output.
- [ ] If a resumed stage is missing/invalid/hash-mismatched, that stage executes normally and downstream stages are recomputed from that point forward.
- [ ] `CacheManager` persists and reloads per-stage input hashes across runs (e.g., `stage_hashes.json`) so resume checks compare current inputs to previous-run inputs, not in-memory-only values.
- [ ] Existing resume idea guard remains enforced: `cache.validate_resume_idea()` mismatch returns `RalphError::PrdCacheMismatch`.
- [ ] Integration tests in `tests/prd.rs` cover: validation pass, validation fail (exit 11 + report), resume skip path (reduced backend calls), and resume idea mismatch.
- [ ] Integration tests also cover resume invalidation when inputs changed (e.g., answers changed) so affected stages rerun.
- [ ] `cargo test` (and project build path used by this repo) passes with new tests.

## Files to Modify/Create
- `src/prd/pipeline.rs` - Implement `ValidatePrd` state handling, validation parse/retry flow, validation-failure reporting, and resume-aware stage skipping.
- `src/prd/cache.rs` - Add persistence/load APIs for stage input hashes used by resume skip decisions.
- `src/prd/mod.rs` - Export any new cache/pipeline helpers if needed by tests/CLI.
- `tests/prd.rs` - Add integration coverage for validation outcomes and resume behavior (skip, mismatch, invalidation).
