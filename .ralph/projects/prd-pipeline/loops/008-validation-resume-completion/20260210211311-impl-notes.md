# Implementation Notes
## Decisions Made
- Added PRD validation as a real pipeline phase using LLM output parsing with retry (`ValidationResult`, `ValidationIssue`, parse/reformat flow).
- Added cache support for validation/resume metadata:
  - `validation_report.md` writing on validation failure.
  - `stage_hashes.json` read/write for resume-stage invalidation.
- Implemented resume hydration and skip logic in the pipeline:
  - Load cached stage outputs + hashes.
  - Skip stage execution only when `--resume` is enabled and input hash matches.
  - Recompute stages when cache is missing/invalid/hash-mismatched.
- Wired validation into state transitions:
  - Validation pass finalizes to `Done`.
  - Validation failure exits with `PrdValidationFailed` (exit code 11) and writes actionable report.
- Exported validation types/functions from `src/prd/mod.rs` for test/access consistency.

## Spec Deviations
- No functional spec deviations identified.
- Explicitly kept “no auto-repair on validation failure” behavior for v1 (as required).

## Testing
- Added unit tests in `src/prd/gaps.rs` for validation parsing/types and retry behavior.
- Added integration tests in `tests/prd.rs`:
  - `validation_pass_writes_final_prd`
  - `validation_fail_returns_exit_11_with_report`
  - `resume_skips_cached_stages_with_matching_hashes`
  - `resume_invalidates_stages_when_answers_change`
  - `resume_idea_mismatch_returns_cache_mismatch_error`
- Added test helpers for validation stubs (`validation_pass()`, `validation_fail()`).
