# Implementation Notes

## Decisions Made
- **Pipeline Driver**: Implemented `PrdPipeline` as the main execution orchestrator with a `run()` method that executes stages sequentially in `Stage::all()` order (Ideation → Research → Synthesis → Prd).
- **Deterministic Gap Checks Only**: Loop 6 implements only deterministic missing-section detection via `check_stage_output`. LLM-based gap analysis and interactive question/rerun flow are deferred to loop 7.
- **Lock Acquisition**: Pipeline acquires and holds a cache lock for the entire run duration using `CacheManager::acquire_lock()`, preventing concurrent cache corruption.
- **CLI Integration**: Updated `src/cli/prd.rs` to instantiate all components (cache, answers, interaction, pipeline) and execute the pipeline, replacing the placeholder output.
- **TTY Auto-Detection**: Preserved existing behavior where `--non-interactive` or non-TTY stdin (unless `--interactive` is explicitly passed) triggers non-interactive mode.
- **MockBackend Enhancement**: Added `call_count` tracking to `MockBackend` to enable verification that backend is called exactly once per stage in tests.
- **Stage Artifacts**: Each stage's output is written to cache as `01_ideation.md` through `04_prd.md`, with cleaned output (frontmatter stripped) stored in `PipelineContext.stage_outputs`.
- **Final PRD Output**: On success, `04_prd.md` is copied to `PRD.md` in the current working directory and returned in `PrdResult.prd_path`.
- **Metadata Recording**: `PrdMeta` captures `started_at`, `completed_at`, `stage_timings`, `question_rounds`, and `rerun_stages`, written to `meta.json` in cache.

## Spec Deviations
None. All acceptance criteria implemented as specified.
