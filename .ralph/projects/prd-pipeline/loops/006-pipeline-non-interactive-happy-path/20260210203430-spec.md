# Feature: Pipeline + Non-Interactive Happy Path

## Description
Loops 1-5 are complete (scaffolding/CLI wiring, core types, cache+answers, stage prompts/parsers, interaction layer). The next logical feature is implementing the first runnable PRD pipeline driver and wiring `ralph prd` to execute it end-to-end in non-interactive mode. This loop should cover sequential stage execution, cache artifact persistence, metadata/result output, and deterministic missing-info failure handling, while deferring LLM gap-analysis reruns and PRD validation to later loops.

## Acceptance Criteria
- [ ] `src/prd/pipeline.rs` is implemented (no stub) with `PrdOptions`, `PrdPipeline`, and `PrdResult` types aligned to the PRD prompt contract.
- [ ] `PrdPipeline::run()` executes stages strictly in `Stage::all()` order: `Ideation -> Research -> Synthesis -> Prd`.
- [ ] Each stage uses `StagePromptBuilder::build_stage_prompt(stage)` and calls `backend.execute()` exactly once per stage in the happy path.
- [ ] Stage output is checked with deterministic parsing via `check_stage_output`; cleaned output is used for downstream stages and persisted artifacts.
- [ ] On deterministic missing sections, pipeline writes `missing_info_report.md` in cache and returns `RalphError::PrdMissingInfo` (exit code 12).
- [ ] Successful stage runs write stage artifacts (`01_...md` through `04_prd.md`) and update `PipelineContext.stage_outputs` + `stage_input_hashes`.
- [ ] Pipeline records run metadata in `PrdMeta` (`started_at`, `completed_at`, `stage_timings`, `question_rounds`) and writes `meta.json`.
- [ ] Pipeline acquires and holds cache lock (`CacheManager::acquire_lock`) for run duration to prevent concurrent cache corruption.
- [ ] On success, final PRD is written to `PRD.md` in current working directory and returned in `PrdResult.prd_path` with summary text.
- [ ] `src/cli/prd.rs` is updated to instantiate cache/answers/interaction/pipeline and execute `pipeline.run().await` instead of placeholder printing.
- [ ] CLI keeps current TTY auto-detection behavior; non-interactive mode is used when `--non-interactive` or non-TTY stdin (unless `--interactive`).
- [ ] Integration tests in `tests/prd.rs` cover:
- [ ] Happy path: 4 mock backend responses produce `PRD.md`, cache artifacts, and success result.
- [ ] Non-interactive gap path: missing required section triggers `PrdMissingInfo` and writes `missing_info_report.md`.
- [ ] This loop intentionally does not implement LLM gap-analysis retries, interactive question/rerun flow, or PRD validation/resume logic (reserved for subsequent loops).

## Files to Modify/Create
- `src/prd/pipeline.rs` - Implement pipeline driver, options/result types, stage execution loop, deterministic gap failure handling, metadata writing, final PRD output.
- `src/cli/prd.rs` - Replace placeholder output with real pipeline construction/execution and result reporting.
- `src/prd/mod.rs` - Export pipeline types (`PrdPipeline`, `PrdOptions`, `PrdResult`) as needed by CLI/tests.
- `tests/prd.rs` - Add integration tests for non-interactive happy path and deterministic-gap failure behavior.

## Dependencies
- Requires: Interaction Layer (loop 5), plus completed loops 1-4 foundations
- Blocks: Gap Analysis + Interactive Flow (loop 7), Validation + Resume (loop 8)
