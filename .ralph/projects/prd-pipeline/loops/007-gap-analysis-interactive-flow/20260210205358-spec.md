# Feature: Gap Analysis + Interactive Flow

## Description
Wire the LLM-based gap analysis into the pipeline's `CheckGaps` phase, implementing fenced JSON parsing with up to 3 retries, and connect the full interactive loop: `CheckGaps → AskUser → ApplyAnswers → MaybeRerun`. When the LLM gap analyzer detects missing information or ambiguities after a stage, the pipeline presents questions to the user via the `UserInteraction` trait, merges their answers, determines the earliest impacted stage via `min(question.impact_stage)`, invalidates downstream outputs, and reruns from that stage. In non-interactive mode or when `ask_max` question rounds are exceeded, the pipeline writes `missing_info_report.md` and returns `PrdMissingInfo` (exit 12). This transforms the pipeline from a linear non-interactive executor into the full gap-detection-and-rerun state machine described in the master prompt.

- [ ] `src/prd/gaps.rs` gains a public `run_llm_gap_analysis(backend, stage, stage_output, context) -> Result<GapReport>` async function that: builds the gap analysis prompt via `StagePromptBuilder::build_gap_analysis_prompt()`, calls `backend.execute()`, parses the response, and on parse failure retries up to 3 times with a reformat prompt (following the `execute_with_parse_retries` pattern from the orchestrator)
