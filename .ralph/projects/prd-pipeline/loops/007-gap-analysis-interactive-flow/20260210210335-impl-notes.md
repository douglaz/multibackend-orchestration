# Implementation Notes

## Decisions Made
- Added `parse_gap_report`, fenced JSON extraction, `gap_report_has_questions`, and `run_llm_gap_analysis` in `src/prd/gaps.rs` with 3 parse attempts using a reformat prompt.
- Implemented parse-failure fallback in `run_llm_gap_analysis` to return an empty `GapReport` after retries so pipeline execution can continue.
- Refactored `src/prd/pipeline.rs` from sequential execution into a `PrdPhase` state machine with `CheckGaps -> AskUser -> ApplyAnswers -> MaybeRerun`.
- Implemented `CheckGaps` to run deterministic checks first, then LLM gap analysis, and return `PrdMissingInfo` with `missing_info_report.md` in non-interactive mode or when `ask_max` is reached.
- Implemented `AskUser`, `ApplyAnswers`, and `MaybeRerun` phases with answer merge/save/hash updates and rerun start at `min(question.impact_stage)` for answered questions.
- Added markdown missing-info reporting for gap reports (questions, missing fields, ambiguities, suggested defaults).
- Added `is_interactive()` to `UserInteraction` in `src/prd/interaction.rs` for explicit mode handling.
- Updated `src/prd/mod.rs` re-exports for new gap-analysis APIs/types.
- Added loop-7 integration coverage in `tests/prd.rs` and parse unit coverage in `src/prd/gaps.rs`.

## Spec Deviations
- `ValidatePrd` remains a pass-through to `Done` (validation logic is still loop 8 scope).
- Gap-analysis parse exhaustion falls back to an empty `GapReport` instead of hard-failing, to satisfy the required fallback behavior.

- Added integration test for gap-analysis JSON parse failures retried 3 times then fallback.
