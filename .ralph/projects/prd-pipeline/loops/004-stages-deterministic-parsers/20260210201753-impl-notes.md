# Implementation Notes

## Decisions Made

### Prompt Template Design
- Embedded prompts as `const &str` with `{{placeholder}}` syntax for simple string replacement
- Each stage prompt includes explicit role assignment, required output sections, and formatting instructions
- Gap analysis and validation prompts explicitly request fenced JSON blocks with schema examples
- Used multi-line string literals for readability with preserved formatting

### Stage Dependency Injection
- `build_stage_prompt()` function handles conditional inclusion of prior stage outputs based on stage type
- Ideation: only idea + answers
- Research: adds ideation output
- Synthesis: adds ideation + research outputs
- PRD: adds all three prior outputs

### Output Validation Strategy
- `check_stage_output()` performs deterministic heading validation after stripping frontmatter
- Returns `StageCheckResult` with cleaned content and list of missing sections
- Reuses `strip_frontmatter()` from existing `src/workflow/parser.rs`
- Simple substring matching for `## <heading>` patterns (case-sensitive, exact match)

### Structured Result Types
- `StagePromptContext` encapsulates all inputs needed for prompt building
- `StageCheckResult` provides both cleaned output and validation results for downstream consumption
- All functions return `Result<T>` for consistent error handling

## Spec Deviations

None - all acceptance criteria implemented as specified.
