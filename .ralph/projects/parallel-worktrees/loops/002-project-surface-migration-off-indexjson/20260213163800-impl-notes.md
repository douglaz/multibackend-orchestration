# Implementation Notes

## Decisions Made

- **Migrated all index consumers, not just scoped files:** The spec listed only `workspace/mod.rs`, `lifecycle.rs`, `cli/project.rs`, validate tests, and `tests/init_command.rs` as files to modify. However, removing index writes from `create_project` broke every consumer that read from `workspace.index` (MCP handlers, status, history, tail, config, rollback, orchestrator). Rather than leaving those broken, I migrated all of them to use the new scan-based APIs (`workspace.active_project_id()`, `workspace.project_exists()`, `workspace.list_projects()`, `workspace.load_project_summary()`) and removed the `persist_state_and_index` function (renamed to `persist_state` which only writes `state.json`).

- **Kept `index.rs` and `index` field on `Workspace`:** The `WorkspaceIndex` struct, `ProjectRef`, and `ProjectLifecycleStatus` are retained in `src/workspace/index.rs` for now. The `Workspace` struct still carries an `index` field populated with a default empty index. This allows `Workspace::load` to gracefully handle both presence and absence of `index.json` and supports the one-time migration path. The index module can be deleted in a follow-up loop once all references are confirmed removed.

- **`create_project` signature changed from `&mut Workspace` to `&Workspace`:** Since we no longer mutate `workspace.index` in `create_project`, the function now takes an immutable reference. All callers were updated accordingly (`cli/project.rs`, `cli/auto.rs`, `mcp/handlers.rs`, `tests/mcp_handlers.rs`).

- **Rollback no longer syncs to index:** The rollback command's block that updated `ProjectRef` fields and called `save_index()` (lines 149-174) was removed entirely. Rollback now only writes `state.json`.

- **Orchestrator `persist_state_and_index` renamed to `persist_state`:** The function body was simplified to just call `save_project_state`. All 6 call sites were updated.

- **`check_parent_project_consistency` simplified:** Instead of comparing `index_entry.parent_project` vs `state.parent_project`, it now just checks whether the referenced parent project directory exists via `workspace.project_exists()`.

- **`project show --json` output format changed:** The `project` section in JSON output now uses `ProjectSummary` fields instead of serialized `ProjectRef`. The fields are the same semantically but the serialization format differs slightly (e.g., `status` is now the `ProjectStatus` enum value, `created_at` uses RFC3339 format).

## Spec Deviations

- **Broader migration scope than specified:** The spec listed 8 files to modify. I modified 14 source files and 1 test file because all index consumers needed updating to avoid breaking the test suite. The additional files are: `src/cli/status.rs`, `src/cli/history.rs`, `src/cli/tail.rs`, `src/cli/config.rs`, `src/cli/rollback.rs`, `src/cli/auto.rs`, `src/workflow/orchestrator.rs`, `src/mcp/handlers.rs`, `tests/mcp_handlers.rs`.

- **`index.rs` not deleted:** The spec suggested keeping it temporarily. It is retained with all types intact, but no code writes to or reads from `index.json` any longer. The `Workspace.index` field is populated with a default empty `WorkspaceIndex` when no `index.json` exists.

- **`save_index()` and `active_project()` methods retained but unused:** These methods remain on `Workspace` for now since `index.rs` is retained. They have no callers and can be removed in a follow-up.
