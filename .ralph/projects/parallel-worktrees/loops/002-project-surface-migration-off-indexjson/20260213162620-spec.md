# Feature: Project Surface Migration Off `index.json`

## Description
Loop 1 completed the core infrastructure (`ProjectSummary`, scan APIs, atomic `ProjectState::save`, and worktree-local active project storage).  
The next logical feature is cutting over project-management workflows so `ralph init` and `ralph project {new,list,use,show}` no longer depend on or mutate `.ralph/index.json`, including one-time migration of legacy `active_project` into local worktree storage.

## Acceptance Criteria
- [ ] `Workspace::init` no longer creates `.ralph/index.json`.
- [ ] `Workspace::load` does not require `.ralph/index.json` and does not fail if it is missing.
- [ ] One-time migration exists: if local active-project file is absent and legacy `.ralph/index.json` contains `active_project` for an existing project, it is copied to local active storage and a migration message is logged.
- [ ] Legacy `index.json` parse errors or missing project IDs during migration are ignored without failing workspace load.
- [ ] `create_project` checks duplicates via `workspace.project_exists()` and removes `workspace.index.add_project(...)` / `workspace.save_index()` writes.
- [ ] `create_project` auto-activates via `workspace.set_active_project_id()` only when no local active project is already set.
- [ ] `ralph project new` writes project files (`prompt.md`, `state.json`, optional `config.toml`) without updating shared registry state.
- [ ] `ralph project list` uses `workspace.list_projects()`, remains deterministically sorted by project ID, and uses `workspace.active_project_id()` for the active marker.
- [ ] `ralph project use <id>` validates project existence via `.ralph/projects/<id>/state.json` and writes only worktree-local active-project storage.
- [ ] `ralph project show` resolves project ID from `--project` or `workspace.active_project_id()`, loads metadata via `workspace.load_project_summary()`, and does not read `workspace.index`.
- [ ] Stale active-project IDs (file points to missing project) are treated as no active project with a user-facing hint to run `ralph project use <id>`.
- [ ] Validate conformance tests are updated so init/project coverage no longer depends on `index.json` and includes migration + stale/corrupt active-project cases.

## Files to Modify/Create
- `src/workspace/mod.rs` - migrate init/load behavior, add one-time legacy active-project migration path, and remove project-command reliance on index-backed helpers.
- `src/project/lifecycle.rs` - remove index writes from `create_project`; use `project_exists` and `set_active_project_id`.
- `src/cli/project.rs` - migrate `new`, `list`, `use`, and `show` to scan-based summaries and local active-project resolution.
- `src/validate/harness.rs` - add/standardize `load_active_project()` and `assert_no_index_json()` helpers for conformance tests.
- `src/validate/tests_init.rs` - assert `ralph init` does not create `index.json`.
- `src/validate/tests_project.rs` - migrate project command assertions to scan/local-active behavior; add migration and stale-active scenarios.
- `tests/init_command.rs` - remove `index.json` expectations and assert local active-project behavior.
- `src/workspace/index.rs` - keep temporarily for non-migrated consumers, but remove project workflow dependencies on it in this loop.

## Dependencies
- Requires: Core Infrastructure — ProjectSummary, Atomic Save, and Worktree-Local Active Project
- Blocks: Runtime and MCP migration off index (`run/status/history/tail/rollback`, `config`, `mcp` handlers) and final removal of `WorkspaceIndex`
