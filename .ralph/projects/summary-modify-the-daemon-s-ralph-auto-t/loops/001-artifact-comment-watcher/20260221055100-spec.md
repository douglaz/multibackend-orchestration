# Feature: Artifact Comment Watcher

## Description
Implement an async watcher task that runs alongside each daemon-dispatched child process, polling the child's worktree for artifact files (Quick PRD `SPEC.md` and final reviewed `prompt.md`) and posting them as idempotent GitHub issue comments. The watcher is spawned at child dispatch time, polls every 2 seconds, performs a final sweep on child exit, and handles transient GitHub failures gracefully. This requires extending `ChildHandle` with watcher lifecycle management, adding `tokio-util` for `CancellationToken`, and implementing the full `post_artifact_comments` async function in `src/daemon/runtime.rs`.

## Acceptance Criteria
- [ ] `tokio-util` added to `Cargo.toml` with `rt` feature for `CancellationToken` support.
- [ ] `ChildHandle` in `src/daemon/mod.rs` extended with `watcher_cancel: CancellationToken` and `watcher_handle: Option<tokio::task::JoinHandle<()>>` fields.
- [ ] New `post_artifact_comments(...)` async function in `src/daemon/runtime.rs` that polls every 2 seconds for artifact files in the child worktree.
- [ ] Quick PRD detection: scans `.ralph/quick-prd/*/SPEC.md` glob, selects newest file by mtime (with lexical tiebreak) that has mtime >= `child_start_time`, reads content, and posts idempotent comment with marker `<!-- ralph:task:{task_id}:quick-prd -->` and header `### Quick PRD`.
- [ ] Final prompt detection: looks for `.ralph/projects/*/prompt-original.md` signal with mtime >= `child_start_time`, then reads sibling `prompt.md` in same directory; posts idempotent comment with marker `<!-- ralph:task:{task_id}:final-prompt -->` and header `### Final Prompt (after review)`.
- [ ] Multiple `SPEC.md` candidates are resolved deterministically: newest mtime wins, lexical path order as tiebreaker.
- [ ] Comment body includes full artifact content, truncated with `[truncated]` note if exceeding GitHub's ~65536-character comment limit.
- [ ] Empty, missing, or unreadable artifacts are never posted.
- [ ] Watcher is spawned in `dispatch_task(...)` immediately after child spawn, only when GitHub context (owner/repo/issue_number) is available.
- [ ] `child_start_time` captured at spawn time and passed to watcher; artifacts older than this timestamp are ignored.
- [ ] `collect_children(...)` signals watcher cancellation, performs one final sweep (by awaiting the watcher join handle), then proceeds with label updates and cleanup.
- [ ] Transient GitHub post failures logged and retried on subsequent poll cycles without crashing the dispatch or watcher.
- [ ] If artifact never appears before child exits, no comment is posted for that artifact type.
- [ ] Existing daemon behaviors (labels, PR flow, refined-prompt comment, rebase logic) remain unchanged.
- [ ] Unit test: Quick PRD detection posts correct marker, header, and body content.
- [ ] Unit test: Final prompt uses `prompt-original.md` as signal and reads sibling `prompt.md`.
- [ ] Unit test: Artifacts with mtime older than `child_start_time` are ignored.
- [ ] Unit test: Multiple `SPEC.md` candidates select deterministic newest file.
- [ ] Unit test: Cancellation triggers final sweep (no missed artifact at shutdown boundary).
- [ ] Unit test: GitHub post failure retries without panic.
- [ ] Integration test: Single dispatch posts both comments (with mock GitHub).
- [ ] Idempotency test: Re-dispatch or retry does not duplicate either comment.
- [ ] Conformance test: Validates artifact-comment behavior in real binary flow with mocks.
