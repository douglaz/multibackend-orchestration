# Implementation Notes

## Decisions Made
- Added `tokio-util` with `rt` feature in `Cargo.toml` (and lockfile) and extended `ChildHandle` with `watcher_cancel` + `watcher_handle` in `src/daemon/mod.rs`.
- Implemented daemon artifact watcher flow in `src/daemon/runtime.rs`:
  - New async watcher `post_artifact_comments(...)` polling every 2 seconds.
  - Detection helpers for:
    - Quick PRD: `.ralph/quick-prd/*/SPEC.md` (newest by mtime, lexical tiebreak, mtime >= `child_start_time`).
    - Final prompt: `.ralph/projects/*/prompt-original.md` as signal + sibling `prompt.md`.
  - Truncation helper for GitHub comment size with `[truncated]` note.
  - Idempotent posting via existing marker-based GitHub comment API.
  - Retry behavior on transient post failures by only marking artifact posted after marker verification.
- Wired watcher lifecycle:
  - Spawned immediately after child spawn in `dispatch_task(...)` with captured `child_start_time`.
  - On child completion/abort/drain timeout, cancel + await watcher join before cleanup/terminal transitions.
- Added unit/integration-style runtime tests in `src/daemon/runtime.rs` for:
  - Quick PRD post content/marker/header.
  - Final prompt signal behavior.
  - Stale artifact mtime filtering.
  - Deterministic candidate selection.
  - Truncation behavior.
  - Cancellation final sweep.
  - Retry-after-failure behavior.
  - Single-run posting of both artifacts.
  - Idempotency across reruns.
- Added validate conformance case in `src/validate/tests_daemon.rs`:
  - `daemon::runtime_artifact_comments_posted` validates real binary daemon flow posts both artifact comments with markers/headers/content and no duplicates.
