# Implementation Notes

## Decisions Made
- **Echo backend setup**: Created a shared `setup_echo_backend` helper in `tests_backend_exec.rs` that initializes the workspace and configures both `claude` and `codex` backends to use the `backend_exec_echo_script()` POSIX mock. Args are set to `[]` to prevent stale default args from interfering.
- **Unknown backend test**: Uses `nonexistent_backend_xyz` as the backend name to trigger the `unknown backend` error path in `cli/backend.rs:58-63`. Asserts non-zero exit and stderr contains `"unknown"` (contains-based only, per spec).
- **Disabled-default-backend test**: Uses `ralph run --project ... --loops 1` as the command that resolves the default backend through `BackendRegistry`, which checks `BackendEnabled::Disabled` and returns `BackendUnavailable { backend }` → error message `"backend unavailable: openrouter"`. This is the cleanest path to exercise the disabled-backend check, since `backend exec` bypasses `BackendRegistry` and calls `backend_from_config` directly.
- **Non-spawn proof**: The disabled-backend test sets up an arg-logging mock script and asserts the log file is absent after the command fails, proving the openrouter process was never spawned.
- **Failure-mode invariant for unknown backend**: Asserts that the `.ralph/projects/` directory either doesn't exist or is empty, proving no project state was mutated.
- **Model injection test**: Uses `openrouter_arg_logging_script` which logs `"$@"` to a file. Configures openrouter with `enabled=true`, empty args, and the mock command. Runs `backend exec "openrouter(test-model)"` and verifies the logged args contain both `--model` and `test-model`.

## Spec Deviations
- None. All 6 tests (4 backend_exec + 2 openrouter) implemented exactly as specified. All assertions are contains-based and use zero/non-zero exit checks only.
