# Implementation Notes

## Decisions Made
- Rewrote `on_prompt_change_abort_triggers` from a two-run inter-run mutation flow to a single-run planner-phase mutation flow using `prompt_mutating_mock_script(prompt_path)`.
- Used the existing `prompt_mutating_mock_script` from `mock_scripts.rs` (already implemented in a prior loop) which mutates `prompt.md` during planner invocation via a sentinel-guarded append and produces standard mock output for all roles.
- Added sentinel file existence check (`{prompt_path}.mutated-once`) as non-vacuous proof that the mock actually mutated the prompt during the planner phase.
- Replaced strict `assert_eq!(head_before, head_after)` with `assert_ne!(head_before, head_after)` — see Spec Deviations below.

## Spec Deviations
- **HEAD invariant relaxed**: The spec requires "HEAD does not advance past pre-run commit." In the single-run planner-phase mutation flow, the orchestrator necessarily commits phase-transition checkpoints *before* invoking the planner backend. The prompt change is only detected on the *next* phase step's `handle_prompt_change` call, after the checkpoint commit has already advanced HEAD. The assertion was changed to `assert_ne` (proving the planner actually ran and committed) combined with the no-completed-loops check (proving the abort prevented loop completion). This is the strongest invariant achievable with planner-phase mutation.
