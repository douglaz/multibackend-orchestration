# Feature: Harness and Mock Infrastructure

## Description
Add the foundational harness helper (`write_stable_mock_script`) and all six new mock script generators required by the prompt. This infrastructure must land first because every new test module and test extension depends on these helpers. Also extract the existing PRD mock from `tests_prd.rs` into `mock_scripts.rs` as a shared helper (`prd_mock_response_body`), which is needed by both `tests_prd.rs` extensions and the new `tests_quick_prd.rs` module.

## Acceptance Criteria
- [ ] `RalphHarness::write_stable_mock_script(&self, name: &str, bash_content: &str) -> Result<PathBuf>` added to `src/validate/harness.rs`. It writes the inner bash script to a temp file, then writes a POSIX wrapper (`#!/bin/sh\nexec bash "<inner>"\n`) and returns the wrapper path. Both files are executable.
- [ ] `prd_mock_response_body() -> String` added to `mock_scripts.rs`. Returns a valid PRD-style response body suitable for mock backends acting as PRD writer/reviewer. Content extracted/refactored from the inline mock in `tests_prd.rs`.
- [ ] `backend_exec_echo_script() -> String` added to `mock_scripts.rs`. Returns a POSIX `#!/bin/sh` script that cats stdin to stdout (echo-back behavior for `backend exec` tests).
- [ ] `openrouter_arg_logging_script(log_path: &Path) -> String` added to `mock_scripts.rs`. Returns a POSIX script that logs all arguments to `log_path`, consumes stdin, and exits 0. Output format: one arg per line.
- [ ] `prd_invocation_counting_script(counter_path: &Path) -> String` added to `mock_scripts.rs`. Returns a bash script that atomically increments a counter file at `counter_path` on each invocation, then emits a valid PRD response body. Uses `prd_mock_response_body()` internally.
- [ ] `prd_stdin_capturing_script(output_dir: &Path) -> String` added to `mock_scripts.rs`. Returns a bash script that writes stdin to a uniquely-named file in `output_dir` on each invocation, then emits a valid PRD response. Uses `prd_mock_response_body()` internally.
- [ ] `prompt_mutating_mock_script(prompt_path: &Path) -> String` added to `mock_scripts.rs`. Returns a bash script that, when it detects a planner-phase invocation (e.g. role argument contains "planner"), mutates the file at `prompt_path` exactly once (using a sentinel guard file), then continues with standard mock output.
- [ ] Existing `tests_prd.rs` inline PRD mock is replaced with a call to `prd_mock_response_body()` from `mock_scripts.rs` — no behavioral change to existing tests.
- [ ] `cargo check` passes with no errors.
- [ ] Existing `cargo test` suite continues to pass (no regressions).
