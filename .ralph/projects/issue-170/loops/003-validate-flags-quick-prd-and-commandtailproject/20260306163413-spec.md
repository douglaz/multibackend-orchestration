# Feature: Validate Flags, Quick-PRD, and Command/Tail/Project Extensions

## Description
With the harness/mock infrastructure (loop 1) and backend-exec/openrouter modules (loop 2) complete, this feature delivers the two remaining new test modules (`tests_validate_flags.rs`, `tests_quick_prd.rs`) and six extensions to existing modules (`tests_commands.rs`, `tests_tail.rs`, `tests_project.rs`). Together these add 12 conformance tests covering `ralph validate` self-flags, standalone `quick-prd` behavior, rollback edge cases, `config edit` error handling, `tail --follow` liveness, and `project new --from` parent linkage.

## State Invariants
- `rollback_dry_run`: After dry-run rollback, HEAD must be identical to pre-rollback HEAD, and all loop directories must still exist. No state mutation occurs.
- `rollback_with_completion_attempts`: After rollback past a completion attempt, the completion-attempt artifact directory must not exist and state must reflect only loops up to the rollback target. If rollback fails mid-operation, loop artifacts above the target may still exist but state must not advance beyond the target.
- `rollback_force_push`: The three-way assertion (remote-before ≠ target, local-after == target, remote-after == local-after) must all hold. If the force-push step fails but the local reset succeeded, local HEAD will differ from remote HEAD — the test must detect this inconsistency by checking remote HEAD explicitly.
- `config_edit_no_editor`: The workspace config file must not be modified when the editor launch fails. The error is surfaced via stderr, not a panic.
- `tail --follow`: The child process must be in a running state (not exited) when liveness is checked. If the child exits before the liveness check, the test fails — this guards against the flag being silently ignored. The child is always killed in a finally-style cleanup regardless of assertion outcome.
- `quick_prd::backend_override_proof`: The poisoned default path must actually fail if used — the test is non-vacuous only because the override routes to a working mock. If both paths succeed, the test provides no override proof.
