# Feature: BackendRegistry Role-Model Resolution

## Description
Loop 1 completed the config layer (`BackendRoleModels`, defaults, and TOML support), but backend selection still returns mostly bare backend specs. This feature wires role-specific model defaults into backend assignment by adding `BackendRegistry::resolve_backend_for_role` and applying it in feature/completion role assignment paths, while preserving alternation behavior and explicit per-role model overrides.

## Acceptance Criteria
- [ ] Add `BackendRegistry::resolve_backend_for_role(&self, base_backend: &str, role: &str) -> String` in `src/backend/mod.rs`.
- [ ] `resolve_backend_for_role` returns `base_backend` unchanged when `base_backend` already includes an explicit model (for example `claude(opus)`).
- [ ] `resolve_backend_for_role` injects the configured role model when `base_backend` is bare and `backends.<name>.models.<role>` is set (for example `claude` + `planner` -> `claude(claude-sonnet-4-5-20250929)`).
- [ ] `resolve_backend_for_role` returns `base_backend` unchanged when role is unknown, backend is unknown, no role model is configured, or spec parsing fails.
- [ ] `assign_feature_backends()` applies `resolve_backend_for_role` to planner, implementer, and reviewer after alternation and per-role override selection.
- [ ] `assign_completion_backends()` applies `resolve_backend_for_role` to planner and completer after alternation and per-role override selection.
- [ ] Per-role override precedence remains correct: explicit override models are not replaced by role-model defaults.
- [ ] Bare per-role overrides (for example `planner_backend = "claude"`) still receive role-model injection.
- [ ] Existing alternation semantics remain intact (odd/even planner alternation and opposite backend selection still work).
- [ ] Add unit tests for `resolve_backend_for_role` covering: model injection, no configured model, explicit model passthrough, and unknown role/backend behavior.
- [ ] Update backend assignment tests to assert model-injected specs for default configs.
- [ ] Update orchestrator/integration assertions that currently expect bare saved backend names where role-model injection now applies.
- [ ] All tests pass.

## Files to Modify/Create
- `src/backend/mod.rs` - add `resolve_backend_for_role` and integrate it into `assign_feature_backends` / `assign_completion_backends`.
- `tests/backend.rs` - add resolver-specific tests and update assignment expectations for injected model specs.
- `tests/orchestrator.rs` - update persisted backend expectation checks that currently assume bare names.

## Dependencies
- Requires: BackendRoleModels Config Layer (loop 1)
- Blocks: Reformatter role-model application in parse retries; startup role-model pre-creation/health-check coverage
