# Implementation Notes

## Decisions Made
- **Template naming strategy**: Canonical template files are `spec.md`, `implementation.md`, `review.md`, `completion.md` — matching the artifact/phase names from `prompt.md`. Legacy names (`planner.md`, `implementer.md`, `reviewer.md`, `completer.md`) are preserved as Unix symlinks pointing to the canonical files. This gives zero-cost backward compatibility: existing workspaces that reference legacy names in `ralph.toml` continue to work transparently because symlinks resolve to the same content.
- **`planner_backend` alias**: Implemented as a single `resolve_config_alias()` function called at the entry points of both `execute_get` and `execute_set`, mapping `"planner_backend"` → `"workflow.planner_backend"`. This ensures alias resolution happens in all scopes (global and project) since the underlying `set_global_value`/`set_project_value` already handle the canonical `workflow.planner_backend` key.
- **`history --json` output**: Changed from serializing the full `ProjectState` to building a `Vec<serde_json::Value>` from feature loops + completion attempts, sorted by `loop_number`, and emitting as a top-level JSON array. This matches the spec contract while preserving all per-loop detail.
- **Binary discovery hardening**: The fallback in `tests/validate_cli.rs` now probes `target/debug` then `target/release`, then checks `CARGO_TARGET_DIR` env var for custom target dirs (Nix builds), then tries `which ralph` as a last resort. This covers debug, release, and Nix sandboxed test environments.
- **Config test fixtures**: All TOML test fixtures in `src/config/global.rs` were updated from legacy template paths to canonical paths to match the new defaults.

## Spec Deviations
- The TemplateConfig struct field names (`planner`, `implementer`, `reviewer`, `completer`) remain unchanged — only the default *values* they hold change. This means existing TOML files with `[templates] planner = "..."` continue to parse and work. The TOML key names are role names, not file names, so renaming them is unnecessary and would break backward compatibility with no benefit.

## Testing
- Run `cargo check` to verify compilation
- Run `cargo test --test init_command` to verify init creates canonical files and legacy symlinks
- Run `cargo test --test orchestrator` to verify orchestration flows with new template paths
- Run `cargo test --test validate_cli` to verify binary discovery
- Build and run `ralph validate --bin <binary>` for full 40-test conformance
