# Implementation Notes

## Decisions Made
- **`--bin` path resolution uses `std::fs::canonicalize`**: This resolves symlinks and relative paths to a stable absolute path before any test harness changes the working directory. If the path does not exist, `canonicalize` returns an error that we map to a `RalphError::Validation` with a clear message. On Unix, we additionally check the execute permission bits.
- **Template filename assertions aligned to spec contract, not implementation**: The spec contract (`prompt.md`) specifies `spec.md`, `implementation.md`, `review.md`, `completion.md` as template filenames. The current implementation uses `planner.md`, `implementer.md`, `reviewer.md`, `completer.md`. The conformance tests now assert the *spec contract* filenames. This means these tests will correctly fail against the current implementation, flagging the drift for resolution. The `default_config` TOML path assertions were also updated to match (`templates/spec.md`, etc.).
- **`history --json` asserts top-level JSON array**: The spec contract says the output is a "JSON array". The current implementation outputs a full `ProjectState` object. The conformance test now uses `assert_json_array()` to enforce the spec contract, which will fail against the current implementation.
- **Config keys use flat `planner_backend` per spec**: The spec contract says `ralph config get planner_backend`, not `workflow.planner_backend`. The config tests now use the flat key. The current implementation requires the `workflow.` prefix, so these tests will fail against it, correctly flagging the drift.
- **Backend alternation uses explicit claude/codex assertions with normalization**: Rather than just `assert_ne`, the test now verifies loop 1 planner = `claude` and loop 2 planner = `codex` specifically. The `normalize_backend()` helper strips parenthesized model suffixes like `claude(sonnet-4)` → `claude`.
- **Regression test uses library API with `--list` flag**: The `tests/validate_cli.rs` regression test calls `validate::execute()` directly with a relative path and `list: true` to avoid needing to actually run conformance tests (which would require a full environment). This isolates the path resolution behavior.

## Spec Deviations
- The regression test in `tests/validate_cli.rs` uses `validate::execute()` (library call) rather than invoking the CLI binary as a subprocess. This is because the test needs to exercise the path canonicalization logic inside `execute()`, and using the library API is the most reliable way to do this in a Rust integration test without external tooling. The test still verifies the exact same code path that the CLI uses.
- The `make_relative()` helper in the regression test computes relative paths without the `pathdiff` crate to avoid adding a new dependency.

## Testing
- Run `cargo test --test validate_cli` to verify the relative `--bin` path resolution regression tests.
- Run `cargo test --test validate_cli -- validate_nonexistent_bin_fails_with_error` to verify the non-existent binary error path.
- The conformance tests themselves (`ralph validate --bin <path>`) will intentionally fail for `init::creates_template_files`, `init::default_config`, `commands::history_json`, `commands::config_get`, and `commands::config_set` until the corresponding implementation changes are made to align with the spec contract. This is the expected behavior — the conformance tests now test the *spec*, not the current implementation.
- Test inventory remains exactly 40 conformance tests (5 init + 9 project + 14 run + 12 commands). No tests were added, removed, or renamed.
