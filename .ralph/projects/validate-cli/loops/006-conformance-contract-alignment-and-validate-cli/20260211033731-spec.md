# Feature: Conformance Contract Alignment and Validate CLI Path Resolution

## Description
Loops 1-4 delivered the full `ralph validate` framework and all 40 conformance tests, but completion analysis shows remaining contract drift against `prompt.md`. The next feature is to harden `--bin` path handling and align mismatched conformance assertions (template filenames, `history --json` shape, config key usage, and backend alternation expectations) so validator behavior matches the stated spec rather than local implementation quirks.

## Acceptance Criteria
- [ ] `validate::execute` resolves `--bin` to a stable absolute path before test execution, so relative paths work regardless of per-test harness `cwd`.
- [ ] If `--bin` does not exist or is not executable, `ralph validate` fails deterministically with a clear validation/orchestration error (non-zero exit).
- [ ] `init::creates_template_files` validates the spec contract filenames: `spec.md`, `implementation.md`, `review.md`, and `completion.md` in `.ralph/templates/`, all non-empty.
- [ ] `commands::history_json` validates that `ralph history --json` is a JSON array (not an object wrapper), with at least one loop entry after a run.
- [ ] `commands::config_get` and `commands::config_set` use the spec key `planner_backend` (not `workflow.planner_backend`) and verify read-after-write behavior.
- [ ] `run::two_loops_alternation` verifies loop 1 planner backend is `claude` and loop 2 is `codex`; if backend strings include model suffixes, tests normalize before comparison.
- [ ] A regression test covers relative `--bin` invocation for `ralph validate` and fails before this feature, passes after it.
- [ ] Test inventory remains 40 total conformance tests; no previously completed suite is removed or renamed.

## Files to Modify/Create
- `src/validate/mod.rs` - canonicalize/validate `--bin` path before constructing `TestRunner`.
- `src/validate/tests_init.rs` - align template filename assertions to prompt contract.
- `src/validate/tests_commands.rs` - update `history_json` and config key tests to contract expectations.
- `src/validate/tests_run.rs` - tighten backend alternation assertion to explicit canonical sequence.
- `src/validate/assertions.rs` - add helper(s) for backend normalization and strict JSON-array assertions.
- `tests/validate_cli.rs` - add regression coverage for relative `--bin` resolution (create if missing).
