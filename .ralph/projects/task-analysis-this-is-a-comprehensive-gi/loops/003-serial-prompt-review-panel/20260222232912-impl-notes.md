# Implementation Notes

## Decisions Made
- Replaced single prompt-review backend flow with a serial panel flow: first backend is the refiner, remaining backends run as validators and must emit `ACCEPT` or `REJECT(<reason>)`.
- Added `prompt_review_backends` + `prompt_review_min_reviewers` across global/project/effective config, with plural-over-singular alias precedence and backward compatibility for `prompt_review_backend`.
- Added prompt-review panel validation mirroring completion panel semantics: non-empty list, `min_reviewers >= 1`, dedupe/collision checks, and panel-list backend surface validation (including optional `?` specs).
- Added validator parser/template support: `PromptReviewValidatorVerdict`, `parse_prompt_review_validator_output`, and `templates/prompt_review_validator.md` wiring in effective template config.
- Implemented optional-backend runtime behavior for refiner/validators (skip optional unavailable backends, fail required unavailable backends, enforce minimum validators actually run).
- Preserved canonical `prompt-review.md` from refiner output even on reject paths; added per-validator project-scoped artifacts via `write_project_scoped_artifact`.
- Updated prompt-review completion reconstruction to require both `prompt-review.md` and `prompt-original.md`, preventing rejected validation runs from being reconstructed as completed.
- Added and registered new conformance module `src/validate/tests_prompt_review_panel.rs` covering accept/reject/aggregation/optional-skip/alias/min-reviewers behavior.
