# Feature: Multi-Completer Completion Panel

## Description
Loop 1 (Gemini backend plumbing) is already completed, and the codebase now supports Gemini parsing/registry/guardrails. The next missing scope is Phase 2: replace the single-completer completion flow with a panelized completion flow that runs multiple completers (including optional `?gemini`), records one verdict artifact per completer, applies consensus math, and runs acceptance QA exactly once when the panel reaches `Complete`. This also includes backward-compatible state/artifact reconstruction for existing projects.

## Acceptance Criteria
- [ ] `WorkflowConfig` adds `completion_backends: Vec<String>`, `completion_min_completers: u32`, and `completion_consensus_threshold: f64`.
- [ ] Defaults are exactly: `completion_backends = ["claude","codex","?gemini"]`, `completion_min_completers = 2`, `completion_consensus_threshold = 1.0`.
- [ ] Effective config merge supports project/global overrides for all three new completion fields.
- [ ] Config validation enforces `completion_backends` non-empty, `completion_min_completers >= 1`, and `completion_consensus_threshold > 0.0 && <= 1.0`.
- [ ] Config validation rejects duplicate resolved completer specs after canonicalization (including optional/required variants collapsing to the same backend+model target).
- [ ] Config validation prevents per-backend verdict filename collisions for resolved completer specs.
- [ ] Completion backend resolution applies optional semantics: unavailable optional completers are skipped with warning; unavailable required completers fail the run.
- [ ] Completion backend resolution verifies enough effective completers remain to satisfy `completion_min_completers`.
- [ ] `CompletionLoopBackends` changes from single `completer: String` to `completers: Vec<String>`.
- [ ] Completion artifacts support per-backend verdict files (one file per completer backend) with deterministic backend-specific filenames.
- [ ] Orchestrator completion phase invokes all effective completers and writes one verdict artifact per completer.
- [ ] Completion panel decision is computed with inclusive thresholds: `complete_votes >= completion_min_completers` and `complete_votes / total_effective_completers >= completion_consensus_threshold`.
- [ ] Consensus behavior is covered for 100% threshold, partial threshold (e.g. 0.5/0.67/0.75), and insufficient-vote cases.
- [ ] Acceptance QA executes exactly once after the panel reaches `Complete`, never once per completer.
- [ ] Backward reconstruction maps legacy `completer-verdict.md` into single-completer state and also reconstructs new per-backend verdict layouts.
- [ ] Existing single-completer behavior remains compatible when only one completer is configured.
- [ ] Unit tests cover new defaults, validation, panel resolution, consensus math, and backward reconstruction.
- [ ] Conformance tests cover optional skip vs required failure, multi-completer artifacts/state, and consensus outcomes.
- [ ] `nix develop -c cargo check`, `nix develop -c cargo test`, `nix build -L`, and `./result/bin/ralph validate --bin ./result/bin/ralph` pass.

- `src/validate/mod.rs` - register new completion panel validate module.
