# Review: SUGGESTIONS

## Required Changes
1. **Completion backend failure semantics are bypassed in orchestration**
   - Current: `Phase::Planning` catches *all* errors from completion panel resolution and silently falls back to a single legacy completer (`Err(_) => base_backends.completers.clone()`), which bypasses required-backend failure and min-completer enforcement (`src/workflow/orchestrator.rs:523`, `src/workflow/orchestrator.rs:531`).  
   - Expected: propagate resolution errors for required/unavailable backends and insufficient effective completers; only optional backends should be skipped by `resolve_completion_panel` (`src/backend/mod.rs:1046`, `src/backend/mod.rs:1063`).  
   - Reference: Feature spec acceptance criteria "optional skip vs required failure" and "verify enough effective completers remain to satisfy `completion_min_completers`".

2. **Duplicate completer specs are not actually rejected after canonicalization**
   - Current: `normalize_backend_specs_labeled` deduplicates canonical specs before duplicate checking (`src/config/mod.rs:617`, `src/config/mod.rs:623`), so the later duplicate check cannot fire (`src/config/mod.rs:676`).  
   - Expected: validate duplicates on canonicalized input *before* deduplication, and fail when variants collapse to the same resolved target (e.g. `claude` + `?claude`).  
   - Reference: Feature spec acceptance criterion "Config validation rejects duplicate resolved completer specs after canonicalization".

3. **Filename-collision validation does not match real artifact naming**
   - Current: collision checking uses `completion_verdict_filename` slug logic (`src/config/mod.rs:706`) that differs from artifact writer slug logic (`src/project/artifacts.rs:12`, `src/project/artifacts.rs:23`), so collisions can be missed.  
   - Expected: use the exact same slugification/path logic used by `ArtifactKind::CompleterVerdictBackend` when validating collisions.  
   - Reference: Feature spec acceptance criterion "Config validation prevents per-backend verdict filename collisions".

4. **Reconstruction of new per-backend completion artifacts ignores configured consensus thresholds**
   - Current: reconstruction marks panel `COMPLETE` only when all per-backend verdicts are `COMPLETE` (`src/project/lifecycle.rs:671`, `src/project/lifecycle.rs:693`), while runtime consensus uses `min_completers` + ratio threshold (`src/workflow/orchestrator.rs:1738`, `src/workflow/orchestrator.rs:1742`).  
   - Expected: reconstruction must preserve panel outcomes under partial thresholds (e.g. 0.5/0.67/0.75), not hardcode unanimity.  
   - Reference: Feature spec acceptance criteria for consensus math and backward reconstruction of new per-backend layouts.

5. **Required test coverage for completion panel is incomplete**
   - Current: conformance tests in `src/validate/tests_completion_panel.rs` only exercise threshold `1.0` paths (`src/validate/tests_completion_panel.rs:68`, `src/validate/tests_completion_panel.rs:231`) and do not cover completion-panel optional-skip/required-fail, partial-threshold cases, or insufficient-vote/min-completer failures; unit coverage for completion-panel validation/consensus is also missing in config/orchestrator test modules.  
   - Expected: add the required unit + conformance coverage from the spec (optional skip vs required failure on completion panel, 100% + partial thresholds + insufficient-vote cases, and panel validation paths).  
   - Reference: Required Tests section (items 1–3) and acceptance criteria for consensus outcomes.
