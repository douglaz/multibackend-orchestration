# Feature: Config schema and role timeout resolution

## Description
Add the `RoleTimeouts` struct and all config-layer plumbing: the struct itself with `for_role` / `fill_from` methods, its integration into `BackendConfig` and `PartialBackendConfig`, the partial-config merge logic, `BackendConfig::timeout_for_role`, `BackendRegistry::timeout_for_role`, the enriched `BackendTimeoutExhausted` error variant, and `config set/get/show` CLI support for role timeout keys. This feature establishes the full data model and resolution API that subsequent features (backend trait changes, orchestrator plumbing) will consume.

## Acceptance Criteria
- [ ] `RoleTimeouts` struct exists with all 8 role fields (`planner`, `implementer`, `reviewer`, `qa`, `completer`, `acceptance_qa`, `reformatter`, `prompt_reviewer`) as `Option<u64>`, with `#[serde(default)]` and derives for `Debug, Clone, Serialize, Deserialize, Default, PartialEq, Eq`.
- [ ] `RoleTimeouts::for_role(&self, role: &str) -> Option<u64>` returns the matching field or `None` for unknown roles.
- [ ] `RoleTimeouts::fill_from(&mut self, defaults: &RoleTimeouts)` fills `None` fields from defaults, mirroring `BackendRoleModels::fill_from`.
- [ ] `BackendConfig` has `#[serde(default)] pub role_timeouts: RoleTimeouts`.
- [ ] `PartialBackendConfig` has `role_timeouts: Option<RoleTimeouts>`.
- [ ] `into_backend_config_with_defaults` merges `role_timeouts` using `fill_from`, mirroring the `models` merge pattern.
- [ ] `BackendConfig::timeout_for_role(&self, role: &str) -> Duration` returns the role override (as seconds) when present, otherwise returns `Duration::from_secs(self.timeout_seconds)`.
- [ ] `BackendRegistry::timeout_for_role(&self, backend_spec: &str, role: &str) -> Duration` parses the spec, looks up the base backend config, delegates to `BackendConfig::timeout_for_role`, and falls back to 7200s on any failure.
- [ ] `BackendTimeoutExhausted` error variant is enriched with `role: String` and `timeout_secs: u64` fields; display format and all match arms updated in `orchestrator.rs` and `cli/run.rs`.
- [ ] `config set` supports `backends.claude.role_timeouts.<role>` and `backends.codex.role_timeouts.<role>` with `u64` or `null` values and validates against the 8-role set.
- [ ] `config get` / `config show` expose role timeout values through existing serialization.
- [ ] TOML configs with only `timeout_seconds` (no `role_timeouts` table) deserialize and behave identically to before.
- [ ] Default effective timeout remains 7200s when no role override is configured.
- [ ] Unit tests in `src/config/global.rs`: `for_role` for all 8 roles + unknown role, `fill_from` merge, `timeout_for_role` override + fallback, TOML deserialize with and without `[backends.<name>.role_timeouts]`, partial backend merge of role timeouts.
- [ ] Unit tests in `src/backend/mod.rs`: `BackendRegistry::timeout_for_role` with bare and modeled specs (e.g. `claude(opus)`), unknown backend spec fallback to 7200.
- [ ] Validate conformance test: `config set/get` roundtrip for `backends.<backend>.role_timeouts.<role>` and `null` clearing.
- [ ] New validate module registered in `src/validate/mod.rs`.
- [ ] `cargo check` and `cargo test` pass.
