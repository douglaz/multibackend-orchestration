# Implementation Notes

## Decisions Made
- Added `RoleTimeouts` in `src/config/global.rs` with all 8 roles, `for_role`, and `fill_from`, then integrated it into `BackendConfig` (`role_timeouts`) and `PartialBackendConfig` merge behavior (`fill_from` on partial role timeout tables).
- Added `BackendConfig::timeout_for_role` in `src/config/global.rs` and `BackendRegistry::timeout_for_role` in `src/backend/mod.rs` with 7200s fallback on parse/config lookup failure.
- Enriched `RalphError::BackendTimeoutExhausted` in `src/error.rs` with `role` and `timeout_secs`, and updated construction in `src/workflow/orchestrator.rs` to pass `role` and placeholder `timeout_secs: 0` per spec.
- Added CLI support in `src/cli/config.rs` for `backends.<backend>.role_timeouts.<role>` (`u64` or `null`) via new `set_role_timeout` helper with strict 8-role validation.
- Added unit tests in `src/config/global.rs` for role timeout role mapping, merge behavior, timeout resolution fallback/override, TOML deserialize with/without role timeout table, and partial merge behavior.
- Added unit tests in `src/backend/mod.rs` for `BackendRegistry::timeout_for_role` (bare spec, modeled spec, invalid/unknown fallback).
- Added validate conformance module `src/validate/tests_role_timeouts.rs` and registered it in `src/validate/mod.rs` for config set/get roundtrip + null clearing.
- `src/cli/run.rs` required no code change because existing `BackendTimeoutExhausted { .. }` pattern already handles added fields.
