# Feature: MCP Tool Handlers and Tail Event Execution

## Description
Implement the remaining MCP functionality after loop 1’s server skeleton: replace stubbed tool handlers with real implementations for all 9 tools, implement MCP-specific tail event collection, and enforce MCP tool-result semantics (`CallToolResult` success/error envelopes) for `tools/call`. This feature should make `ralph mcp serve` fully functional against existing workspace/orchestration code without re-implementing baseline CLI features.

## Acceptance Criteria
- [ ] `src/mcp/handlers.rs` no longer returns `"not yet implemented"` for known tools; it dispatches all 9 tools to real async handlers: `project_new`, `project_list`, `project_show`, `run`, `status`, `history`, `tail`, `quick_prd`, `config_show`.
- [ ] Each handler re-discovers workspace state on every call via `Workspace::discover()` (no cached workspace in MCP state), so mutations are visible immediately to subsequent tool calls.
- [ ] `tools/call` success responses are emitted as MCP `CallToolResult` with `isError: false` and one text content block containing serialized JSON output.
- [ ] Tool execution failures (validation errors, missing project, orchestration failures, etc.) are emitted as MCP `CallToolResult` with `isError: true` and error text; JSON-RPC `error` is not used for tool-domain failures.
- [ ] `project_new` validates `id` + `name` and enforces exactly one of `prompt_file` or `from_project`; optional `backend` is validated before project creation.
- [ ] `config_show` enforces mutual exclusivity of `project` and `global`; default scope behavior matches existing config logic (active project if present, otherwise global).
- [ ] `run` maps MCP arguments to `RunOptions` including `on_prompt_change` and `skip_commit`, always sets `tmux: None`, and returns structured JSON output from orchestration result fields.
- [ ] `quick_prd` supports `idea` (required), optional backend overrides, `max_revisions`, and `dry_run`; non-dry-run returns metadata (`spec_path`, `summary`, `revision_count`, `approved`) without inlining full spec content.
- [ ] `src/mcp/tail_events.rs` is implemented (no longer placeholder) and returns `Vec<serde_json::Value>` matching tail JSON event shape (artifact/state/git) with deterministic sort ordering and optional `last` truncation in handler logic.
- [ ] `src/mcp/schema.rs` is updated to match MCP surface exactly (including `on_prompt_change`, `dry_run`, and mutual exclusivity constraints) and excludes non-applicable CLI-only controls (`tmux`/`no_tmux` on `run`, interactive flags on `quick_prd`).
- [ ] Unknown/extra tool arguments are ignored (Postel behavior), while missing/invalid required arguments produce `isError: true`.
- [ ] New tests cover handler parameter validation, success/error wrapping, mutual-exclusion constraints, dry-run paths for backend-heavy tools, and tail event serialization/ordering; `cargo test` passes.

## Files to Modify/Create
- `src/mcp/handlers.rs` - Replace stub dispatcher with full tool implementations, argument parsing/validation helpers, and handler tests.
- `src/mcp/tail_events.rs` - Implement MCP-level tail event collection/serialization logic returning JSON values.
- `src/mcp/server.rs` - Ensure `tools/call` wraps both success and failure paths into `CallToolResult` consistently.
- `src/mcp/schema.rs` - Align tool schemas/params with implemented MCP contract and mutual-exclusion rules.
- `src/mcp/protocol.rs` - Add/adjust helper constructors if needed for consistent `CallToolResult` creation.
- `tests/mcp_handlers.rs` - Add end-to-end MCP tool-call integration tests with temp workspace setup and in-memory/stdin-stdout harnessing.

## Dependencies
- Requires: MCP Protocol Types, Transport, and Server Core
- Blocks: none
