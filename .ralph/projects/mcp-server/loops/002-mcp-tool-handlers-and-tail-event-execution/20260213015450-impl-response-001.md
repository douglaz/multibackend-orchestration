# Implementation Response (Iteration 1)

## Changes Made

### 1. `src/mcp/protocol.rs` — CallToolResult helper constructors

Added two static methods to `CallToolResult`:

- `success_json(output: Value) -> Value`: wraps a JSON payload as a `CallToolResult` with `isError: false`, serialized text content block.
- `error_text(message: impl Into<String>) -> Value`: wraps a plain error message as `CallToolResult` with `isError: true`.

These are used by all handlers and the server's error-wrapping path.

### 2. `src/mcp/schema.rs` — Tool schemas updated

Removed CLI-only controls from tool schemas:
- **run**: removed `tmux` / `no_tmux`; added `on_prompt_change` with `enum: ["continue", "restart-loop", "abort"]`; added descriptions to all properties.
- **tail**: removed `follow`, `poll_interval_ms`, `json`, `tmux`.
- **quick_prd**: removed `interactive` / `non_interactive`.
- **history**: removed `verbose`, `json`.
- **project_show**: removed `json`.
- **project_new**: added `oneOf` constraint for mutual exclusivity of `prompt_file` / `from_project`.
- **config_show**: added `not: { required: ["project", "global"] }` constraint.

Added 3 new schema validation tests: `run_excludes_tmux_and_includes_on_prompt_change_enum`, `tail_excludes_cli_only_controls`, `quick_prd_excludes_interactive_flags`.

### 3. `src/mcp/tail_events.rs` — Full implementation (replaced placeholder)

Implemented `collect_tail_events(project_dir, project_id, last) -> Result<Vec<Value>>` returning sorted JSON events:

- **Artifact events**: reads `.md` files from `loops/*/`, parses YAML frontmatter (`artifact`, `role`, `backend`, `loop`, `iteration`, `created_at`), extracts first H1 heading, normalizes timestamps from `created_at` > filename timestamp > file mtime.
- **State events**: derives from `ProjectState` — feature loop started/completed, completion loop started/verdict, git commit records.
- **Sort order**: `(epoch_ms, tiebreaker[artifact=0,state=1,git=2], signature)` for deterministic ordering.
- **`last` parameter**: truncates to final N events.

4 unit tests: `collects_state_and_git_events_as_json`, `last_truncates_events`, `returns_empty_when_no_state`, `deterministic_sort_ordering`.

### 4. `src/mcp/handlers.rs` — All 9 tool handlers implemented (replaced stubs)

Replaced the stub `handle_tool_call` with full async implementations:

| Handler | Key behavior |
|---|---|
| `project_new` | Validates id/name required, exactly one of prompt_file/from_project, validates backend spec |
| `project_list` | Lists all projects with active flag |
| `project_show` | Returns project metadata + full state as JSON |
| `run` | Parses on_prompt_change enum, sets tmux=None, delegates to Orchestrator |
| `status` | Returns structured JSON with phase, backends, completion info |
| `history` | Returns sorted loop entries (feature + completion) |
| `tail` | Delegates to collect_tail_events |
| `quick_prd` | Validates idea non-empty, handles dry_run, validates backends, runs pipeline |
| `config_show` | Enforces global/project mutual exclusivity, resolves effective config |

Design decisions:
- Every handler re-discovers workspace via `Workspace::discover()` (no cached state).
- Unknown/extra arguments are silently ignored (Postel's law).
- Missing/invalid required arguments return `Err(String)` which the server wraps as `CallToolResult { isError: true }`.
- Tool-domain errors always use `isError: true` (never JSON-RPC `error`).

11 unit tests covering: unknown tool, project_new validation (5 cases), run on_prompt_change, quick_prd (3 cases), config_show mutual exclusivity, extra arguments ignored.
