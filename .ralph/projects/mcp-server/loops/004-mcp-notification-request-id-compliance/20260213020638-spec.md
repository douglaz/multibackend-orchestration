# Feature: MCP Notification Request-ID Compliance

## Description
Loops 1 and 2 already delivered MCP protocol/transport/server core plus full tool handlers. The remaining gap is lifecycle compliance for notification-like methods: `notifications/*` is currently ignored even when an `id` is present. This feature updates dispatch behavior so only true notifications (no `id`) are ignored, while unknown methods with an `id` correctly return JSON-RPC `-32601`, and adds regression coverage.

## Acceptance Criteria
- [ ] `src/mcp/server.rs` dispatch logic ignores `notifications/*` only when `id` is absent.
- [ ] Any request with an `id` and unknown method (including `notifications/custom`) returns JSON-RPC error `code: -32601` with the same `id`.
- [ ] `notifications/initialized` without `id` remains a no-op and produces no response.
- [ ] Existing request methods (`initialize`, `ping`, `tools/list`, `tools/call`) keep current behavior and response shapes unchanged.
- [ ] A regression test covers `{"jsonrpc":"2.0","id":<n>,"method":"notifications/custom"}` and asserts `error.code == -32601`.
- [ ] Existing server lifecycle test(s) continue to verify unknown notifications without `id` are silently ignored.
- [ ] `cargo test` passes with updated MCP server tests.

## Files to Modify/Create
- `src/mcp/server.rs` - adjust notification short-circuit ordering/conditions and add or update unit tests for id-bearing `notifications/*` behavior.

## Dependencies
- Requires: MCP Tool Handlers and Tail Event Execution
- Blocks: Project completion verification
