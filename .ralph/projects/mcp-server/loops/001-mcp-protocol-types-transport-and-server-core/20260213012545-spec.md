# Feature: MCP Protocol Types, Transport, and Server Core

## Description
Implement the foundational MCP infrastructure: JSON-RPC 2.0 protocol types (`src/mcp/protocol.rs`), the newline-delimited stdio transport layer (`src/mcp/transport.rs`), the server dispatch loop (`src/mcp/server.rs`), tool schema definitions (`src/mcp/schema.rs`), and the module entry point (`src/mcp/mod.rs`). Wire in the `ralph mcp serve` CLI command by editing `src/cli/mod.rs` and `src/lib.rs`. This feature establishes the complete MCP server skeleton that handles the full protocol lifecycle (`initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call` dispatch, unknown method errors, unknown notification ignoring) — but with tool handlers returning stub "not yet implemented" errors. The transport is generic over `AsyncBufRead`/`AsyncWrite` to enable in-memory testing.

- [ ] `src/mcp/mod.rs` exists, declares submodules (`protocol`, `transport`, `server`, `handlers`, `schema`, `tail_events`), re-exports `McpServer`, and provides `pub async fn serve()` that creates an `McpServer::stdio()` and runs it
- [ ] `src/mcp/protocol.rs` defines `JsonRpcMessage` (deserialized from stdin with `jsonrpc`, `id: Option<Value>`, `method: Option<String>`, `params: Option<Value>`), `JsonRpcResponse` (serialized to stdout with `jsonrpc`, `id`, optional `result`/`error`), `JsonRpcError { code, message, data }`, `CallToolResult { content, isError }`, and `ContentBlock { type, text }` — all with serde derives
- [ ] `src/mcp/transport.rs` defines `StdioTransport<R: AsyncBufRead + Unpin, W: AsyncWrite + Unpin>` with `new()`, `async read_message() -> Result<Option<JsonRpcMessage>>` (returns `None` on EOF, writes parse-error response on malformed JSON), and `async write_message(&JsonRpcResponse) -> Result<()>` (single-line JSON + newline + flush)
