# Implementation Notes

## Decisions Made
- Added a new `src/mcp` module with `protocol`, `transport`, `server`, `handlers`, `schema`, and `tail_events`, and exported `McpServer` plus `serve()` from `src/mcp/mod.rs` to provide the MCP entrypoint.
- Implemented JSON-RPC protocol structs in `src/mcp/protocol.rs` with serde derives and helper constructors to keep response creation consistent (`success`/`error`) and enforce newline-safe transport serialization.
- Implemented generic async transport in `src/mcp/transport.rs` over `AsyncBufRead`/`AsyncWrite`, using newline-delimited JSON, parse-error emission (`-32700`), and flush-on-write behavior.
- Implemented dispatch loop in `src/mcp/server.rs` with MCP lifecycle handling:
  - `initialize` response includes `protocolVersion: "2025-06-18"`, `serverInfo`, and `capabilities.tools`.
  - `notifications/initialized` and other `notifications/*` are ignored.
  - `ping`, `tools/list`, `tools/call`, invalid request (`-32600`), method not found (`-32601`), and internal error (`-32603`) paths are handled.
  - Tool execution failures are wrapped as `CallToolResult { isError: true }`.
- Implemented tool schema definitions for all 9 tools in `src/mcp/schema.rs`, including mutual-exclusion constraints for `project_new` (`prompt_file` vs `from_project`) and `config_show` (`project` vs `global`).
- Added stub tool dispatcher in `src/mcp/handlers.rs` returning `"not yet implemented"` for all 9 required tools.
- Wired CLI integration in `src/cli/mod.rs` with `Mcp(McpArgs)` and `McpCommand::Serve`, dispatching to `crate::mcp::serve().await`.
- Exposed MCP from crate root via `pub mod mcp;` in `src/lib.rs`.
