# Implementation Notes

## Decisions Made
- Added `diff_stat()`, `create_pr_with_body_file()`, and `edit_pr()` to `src/daemon/github.rs` as thin wrappers around `git diff --stat` and `gh pr create/edit --body-file` commands. These are blocking sync functions consistent with the existing `github.rs` patterns (called via `spawn_blocking_op`).
- Rewrote `handle_pr_flow` in `src/daemon/runtime.rs` to follow a deterministic 7-step flow: check diff → push → gather context (diff stat + issue body) → build title/body via pure helpers → check existing PR → edit-only or create-only. The edit path never falls through to create on failure.
- Used `tempfile::NamedTempFile` for the `--body-file` approach. The temp file is created once and shared between edit and create paths (only one is ever executed).
- `diff_stat` reuses the existing `detect_base_branch()` logic from `has_diff()` for consistency in base-branch detection.
- The `edit_pr` function takes the PR URL as a positional argument (not branch-targeted), matching the spec requirement for `gh pr edit <pr_url>`.
- Added `daemon_mock_gh_edit_pr_script()` and `daemon_mock_ralph_with_commit_no_diffstat_script()` to `mock_scripts.rs` for test infrastructure.
- Conformance tests use inline mock `gh` scripts (consistent with existing patterns) to precisely control `pr list`/`pr edit`/`pr create` behavior and capture `--body-file` content.

## Spec Deviations
- The `runtime_pr_diff_stat_fallback` conformance test may see actual diff stat output (from `HEAD~1` fallback) rather than strictly "Diff stat unavailable" — this is because `git diff --stat HEAD~1...HEAD` can still succeed even when the primary base branch detection fails. The test verifies the body is well-formed with all expected sections regardless of whether the diff stat is empty or populated. The unit test `runtime_pr_diff_stat_failure_fallback` directly verifies the `None` diff stat → "Diff stat unavailable" path.
- The existing `create_pr()` function in `github.rs` is preserved (not removed) since it may be used elsewhere; the new `create_pr_with_body_file()` is used in the updated `handle_pr_flow`.
