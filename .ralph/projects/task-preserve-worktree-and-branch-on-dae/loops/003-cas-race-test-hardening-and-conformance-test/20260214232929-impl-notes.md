# Implementation Notes

## Decisions Made
- Rewrote `runtime_activation_failed_task_preserved` to exercise the dispatch-time CAS-failure branch deterministically by:
  - Starting from a `pending` task.
  - Using a custom mock `gh` `issue comment` hook to hold a lock on `tasks.json`, wait for child spawn, then flip persisted state to `failed` before CAS activation.
  - Asserting CAS-race logs and preserved worktree behavior.
- Added `runtime_failed_worktree_preserved_and_reused_on_retry`:
  - Seeds a `failed` task with preserved worktree + `project_id`.
  - Resets task to `pending` for retry dispatch.
  - Verifies dispatch uses `ralph run --project <id>` and the existing worktree marker survives (reuse, not recreation).
- Added `runtime_aborted_task_worktree_cleaned`:
  - Transitions task to `aborted`, seeds worktree, runs daemon startup reconciliation, and verifies worktree cleanup.
- Added `runtime_succeeded_task_worktree_cleaned`:
  - Runs a successful dispatch to `completed` and verifies worktree cleanup.
- Registered all new tests in `tests()` inventory in `src/validate/tests_daemon.rs`.
