## Notes

The implementation is clean and well-structured:

- **Shared policy helper** `should_cleanup_worktree()` is the single source of truth for terminal-state cleanup decisions, preventing divergence across the three call sites.
- **`cleanup_worktree_for_terminal_state()`** wrapper adds contextual logging at each decision point (`"dispatch-terminal-race"`, `"complete-task-already-terminal"`, `"complete-task-terminal"`), satisfying the logging/documentation requirement.
- **CAS-failure path** correctly re-reads persisted state from the store before making cleanup decisions, with safe fallback behavior (preserving worktree) when the store read fails or the task is missing.
- **`complete_task()` return type change** from `Ok(Option<DaemonTask>)` to `Ok((Option<DaemonTask>, Option<TaskState>))` cleanly threads the existing terminal state to the caller for policy-aware cleanup.
- **`spawn_ralph_run` / `build_ralph_run_command`** follow the exact same pattern as the existing `spawn_ralph_auto` / `build_ralph_auto_command`, maintaining code consistency.
- **`reconcile_worktrees()`** filter changed from `!t.state.is_terminal()` to `!should_cleanup_worktree(&t.state)`, correctly treating `Failed` tasks as active during startup reconciliation.
- **Test quality** is high — `runtime_task_fails_worktree_preserved` verifies the full dispatch-through-failure-through-preservation flow including project_id retention; `runtime_activation_failed_task_preserved` validates startup reconciliation with a marker file; `runtime_fresh_dispatch_ignores_discovered_project` seeds a discovered project and verifies the mock receives `auto --idea` not `run --project`.
- Formatting-only changes (rustfmt) are harmless and don't affect behavior.
