# Feature: Failed-task worktree preservation and dispatch routing fixes

## Description
Fix two daemon runtime regressions: (1) Failed tasks have their worktrees and branches removed instead of being preserved for retry, and (2) dispatch routing does not yet support resume dispatch via `task.project_id`. This feature adds the `project_id` field to `DaemonTask`, introduces a terminal-state cleanup policy that preserves worktrees for `Failed` tasks while continuing to remove them for `Aborted` and `Succeeded`, fixes the CAS-failure path in `dispatch_task()` to respect that policy, adds `spawn_ralph_run` for project-based resume dispatch, and gates dispatch routing on `task.project_id` (not discovered workspace state). Three new conformance tests validate the behavior.

## Acceptance Criteria
- [ ] `DaemonTask` struct has an `Option<String>` `project_id` field (serde-defaulted for backwards compat)
- [ ] A shared helper `fn should_cleanup_worktree(state: &TaskState) -> bool` returns `true` for `Completed` and `Aborted`, `false` for `Failed`
- [ ] `complete_task()` calls `cleanup_worktree()` only when `should_cleanup_worktree()` returns true; `Failed` tasks preserve worktree and retain `project_id`
- [ ] `dispatch_task()` CAS-failure path re-reads persisted task state and skips worktree removal when state is `Failed`
- [ ] `process.rs` has a new `spawn_ralph_run(ralph_bin, worktree_path, project_id, log_file)` that invokes `ralph run --project <id>`
- [ ] Dispatch routing in `dispatch_task()` uses `task.project_id.as_deref()`: `Some` → `spawn_ralph_run`, `None` → `spawn_ralph_auto` (ignoring any discovered project context)
- [ ] Logs/comments at decision points document the failed-preserve vs aborted-cleanup policy
- [ ] `reconcile_worktrees()` considers `Failed` tasks as "active" (worktree not removed on startup)
- [ ] New conformance test `runtime_task_fails_worktree_preserved` passes
- [ ] New conformance test `runtime_activation_failed_task_preserved` passes
- [ ] New conformance test `runtime_fresh_dispatch_ignores_discovered_project` passes
- [ ] All existing conformance tests continue to pass
- [ ] `nix develop -c cargo test` passes
