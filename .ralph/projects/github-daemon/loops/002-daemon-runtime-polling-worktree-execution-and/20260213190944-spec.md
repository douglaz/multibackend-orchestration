# Feature: Daemon Runtime — Polling, Worktree Execution, and GitHub Completion Flow

## Description
Implement the remaining end-to-end daemon behavior on top of Loop 1 foundation: continuous GitHub polling and claiming, per-task worktree execution via real child processes, startup reconciliation/cleanup, and idempotent GitHub comment/PR completion handling with deterministic task state transitions.

## Acceptance Criteria
- [ ] `ralph daemon start` runs a real loop (poll/claim/dispatch/collect) instead of exiting after validation, with a deterministic single-iteration mode for conformance tests.
- [ ] On startup, all persisted `in_progress` tasks are reconciled to `pending`, with `child_pid`/`child_pgid` cleared, and those tasks are re-adopted before claiming new work.
- [ ] Startup cleanup safely reconciles orphaned/stale worktrees under `.ralph/daemon/worktrees/`.
- [ ] Polling uses `gh issue list --limit 100` and passes repeated `--label` arguments with AND semantics.
- [ ] Issues containing any `ralph:*` label are ignored during claiming.
- [ ] If poll returns exactly 100 issues, daemon emits an overflow/truncation warning.
- [ ] Claiming adds `ralph:in-progress` and persists a single task record with ID format `<owner>-<repo>-<number>` (no duplicate tasks per issue).
- [ ] Scheduler enforces `max_concurrent` and runs each task in `.ralph/daemon/worktrees/<task-id>/`.
- [ ] Task execution uses `std::process::Command` (no `tokio::spawn`) to run `ralph auto` in a separate session/process group (`setsid` or equivalent).
- [ ] Persisted `child_pid` and `child_pgid` are actual OS PID/PGID values from the spawned process/session.
- [ ] Task terminal transitions are deterministic: success -> `completed`, non-zero child exit -> `failed`, abort path -> `aborted`; child PID/PGID are cleared in terminal states.
- [ ] Terminal-task cleanup removes the worktree when safe (including stale/nonexistent PID cases).
- [ ] Every daemon-authored comment includes marker `<!-- ralph:task:<id>:<phase> -->`; existing comments are scanned and duplicate markers are not re-posted.
- [ ] PR flow is idempotent: no diff -> no PR + idempotent note comment; existing PR is reused via `gh pr list --head <branch>`; PR creation failure logs warning but still reaches terminal completion path.
- [ ] `status` and `abort` remain independently lock-safe while daemon runtime is active.
- [ ] `src/validate/tests_daemon.rs` includes new runtime conformance tests for reconciliation, polling/filtering/overflow, worktree isolation, PID/PGID persistence, idempotent comments, PR reuse/no-diff logic, and PR-create-failure terminal behavior.
- [ ] `nix develop -c cargo check`, `nix develop -c cargo test`, and `./result/bin/ralph validate --bin ./result/bin/ralph --filter daemon` pass.

## Files to Modify/Create
- `src/cli/daemon.rs` - replace start stub with runtime loop entrypoint and deterministic test-mode control.
- `src/daemon/mod.rs` - keep shared task/store/abort types and expose new runtime helpers.
- `src/daemon/runtime.rs` - daemon main loop, scheduling, startup reconciliation, and child lifecycle handling.
- `src/daemon/github.rs` - `gh` polling/claiming/comment/PR helper functions with idempotency marker checks.
- `src/daemon/worktree.rs` - create/remove/reconcile per-task worktrees under `.ralph/daemon/worktrees`.
- `src/daemon/process.rs` - child spawn/monitor utilities for `ralph auto` with process-group/session handling.
- `src/validate/tests_daemon.rs` - add runtime conformance coverage for new daemon behavior.
- `src/validate/mock_scripts.rs` - extend mock `gh`/`ralph` script support for daemon runtime tests.
- `Cargo.toml` - add minimal dependency support for Unix `setsid`/PGID handling if needed.
