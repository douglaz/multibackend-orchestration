# Review: SUGGESTIONS

## Required Changes
1. **Dispatch/abort concurrency safety**: `abort` can still be overwritten during runtime dispatch, violating lock-safe terminal semantics.
   - Current: `dispatch_task` always writes `in_progress` + PID/PGID after spawn (`src/daemon/runtime.rs:250`), even if another process already moved the task to `aborted`. This can happen because pending tasks are loaded earlier (`src/daemon/runtime.rs:122`) and dispatch is not CAS-guarded against terminal state.
   - Expected: make dispatch transition atomic/CAS-style (pending/non-terminal -> in_progress). If task is already terminal when updating, preserve terminal state and immediately terminate/cleanup any just-spawned child instead of reactivating the task.
   - Reference: Feature spec acceptance criteria for deterministic terminal transitions (`abort` must remain `aborted`) and "`status` and `abort` remain independently lock-safe while daemon runtime is active."

## Recommended Improvements
1. Add a daemon conformance test that aborts a task while runtime is dispatching/re-adopting and asserts final state remains `aborted` (never reverts to `in_progress`/`completed`).
