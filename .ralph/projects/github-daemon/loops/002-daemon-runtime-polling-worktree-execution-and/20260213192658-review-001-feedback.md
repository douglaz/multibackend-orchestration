# Review: SUGGESTIONS

## Required Changes
1. **Abort path can be overwritten by runtime child collection**: `abort` is not deterministic while daemon is running.
Current: `abort_task` sets `aborted` in `src/daemon/mod.rs:161`, but `collect_children` recomputes terminal state from exit status and `complete_task` overwrites state unconditionally in `src/daemon/runtime.rs:274` and `src/daemon/runtime.rs:306`.
Expected: if a task is already `aborted`, runtime must not transition it to `failed`/`completed` on child exit; keep `aborted` terminal semantics and cleanup/labels consistent.
Reference: Feature spec acceptance criteria for deterministic terminal transitions and "`status`/`abort` remain independently lock-safe while daemon runtime is active".

2. **PR no-diff detection is incorrect for committed changes**: PR flow can skip valid PR creation.
Current: `has_diff` uses `git diff --quiet HEAD` in `src/daemon/github.rs:278`, which only checks working tree/index vs `HEAD`, not whether the task branch diverged from base.
Expected: compare branch against base/default branch (for example `<base>...HEAD`) so committed changes still trigger PR reuse/create flow.
Reference: Feature spec idempotent PR behavior ("no diff -> no PR", existing PR reuse, otherwise create).

3. **Single-iteration mode is not deterministic and may leave child processes running**.
Current: `--single-iteration` sleeps 200ms then exits in `src/daemon/runtime.rs:63`; tests explicitly allow multiple end states in `src/validate/tests_daemon.rs:681`, indicating nondeterministic outcomes.
Expected: make single-iteration behavior deterministic for conformance (exactly defined lifecycle per run), including explicit handling of still-running children.
Reference: Feature spec acceptance criteria for deterministic single-iteration mode and deterministic state transitions.

4. **Startup worktree reconciliation only handles unknown IDs, not stale known tasks**.
Current: reconcile removes only directories not in `known_task_ids` in `src/daemon/worktree.rs:120`; runtime passes all task IDs (including terminal) in `src/daemon/runtime.rs:101`.
Expected: reconcile stale worktrees for terminal/non-active tasks as well, not just orphan IDs.
Reference: Feature spec acceptance criteria for startup cleanup of orphaned/stale worktrees.

5. **New daemon runtime conformance tests are largely smoke tests and do not verify required side effects**.
Current: several tests only assert exit code or non-crash (for example `src/validate/tests_daemon.rs:633`, `src/validate/tests_daemon.rs:789`, `src/validate/tests_daemon.rs:865`, `src/validate/tests_daemon.rs:938`) and do not assert required behavior (idempotent marker de-dup, PR reuse path, no-diff comment path, worktree isolation effect).
Expected: strengthen assertions to validate concrete runtime behavior required by spec, not just process exit.
Reference: Feature spec acceptance criteria requiring runtime conformance coverage for reconciliation, worktree isolation, PID/PGID persistence, idempotent comments, PR reuse/no-diff, and PR-create-failure handling.
