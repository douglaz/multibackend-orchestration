# Review: SUGGESTIONS

## Required Changes
1. **Process/session isolation portability**
   - Current: Task execution depends on external `setsid` (`src/daemon/process.rs:27`). In the Nix release build environment this is not available, and daemon runtime conformance tests fail during child spawn (`No such file or directory`), so dispatch does not occur.
   - Expected: Use an in-process Unix session/group setup (`setsid()` via `CommandExt::pre_exec` + libc/nix, or equivalent fallback logic) so daemon child spawning is not dependent on a PATH-provided binary.
   - Reference: Feature spec “Process Execution Requirements” (`setsid or equivalent`) and acceptance criterion requiring deterministic daemon runtime behavior/conformance.

2. **No-diff PR path is not covered by conformance tests**
   - Current: `daemon::runtime_pr_reuse_no_diff` only exercises the PR reuse path with committed changes (`src/validate/tests_daemon.rs:930` onward). It does not validate the “no diff -> no PR + idempotent note comment” behavior.
   - Expected: Add a daemon runtime conformance test that drives `has_diff == false` and asserts: no `gh pr create`, idempotent `no-diff` marker comment (`<!-- ralph:task:<id>:no-diff -->`), and terminal completion path.
   - Reference: Feature spec acceptance criteria for idempotent PR flow and required runtime conformance coverage (“PR reuse/no-diff logic”).

## Recommended Improvements
1. Consolidate process-kill behavior by reusing one implementation path (`src/daemon/mod.rs` vs `src/daemon/process.rs`) to reduce drift between abort-time and runtime-time process handling.
