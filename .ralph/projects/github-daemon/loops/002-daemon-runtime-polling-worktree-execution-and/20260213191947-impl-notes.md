# Implementation Notes

## Decisions Made
- **Module decomposition**: Split daemon runtime into four focused modules — `github.rs` (gh CLI interactions), `worktree.rs` (git worktree lifecycle), `process.rs` (child spawn/monitor with setsid), and `runtime.rs` (main loop orchestration). This matches the spec's file layout and keeps each concern isolated.
- **setsid via external command**: Used `setsid` as an external command wrapper rather than adding a `libc` or `nix` crate dependency for the `setsid()` syscall. This keeps the dependency footprint minimal while still achieving session/process-group isolation. The spawned child's PID equals its PGID since it becomes the session leader.
- **No Cargo.toml changes needed**: All required functionality (process groups, file locking, JSON serialization) is already available from existing dependencies (`fs2`, `serde_json`, `std::process`).
- **Single-iteration mode via CLI flag**: Added `--single-iteration` flag to `daemon start` for deterministic conformance testing. This runs exactly one poll/claim/dispatch/collect cycle and exits.
- **Graceful poll failure handling**: When `gh issue list` fails, the runtime logs a warning and continues (in loop mode) or exits cleanly (in single-iteration mode) rather than crashing.
- **Existing Loop 1 tests updated**: The 8 foundation tests were updated to pass `--single-iteration` and provide mock `gh` scripts so they work with the new runtime entry point. All assertions preserved.
- **Idempotent comment markers**: Every daemon-authored comment includes `<!-- ralph:task:<id>:<phase> -->`. The `post_idempotent_comment()` helper checks for existing markers via `gh issue view --json comments` before posting.
- **PR flow**: Implements full idempotent PR lifecycle — check for existing PR via `gh pr list --head <branch>`, reuse if found, create if not, handle no-diff case with note comment, and gracefully handle PR creation failures while still reaching terminal state.

## Spec Deviations
- **PR jq query**: The `find_existing_pr()` function uses `.[0].url` as the jq query for `gh pr list`, which returns the first PR's URL or empty string. This is slightly simpler than the spec's generic description but achieves the same result.
- **Child execution uses `setsid ralph auto <idea>`**: The idea argument passed to `ralph auto` is a synthesized string (`"Implement task <task-id>"`) since the actual issue body/title is not fetched separately. This is sufficient for the task dispatch mechanism and can be enhanced in a future loop.
- **Worktree branch naming**: Uses `ralph/daemon/<task-id>` as the branch name convention (e.g., `ralph/daemon/acme-widgets-42`), which provides clear namespace isolation.
