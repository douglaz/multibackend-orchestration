# Feature: Daemon Foundation — Task State Model, TaskStore with File Locking, CLI Skeleton, Config, and Conformance Tests

## Description
Establish the complete foundation for the `ralph daemon` subsystem. This includes the task state data model (`DaemonTask`, `TaskState` enum, task ID format), the `TaskStore` with `fs2` file-locking (shared for reads, exclusive for writes), daemon configuration fields in `WorkspaceConfig` with defaults and merge semantics, the `ralph daemon start|status|abort` CLI subcommand skeleton (parsing and dispatch, with `start` and full daemon loop deferred to a later feature), and all 8 required conformance tests in `src/validate/tests_daemon.rs`. The `status` subcommand will read and display task state. The `abort` subcommand will perform full abort logic (task ID resolution, bare-number ambiguity detection, terminal-state rejection, PID/PGID kill with SIGTERM→SIGKILL escalation, label updates via `gh`, and state transitions) operating directly on `tasks.json` so it works even when the daemon is not running. The `start` subcommand will validate inputs and workspace but will not yet run the polling loop or spawn child processes — those are deferred to the next feature.

## Acceptance Criteria
- [ ] `DaemonTask` struct with fields: `task_id` (String, format `<owner>-<repo>-<number>`), `state` (enum: `pending`, `in_progress`, `completed`, `failed`, `aborted`), `issue_number` (u32), `owner` (String), `repo` (String), `child_pid` (Option<u32>), `child_pgid` (Option<u32>), `branch` (Option<String>), `pr_url` (Option<String>), `created_at` (String), `updated_at` (String)
- [ ] `TaskStore` struct that reads/writes `.ralph/daemon/tasks.json` with `fs2` file locking: shared lock for reads, exclusive lock for read-modify-write cycles, minimal lock scope
- [ ] `TaskStore::load()` returns `Vec<DaemonTask>` (shared lock)
- [ ] `TaskStore::save()` writes full task list (exclusive lock)
- [ ] `TaskStore::update_task()` does atomic read-modify-write under exclusive lock
- [ ] Daemon config fields added to `WorkspaceConfig`: `daemon_poll_seconds` (u64, default 60), `daemon_max_concurrent` (u32, default 1), `daemon_labels` (Vec<String>, default `["ralph:ready"]`), `daemon_repo` (Option<String>, default None)
- [ ] Config fields merge correctly (project overrides workspace) and deserialize from TOML
- [ ] CLI: `ralph daemon start` subcommand parses `--repo <owner/repo>` (optional), `--poll-seconds <N>` (optional), `--max-concurrent <N>` (optional), `--label <L>` (repeatable, optional)
- [ ] CLI: `ralph daemon status` subcommand parses with no required args
- [ ] CLI: `ralph daemon abort <task-id-or-number>` subcommand parses a positional argument
- [ ] `ralph daemon start` validates: workspace is initialized, repo is resolvable (from arg, config, or `gh repo view`), and returns early with a message (no polling loop yet)
- [ ] `ralph daemon status` reads `tasks.json` via `TaskStore` with locking and displays task list (or "no tasks" message)
- [ ] `ralph daemon abort` resolves task ID: accepts full `<owner>-<repo>-<number>` or bare number; bare number must match exactly one task or return ambiguity error; aborting a terminal task (`completed`, `failed`, `aborted`) returns an error; kills process group (SIGTERM → 10s wait → SIGKILL) if `child_pid`/`child_pgid` present and process exists; updates task state to `aborted`; removes `ralph:in-progress` label and adds `ralph:aborted` label via `gh` (best-effort, log warning on failure)
