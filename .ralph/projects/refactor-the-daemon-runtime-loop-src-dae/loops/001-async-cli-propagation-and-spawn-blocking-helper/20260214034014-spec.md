# Feature: Async CLI Propagation and spawn_blocking Helper

## Description
Establish the async foundation by: (1) introducing a `spawn_blocking` JoinError-to-RalphError helper, (2) converting `cli::daemon::execute` and `execute_start` to async, and (3) updating `cli/mod.rs` to `.await` the daemon dispatch. `execute_status` and `execute_abort` remain synchronous and are wrapped with `spawn_blocking` at the call site. `runtime::run` becomes an `async fn` with a minimal conversion — its body is temporarily wrapped in `spawn_blocking` so the existing synchronous internals continue to work, providing a compiling, test-passing checkpoint before deeper conversion in subsequent loops.

## Acceptance Criteria
- [ ] A new helper function (e.g., `spawn_blocking_op` or similar) exists in `src/daemon/runtime.rs` (or a shared location within `src/daemon/`) that converts `tokio::task::JoinError` into `RalphError::Orchestration` and is used for all `spawn_blocking(...).await` calls.
- [ ] `cli::daemon::execute(args)` is `pub async fn execute(args: DaemonArgs) -> Result<()>`.
- [ ] `cli::daemon::execute_start(args)` is `async fn execute_start(args: DaemonStartArgs) -> Result<()>`.
- [ ] `cli/mod.rs` dispatches daemon via `daemon::execute(args).await` in the `Commands::Daemon` match arm.
- [ ] `execute_status` and `execute_abort` remain synchronous functions; they are called from `execute` via `spawn_blocking` (since `execute` is now async) using the new helper for error mapping.
- [ ] `runtime::run` signature becomes `pub async fn run(...)` — its body delegates to `spawn_blocking` wrapping the current synchronous logic so that the existing poll loop, child management, and `thread::sleep` calls continue working without modification yet.
- [ ] `refine::refine_prompt` is NOT changed in this loop (it will be converted in a subsequent loop once `runtime::run` internals are async).
- [ ] `cargo check` passes.
- [ ] `cargo test` passes.
- [ ] `cargo clippy --all-targets --all-features -- -D warnings` has no new warnings.
- [ ] No behavioral regressions — the daemon starts, polls, and drains identically to before.
