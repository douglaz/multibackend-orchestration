# Feature: Tokio Process Migration and Async Kill/Reap Semantics

## Description
Convert `src/daemon/process.rs` from `std::process` to `tokio::process` APIs, completing the final piece of the async daemon refactor. This migrates child spawning to `tokio::process::Command`, updates `SpawnedChild` and `ActiveChild` to hold `tokio::process::Child`, captures PID immediately after spawn via `child.id().ok_or(...)` (handling `Option<u32>`), and converts kill/reap/drain paths to async Tokio child semantics. The `terminate_process_group()` escalation flow replaces `thread::sleep` with `tokio::time::sleep`. All call sites in `runtime.rs` that interact with child processes are updated to match the new async signatures. Process group isolation (`setsid` at spawn) and the SIGTERM/SIGKILL escalation pattern are preserved.

## Acceptance Criteria
- [ ] `spawn_ralph_auto()` in `src/daemon/process.rs` is `async fn` and uses `tokio::process::Command` instead of `std::process::Command`.
- [ ] `SpawnedChild` holds a `tokio::process::Child` instead of `std::process::Child`.
- [ ] PID is captured immediately after spawn via `child.id().ok_or(...)` and stored as `u32`; code never re-reads `Child::id()` after initial capture.
- [ ] PGID is derived from the captured PID (same value due to `setsid`) and stored; `setsid` is configured via `unsafe { pre_exec }` on the Tokio command builder.
- [ ] `ActiveChild` in `runtime.rs` holds `tokio::process::Child` and stores the captured `u32` PID/PGID.
- [ ] `terminate_process_group()` is `async fn` and replaces `thread::sleep` with `tokio::time::sleep(...).await` in the escalation wait loop.
- [ ] Child reaping in `collect_children()` uses `child.try_wait()` on `tokio::process::Child` (which returns `Result<Option<ExitStatus>>` like the std version).
- [ ] Child killing in best-effort cleanup paths (e.g., failed-activation kill in `dispatch_task`) uses async-compatible Tokio child methods or is wrapped in `spawn_blocking_op`.
- [ ] `drain_all_children()` uses async kill/wait semantics for final child cleanup.
- [ ] No `std::process::Command` or `std::process::Child` remains in `src/daemon/process.rs`.
- [ ] No `thread::sleep` remains in `src/daemon/process.rs`.
- [ ] Process group isolation is preserved: `setsid` is still called at spawn, and `terminate_process_group()` still sends SIGTERM to `-pgid` then escalates to SIGKILL.
- [ ] `cargo check` passes.
- [ ] `cargo test` passes.
- [ ] `cargo clippy --all-targets --all-features -- -D warnings` has no new warnings.
- [ ] No behavioral regressions in single-iteration draining and process cleanup.
