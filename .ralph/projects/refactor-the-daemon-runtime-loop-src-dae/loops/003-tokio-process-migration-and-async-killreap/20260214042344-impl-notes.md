# Implementation Notes

## Decisions Made
- Migrated daemon spawning to Tokio process APIs: `spawn_ralph_auto` is now async and `SpawnedChild` now stores `tokio::process::Child` (`src/daemon/process.rs:10`, `src/daemon/process.rs:21`).
- Captured PID once at spawn with `child.id().ok_or(...)`, derived PGID from that captured PID, and propagated captured values into task state and active-child tracking (`src/daemon/process.rs:46`, `src/daemon/runtime.rs:393`, `src/daemon/runtime.rs:460`).
- Kept `setsid` process-group isolation and converted termination escalation wait to `tokio::time::sleep(...).await` (`src/daemon/process.rs:31`, `src/daemon/process.rs:78`, `src/daemon/process.rs:106`).
- Updated runtime kill/reap cleanup to Tokio semantics (`kill().await` / `wait().await`) for failed activation and drain timeout paths; reaping still uses `try_wait()` (`src/daemon/runtime.rs:431`, `src/daemon/runtime.rs:519`, `src/daemon/runtime.rs:578`).
- Added a sync bridge for abort flow so synchronous CLI code can call the new async process-group terminator without behavior changes (`src/daemon/process.rs:116`, `src/daemon/mod.rs:246`).
