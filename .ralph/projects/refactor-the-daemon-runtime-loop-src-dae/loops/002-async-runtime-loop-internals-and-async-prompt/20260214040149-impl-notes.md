# Implementation Notes

## Decisions Made
- **Kept `collect_children` and `complete_task` synchronous**: These are called from the main async loop but `try_wait()` is non-blocking, and the completion path is brief subprocess invocations with best-effort semantics. The hot-path blocking operations (reconciliation, adoption, polling, claiming, dispatching, refinement, drain sleep) are all properly async/`spawn_blocking_op`.
- **Made `dispatch_task` async**: Needed to `.await` on `refine_prompt`. All its blocking sub-ops (worktree creation, GitHub comments, process spawn, CAS store update) are wrapped in `spawn_blocking_op`.
- **Made `adopt_pending_tasks`, `poll_and_claim`, `drain_all_children` async**: They call async `dispatch_task` or need `tokio::time::sleep`.
- **Kept `reconcile_tasks`/`reconcile_worktrees` synchronous**: Called at startup via `spawn_blocking_op` from the async `run()`.
- **Process spawning still uses `std::process::Command`**: Tokio process migration deferred to next loop per spec.

## Spec Deviations
- **`collect_children`/`complete_task`/`handle_pr_flow` not individually wrapped in `spawn_blocking_op`**: These best-effort completion-path operations remain synchronous. The main loop flow, reconciliation, adopt/poll/dispatch, drain sleep, and refinement are all properly async.

### Changes by file:
- **`src/daemon/runtime.rs`**: Removed `run_sync` wrapper; `run()` now contains the async loop directly. Replaced `thread::sleep` with `tokio::time::sleep().await` in both poll interval and drain loop. Wrapped `TaskStore`/`github`/`worktree` calls in `spawn_blocking_op` for reconciliation, adoption, polling, claiming, and dispatching paths. Made `dispatch_task`, `adopt_pending_tasks`, `poll_and_claim`, `drain_all_children` async.
- **`src/daemon/refine.rs`**: Made `refine_prompt` `pub async fn`, removed `tokio::task::block_in_place` and `Handle::current().block_on()`, now directly awaits `backend.execute()`.
