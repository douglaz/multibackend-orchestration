# Review: SUGGESTIONS

## Required Changes
1. **Blocking isolation in completion/cleanup path**: move remaining blocking `TaskStore`/`github`/`worktree` calls off async runtime threads.
   - Current: `collect_children` is called directly from async `run()` and invokes synchronous `complete_task`; `complete_task` and `handle_pr_flow` perform direct blocking calls (`store.with_exclusive_tasks`, `store.update_task`, `github::*`, `worktree::*`) without `spawn_blocking_op` (`src/daemon/runtime.rs:491`, `src/daemon/runtime.rs:566`, `src/daemon/runtime.rs:665`).
   - Expected: all `TaskStore` and synchronous `github`/`worktree` operations reached from async runtime flow should execute via `spawn_blocking_op` (either wrap each call or run completion flow inside a blocking wrapper and await it from async code).
   - Reference: Feature spec acceptance criteria: “All `TaskStore` operations called from async runtime code are executed via `spawn_blocking_op`” and “All synchronous `github` and `worktree` calls from async runtime code are executed via `spawn_blocking_op`.”

2. **Best-effort spawn_blocking error handling**: warn-and-continue behavior is incomplete for one cleanup path.
   - Current: worktree cleanup in the terminal-race branch ignores `spawn_blocking_op` errors silently (`let _ = ...`) at `src/daemon/runtime.rs:434`.
   - Expected: if `spawn_blocking_op(...).await` fails in best-effort paths, log a warning and continue.
   - Reference: Feature spec acceptance criterion: “Required operations propagate `spawn_blocking_op` errors; best-effort operations (cleanup/comment/label paths) log warnings and continue.”

## Recommended Improvements
1. Add/adjust daemon validate coverage for completion-path behavior after the blocking isolation change, so regressions in single-iteration drain/cleanup are caught automatically.
