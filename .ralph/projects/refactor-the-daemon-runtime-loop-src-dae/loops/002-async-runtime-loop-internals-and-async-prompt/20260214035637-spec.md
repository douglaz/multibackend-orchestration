# Feature: Async Runtime Loop Internals and Async Prompt Refinement

## Description
Loop 1 completed async CLI propagation and introduced `spawn_blocking_op`, but daemon runtime internals are still synchronous (`run_sync`, `thread::sleep`) and refinement still uses `block_in_place` + nested `Handle::block_on`.  
This feature converts the daemon runtime path to real async execution in `runtime.rs` and `refine.rs` while preserving existing daemon behavior. It removes blocking-in-runtime patterns by:
- Running the runtime loop directly as async logic (no sync wrapper loop).
- Replacing poll/drain sleeps with `tokio::time::sleep(...).await`.
- Making `refine::refine_prompt` async and awaiting backend execution directly.
- Wrapping all `TaskStore` and synchronous `github`/`worktree` calls made from async runtime code in `spawn_blocking_op`, with required-path error propagation and best-effort warn-and-continue handling unchanged.

Tokio child-process migration (`tokio::process::Command`, Tokio child kill/wait APIs, PID capture from `Option<u32>`) is intentionally deferred to the next feature.

## Acceptance Criteria
- [ ] `src/daemon/runtime.rs` no longer uses the `run_sync` wrapper pattern for the main daemon loop; `runtime::run` contains async loop flow directly.
- [ ] Poll interval sleep in runtime loop uses `tokio::time::sleep(...).await` and `thread::sleep` is removed from `src/daemon/runtime.rs`.
- [ ] Single-iteration child drain loop uses `tokio::time::sleep(...).await` and preserves “drain active children before exit” behavior.
- [ ] All `TaskStore` operations called from async runtime code are executed via `spawn_blocking_op` (no direct blocking store calls on async runtime threads).
- [ ] All synchronous `github` and `worktree` calls from async runtime code are executed via `spawn_blocking_op`.
- [ ] Required operations propagate `spawn_blocking_op` errors; best-effort operations (cleanup/comment/label paths) log warnings and continue.
- [ ] `src/daemon/refine.rs` exposes `pub async fn refine_prompt(...) -> Result<String>` and directly awaits backend execution.
- [ ] No `tokio::task::block_in_place` or `Handle::current().block_on(...)` remains in daemon runtime/refinement path.
- [ ] Existing daemon validate behavior remains unchanged (`./result/bin/ralph validate --bin ./result/bin/ralph --filter daemon` passes).

## Files to Modify/Create
- `src/daemon/runtime.rs` - Convert runtime internals to async flow, replace sleeps, and isolate blocking store/github/worktree calls behind `spawn_blocking_op`.
- `src/daemon/refine.rs` - Convert refinement API to async and remove nested blocking runtime usage.
- `src/validate/tests_daemon.rs` - Adjust or extend daemon conformance checks only if needed to cover async refactor regressions without changing intended behavior.

## Dependencies
- Requires: Async CLI Propagation and spawn_blocking Helper (Loop 1)
- Blocks: Tokio process migration in `src/daemon/process.rs` and runtime child handling (`tokio::process::Child`, PID/PGID `Option<u32>` capture, async kill/wait semantics)
