# Implementation Notes

## Decisions Made
- Named the test `concurrent_refresh_ordering` to match the spec suggestion (`interactive_prd::concurrent_refresh_ordering`) and align with the existing `concurrent_*` naming convention for concurrency-related conformance tests.
- Used issue numbers 400/401 to avoid collisions with other conformance tests (dedup uses 50, error isolation uses 60/70, panic isolation uses 80/90, bounded worker uses 300-303).
- Created `.git` subdirectory under the clone dir to trigger `refresh_repo_clone` execution (matching the pattern from the integration test).
- Mock git logs `"refresh"` on fetch; mock gh logs `"edit:<N>"` on label edits — both to a shared event log file for deterministic ordering verification.
- Added an extra assertion beyond the spec minimum: verifies all events after the first are `edit:*` events, providing stronger ordering guarantees.
- Used `ENV_MUTEX` for PATH serialization, matching all other conformance tests that call `poll_and_advance_prd`.
