# Implementation Notes

## Decisions Made
- Replaced file-based barrier (polling with `sleep 0.1` loop) with FIFO (named pipe) deterministic synchronization in `concurrent_advancement_slow_and_fast` integration test. FIFO reads block until written, eliminating all timing assumptions.
- Used `mkfifo` shell command to create the named pipe, which is available on all POSIX systems.
- Added a `slow_unblocked` tracking file to ensure the FIFO handshake only blocks the first `issue edit` call for the slow issue. Subsequent `gh issue edit 80` calls (label remove, etc.) pass through immediately, preventing a second deadlock on the FIFO.
- Similarly, the fast issue uses a flag file (`ISSUE90_FLAG`) to ensure only the first `issue edit 90` call logs the event and writes to the FIFO, preventing duplicate writes.
- Used `flock`-based atomic append to an event log file to capture ordering deterministically across concurrent shell processes.
- Reduced `backend_timeout_secs` from 60 to 2 for both the integration and conformance slow/fast tests, since backend CLI commands (claude, codex) are not mocked and would otherwise cause a 60-second wait. The test only observes concurrent `gh` command behavior via the FIFO handshake.
- Conformance test follows the same pattern as existing concurrency conformance tests: uses `run_case`, `ENV_MUTEX`, and `PrdPollConfig` with `max_concurrent: 2`.

## Spec Deviations
- None. All acceptance criteria are met:
  - Integration test uses deterministic FIFO synchronization (no polling/sleep).
  - Event log ordering assertion proves fast issue (#90) reaches advancement before slow issue (#80) is released.
  - Under sequential processing, the FIFO read would deadlock — test completion proves concurrent execution.
  - Conformance test `interactive_prd::concurrent_advancement_slow_fast` is registered and validates the same property.
  - All existing concurrency conformance tests (dedup, error isolation, panic isolation, bounded worker count, refresh ordering) remain unchanged and passing.

## Testing
- `cargo check --tests` — compiles cleanly.
- `cargo test --test daemon_interactive_prd concurrent_advancement_slow_and_fast` — passes in ~2s (down from ~52s with 60s timeout, and fully deterministic vs. sleep-based).
- `cargo test --test daemon_interactive_prd` — all 35 integration tests pass.
- Conformance test `interactive_prd::concurrent_advancement_slow_fast` compiles and is registered in `tests()`.
