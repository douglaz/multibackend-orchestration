# Feature: Bounded Concurrent PRD Tick Processing and Isolation

## Description
Implement the remaining core of parallel PRD advancement in `poll_and_advance_prd()`: bounded worker concurrency, per-issue panic/error isolation, per-thread cache ownership, and once-per-tick repo refresh ordering. Loop 1 already delivered CWD safety (`CliBackend` cwd + `CwdGuard` removal), so this feature focuses only on the still-missing concurrent tick behavior and its deterministic test coverage.

## Acceptance Criteria
- [ ] `PrdPollConfig` includes `max_concurrent: u32`, and `run_prd_phase` populates it from daemon config (`0` treated as `1`).
- [ ] `poll_and_advance_prd()` keeps the two label polls sequential, deduplicates issues across both passes before work starts, and returns early when no deduplicated issues exist.
- [ ] `refresh_repo_clone()` is called exactly once per non-empty tick, after poll/dedup and before any per-issue processing.
- [ ] Per-issue work runs via a bounded thread pool using stable std primitives (`std::thread::scope` + shared queue), with effective worker count `max(1, max_concurrent)`.
- [ ] Each worker owns its own `bot_login_cache: Option<String>`; no mutable per-issue transition state is shared between workers.
- [ ] Each issue execution is wrapped with `std::panic::catch_unwind`; panic/failure for one issue is converted into an issue-scoped error and does not stop other issues in that tick.
- [ ] Per-issue errors are aggregated thread-safely and emitted after worker joins; the tick is not short-circuited by first failure.
- [ ] Dedup invariant remains true: an issue present in both `ralph:prd` and `ralph:prd-active` is processed at most once per tick.
- [ ] `run_prd_phase` remains blocking (returns only after all per-issue workers complete).
- [ ] Deterministic integration tests are added for: concurrent advancement, bounded concurrency cap, error isolation, panic isolation, dedup invariant, and repo refresh ordering.
- [ ] Conformance coverage in `src/validate/tests_interactive_prd.rs` is extended for the same concurrency/isolation guarantees, and existing PRD tests remain green.

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - add `max_concurrent` to config, replace sequential loop with bounded worker processing, add per-thread cache + panic handling + error aggregation, and enforce once-per-tick refresh ordering.
- `src/daemon/runtime.rs` - wire daemon `max_concurrent` into `PrdPollConfig` for PRD polling.
- `tests/daemon_interactive_prd.rs` - add deterministic integration tests for concurrency bounds, isolation behavior, dedup, and refresh order.
- `src/validate/tests_interactive_prd.rs` - add/extend conformance tests for concurrent PRD tick guarantees.
