# Implementation Notes

## Decisions Made
- **Concurrent worker model**: Used `std::thread::scope` with a shared `Mutex<VecDeque<GhIssue>>` work queue and `worker_count` scoped threads. This is the simplest stable-Rust approach that provides bounded concurrency without external dependencies. Workers drain the queue in a loop, processing one issue at a time.
- **Per-thread bot_login_cache**: Each worker thread initializes its own `bot_login_cache: Option<String> = None`. This eliminates shared mutable state between workers. The first issue per thread triggers a `gh api user` call to populate the cache, which is then reused for subsequent issues on the same thread.
- **Dedup before spawning**: Both label polls (`ralph:prd` and `ralph:prd-active`) are performed sequentially first, then issues are deduplicated using a `HashSet<u32>` into a single `Vec<GhIssue>` before any worker threads are spawned. This is cleaner than the previous approach of deduplicating during iteration.
- **Error aggregation**: Errors are collected into a `Mutex<Vec<(u32, String)>>` shared across workers. After all workers join, errors are emitted to stderr. The tick always returns `Ok(())` — per-issue errors are informational, not propagated.
- **Panic isolation**: Each issue is processed inside `std::panic::catch_unwind(AssertUnwindSafe(|| ...))`. Panics are downcast to extract the message and logged as errors alongside normal errors.
- **Once-per-tick refresh**: `refresh_repo_clone()` is called exactly once after dedup and before worker spawn, only when there are deduplicated issues to process (non-empty tick). The `#[allow(dead_code)]` attribute was removed since the method is now actively called.
- **CWD safety preserved**: Loop 1 already added `cwd: Option<PathBuf>` to `CliBackend` and wired it through `create_backend`. No `CwdGuard` usage exists in `interactive_prd.rs`. Each backend call uses explicit cwd via `Command::current_dir`.

## Spec Deviations
- **No removal of per-generation refresh calls**: The spec mentions "Remove per-issue/per-generation refresh calls from `generate_*_with_timeout` paths." However, examination of the code shows that `refresh_repo_clone()` was marked `#[allow(dead_code)]` and was NOT called from any `generate_*_with_timeout` function. There are no per-issue refresh calls to remove — the only refresh call is the new once-per-tick call added in this loop.
- **CWD guard already eliminated**: The spec's "CWD safety" section (§3) describes adding `cwd: Option<PathBuf>` to `CliBackend` and removing `CwdGuard` from PRD processing. This was already completed in Loop 1. No changes were needed in `src/backend/mod.rs`.
- **Conformance tests use structural/pattern-level validation**: Some concurrency conformance tests (bounded worker count, error/panic isolation, dedup invariant) validate the concurrency patterns in isolation rather than calling `poll_and_advance_prd` directly. This is because the conformance test framework (`RalphHarness`) doesn't easily support PATH-level mocking needed for `gh` CLI calls within the `src/validate/` module. The integration tests in `tests/daemon_interactive_prd.rs` provide the full end-to-end coverage calling `poll_and_advance_prd` directly.
