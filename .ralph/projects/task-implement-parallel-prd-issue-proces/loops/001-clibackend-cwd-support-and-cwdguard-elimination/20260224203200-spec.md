# Feature: CliBackend CWD Support and CwdGuard Elimination

## Description
Add an optional `cwd` field to `CliBackend` so that each backend instance can specify its own working directory for subprocess execution, eliminating the need for the process-global `CwdGuard` in PRD processing. This is the foundational change required before parallelizing issue processing — without per-backend cwd, concurrent threads would race on `std::env::set_current_dir`.

The feature adds `cwd: Option<PathBuf>` to `CliBackend`, applies it via `Command::current_dir()` in `execute_streaming`, updates `create_backend()` in `interactive_prd.rs` to accept and forward a cwd path, removes all `CwdGuard` usage from `generate_*_with_timeout` functions (along with their per-generation `refresh_repo_clone()` calls which will be relocated in a later feature), and updates all existing callers to preserve current default behavior by passing `None`.

## Acceptance Criteria
- [ ] `CliBackend` struct has a `cwd: Option<PathBuf>` field.
- [ ] `CliBackend::new()` accepts an optional `cwd` parameter (or a builder/`with_cwd` method is provided) and stores it.
- [ ] `CliBackend::execute_streaming()` calls `cmd.current_dir(path)` when `self.cwd` is `Some(path)`.
- [ ] When `self.cwd` is `None`, `execute_streaming` behavior is unchanged (inherits process cwd).
- [ ] All existing `CliBackend` construction sites (claude, codex, and any other backend modules) compile and pass `None` for cwd, preserving default behavior.
- [ ] `create_backend()` in `interactive_prd.rs` accepts a `cwd: Option<PathBuf>` parameter and forwards it to the backend constructor.
- [ ] `generate_questions_with_timeout`, `generate_draft_from_answers_with_timeout`, and `generate_revision_from_feedback_with_timeout` pass `config.repo_clone_path()` as cwd when creating backends instead of using `CwdGuard`.
