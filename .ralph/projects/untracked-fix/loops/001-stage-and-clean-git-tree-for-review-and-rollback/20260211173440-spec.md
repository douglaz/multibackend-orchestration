# Feature: Stage and Clean Git Tree for Review and Rollback

## Description
Add two git helpers (`stage_implementation_changes` and `reset_and_clean_working_tree`) in `src/git/commit.rs` and integrate them into the orchestrator so that (a) newly created implementation files appear in the reviewer diff context and (b) rollback restores a clean working tree while preserving `.ralph/**` orchestration state. This is a single cohesive change because the staging helper and the cleanup helper share the same pathspec exclusion pattern and both must be wired into `src/workflow/orchestrator.rs` at related call sites.

## Acceptance Criteria
- [ ] `stage_implementation_changes(workdir)` stages all non-`.ralph/**` changes so `git diff HEAD` (used by the reviewer) includes newly created files
- [ ] `reset_and_clean_working_tree(workdir)` restores tracked files, unstages index entries, and removes untracked files/dirs while preserving `.ralph/**`
- [ ] `reset_and_clean_working_tree` handles unborn-branch repos (no HEAD) gracefully
- [ ] `stage_implementation_changes` is called in `orchestrator.rs` immediately before each transition to `Phase::Reviewing` (initial impl-notes and post-review-feedback), guarded by `is_git_repo`
- [ ] `rollback_current_loop` signature gains a `workspace_root: &Path` parameter; both call sites (review-limit in `run()` and `PromptChangeAction::RestartLoop` in `handle_prompt_change`) are updated
- [ ] `rollback_current_loop` calls `reset_and_clean_working_tree` when inside a git repo, before removing loop artifacts
- [ ] `.ralph/**` orchestration state is never disturbed by staging or cleanup
- [ ] `commit_feature_loop()` and `ensure_clean_start_for_new_loop()` remain unchanged
- [ ] Test A (`tests/git.rs`): staging makes a new non-`.ralph` file visible in `working_tree_diff_excluding_orchestration_state` and keeps `.ralph` paths out of the staged diff
- [ ] Test B (`tests/git.rs`): `reset_and_clean_working_tree` removes non-`.ralph` tracked modifications and untracked files while preserving `.ralph` runtime files, and `changed_paths_excluding_prefixes` returns empty afterward
- [ ] Test C (`tests/orchestrator.rs`): `review_iteration_limit_rollback` extended so the implementer creates a new file; after rollback the file is gone, state rewinds to planning, and a subsequent run is not blocked by dirty-tree validation
- [ ] `nix build` succeeds
- [ ] No new dependencies, config fields, CLI flags, or schema changes are introduced
