# Implementation Notes

## Decisions Made
- **Removed `Workspace::discover()` from daemon start**: The start flow now derives repo roots entirely from `--data-dir` + `--repo` slugs, calling `clone_or_bootstrap` per repo then `Workspace::load(repo_dir.join(".ralph"))`.
- **Removed `resolve_git_root()` and `effective_daemon_config()`**: These helpers were tied to the legacy single-repo path. Per-repo config is now resolved inline using `resolve_daemon_config` on each repo's workspace.
- **`guard_not_git_repo` uses nearest existing ancestor**: Since `--data-dir` may not exist yet, the guard walks up to find the nearest existing ancestor and runs `git rev-parse --show-toplevel` there.
- **`clone_or_bootstrap` is synchronous**: Both clone (via `gh repo clone`) and bootstrap (`ensure_repo_ready_sync`) are synchronous operations called before async runtime setup. This simplifies the flow since these are one-time provisioning steps.
- **`scan_task_stores` for status/abort**: Instead of using `Workspace::discover()`, status and abort scan `<data-dir>/*/*/.ralph/daemon/tasks.json` to find all task stores. Abort uses `resolve_task_index` on the combined task list across all stores to handle cross-repo ambiguity.
- **JoinSet for parallel runtime**: Each repo gets its own `runtime::run()` spawned on a `tokio::task::JoinSet`. The first error triggers `abort_all()` on remaining tasks.
- **Deprecation warning is one-time**: Only printed once if any repo's config has `daemon.repo` set, to avoid spam with multi-repo starts.
- **Mock gh clone support**: Added `repo clone` handler to `daemon_mock_gh_script()` so existing tests work when the repo dir doesn't have `.git` yet. Also created a standalone `daemon_mock_gh_clone_script()` with `MOCK_GH_CLONE_FAIL` env var for testing failure paths.
- **All daemon tests migrated to `new_daemon` harness**: Every conformance test that interacts with daemon CLI now creates its own `RalphHarness::new_daemon()` harness, ensuring the `data_dir/owner/repo/` layout is correct for `scan_task_stores` and `clone_or_bootstrap`.

## Spec Deviations
- **`start_validates_inputs_and_workspace` test simplified**: The original test checked that daemon start fails without a workspace. Since `clone_or_bootstrap` now auto-creates workspaces, this test was changed to verify `--repo` validation (missing repo -> error) and successful start with proper setup.
- **Multi-repo status/abort tests use `copy_dir_recursive`**: Since each `new_daemon` harness creates its own temp dir, multi-repo tests copy repo dirs under a single combined data-dir for status/abort scanning. This is a test-only pattern, not a production behavior.
- **`execute_abort` cross-repo lookup**: The abort command first collects all tasks across all stores, resolves the task index on the combined list (handling ambiguity), then calls `abort_task` on the correct per-repo store.

## Testing
- `cargo check` — clean compilation, no warnings
- `cargo test` — all 577 tests pass (375 lib + 202 integration)
- 7 new conformance tests covering all spec-required scenarios:
  1. `daemon_start_bootstraps_empty_dir` — clone+bootstrap success
  2. `daemon_start_rejects_git_data_dir` — guard rejection
  3. `daemon_start_rejects_duplicate_repo` — duplicate --repo rejection
  4. `daemon_start_clone_failure_propagates` — clone failure, no silent bootstrap
  5. `daemon_status_multi_repo` — multi-repo status aggregation
  6. `daemon_abort_cross_repo` — cross-repo abort by full task ID
  7. `daemon_abort_ambiguous_bare_number` — ambiguous bare number across repos
