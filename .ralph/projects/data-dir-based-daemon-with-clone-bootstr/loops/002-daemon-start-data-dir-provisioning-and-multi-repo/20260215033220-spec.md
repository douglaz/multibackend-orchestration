# Feature: Daemon Start Data-Dir Provisioning and Multi-Repo Runtime Fan-Out

## Description
Loop 1 already completed the CLI surface (`--data-dir`, repeatable `--repo`, strict slug validation, duplicate rejection). The main missing behavior is `daemon start`: it still uses `Workspace::discover()`, ignores `--data-dir` operationally, provisions no repo directories, and runs only one runtime.  
This feature implements the real start flow for data-dir mode: safe data-dir guard, clone/bootstrap per repo, per-repo task stores/config, and parallel runtime execution with fail-fast cancellation.

## Acceptance Criteria
- [ ] `execute_start` derives repo roots only from `--data-dir` + each `--repo` slug, and no longer depends on `Workspace::discover()` for daemon startup context.
- [ ] A new `guard_not_git_repo(data_dir: &Path)` rejects `--data-dir` paths inside a git working tree by checking the nearest existing ancestor with `git rev-parse --show-toplevel`.
- [ ] The guard runs before any directory creation; after passing, `--data-dir` is created with `create_dir_all`.
- [ ] A new `clone_or_bootstrap(owner, repo, repo_dir)` helper implements: skip clone if `repo_dir/.git` exists; otherwise create parent directories and run `gh repo clone owner/repo <repo_dir>`.
- [ ] Clone failure is propagated immediately (no bootstrap fallback for failed clone into missing/empty target).
- [ ] `clone_or_bootstrap` always calls `bootstrap::ensure_repo_ready_sync(repo_dir)` after clone/clone-skip.
- [ ] `bootstrap::ensure_repo_ready_sync` is public so start flow can call it directly.
- [ ] Start iterates all validated `--repo` values, loads each workspace from `<data-dir>/owner/repo/.ralph`, resolves daemon config per repo, and creates one `TaskStore` per repo.
- [ ] `daemon start` ignores `workspace.daemon_repo` / project `daemon.repo` for repo selection and prints a one-time deprecation warning if configured.
- [ ] Start runs one `runtime::run()` per repo using `tokio::task::JoinSet`; first join/runtime error triggers `abort_all()` and returns that error.
- [ ] New conformance tests cover: empty-dir clone+bootstrap success, git-repo-as-data-dir rejection, clone failure propagation, and deprecation warning for ignored config repo key.

## Files to Modify/Create
- `src/cli/daemon.rs` - add `guard_not_git_repo` and `clone_or_bootstrap`; rewrite `execute_start` for per-repo provisioning and `JoinSet` orchestration; remove legacy single-repo startup path.
- `src/daemon/bootstrap.rs` - make `ensure_repo_ready_sync` public.
- `src/validate/tests_daemon.rs` - add conformance tests for start-path guard/clone/bootstrap/deprecation behaviors.
- `src/validate/mock_scripts.rs` - extend `gh` mock behavior for clone success/failure test scenarios.

## Dependencies
- Requires: CLI Argument Restructuring and Validation Hardening (Loop 1)
- Blocks: Multi-repo `daemon status` aggregation and cross-repo `daemon abort` scanning/ambiguity handling
