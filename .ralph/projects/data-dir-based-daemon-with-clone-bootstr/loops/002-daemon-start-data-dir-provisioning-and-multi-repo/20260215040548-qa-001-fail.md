# QA: FAIL
## Failures
1. `daemon_start_rejects_git_data_dir` fails because `preflight_check_gh()` runs before `guard_not_git_repo()` in `src/cli/daemon.rs`, so in the nix sandbox it errors on missing `gh` instead of returning the expected git-repo guard error.

2. `rebase_pr_comment_not_issue`, `rebase_dedup_by_head_sha`, and `rebase_force_with_lease_rejection` fail because the mock `git` script in `src/validate/mock_scripts.rs` returns success for `rev-parse --show-toplevel` unconditionally, causing `guard_not_git_repo()` to treat the data directory as a git repo.

3. `config_merge_and_defaults` fails because the test writes project config for `acme/widgets` but executes with `--repo acme/project-override`, so no project override config is loaded and defaults are observed.

## Suggested Fixes
1. In `src/cli/daemon.rs`, run `guard_not_git_repo(data_dir)` before `preflight_check_gh()` so repo-safety validation happens first and deterministically.

2. In `src/validate/mock_scripts.rs`, update mock `git rev-parse --show-toplevel` behavior to return non-zero when CWD is the daemon data directory (not a repo), while preserving success in actual repo contexts.

3. Fix `config_merge_and_defaults` setup to align config target and runtime repo slug (either write config for `acme/project-override` or run the command against `acme/widgets`).
