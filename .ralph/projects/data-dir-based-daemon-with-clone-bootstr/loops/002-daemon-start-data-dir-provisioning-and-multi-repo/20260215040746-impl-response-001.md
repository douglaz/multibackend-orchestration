# Implementation Response (Iteration 1)

## Changes Made
1. **Reordered guard vs preflight in `src/cli/daemon.rs`**: Moved `guard_not_git_repo(&args.data_dir)` to run *before* `preflight_check_gh()` so that the git-repo safety check executes deterministically even when `gh` is not installed (e.g., in a nix sandbox). This fixes `daemon_start_rejects_git_data_dir` which was hitting the `gh` preflight error before the guard could reject the data-dir.

2. **Fixed mock git `rev-parse --show-toplevel` in `src/validate/mock_scripts.rs`**: Updated both `daemon_mock_git_rebase_fail_push_script()` and `daemon_mock_git_lease_reject_script()` to walk up from CWD looking for `.git` (directory or file) before returning success. If no `.git` is found, the mock returns `exit 128` with a "not a git repository" message. This prevents `guard_not_git_repo()` from falsely rejecting the daemon data-dir when the mock git is on PATH, fixing `rebase_pr_comment_not_issue`, `rebase_dedup_by_head_sha`, and `rebase_force_with_lease_rejection`.

3. **Aligned `config_merge_and_defaults` repo slug in `src/validate/tests_daemon.rs`**: Changed the merged-start invocation from `--repo acme/project-override` to `--repo acme/widgets`, matching the repo where the daemon harness and project config are actually initialized. Updated the corresponding assertion from `"daemon start validated for repo acme/project-override"` to `"daemon start validated for repo acme/widgets"`. The project-level config overrides (poll=15s, max_concurrent=3, etc.) now load correctly because the daemon operates on the same workspace where the "daemon-config" project was configured.
