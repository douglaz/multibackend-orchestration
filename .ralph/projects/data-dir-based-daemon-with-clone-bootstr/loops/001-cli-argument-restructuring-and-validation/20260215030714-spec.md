# Feature: CLI Argument Restructuring and Validation Hardening

## Description
Restructure the daemon CLI arguments to require `--data-dir <path>` on `start`, `status`, and `abort` subcommands, change `--repo` from `Option<String>` to `Vec<String>`, add `DaemonStatusArgs` struct, harden `validate_repo_slug()` with strict GitHub pattern and `.`/`..` rejection, add duplicate `--repo` rejection, and update all clap parse tests. This is the foundational change that all subsequent features (guard, clone-or-bootstrap, execute rewrites, test migration) depend on. The `execute_start`, `execute_status`, and `execute_abort` functions are updated only enough to compile with the new arg types — full behavioral rewrites come in later features.

## Acceptance Criteria
- [ ] `DaemonStartArgs` has a required `--data-dir: PathBuf` field (`#[arg(long)]`)
- [ ] `DaemonStartArgs.repo` changes from `Option<String>` to `Vec<String>` (`#[arg(long = "repo")]`)
- [ ] `DaemonCommand::Status` changes from unit variant to `Status(DaemonStatusArgs)` with `DaemonStatusArgs { data_dir: PathBuf }`
- [ ] `DaemonAbortArgs` gains a required `--data-dir: PathBuf` field
- [ ] `execute()` dispatch updates `Status` match arm to destructure `DaemonCommand::Status(status_args)`
- [ ] `execute_start` rejects empty `--repo` vec with a clear usage error before any I/O
- [ ] `validate_repo_slug()` is hardened: splits on exactly one `/`, each component matches `^[a-zA-Z0-9._-]+$`, explicitly rejects `.` and `..` as either component
- [ ] After validation, `--repo` slugs are normalized (lowercase, trim) and checked for duplicates; duplicate produces `RalphError::Validation("duplicate --repo: {slug}")`
- [ ] `execute_start`, `execute_status`, `execute_abort` compile with new arg types (minimal behavioral changes — just enough to wire through new fields)
- [ ] Clap parse test for `daemon start` updated to include `--data-dir /tmp/test` and verify `data_dir` field parsed
- [ ] Clap parse test for `daemon abort` updated to include `--data-dir /tmp/test` and verify `data_dir` field parsed
- [ ] New clap parse test assertion that `DaemonCommand::Status(args)` carries `data_dir`
- [ ] `nix develop -c cargo check` passes
