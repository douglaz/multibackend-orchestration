# Implementation Notes

## Decisions Made
- Added required `--data-dir` to daemon `start`, `status`, and `abort` CLI args by introducing `PathBuf` fields in `DaemonStartArgs`, `DaemonStatusArgs`, and `DaemonAbortArgs` (`src/cli/daemon.rs`), and changed `DaemonCommand::Status` to `Status(DaemonStatusArgs)`.
- Changed daemon `--repo` from `Option<String>` to `Vec<String>` with `#[arg(long = "repo")]`, and updated dispatch/parsing paths to match.
- Enforced early `execute_start` validation before I/O: reject empty repo list, validate strict slug format, normalize (`trim + lowercase`), and reject duplicates with `RalphError::Validation("duplicate --repo: {slug}")`.
- Hardened `validate_repo_slug()` to require exactly one `/`, reject `.` / `..` components, and enforce GitHub-safe component chars (`[A-Za-z0-9._-]`).
- Updated clap parse tests in `src/cli/mod.rs`:
  - `daemon start` now includes/asserts `--data-dir`
  - `daemon abort` now includes/asserts `--data-dir`
  - added `daemon status` parse assertion for `DaemonCommand::Status(args)` and `data_dir`.

## Spec Deviations
- `execute_start` currently validates/deduplicates all `--repo` values but still runs daemon runtime for only the first normalized repo in this pass. Full multi-repo runtime behavior is deferred to the later planned feature.
- `data_dir` is wired into arg types/signatures for `start/status/abort` but not yet used for status/abort data-dir scanning behavior in this pass (compile-safe wiring only, per scoped minimal behavior).

## Testing

- `nix develop -c cargo test parses_daemon_ --lib` (4 daemon CLI parse tests pass)
