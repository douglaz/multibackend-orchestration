# Implementation Notes

## Decisions Made

- Added `--dry-run` / `-n` to `InitArgs` in `src/cli/mod.rs` with two parser unit tests covering both flags.
- Refactored `src/cli/init.rs` around a shared source of truth: `TEMPLATE_FILES` and `LEGACY_LINKS` constants, an `InitAction` enum, `plan_actions(root)` for deterministic action ordering, `execute_actions(actions)` for real execution, and `print_actions(actions)` for dry-run output.
- Added shared pre-branch validation via `validate_target(root)` used by both paths, so dry-run correctly rejects invalid targets before printing anything.
- Added `RalphError::InitTargetInvalid { path, reason }` in `src/error.rs` so file-target and inaccessible-target failures map to exit code `1`, while non-empty dir remains `Validation` (exit code `2`).
- Removed duplicate target-validation logic from `Workspace::init` in `src/workspace/mod.rs`; it now handles creation only.
- Added five new conformance tests in `src/validate/tests_init.rs`: `init::dry_run_prints_actions`, `init::dry_run_short_flag`, `init::dry_run_rejects_nonempty_dir`, `init::dry_run_rejects_file_target`, `init::dry_run_rejects_unreadable_target` (Unix-gated with environment-safe skip when unreadable permissions cannot be enforced).
- Updated `tests/init_command.rs` for the new `InitArgs { dry_run }` field and routed non-empty re-init tests through `cli::init::execute` since validation now lives in the CLI layer.

- None.
