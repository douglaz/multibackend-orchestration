# Feature: Dry-run support for `ralph init`

## Description
Add `--dry-run` (long) and `-n` (short) flags to `ralph init` so users can preview planned workspace setup actions without creating or modifying any files. This involves:

1. Introducing shared constants (`TEMPLATE_FILES`, `LEGACY_LINKS`) so both dry-run output and real execution derive from the same source of truth.
2. Introducing a shared action representation (`InitAction` enum) and a `plan_actions(root)` function that returns a deterministic, ordered list of actions.
3. Extracting a `validate_target(root)` function from `Workspace::init` so both dry-run and real init run identical validation with identical exit codes before branching.
4. Updating `InitArgs` to accept `--dry-run` / `-n` and branching in `execute()` to either print actions or execute them.
5. Adding five conformance tests covering dry-run behavior and validation parity.

## Acceptance Criteria
- [ ] `ralph init <target> --dry-run` and `ralph init <target> -n` are equivalent and accepted by the CLI.
- [ ] Dry-run runs the same target validation as real init before branching: non-empty directory → exit code `2`; target is a file/non-directory → exit code `1`; unreadable/inaccessible target → exit code `1`.
- [ ] On a valid dry-run: exit code `0`, deterministic planned actions printed in execution order, no "initialized workspace at …" line, zero filesystem mutations.
- [ ] On a valid non-dry-run: behavior and output remain identical to current behavior.
- [ ] Shared constants `TEMPLATE_FILES` and `LEGACY_LINKS` are the single source of truth for both dry-run output and real execution.
- [ ] An `InitAction` enum and `plan_actions(root)` function exist; both `execute_actions()` and dry-run printing iterate the same action list.
- [ ] A `validate_target(root)` function is extracted and used by both paths.
- [ ] Conformance test `init::dry_run_prints_actions` passes: runs `init --dry-run` on an empty target, asserts full stdout action sequence and order, asserts no workspace artifacts are created.
- [ ] Conformance test `init::dry_run_short_flag` passes: verifies `-n` behaves exactly like `--dry-run`.
- [ ] Conformance test `init::dry_run_rejects_nonempty_dir` passes: asserts same failure behavior / exit code `2` as real init.
- [ ] Conformance test `init::dry_run_rejects_file_target` passes: asserts exit code `1`.
- [ ] Conformance test `init::dry_run_rejects_unreadable_target` passes: asserts exit code `1` (platform-gated if needed).
- [ ] `cargo test` passes with no regressions.
- [ ] Adding or removing a template/link item in the shared constants automatically updates both dry-run output and real execution without duplicate edits.

## Files to Modify/Create
- `src/cli/mod.rs` — Add `--dry-run` / `-n` fields to `InitArgs`.
- `src/cli/init.rs` — Major refactor: extract `validate_target()`, introduce `TEMPLATE_FILES` and `LEGACY_LINKS` constants, define `InitAction` enum and `plan_actions()`, refactor `create_workspace()` to iterate actions, add `print_actions()` for dry-run output, update `execute()` to branch on dry-run flag. Update unit tests to cover new internals.
- `src/error.rs` — Add `RalphError::InitTargetInvalid` variant (or similar) for the file-target / unreadable-target cases that should exit with code `1` (currently these fall through to the `Io` variant, but we need explicit handling to distinguish exit code `1` from exit code `2` for validation errors).
- `src/workspace/mod.rs` — Remove or delegate the validation logic from `Workspace::init()` to the new `validate_target()` in init.rs, so validation is not duplicated. `Workspace::init()` may retain directory creation only.
- `src/validate/tests_init.rs` — Add five new conformance tests: `dry_run_prints_actions`, `dry_run_short_flag`, `dry_run_rejects_nonempty_dir`, `dry_run_rejects_file_target`, `dry_run_rejects_unreadable_target`.
- `src/validate/mod.rs` — No changes needed (tests_init is already registered).
