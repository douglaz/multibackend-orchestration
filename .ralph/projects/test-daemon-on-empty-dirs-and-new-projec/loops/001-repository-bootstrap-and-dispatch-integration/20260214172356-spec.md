# Feature: Repository Bootstrap and Dispatch Integration

## Description
Create `src/daemon/bootstrap.rs` with the `ensure_repo_ready()` function that prepares greenfield repositories for daemon task dispatch, and integrate it into `dispatch_task()` in `runtime.rs`. This is the core enabler for the entire project: it detects the repository state (non-git, bare, zero-commit, or normal), performs the minimal idempotent operations to reach a worktree-ready state (git init, bootstrap commit, workspace init), and wires into the existing dispatch path so all subsequent worktree creation succeeds.

The function must handle: (a) non-git directories by running `git init`, (b) bare repos by returning a typed unsupported error, (c) unborn HEAD by creating a single empty bootstrap commit with signing/hooks disabled and fallback identity, (d) missing `.ralph/` by initializing the workspace, and (e) already-ready repos as a no-op. All operations must be idempotent — calling `ensure_repo_ready()` twice must not add extra commits or fail.

## Acceptance Criteria
- [ ] New file `src/daemon/bootstrap.rs` exists with `pub async fn ensure_repo_ready(repo_root: &Path) -> Result<()>`
- [ ] If `repo_root` is not a git repository, `git init` is executed to create one
- [ ] If the repository is bare (`--is-bare-repository` returns true), a typed error is returned (not a panic or generic string)
- [ ] If `HEAD` is unborn (no commits), exactly one empty bootstrap commit is created with message like `"ralph: bootstrap empty commit"`
- [ ] Bootstrap commit uses `-c commit.gpgsign=false` and `--no-verify` to avoid signing and hook failures
- [ ] If git user identity is not resolvable (no `user.name`/`user.email` in any scope), repo-local fallback identity `ralph-daemon` / `ralph@localhost` is set without overwriting existing config
- [ ] If `.ralph/` directory is missing after git is ready, workspace initialization is performed (either via internal init logic or equivalent idempotent file creation)
- [ ] Existing repos with valid `HEAD` are not modified — commit count and HEAD SHA remain unchanged
- [ ] Calling `ensure_repo_ready()` twice on the same directory produces no additional side effects (idempotent)
- [ ] `src/daemon/mod.rs` exports the new `bootstrap` module
- [ ] `dispatch_task()` in `src/daemon/runtime.rs` calls `ensure_repo_ready(&config.repo_root)` before `create_worktree()`, propagating errors as task failures
- [ ] All bootstrap git operations are deterministic under absent global git config (no dependency on `~/.gitconfig`)

## Files to Modify/Create
