# Feature: Worktree hardening with stale-metadata recovery, branch-mismatch correction, and artifact preservation validation

## Description
Harden the worktree lifecycle in the daemon's `create_worktree` and `clean_worktree` paths to handle real-world edge cases that arise during retry dispatch. Three concerns are addressed together because they share the same code surface (`src/daemon/worktree.rs`) and exercise the same retry-dispatch flow:

1. **Stale worktree metadata recovery**: Before `git worktree add`, run `git worktree prune` so that leftover `.git/worktrees/<name>` entries from deleted-on-disk worktrees do not block creation. This makes worktree creation idempotent across hard crashes and manual directory deletions.

2. **Branch-mismatch correction on reuse**: When the target worktree directory already exists (reuse path), add a `verify_worktree_branch()` check that reads the current HEAD branch of the worktree and compares it to the expected daemon branch. If the branch does not match, attempt a best-effort `git checkout --force <expected_branch>`. If force checkout fails, fail dispatch with an explicit error rather than silently running on the wrong branch.

3. **Artifact preservation validation**: Add an explicit end-to-end test that proves `.ralph/projects/<id>/loops/` artifacts survive the full retry-dispatch-and-clean cycle. While the underlying `clean_worktree` implementation already excludes `.ralph/` via `git clean --exclude=.ralph`, the required test `runtime_retrigger_preserves_project_artifacts` has not been written yet.

This is the final feature loop — once it is complete, all 7 required tests and all 6 functional requirements from the master prompt will be satisfied.

## Acceptance Criteria
- [ ] `create_worktree()` runs `git worktree prune` (in the parent repo root) before every `git worktree add` invocation, so stale metadata from previously deleted worktrees is cleaned up.
- [ ] When `create_worktree()` detects an existing worktree directory (reuse path), it calls `verify_worktree_branch(wt_path, expected_branch)` before returning success.
- [ ] `verify_worktree_branch()` reads the worktree's current branch (via `git rev-parse --abbrev-ref HEAD` executed inside the worktree) and compares it to the expected daemon branch name.
- [ ] If the branch matches, `verify_worktree_branch()` returns `Ok(())` silently.
- [ ] If the branch does not match, `verify_worktree_branch()` attempts `git checkout --force <expected_branch>` inside the worktree and logs a structured warning about the branch correction.
- [ ] If force checkout fails, `verify_worktree_branch()` returns an error with an explicit message including both the actual and expected branch names; this error propagates up to fail dispatch.
- [ ] A structured log is emitted when `git worktree prune` removes stale entries (prune is logged at debug level regardless of outcome).
- [ ] `clean_worktree` continues to preserve `.ralph/` contents (existing behavior confirmed, no code change needed — only test coverage).
- [ ] Test `runtime_create_worktree_handles_stale_metadata` passes: creates a worktree, deletes the directory on disk but leaves `.git/worktrees/<name>` metadata, then calls `create_worktree` again — asserts it succeeds (prune clears stale metadata before add).
- [ ] Test `runtime_reuse_worktree_corrects_branch_mismatch` passes: creates a worktree on the expected branch, then checks out a different branch manually, then calls `create_worktree` — asserts force checkout restores the expected branch.
- [ ] Test `runtime_retrigger_preserves_project_artifacts` passes: sets up a task with `.ralph/projects/<id>/loops/001-*/artifact.md` files in its worktree, runs the retry-dispatch-clean cycle, then asserts those files still exist with original content.
