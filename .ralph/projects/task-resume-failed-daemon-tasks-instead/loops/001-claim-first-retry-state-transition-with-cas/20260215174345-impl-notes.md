# Implementation Notes

## Decisions Made
- Added `retrigger_failed_task()` in `src/daemon/runtime.rs` with strict claim-first ordering:
  - Calls `claim_issue` before any state mutation.
  - Performs CAS via `store.with_exclusive_tasks()` and only transitions `failed -> pending` if still `failed`.
  - On CAS conflict/missing task, performs best-effort claim release and returns `RalphError::GitConflict`.
- Added `release_claim()` in `src/daemon/github.rs` to remove `ralph:in-progress`.
- Added CLI support in `src/cli/daemon.rs`:
  - New subcommand: `ralph daemon retrigger <task_id>`
  - Invokes runtime retrigger flow and prints success output.
- Added CLI parse coverage in `src/cli/mod.rs` for the new `retrigger` subcommand.
- Added conformance tests in `src/validate/tests_daemon.rs`:
  - `runtime_retrigger_claim_failure_preserves_failed_state`
  - `runtime_retrigger_claim_then_cas_conflict_does_not_set_pending`
  - Also updated daemon help test to assert `retrigger` appears.
- Added structured runtime logs for:
  - claim failure (`event=claim_failure`)
  - CAS conflict (`event=cas_conflict`)
  - successful retrigger (`event=success`)
