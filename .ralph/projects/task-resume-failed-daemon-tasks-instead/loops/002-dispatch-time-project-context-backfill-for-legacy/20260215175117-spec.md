# Feature: Dispatch-time project context backfill for legacy failed retries

## Description
Loop 1 completed claim-first retrigger CAS safety. The next missing capability is recovering `project_id` for legacy failed tasks that were stored without it. Add dispatch-time discovery in the task worktree by scanning `.ralph/projects/<id>/state.json`, treating only directories with `state.json` as valid projects, and persisting `project_id` before spawn when exactly one valid project is found. Dispatch must then route from persisted context (`ralph run --project <id>`), while zero or ambiguous matches continue with `project_id = None` (`ralph auto --idea ...`) with structured warnings.

## Acceptance Criteria
- [ ] `dispatch_task()` performs project discovery only when `task.project_id` is `None`, scanning `worktree/.ralph/projects/*/state.json`.
- [ ] Discovery ignores stray project directories without `state.json`; directory presence alone is never treated as valid.
- [ ] If exactly one valid project is found, daemon persists `task.project_id` to the task store before spawn.
- [ ] If persisting discovered `project_id` fails, dispatch aborts and the task is not moved to running state.
- [ ] If zero valid projects are found, dispatch continues with `project_id = None`.
- [ ] If multiple valid projects are found, dispatch continues with `project_id = None` and logs an ambiguity warning.
- [ ] Spawn routing uses persisted context only: `project_id` present => `ralph run --project <id>`; absent => `ralph auto --idea ...`.
- [ ] Add validate test `discover_project_id_ignores_dirs_without_state_json`.
- [ ] Add validate test `runtime_dispatch_backfills_legacy_failed_task_project_id`.

## Files to Modify/Create

- `src/validate/tests_daemon.rs` - add conformance tests for discovery filtering and legacy failed-task backfill dispatch behavior.
