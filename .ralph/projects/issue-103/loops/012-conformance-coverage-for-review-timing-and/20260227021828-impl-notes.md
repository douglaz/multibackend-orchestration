# Implementation Notes

## Decisions Made
- **Strengthened `review_retry_per_attempt_timing_guarantee`**: Replaced the simple label-existence checks with per-attempt semantic field assertions. Attempt 1 (malformed) asserts `raw_output` present, `error == null`, and `validation.status == "review_parse_failed"`. Attempt 2 (approved) asserts `raw_output` present, `error == null`, and `validation.status == "ok"`. This uses `find()` to locate each specific attempt entry rather than relying on position.
- **New `transport_failure_log_schema` test**: Uses a backend script that returns valid specs for draft generation but exits with code 1 (printing an error to stderr) when review is requested. This exercises the `Ok(Err(err))` branch in `run_review_with_retry_sync` (line 2244 of `interactive_prd.rs`), which logs with `raw_output: None`, `error: Some(...)`, and `ValidationResult::NotChecked`.
- **Issue number 30**: Chose a unique issue number (30) for the transport failure test to avoid collision with existing tests (which use 11-24, 99).
- **Exit code tolerance**: The transport failure test uses `_output` (ignoring exit code) because the daemon may exit non-zero when the review backend fails, but the key invariant is that it doesn't panic and the log files are written correctly.
- **No production code changes**: All changes are confined to `tests_interactive_prd_logging.rs` as specified.
