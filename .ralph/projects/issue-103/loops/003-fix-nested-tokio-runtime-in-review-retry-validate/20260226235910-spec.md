# Feature: Fix Nested Tokio Runtime in Review Retry Validate Test

## Description
The `interactive_prd_logging::review_retry_callback_captures_malformed_attempts` conformance test creates a nested Tokio runtime (`tokio::runtime::Builder::new_current_thread()`) inside the validate harness, which already runs under `#[tokio::main]` in `src/main.rs`. This causes a panic: "Cannot start a runtime from within a runtime." The test must be restructured to run its async code without spawning a second runtime — for example, by using `tokio::task::spawn_blocking` to offload the runtime creation to a thread that is not already inside a Tokio context, or by restructuring the test to be purely synchronous using a non-Tokio executor. Additionally, the test should be strengthened to assert that per-attempt review retries produce distinct log files on disk (not just callback events), as recommended by the completion verdict.
