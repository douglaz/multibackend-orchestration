# Feature: Interactive PRD Debug Logging

## Description
Add persistent, structured debug logging for all Interactive PRD backend calls. Every backend attempt—including each individual retry within review-retry loops—produces a JSON log file on disk under a per-issue `logs/` directory. Logging is best-effort: failures emit `eprintln!` and never block the workflow. A per-attempt callback hook is added to `run_review_with_retry` in `src/prd/quick.rs` so callers can observe each attempt before retry/discard logic executes.

## Acceptance Criteria
- [ ] Log structs `PrdDebugLogEntry` and `ValidationResult` are defined in `src/daemon/interactive_prd.rs` with the exact schema from the spec (including `#[serde(tag = "status", rename_all = "snake_case")]` on `ValidationResult`)
- [ ] Logs are written under `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/{issue_number}/logs/` with directories created on demand
- [ ] State file path `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/{issue_number}.json` is unchanged
- [ ] Each log filename follows `{YYYYMMDDTHHMMSSZ}-{label}.json` format using create-new semantics with `-NNN` collision suffix (`001`..`9999`), falling back to `eprintln!` on exhaustion
- [ ] `RALPH_PRD_LOG_TRUNCATE` env var controls optional max-byte truncation of prompt field; `prompt_chars` always reflects original untruncated count; truncation is UTF-8 boundary safe with `... [truncated at N bytes, full length: M bytes]` marker
- [ ] All question-generation backend calls emit logs with labels `question-gen-a`, `question-gen-b`, `synthesis`
- [ ] All draft + section-retry calls emit `draft-attempt-{N}` labels
- [ ] All draft review-retry calls emit `draft-review-attempt-{N}-of-3` labels
- [ ] All draft revision calls emit `draft-revision-{N}` labels
- [ ] All feedback-revision draft calls emit `feedback-draft-attempt-{N}` labels

- [ ] All feedback revision calls emit `feedback-revision-{N}` labels
- [ ] `run_review_with_retry` in `src/prd/quick.rs` gains an `on_attempt: Option<&mut dyn FnMut(ReviewAttemptEvent)>` parameter and fires the callback on every attempt immediately after parse, before retry/discard
