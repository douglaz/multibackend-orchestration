# Feature: Per-Attempt Immediate Log Persistence in Review Retry

## Description
Move review-retry attempt logging from deferred batch persistence to immediate per-attempt disk writes inside the `on_attempt` callback. Currently, `run_review_with_retry_sync` buffers all `ReviewAttemptEvent` objects in a `Vec` during the timeout-wrapped execution, then writes all log files in a loop after the entire retry sequence completes (lines 2213–2243 of `interactive_prd.rs`). This violates the requirement that each review attempt's debug log file is persisted to disk **before** the next retry/discard decision executes. Additionally, add a conformance test that proves the timing guarantee — specifically, that attempt-1's log file exists on disk before attempt-2 begins.

## Acceptance Criteria
- [ ] In `run_review_with_retry_sync`, the `on_attempt` callback calls `logger.log_attempt()` immediately for each `ReviewAttemptEvent` (computing label and `ValidationResult` inline), rather than deferring writes to after the retry loop.
- [ ] The in-memory `attempt_events` buffer is retained only for tracking attempt count (used by timeout/transport error fallback labeling at lines 2248–2282), not for deferred log writes.
- [ ] Log writes inside the callback remain outside the `tokio::time::timeout` boundary — the callback fires inside `quick.rs` but the actual `logger.log_attempt()` I/O must not consume timeout budget. This can be achieved by having the callback write through a `std::sync::mpsc` channel that is drained after the timeout block, or by accepting that the callback's synchronous write is fast enough (local filesystem) and documenting that choice. Preferred: accept synchronous write in callback since it's local I/O to tmpdir-class paths, and the original `run_backend_sync` already does synchronous log writes in-line.
- [ ] Existing `run_backend_sync` behavior (which already writes logs synchronously inline) is unchanged.
- [ ] All existing conformance tests continue to pass.
- [ ] A new or extended conformance test verifies the per-attempt timing guarantee: the backend mock script for attempt-2 (or later) checks that a log file from the prior attempt exists on disk before it produces its response.
- [ ] No panics introduced; best-effort semantics preserved (log failure emits `eprintln!`, does not block retry).

## Files to Modify/Create

Keep minimal `attempt_events` tracking (attempt count + prompt info) for the timeout/transport fallback paths at lines 2248–2282.
