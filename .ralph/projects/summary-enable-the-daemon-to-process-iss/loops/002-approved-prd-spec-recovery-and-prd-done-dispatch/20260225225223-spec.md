# Feature: Approved PRD Spec Recovery and `prd-done` Dispatch Input Selection

## Description
Implement deterministic approved-spec recovery for `ralph:prd-done` issues and wire it into daemon dispatch so claimed `ralph:ready` issues use the latest approved PRD draft body (with strict cleanup and fallback). This builds on the completed label-gating and shared draft-format constants from Loop 1.

## Acceptance Criteria
- [ ] Add `extract_approved_spec(gh_bin: &str, owner: &str, repo: &str, issue_number: u32) -> Option<String>` to `interactive_prd`.
- [ ] `extract_approved_spec` resolves authenticated bot login and fetches issue comments via existing GitHub helpers; bot-login or comments-fetch failure returns `None`.
- [ ] Add a pure parsing helper that scans bot-authored comments only, finds all `status-approved-vN` markers, selects highest `N`, then selects the latest `draft-vN` comment in API order.
- [ ] User-authored spoofed `status-approved-vN` and `draft-vN` markers are ignored.
- [ ] Draft cleanup removes PRD marker lines, strips heading only when the first content line starts with `DRAFT_HEADING_PREFIX`, strips footer only when trailing content line equals `DRAFT_FOOTER`, then trims surrounding whitespace.
- [ ] Parser returns `None` when no approved marker exists, no matching draft exists, cleaned content is empty, or parsing preconditions fail.
- [ ] `poll_and_claim()` uses `extract_approved_spec(...)` only when the claimed issue has `ralph:prd-done`, through the existing blocking wrapper path before dispatch.
- [ ] On `Some(spec)`, dispatch uses `raw_idea = spec` and stderr contains `prd-done: using approved spec`.
- [ ] On `None` or extraction error, dispatch falls back exactly to `compose_raw_idea(&issue.title, issue.body.as_deref())` and stderr contains `approved spec not found, falling back`.
- [ ] Non-`ralph:prd-done` issues continue using the existing `compose_raw_idea(...)` path.
- [ ] Unit tests in `interactive_prd` cover: highest approved revision wins, duplicate `draft-vN` latest-wins, bot-only filtering, cleanup behavior, empty-cleaned-body `None`, and formatter/extractor consistency.
- [ ] Validate conformance tests cover: PRD-done dispatch uses approved spec, mixed labels (`prd-done` + `prd-approved`) are not blocked, missing markers fallback + warning, comments API failure fallback + warning, user spoof ignored, highest revision wins end-to-end.
- [ ] Existing in-progress PRD conflict tests remain passing.

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - add approved-spec extraction API, pure parser/cleanup helper(s), and unit tests for revision selection/filtering/cleanup/failure cases.
- `src/daemon/runtime.rs` - update `poll_and_claim()` dispatch input selection for `ralph:prd-done`, including required success/fallback logging.
- `src/validate/tests_interactive_prd.rs` - add conformance tests for PRD-done approved-spec dispatch and fallback/error scenarios.
