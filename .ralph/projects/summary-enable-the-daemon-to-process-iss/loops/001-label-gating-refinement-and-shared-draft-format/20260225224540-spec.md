# Feature: Label gating refinement and shared draft format constants

## Description
Refactor PRD label checking to distinguish between in-progress PRD labels and the terminal `ralph:prd-done` label, allowing `ralph:prd-done` issues to pass through the daemon claim loop. Simultaneously, extract the inline draft comment formatting into shared constants and a `format_draft_comment` helper function so that both the posting and future extraction code use identical format strings.

## Acceptance Criteria
- [ ] New `has_in_progress_prd_label(labels: &[String]) -> bool` function added to `interactive_prd.rs` that returns `true` only for `ralph:prd`, `ralph:prd-active`, `ralph:prd-approved`, `ralph:prd-failed`.
- [ ] `has_in_progress_prd_label` returns `false` when `ralph:prd-done` is present, even if in-progress labels are also present (`ralph:prd-done` precedence).
- [ ] Existing `has_prd_label()` function remains unchanged and continues to match all PRD labels including `ralph:prd-done`.
- [ ] `poll_and_claim()` in `runtime.rs` replaces the `has_prd_label()` guard with `has_in_progress_prd_label()`, so `ralph:prd-done` + `ralph:ready` issues are no longer skipped.
- [ ] Verbose skip log message in `poll_and_claim()` updated to say "in-progress PRD label" instead of generic "PRD label".
- [ ] `DRAFT_HEADING_PREFIX` constant defined as `"## Draft Engineering Specification (Revision "` in `interactive_prd.rs`.
- [ ] `DRAFT_FOOTER` constant defined as `"*Reply with feedback. Reply with \"approved\" or \"lgtm\" when this draft is ready.*"` in `interactive_prd.rs`.
- [ ] `format_draft_comment(revision: u32, spec_body: &str) -> String` public function added that produces the same output as the current inline `format!` calls.
- [ ] Both inline draft formatting sites in `interactive_prd.rs` (initial draft posting ~line 1181 and revision posting ~line 1342) replaced with calls to `format_draft_comment(...)`.
- [ ] Unit tests for `has_in_progress_prd_label`: positive cases for each in-progress label, negative for `ralph:prd-done`, negative for empty, negative for unrelated labels, and precedence test with mixed labels including `ralph:prd-done`.
- [ ] Unit test confirming `has_prd_label` still matches `ralph:prd-done` (regression guard).
- [ ] Unit test confirming `format_draft_comment` round-trip: output starts with `DRAFT_HEADING_PREFIX`, ends with `DRAFT_FOOTER`, and contains the spec body.
- [ ] All existing tests continue to pass.
