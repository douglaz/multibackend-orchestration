# Feature: Daemon Quick-Dev Dispatch and `ralph:quick` Label Routing

## Description

The next missing feature is daemon integration: recognize `ralph:quick`, bootstrap that label, and route daemon dispatch to quick-dev commands (fresh vs resume) without changing existing non-quick behavior.

## Acceptance Criteria
- [ ] `src/daemon/github.rs` adds required label tuple: `("ralph:quick", "#5319e7", "Use quick-dev orchestration flow")`.
- [ ] `ralph:quick` is included in `REQUIRED_LABELS` but excluded from `LIFECYCLE_LABELS`.
- [ ] Label-table tests verify `ralph:quick` is non-lifecycle and lifecycle classification behavior is unchanged.
- [ ] `src/daemon/process.rs` adds `spawn_ralph_quick_dev_auto()` and `spawn_ralph_quick_dev_run()` plus `build_*` helpers.
- [ ] Quick-dev process builders pass correct commands/flags:
- [ ] Fresh quick path: `quick-dev-auto --idea ... --project-id ... --workspace-root ...` (+ optional `--pr-url`).
- [ ] Resume quick path: `quick-dev-run --project ... --workspace-root ...` (+ optional `--pr-url`).
- [ ] New quick-dev spawns preserve current daemon process semantics (new session/process group, stdout/stderr redirected to task log).
- [ ] `src/daemon/runtime.rs` threads issue labels into dispatch and branches command selection by `issue_labels.contains("ralph:quick")`.
- [ ] Dispatch matrix is exact:
- [ ] quick label + new project -> `quick-dev-auto`
- [ ] quick label + resumed project -> `quick-dev-run`

- [ ] no quick label + resumed project -> existing `run`
- [ ] Failure invariant: quick-labeled issues never silently fall back to `auto/run`; quick-dispatch spawn errors remain fatal for that dispatch attempt and follow existing label rollback/terminal handling.

- [ ] Daemon conformance tests cover quick-label fresh/resume routing and confirm non-quick routing remains intact.
