# Feature: Quick-Dev Foundation — State Types, Parser Contracts, Config Fields, and Prompt Templates

## Description
Implement the foundational data types, parser contracts, configuration plumbing, and prompt template builders required by the quick-dev orchestration mode. This feature adds:
1. The `QuickDevPhase` enum and `quick_dev_phase` field to `ProjectState` for crash-safe resume.
2. Two strict parser functions (`parse_codex_review_output`, `parse_quick_final_review_output`) with their decision enums.
3. Four template config fields across `TemplateConfig`, `ProjectTemplateOverrides`, and `EffectiveTemplateConfig` with resolution logic.
4. A prompt builder module (`src/prompts/quick_dev.rs`) with default templates containing `CRITICAL FORMAT REQUIREMENTS` sections matching the parser contracts.
5. Unit tests for all new parsers, state serde backward compatibility, and config resolution.

This is the prerequisite layer that the orchestrator, CLI commands, and daemon integration will build on.

## Acceptance Criteria
- [ ] `QuickDevPhase` enum added to `src/project/state.rs` with variants `PlanAndImplement`, `CodexReview`, `ApplyFixes`, `FinalReview` and `#[serde(rename_all = "snake_case")]`.
- [ ] `quick_dev_phase: Option<QuickDevPhase>` field added to `ProjectState` with `#[serde(default)]`.
- [ ] Legacy state JSON without `quick_dev_phase` deserializes to `None` (backward-compatible serde default).
- [ ] `ProjectState::new()` initializes `quick_dev_phase: None`.
- [ ] `CodexReviewDecision` enum added to `src/workflow/parser.rs` with variants `ReviewSatisfied { body: String }` and `ChangesRequested { body: String }`.
- [ ] `QuickFinalReviewDecision` enum added to `src/workflow/parser.rs` with variants `Complete { body: String }` and `IssuesFound { body: String }`.
- [ ] `parse_codex_review_output(raw: &str) -> Result<CodexReviewDecision>` implemented: strips frontmatter, extracts first H1, matches exact case-sensitive headers `# Review: SATISFIED` and `# Review: CHANGES REQUESTED` (allowing trailing whitespace), returns descriptive `RalphError::ParseError` for any other header.
- [ ] `parse_quick_final_review_output(raw: &str) -> Result<QuickFinalReviewDecision>` implemented: same stripping/extraction logic, matches `# Final Review: COMPLETE` and `# Final Review: ISSUES FOUND` (allowing trailing whitespace).
- [ ] Both parsers return `ParseError` when no H1 is found.
- [ ] Four template fields added to `TemplateConfig` in `src/config/global.rs`: `quick_dev_plan_implement`, `quick_dev_codex_review`, `quick_dev_apply_fixes`, `quick_dev_final_review` with `#[serde(default = "default_quick_dev_*_template_path")]` defaults pointing to `"templates/quick_dev_*.md"`.
- [ ] Matching `Option<String>` fields added to `ProjectTemplateOverrides` in `src/config/project.rs`.
- [ ] Matching `PathBuf` fields added to `EffectiveTemplateConfig` in `src/config/mod.rs`.
- [ ] Resolution logic in `resolve_effective_config` wires project override → global value → computed path for all four fields using `resolve_template_path`.
- [ ] `src/prompts/quick_dev.rs` created with four public builder functions: `build_quick_dev_plan_implement_prompt`, `build_quick_dev_codex_review_prompt`, `build_quick_dev_apply_fixes_prompt`, `build_quick_dev_final_review_prompt`.
- [ ] Each builder accepts a `&Path` (template path) and a `&BTreeMap<String, String>` (vars), calls `render_template_with_fallback()` with an inline default template.
- [ ] Default templates for `codex_review` include `CRITICAL FORMAT REQUIREMENTS` specifying the exact H1 headers: `# Review: SATISFIED` or `# Review: CHANGES REQUESTED`.
- [ ] Default templates for `final_review` include `CRITICAL FORMAT REQUIREMENTS` specifying the exact H1 headers: `# Final Review: COMPLETE` or `# Final Review: ISSUES FOUND`.
- [ ] `pub mod quick_dev;` added to `src/prompts/mod.rs`.
- [ ] Unit tests cover: parser happy-path for all 4 decision variants, parser error for missing H1, parser error for wrong H1 text, parser tolerance of trailing whitespace, parser frontmatter stripping, state serde roundtrip with `quick_dev_phase` present and absent, `TemplateConfig` serde default for new fields.
