# Implementation Notes

## Decisions Made
- Fixed tracing subscriber to write to stderr via `.with_writer(std::io::stderr)` in `src/main.rs`. The `tracing_subscriber::fmt()` builder defaults to stdout, which caused all `tracing::warn!` diagnostics to contaminate machine-readable command output (config show, config get). Redirecting to stderr is the standard practice and the minimal correct fix — no warn-site changes or output-path gating needed.
- Fixed the PRD-disabled concurrency test's TOML config writing to insert `daemon_prd_enabled = false` immediately after the `[workspace]` section header, rather than appending at end-of-file. The previous append placed the key after `[backends.claude]` (introduced by `enable_fast_daemon_refinement`), so TOML parsing attributed it to the wrong section and the workspace default (`true`) was used instead.

## Spec Deviations
- The spec lists modifications to `src/config/mod.rs`, `src/daemon/runtime.rs`, and `src/daemon/refine.rs` for the config output and PRD gating fixes. The actual root causes were in `src/main.rs` (tracing writer) and `src/validate/tests_daemon_concurrency.rs` (TOML section placement). The runtime PRD gating logic in `src/daemon/runtime.rs` was already correct — it properly checks `config.prd_enabled` before spawning background or inline PRD tasks. No changes were needed to `src/daemon/refine.rs` as the refinement bypass and dispatch payload paths were not contributing to any test failures.
- The spec mentions 16 conformance failures but the actual failure count at time of implementation was 10 (9 stdout pollution + 1 PRD concurrency). The remaining 6 may have been fixed in a prior loop or the count was from an earlier snapshot.
