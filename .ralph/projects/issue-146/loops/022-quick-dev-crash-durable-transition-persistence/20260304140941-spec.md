# Feature: Quick-Dev Crash-Durable Transition Persistence

## Description
Core quick-dev functionality is in place (state model, 4-phase orchestrator, CLI commands, daemon routing, parser/template/config wiring, and conformance coverage).  
The remaining high-risk gap is crash-resume behavior at transition boundaries: destination phase state is not durably written before some checkpoints, and guard limits are not enforced at phase entry after crash recovery. This feature hardens those paths so resume is deterministic and guard-safe.

## Acceptance Criteria
- [ ] For every non-terminal quick-dev transition, destination state is persisted before checkpoint work: `quick_dev_phase`, mapped `current_phase`, `phase_iteration`, `quick_dev_review_iteration`, and `quick_dev_final_review_attempts`.
- [ ] Transition persistence is centralized via a shared helper so all branches use identical ordering and invariants.
- [ ] Failure invariant: if destination-state persistence fails, no checkpoint call is attempted and prior on-disk `state.json` remains valid.
- [ ] Failure invariant: if checkpoint/commit fails after destination-state persistence, resume starts from the destination phase (not the source phase) and does not re-run the source-phase backend call.
- [ ] Guard-at-entry invariant: when resuming in `CodexReview` with `review_iteration >= max_review_iterations`, reviewer call is skipped and flow moves directly to `FinalReview` guard path.
- [ ] Guard-at-entry invariant: when resuming in `FinalReview` with `final_review_attempts >= max_final_review_retries`, both final-review backend calls are skipped, force-complete artifact is written, and project is marked completed.
- [ ] Add regression tests that seed crash-window states and assert phase-correct resume and no extra backend invocations in guarded-entry scenarios.
- [ ] Add/extend validate conformance tests to cover transition-boundary resume correctness (not just eventual completion).

## Files to Modify/Create
- `src/workflow/quick_dev_orchestrator.rs` - persist destination phase/counters before transition checkpoints; add shared transition-persist helper; enforce guard checks at `CodexReview`/`FinalReview` entry.
- `tests/quick_dev_orchestrator.rs` - add crash-boundary and guard-at-entry resume regression tests with phase/order and call-count assertions.
- `src/validate/tests_quick_dev.rs` - add conformance cases for transition-boundary resume semantics and guard-resume behavior.
