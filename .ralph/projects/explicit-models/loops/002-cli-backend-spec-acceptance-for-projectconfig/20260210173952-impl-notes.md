# Implementation Notes

## Decisions Made
- Created `src/cli/backend_spec.rs` as a shared CLI helper module with two validation functions: `validate_backend_spec` (takes `GlobalConfig` for dynamic backend lookup) and `validate_backend_spec_name` (hardcodes `claude`/`codex` for contexts without config access). The `project new` command and `config set` command both use `validate_backend_spec_name` since they operate before full config resolution.
- Replaced the hardcoded `backend != "claude" && backend != "codex"` check in `src/cli/project.rs` with a call to `validate_backend_spec_name`, which delegates parsing to the existing `parse_backend_spec` in `src/backend/mod.rs` and then validates the base name.
- Replaced the hardcoded `ensure_backend` match in `src/cli/config.rs` with a delegation to `validate_backend_spec_name`. This ensures both `workspace.default_backend` (global) and `workflow.starting_backend` (project) go through the same spec-aware validation.
- Module registered as `pub(crate)` in `src/cli/mod.rs` since it's only used within the crate's CLI layer.

## Spec Deviations
- None. All acceptance criteria are addressed as specified.

## Testing
- `src/cli/backend_spec.rs` contains 13 unit tests covering: valid bare names, valid model specs, unknown base backends (both bare and with model), malformed specs (empty model, missing paren, empty name, empty string), and `validate_backend_spec_name` variants.
- `src/cli/project.rs` contains 8 unit tests covering the project backend validation path: bare names, model specs, unknown backends, and malformed input.
- `src/cli/config.rs` contains 14 unit tests covering: `ensure_backend` for bare names, model specs, unknown backends, malformed specs; and `parse_optional_backend` for model specs, bare names, null values, unknown backends, and malformed specs.
- To verify: run `cargo test` and ensure all new tests pass. Also run `cargo build` to confirm no compilation errors.
