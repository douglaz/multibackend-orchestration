# Feature: CLI Backend Spec Acceptance for Project/Config Commands

## Description
Loop 1 completed the runtime/backend layer (`parse_backend_spec`, model arg injection, registry caching, orchestration propagation, and config resolution).  
The remaining gap is CLI input validation: `project new --backend` and `config set` backend fields still reject `backend(model)` and only allow bare `claude`/`codex`.  
This feature updates CLI validators so every backend-entry surface accepts `backend(model)`, validates only the base backend name, and preserves the full spec string in config/state.

## Acceptance Criteria
- [ ] `ralph project new --backend "claude(opus)"` succeeds and stores `workflow.starting_backend = "claude(opus)"`.
- [ ] `ralph project new --backend "codex(gpt-5.3-codex-xhigh)"` succeeds; bare names still work unchanged.
- [ ] `ralph project new --backend "unknown(opus)"` fails with unknown-base-backend validation.
- [ ] `ralph config set workspace.default_backend "claude(opus)" --global` succeeds and preserves the exact value.
- [ ] `ralph config set workflow.starting_backend "claude(opus)" --project <id>` succeeds and preserves the exact value.
- [ ] Malformed specs (`claude()`, `claude(opus`, `(opus)`) are rejected in CLI setters using `parse_backend_spec` semantics.
- [ ] CLI backend validation no longer hardcodes only `"claude"`/`"codex"` string matches without parsing.
- [ ] Unit tests cover valid model specs, malformed specs, unknown base names, and backward compatibility with bare names.

## Files to Modify/Create
- `src/cli/project.rs` - replace hardcoded `--backend` validation with parsed spec validation against base backend name; keep stored string unchanged.
- `src/cli/config.rs` - update backend validation helpers used by `workspace.default_backend` and `workflow.starting_backend` setters to parse spec + validate base name.
- `src/cli/backend_spec.rs` - add shared CLI helper for backend-spec validation (parse + base-name check) to avoid duplicated logic.
- `src/cli/mod.rs` - register the new CLI helper module.
- `src/cli/project.rs` - add unit tests for project backend validation paths.
- `src/cli/config.rs` - add unit tests for config-set backend validation paths.
