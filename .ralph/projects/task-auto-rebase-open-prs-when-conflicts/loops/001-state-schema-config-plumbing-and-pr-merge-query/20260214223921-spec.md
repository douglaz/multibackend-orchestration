# Feature: State Schema, Config Plumbing, and PR Merge Query Infrastructure

## Description
Add the foundational data types, state schema extensions, configuration plumbing, and GitHub PR mergeability query/parsing that all subsequent auto-rebase behavior depends on. This includes the `PrMergeStatus` enum, `PrMergeInfo` struct, `last_rebase_at` and `last_rebase_head_sha` fields on `DaemonTask`, backward-compatible serde, new config keys for auto-rebase settings (enable flag, rebase interval, per-cycle cap, timeout), config get/set/show support in both global and project scopes, the `query_pr_merge_info` function wrapping `gh pr view --json mergeable,state,baseRefName,headRefOid`, the `post_pr_comment` helper, the `create_worktree_on_branch` function, and the `LAST REBASE` column in `ralph daemon status` output.

## Acceptance Criteria
- [ ] `PrMergeStatus` enum exists with variants `Conflicting`, `Mergeable`, `Unknown` and maps from GitHub's `CONFLICTING`, `MERGEABLE`, `UNKNOWN` strings exactly
- [ ] `PrMergeInfo` struct exists with fields: `merge_status: PrMergeStatus`, `state: String`, `base_branch: String`, `head_oid: String`
- [ ] `query_pr_merge_info(owner, repo, pr_number) -> Result<PrMergeInfo>` calls `gh pr view <pr_number> --repo <owner/repo> --json mergeable,state,baseRefName,headRefOid` and parses response correctly
- [ ] `DaemonTask` gains `last_rebase_at: Option<String>` and `last_rebase_head_sha: Option<String>` fields with `#[serde(default)]` for backward compatibility
- [ ] Old state files without `last_rebase_at` / `last_rebase_head_sha` deserialize without error (backward-compatible)
- [ ] New config keys added to `WorkspaceConfig`: `daemon_auto_rebase_enabled: bool` (default `true`), `daemon_rebase_interval_seconds: u64` (default `1800`), `daemon_max_rebases_per_cycle: u32` (default `3`), `daemon_rebase_timeout_seconds: u64` (default `120`)
- [ ] `ProjectDaemonOverrides` gains matching optional override fields for all four auto-rebase settings
- [ ] Config resolution merges project overrides over global defaults for the new keys
- [ ] `ralph config get workspace.daemon_auto_rebase_enabled` (and siblings) works
- [ ] `ralph config set workspace.daemon_auto_rebase_enabled false` works
- [ ] `ralph config show` includes the new auto-rebase keys
- [ ] `post_pr_comment(owner, repo, pr_number, body)` function exists using `gh pr comment <pr_number> --repo <owner/repo> --body <body>` (posts on PR, not issue)
- [ ] `create_worktree_on_branch(repo_root, workspace_root, task_id, branch) -> Result<PathBuf>` exists, creates/reuses `rebase-{task_id}` worktree directory, checks out the provided branch
- [ ] Existing `create_worktree` function is unchanged
- [ ] `ralph daemon status` output includes `LAST REBASE` column showing RFC3339 UTC timestamp or `-` when absent
- [ ] `nix develop -c cargo check` passes with all new types and functions
