# Review: SUGGESTIONS

## Required Changes
1. **Bounded rebase timeout is not enforced per attempt**
   - Current: `execute_rebase` applies `run_command_with_timeout(..., timeout)` separately to fetch and rebase, then does an unbounded push via `github::push_force_with_lease` (`src/daemon/runtime.rs:1087`, `src/daemon/runtime.rs:1102`, `src/daemon/runtime.rs:1123`, `src/daemon/github.rs:400`). This can exceed 120s per attempt and exceed the ~6 minute cycle bound with cap=3.
   - Expected: enforce a single per-attempt 120s budget that covers fetch + rebase + push (or at minimum apply timeout to push and decrement remaining time across steps).
   - Reference: Feature Spec acceptance criteria: per-attempt timeout and bounded runtime (`REBASE_TIMEOUT_SECONDS = 120`, worst-case ~6 minutes), Required Behavior sections 4 and 6.

2. **Missing explicit skip reasons for tasks without PR URL / branch**
   - Current: tasks are pre-filtered with `.filter(|t| t.pr_url.is_some() && t.branch.is_some())`, so missing-PR and missing-branch tasks are silently dropped (`src/daemon/runtime.rs:845`).
   - Expected: process in deterministic order but explicitly log skip reasons for `no PR URL` and `no task branch` as required.
   - Reference: Feature Spec acceptance criteria: “Tasks are skipped (with explicit reason) when: no PR URL … no task branch …”.

3. **Conformance tests do not fully validate required scenarios**
   - Current: several new tests can pass without asserting required behavior:
     - PR comment test only asserts when log file exists (`src/validate/tests_daemon.rs:3708`).
     - Dedup test allows pass when no comment log exists (`src/validate/tests_daemon.rs:3779`).
     - Force-with-lease test does not simulate/assert lease-mismatch-specific handling or “continue to next task” (`src/validate/tests_daemon.rs:3795`).
     - Interval skip uses fixed timestamp (`2026-02-14T22:00:00Z`) and is time-fragile (`src/validate/tests_daemon.rs:4046`).
   - Expected: make these deterministic and strict so they prove PR-comment surface, dedup-by-head-sha, lease-rejection handling, and interval skip behavior.
   - Reference: Validate Conformance Coverage items 8, 9, 10, 13 and Feature Spec acceptance criteria for daemon test coverage.

## Recommended Improvements
1. Handle `post_pr_comment` errors explicitly before updating dedup state (`last_rebase_head_sha`) so failed comment submissions are retried instead of being silently suppressed (`src/daemon/runtime.rs:1051`, `src/daemon/runtime.rs:1062`).
