# Feature: Fix tracing subscriber stdout contamination breaking validate tests

## Description
The `tracing_subscriber::fmt()` initialization in `src/main.rs` uses the default writer, which writes to **stdout**. This causes `warn!()` log output (specifically the "final review arbiter backend family overlaps" warning from `src/config/mod.rs:342-348`) to contaminate stdout on any command that calls `resolve_effective_config()`. Tests that parse stdout as JSON or match exact stdout content then fail because the warning text is prepended to the expected output. This breaks 9 conformance tests in `ralph validate` (296 passed, 9 failed), blocking the project acceptance gate.

The fix is to redirect the tracing subscriber to write to stderr, which is the standard convention for diagnostic/log output. This is a one-line change: adding `.with_writer(std::io::stderr)` to the subscriber builder in `src/main.rs`.

## Acceptance Criteria
- [ ] `tracing_subscriber::fmt()` in `src/main.rs` is configured with `.with_writer(std::io::stderr)` so all tracing log output goes to stderr, not stdout.

- [ ] The 9 previously failing conformance tests pass: `commands::config_show_project`, `prompt_review_panel::*`, `daemon::config_merge_and_defaults`, `daemon_rebase::agent_disabled_parses_none`, and `sessions::*`.

- [ ] No behavioral changes to log content or filtering — only the output destination changes from stdout to stderr.
