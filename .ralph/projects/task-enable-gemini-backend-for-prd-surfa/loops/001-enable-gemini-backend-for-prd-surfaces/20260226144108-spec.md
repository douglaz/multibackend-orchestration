# Feature: Enable Gemini Backend for PRD Surfaces

## Description
Enable the `gemini` backend on all PRD-specific surfaces (daemon interactive PRD config fields and CLI PRD entry points) while keeping `gemini` blocked on non-PRD `Required` surfaces. This involves adding a new `ValidationSurface::Prd` variant, wiring gemini into the daemon `create_backend()` function, fixing the output normalizer's preamble-before-NDJSON routing gap, adding test harness helpers for gemini-enabled mock backends, and comprehensive conformance tests for all PRD entry points and guardrails.

## Acceptance Criteria
- [ ] `ValidationSurface::Prd` variant exists; `allows_gemini()` returns `true` for it; `allows_optional()` returns `false` for it.
- [ ] Daemon PRD config fields (`daemon_prd_reviewer_backend`, `daemon_prd_writer_backend`, `daemon_prd_question_backends[]`) validate using `ValidationSurface::Prd` instead of `Required`.
- [ ] Error message for gemini on disallowed surfaces states it is allowed on "panel surfaces and PRD surfaces".
- [ ] `src/daemon/interactive_prd.rs` `create_backend()` supports `"gemini"` — creates backend via `gemini::backend_from_config()`, propagates `cwd`, and returns `BackendUnavailable` when `backends.gemini.enabled` is disabled.
- [ ] `src/backend/output_normalizer.rs` handles preamble-before-NDJSON: when output starts with non-JSON lines, scans for the first NDJSON stream event (type in `STREAM_EVENT_TYPES`) and routes the stream portion to `normalize_claude_stream_json()`.
- [ ] Output normalizer prefers `result` event text over concatenated `message` text when both exist, and retains `session_id` from `init` (existing behavior preserved through new routing).
- [ ] `setup_mock_backends_with_gemini(script)` harness function exists — configures `claude`, `codex`, `gemini` with gemini enabled.
- [ ] `setup_mock_backends_with_gemini_argv_capture(script)` harness function exists — logs backend argv to file path in `RALPH_ARGV_CAPTURE` before executing script.
- [ ] Unit tests in `src/config/mod.rs`: gemini accepted on PRD reviewer/writer/question backends, `gemini(model)` accepted, `?gemini` rejected on PRD config, non-PRD `Required` still rejects gemini.
- [ ] Daemon interactive PRD conformance tests: reviewer success with bare `gemini`; reviewer success with `gemini(model)` + argv-capture asserting `--model <model>` present; reviewer success with bare `gemini` + argv-capture asserting `--model` absent; reviewer disabled case verifies daemon PRD failure path (error increments, fail-after-3 preserved); question backend list including `gemini` succeeds; writer backend `gemini` succeeds.
- [ ] CLI `ralph prd` conformance tests: bare `gemini` success; `gemini(model)` argv includes `--model`; bare `gemini` argv omits `--model`; disabled gemini fails non-zero; `?gemini` unavailable fails non-zero (hard error).
- [ ] CLI `ralph quick-prd` conformance tests: reviewer and writer each — bare `gemini` success; disabled gemini fails non-zero; `?gemini` unavailable fails non-zero.
- [ ] CLI `ralph auto` conformance tests: `--spec-reviewer gemini` and `--spec-writer gemini` succeed; disabled gemini fails non-zero for both; `?gemini` unavailable fails non-zero for both.
- [ ] Guardrail tests: non-PRD `Required` surfaces still reject `gemini`; daemon PRD surfaces reject `?gemini`.
- [ ] Output normalizer regression tests: long (2KB+) multi-section PRD plain output extraction; stream JSON long PRD extraction from `result`; preamble + NDJSON stream routing with session ID retention and `result`-text preference.
- [ ] `cargo check`, `cargo test`, `nix build -L`, and `ralph validate` all pass.
