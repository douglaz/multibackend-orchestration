# Review: SUGGESTIONS

## Required Changes
1. **Session lifecycle is not wired into orchestrator execution**
   - Current: Session reuse is effectively disabled at runtime (`session_id` is always set to `None` in orchestrator tmux context), normalized session IDs are discarded (`_session_id`), and there are no runtime `session_store.lookup`/`session_store.upsert` calls. `compute_bootstrap_hash` exists but is unused. Evidence: `src/workflow/orchestrator.rs:386`, `src/workflow/orchestrator.rs:538`, `src/workflow/orchestrator.rs:3358`, `src/workflow/orchestrator.rs:3503`.
   - Expected: For `implementer|reviewer|qa`, orchestrator should lookup by `(loop_number, role, backend_spec)`, validate bootstrap hash (with legacy `prompt_hash_at_loop_start` fallback/persist), pass session ID when valid, and upsert/update records per lifecycle rules (including parse-failure path).
   - Reference: Feature Spec D1, D5, D6 acceptance criteria.

2. **Runtime role-policy handling for session reuse is missing**
   - Current: CLI `config set` validates role names, but runtime warning/skip policy is not implemented; helper `is_session_reuse_enabled_for_role` is unused and does not enforce v1 unsupported-role behavior. Evidence: `src/cli/config.rs:813`, `src/workflow/orchestrator.rs:3519`.
   - Expected: Runtime must warn+skip unknown roles, and warn+skip known-but-unsupported v1 roles (`planner`, `completer`) even if configured.
   - Reference: Feature Spec D2 acceptance criteria.

3. **`effective_args` error fallback behavior is not implemented as specified**
   - Current: Error handling is buried in tmux backend and silently falls back to default args with `debug!`; orchestrator never handles rewrite failure to disable session and rebuild fresh full prompt. Evidence: `src/backend/tmux_backend.rs:104`, `src/backend/tmux_backend.rs:110`.
   - Expected: On `effective_args` error, orchestrator should `warn`, disable reuse for that invocation, rebuild fresh prompt path, and continue.
   - Reference: Feature Spec D3 acceptance criteria.

4. **Codex resume arg rewrite is not fully idempotent and not strict to required form**
   - Current: Existing resume IDs can be duplicated because old ID tokens are not removed after `resume`; function only enforces trailing `-`, not strict `exec ... -` form. Evidence: `src/backend/mod.rs:367`, `src/backend/mod.rs:372`, `src/backend/mod.rs:341`.
   - Expected: Deterministically produce exactly `exec resume <id> ... --json -` with one session ID, one `--json`, trailing `-`, and robust idempotency on repeated rewrites.
   - Reference: Feature Spec D3 (Codex rewrite rules) acceptance criteria.

5. **Output normalization error contract is violated**
   - Current: `normalize_output` swallows backend-structured parse errors and always falls back to raw text, including the “structured payload but missing assistant text” case that should return `Err`. Also, reformatter attempt normalization uses original backend name, not the backend that actually produced output. Evidence: `src/backend/output_normalizer.rs:34`, `src/backend/output_normalizer.rs:43`, `src/backend/output_normalizer.rs:190`, `src/workflow/orchestrator.rs:3406`.
   - Expected: Malformed structured output may fall back, but missing required assistant payload in structured output must return `Err`; orchestrator should normalize each attempt using the executing backend identity.
   - Reference: Feature Spec D4 acceptance criteria.

6. **Working-directory invariant is not enforced, and conformance test does not verify it**
   - Current: Only debug logging of cwd exists; no `debug_assert_eq!(current_dir, repo_root)` before invocation. Conformance test only checks run success and does not capture/compare `pwd`. Evidence: `src/workflow/orchestrator.rs:3314`, `src/validate/tests_sessions.rs:315`.
   - Expected: Add explicit cwd equality assert to repo root and validate via mock backend fixture that records `pwd` and asserts repo-root match.
   - Reference: Feature Spec D6 (Working directory invariant) acceptance criteria.

7. **Required conformance/unit coverage for Session Reuse v1 behavior is insufficient**
   - Current: Six conformance test names are present, but several only validate config plumbing, not the behavior implied by their names (history capping behavior, session store/resume lifecycle, prompt-change invalidation execution path). Invalid-role conformance helper exists but is not invoked. Evidence: `src/validate/tests_sessions.rs:48`, `src/validate/tests_sessions.rs:122`, `src/validate/tests_sessions.rs:245`, `src/validate/tests_sessions.rs:335`.
   - Expected: Tests must exercise the actual runtime behaviors in spec D, including bootstrap-hash determinism/invalidation sensitivity.
   - Reference: Feature Spec “Required Conformance Tests” and “Required Unit/Integration Tests”.

## Recommended Improvements
1. Strengthen arg-rewrite tests to assert full token sequences (including no duplicate session IDs), not just sentinel flags like `--json`/`-`.
