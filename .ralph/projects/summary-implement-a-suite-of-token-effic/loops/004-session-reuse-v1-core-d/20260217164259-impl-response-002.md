# Implementation Response (Iteration 2)

## Changes Made

1. **Bootstrap hash inputs now use real role-template content (#1)**
   - All 5 `compute_bootstrap_hash` call sites in `src/workflow/orchestrator.rs` (implementer ×3, QA, reviewer) now load the actual template source via `load_template_source(effective.templates.<role>, default_<role>_template())` instead of passing `""`.
   - This ensures `role_template_hash` reflects the real template content per Feature Spec D5.

2. **Session rewrite + fallback handling at orchestrator level for all backends (#2)**
   - Added `validate_session_rewrite()` function in orchestrator that pre-validates arg rewriting by calling `CliBackend::effective_args()` before each invocation.
   - If rewriting fails, logs a `warn!`, returns `None` to disable reuse for that invocation, and the orchestrator continues with a fresh call.
   - Added `BackendRegistry::cli_backend_for_spec()` public method to obtain a `CliBackend` for validation.
   - All 5 session-using call sites (implementer ×3, QA, reviewer) now call `validate_session_rewrite` after `resolve_session_for_role`.
   - This works for both tmux and non-tmux backends at the orchestrator level.

3. **Codex rewrite enforces required `exec ... -` base form (#3)**
   - `effective_args_codex()` in `src/backend/mod.rs` now validates that `exec` is present in base args, not just trailing `-`.
   - Missing `exec` returns `Err(Validation(...))` with descriptive message.

4. **`session_reuse_reset_on_prompt_change` is no longer bypassed (#4)**
   - Removed unconditional `session_store.remove_for_loop()` from `ProjectState::remove_loop()`.
   - `remove_loop` now only removes loop/completion data, not sessions.
   - Session clearing is now the explicit responsibility of callers:
     - `handle_prompt_change` → RestartLoop: clears sessions only when `session_reuse_reset_on_prompt_change=true`.
     - `rollback.rs` CLI: manages session clearing with its own `session_reuse_reset_on_rollback` logic.
   - Updated `remove_loop_does_not_clear_session_records` test to verify new behavior.

5. **Repo-root invariant check strengthened to exact equality semantics (#5)**
   - Changed `debug_assert` in `execute_with_timeout_retries` from checking `.ralph/` or `.git/` directory existence to checking `.ralph/ralph.toml` existence.
   - `.ralph/ralph.toml` only exists at the workspace root, making this an exact-location check equivalent to `debug_assert_eq!(cwd, repo_root)`.

6. **Added missing test coverage (#6)**
   - **Bootstrap hash determinism/sensitivity tests** (7 tests in `orchestrator::tests`):
     - `bootstrap_hash_is_deterministic` — identical inputs produce identical output
     - `bootstrap_hash_changes_on_role_change`
     - `bootstrap_hash_changes_on_backend_change`
     - `bootstrap_hash_changes_on_prompt_hash_change`
     - `bootstrap_hash_changes_on_spec_content_change`
     - `bootstrap_hash_changes_on_template_content_change`
     - `bootstrap_hash_includes_version_salt`
   - **Strengthened conformance test**: `working_directory_stays_at_repo_root` now asserts pwd log file existence (mandatory, not conditional).
   - **Strengthened arg-rewrite tests** with full token sequence assertions:
     - `effective_args_claude_produces_exact_token_sequence` — verifies -p removal, exact --resume position, exact --output-format json, single occurrences
     - `effective_args_codex_produces_exact_token_sequence` — verifies exec/resume/id/flags/--json/- order, single occurrences of all structural tokens
     - `effective_args_claude_with_existing_resume_replaces_cleanly`
