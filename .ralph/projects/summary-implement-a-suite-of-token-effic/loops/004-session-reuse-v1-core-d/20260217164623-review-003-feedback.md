# Review: SUGGESTIONS

## Required Changes
1. **Session invalidation in loop removal is not spec-compliant**: `ProjectState::remove_loop()` does not remove session records.
   - Current: `remove_loop` explicitly leaves `session_store` untouched (`src/project/state.rs:371`), and internal rollback paths call it (`src/workflow/orchestrator.rs:992`, `src/workflow/orchestrator.rs:1874`, `src/workflow/orchestrator.rs:2128`), which can retain stale sessions for removed loops.
   - Expected: Removing a loop must also remove its session records (or an equivalent guaranteed invalidation at all rollback call sites).
   - Reference: Feature Spec D1 (`ProjectState::remove_loop()` removes loop session records), D6 (rollback invalidation semantics).

2. **Session reuse is not applied for non-tmux backend execution**.
   - Current: Direct `CliBackend` execution always uses base args (`cmd.args(&self.args)`) in `src/backend/mod.rs:430`; orchestrator only pre-validates rewrite via `validate_session_rewrite` (`src/workflow/orchestrator.rs:3478`) and passes `session_id` through tmux context.
   - Expected: Non-tmux invocations must also execute with `effective_args(&BackendInvocationContext)` so resume args are actually used.
   - Reference: Feature Spec D goal (per-loop per-role session reuse), D3 (invocation context + arg rewriting behavior).

3. **Session lifecycle rule for parse-failure persistence is not fully implemented**.
   - Current: Session upsert happens only after successful parse-return paths (for example `src/workflow/orchestrator.rs:579`, `src/workflow/orchestrator.rs:1321`); when parse retries exhaust (`src/workflow/orchestrator.rs:3695`), no store/update occurs.
   - Expected: If normalization yielded a session ID, session state should still be stored/updated even when parse ultimately fails.
   - Reference: Feature Spec D6 (“Parse failure after normalization still updates/stores session record.”).

4. **Repo-root invariant check is weaker than required equality check**.
   - Current: It checks only that `.ralph/ralph.toml` exists in cwd (`src/workflow/orchestrator.rs:3716`), not strict cwd equality to repo root.
   - Expected: Enforce exact `current_dir == repo_root` assertion before backend invocation.
   - Reference: Feature Spec D6 (working directory invariant).

## Recommended Improvements
1. Strengthen `src/validate/tests_sessions.rs` lifecycle/invalidation cases to assert concrete `session_store` mutations (store, reuse, clear) rather than only successful loop completion/config roundtrips.
