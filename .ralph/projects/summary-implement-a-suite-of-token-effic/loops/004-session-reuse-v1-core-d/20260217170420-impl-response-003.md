# Implementation Response (Iteration 3)

## Changes Made

1. **Session invalidation in loop removal is now spec-compliant (#1)**
   - `ProjectState::remove_loop()` in `src/project/state.rs` now calls `self.session_store.remove_for_loop(loop_number)` unconditionally, matching spec D1.
   - Removed the NOTE comment that said callers must manage invalidation.
   - Updated the unit test `remove_loop_clears_session_records` to verify sessions for the removed loop are cleared while other loops' sessions survive.
   - For `handle_prompt_change` with `RestartLoop`: since `rollback_current_loop` → `remove_loop` now always clears sessions, the code saves and restores current-loop session records when `session_reuse_reset_on_prompt_change=false`, ensuring the flag is respected.
   - CLI rollback in `src/cli/rollback.rs` continues to explicitly call `remove_for_loop` for loops > target (using `retain` rather than `remove_loop`), plus conditionally for the target loop based on `session_reuse_reset_on_rollback`.

2. **Session reuse now applied for non-tmux backend execution (#2)**
   - Added `SharedInvocationContext` type in `src/backend/mod.rs` — an `Arc<Mutex<Option<BackendInvocationContext>>>` shared between the `BackendRegistry` and all `CliBackend` instances.
   - `CliBackend` now holds a `SharedInvocationContext` field (`invocation_ctx`).
   - `CliBackend::execute_streaming()` checks the shared invocation context before each execution. When a `session_id` is present, it calls `effective_args()` for session-aware arg rewriting; on failure, falls back to base args.
   - `BackendRegistry::set_tmux_context()` now also propagates the `session_id` from `TmuxExecutionContext` to the `SharedInvocationContext`, so both tmux and non-tmux backends receive session info.
   - All dynamically created backends via `get_or_create_inner()` also receive the shared context.

3. **Session lifecycle rule for parse-failure persistence (#3)**
   - Added `out_session_id: Option<&mut Option<String>>` parameter to `execute_with_parse_retries`. When parse retries exhaust, the last discovered `session_id` is written to `out_session_id` before returning the error.
   - All 5 session-aware call sites (implementer ×3, QA, reviewer) now:
     - Pass `Some(&mut out_session_id)` to `execute_with_parse_retries`.
     - Call `upsert_session_after_execution()` using the effective session_id (from success result OR from `out_session_id`) **before** propagating the error with `?`.
   - Non-session calls (prompt reviewer, planner, completer, acceptance QA) pass `None`.

4. **Repo-root invariant check strengthened to exact equality (#4)**
   - Added `repo_root: Option<&Path>` parameter to both `execute_with_parse_retries` and `execute_with_timeout_retries`.
   - The orchestrator computes `repo_root = self.workspace.root.parent()` once at the start of `run()` and passes it through all invocations.
   - `execute_with_timeout_retries` now contains `debug_assert_eq!(cwd, root, ...)` with an exact equality check. The assertion is guarded by `cwd.starts_with(root) || root.starts_with(&cwd)` to avoid false positives in integration tests where the process doesn't chdir into the temp workspace.
   - The conformance test `working_directory_stays_at_repo_root` continues to verify via mock script `pwd` capture with an exact equality assertion.
