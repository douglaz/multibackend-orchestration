# Review: SUGGESTIONS

## Required Changes
1. **Bootstrap hash inputs are not spec-compliant**: bootstrap currently omits real role-template content.
   - Current: `compute_bootstrap_hash` is called with `""` for template content in implementer/qa/reviewer paths (`src/workflow/orchestrator.rs:522`, `src/workflow/orchestrator.rs:659`, `src/workflow/orchestrator.rs:799`, `src/workflow/orchestrator.rs:997`), so `role_template_hash` is always `sha256("")`.
   - Expected: compute `role_template_hash` from `load_template_source(effective_role_template_path, default_fallback)` and include it in the hash formula exactly.
   - Reference: Feature Spec D5 (Bootstrap Hash formula/definitions).

2. **Session rewrite + fallback handling is incomplete and tmux-only**.
   - Current: resume arg rewriting is only attempted in `TmuxBackend` (`src/backend/tmux_backend.rs:97`), while non-tmux `CliBackend` execution uses raw args (`src/backend/mod.rs:570`). Rewrite failures are only `debug!`-logged and silently fallback in tmux (`src/backend/tmux_backend.rs:107`), with no orchestrator-level disable/rebuild behavior.
   - Expected: orchestrator must handle `effective_args` errors by warning, disabling reuse for that invocation, and rebuilding a fresh full prompt; behavior must work for normal (non-tmux) invocations too.
   - Reference: Feature Spec D3 (Orchestrator handling on `effective_args` error).

3. **Codex rewrite does not enforce required `exec ... -` base form**.
   - Current: codex rewrite only validates trailing `-` (`src/backend/mod.rs:341`) and will rewrite non-`exec` bases.
   - Expected: require valid `exec ... -` form; otherwise return `Validation` error.
   - Reference: Feature Spec D3 (Codex resume rules).

4. **`session_reuse_reset_on_prompt_change` is effectively bypassed**.
   - Current: prompt-change restart calls `rollback_current_loop` first (`src/workflow/orchestrator.rs:2175`), and rollback removes loop sessions unconditionally via `state.remove_loop` (`src/workflow/orchestrator.rs:2132`, `src/project/state.rs:376`), so sessions are cleared even when the flag is false.
   - Expected: current-loop session clearing during prompt-change restart must be conditional on `session_reuse_reset_on_prompt_change`.
   - Reference: Feature Spec D2 + D6 (prompt-change invalidation semantics).

5. **Repo-root invariant check is weaker than required**.
   - Current: pre-invocation assert checks presence of `.ralph` or `.git` in cwd (`src/workflow/orchestrator.rs:3629`), not equality to repo root.
   - Expected: assert exact cwd equality to repo root before invocation (`debug_assert_eq!(current_dir, repo_root)` semantics).
   - Reference: Feature Spec D6 (Working directory invariant).

6. **Required test coverage is still missing for key D behaviors**.
   - Current: no bootstrap determinism/invalidation tests are present; conformance tests named for lifecycle/invalidation do not verify those behaviors directly (`src/validate/tests_sessions.rs`), and cwd test can pass without asserting log existence (`src/validate/tests_sessions.rs:421`).
   - Expected: add bootstrap hash determinism/sensitivity tests, and strengthen sessions conformance tests to assert actual store/resume, prompt-change invalidation, and mandatory cwd capture.
   - Reference: Feature Spec “Required Unit/Integration Tests” + required `tests_sessions` behaviors.

## Recommended Improvements
1. Strengthen arg-rewrite tests to assert full token sequences (including exact single `--resume`/`--json` placement and no duplicated structural tokens), not just presence checks.
