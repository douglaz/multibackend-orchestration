# Implementation Response (Iteration 1)

## Changes Made

### Fix #1+3: Session lifecycle wired into orchestrator + effective_args fallback

**Files:** `src/workflow/orchestrator.rs`

- Changed `normalize_backend_output` to return full `NormalizedOutput` (with `session_id`, `tokens_in`, etc.) instead of just a `String`.
- Introduced `ParseRetryResult<T>` wrapper struct that pairs the parsed artifact value with the `session_id` extracted from backend output.
- Changed `execute_with_parse_retries` return type from `Result<T>` to `Result<ParseRetryResult<T>>` so session IDs propagate upward through the retry/reformatter pipeline.
- Updated all 9 call sites (`run_implementer_loop`, `run_qa_cycle`, `run_review_cycle`, `run_planner`, `run_completer`, `run_acceptance`) to destructure `.parsed` from the retry result.
- Fixed reformatter normalization path: now uses `reformatter_name` (derived from the reformatter backend) instead of the original `backend_name` when normalizing reformatted output.
- Added `resolve_session_for_role()` call before each implementer, QA, and reviewer backend invocation to look up stored session IDs.
- Added `upsert_session_after_execution()` call after each backend invocation to persist session IDs per the lifecycle contract (store on new, update on change, keep prior on omit, upsert even on parse failure).
- Added `ensure_prompt_hash_at_loop_start()` helper that populates `prompt_hash_at_loop_start` for legacy projects missing this field using SHA-256 of the current prompt text.
- Removed `#[allow(dead_code)]` from `compute_bootstrap_hash` since it is now exercised at runtime.
- `effective_args` fallback: when `effective_args()` returns `Err`, the orchestrator logs the error at `warn!` level and falls back to the base args (no session resume), exactly as spec requires.

### Fix #2: Runtime role-policy handling for session reuse

**Files:** `src/workflow/orchestrator.rs`

- Added constants `V1_SESSION_REUSE_SUPPORTED_ROLES` (`["implementer", "reviewer", "qa"]`) and `KNOWN_ROLES` (`["planner", "implementer", "reviewer", "qa", "completer"]`).
- Added `resolve_session_for_role()` function implementing the v1 role-policy matrix:
  - Unknown roles (not in `KNOWN_ROLES`) → `warn!("unknown role")` + return `None` (skip resume)
  - Known but unsupported v1 roles (planner, completer) → `warn!("not supported in v1")` + return `None`
  - Roles not in the user's `session_reuse_roles` config list → silently return `None`
  - Supported and enabled roles → look up session via `SessionStore::lookup(loop, role, backend_spec)` and compute bootstrap hash

### Fix #4: Codex resume arg rewrite fully idempotent

**Files:** `src/backend/mod.rs`

- Completely rewrote `effective_args_codex()` to produce deterministic `exec resume <id> [flags...] --json -` form.
- Algorithm: strip all structural tokens (`exec`, `resume`, old session ID, `--json`, trailing `-`), collect remaining flags, then rebuild from scratch: `["exec", "resume", <new_id>, ...flags, "--json", "-"]`.
- Validates that base args end with `-` (stdin marker) before attempting rewrite.
- Idempotent: calling with already-rewritten args and a new session ID produces the correct form.
- Added unit tests: `codex_effective_args_basic`, `codex_effective_args_idempotent`, `codex_effective_args_missing_stdin_marker_errors`.

### Fix #5: Output normalization error contract

**Files:** `src/backend/output_normalizer.rs`

- **Malformed JSON** (parse failure) → fall back to raw text with `Ok(NormalizedOutput { text: raw, .. })`. This prevents panics and allows the caller to proceed with raw text.
- **Valid structured JSON but missing assistant text** → return `Err(RalphError::ParseError(...))`. This signals to the caller that the backend produced structured output but it's incomplete, allowing proper error handling.
- Updated `normalize_claude_json`: malformed JSON returns Ok fallback; valid JSON with empty content array or no `result` field returns Err.
- Updated `normalize_codex_jsonl`: non-JSON input returns Ok fallback; valid JSONL with no assistant message returns Err.
- Updated unit tests: `claude_json_missing_text_returns_err` now asserts `is_err()`, `codex_jsonl_missing_assistant_returns_err` similarly.

## Could Not Address

- **Bootstrap hash unit tests for determinism and invalidation sensitivity**: The review recommended adding unit tests that verify `compute_bootstrap_hash` is deterministic (same inputs → same hash) and sensitive to each input parameter (changing any single input changes the hash). These tests would strengthen confidence but were not implemented due to the already large scope of this iteration. The function itself is straightforward SHA-256 concatenation and is exercised through the session lifecycle integration.

- **Full token-sequence assertions in arg-rewrite tests**: The review recommended strengthening the existing `effective_args_codex` and `effective_args_claude` unit tests to assert the complete output token sequence (not just key elements). The current tests verify correct behavior but could be more precise about the exact ordering of all tokens.
