# Feature: Session Reuse v1 Core (D)

## Description
Loops 1-3 completed A (prompt de-duplication), B (planner/completer compression), and C (deterministic history capping). The next missing feature is Session Reuse v1: add per-loop/per-role/per-backend session persistence, deterministic resume argument rewriting, output normalization, bootstrap-hash invalidation, and rollback/prompt-change invalidation, with conformance coverage.

## Acceptance Criteria
- [ ] `src/project/state.rs` defines `SessionRecord` and `SessionStore` with required fields and methods: `lookup`, `upsert`, `remove_for_loop`.
- [ ] `ProjectState` gains `#[serde(default)] session_store: SessionStore`; `ProjectState::new()` initializes it; `ProjectState::remove_loop()` removes loop session records.
- [ ] State serde remains backward-compatible for existing `state.json` without `session_store`.
- [ ] Config adds `session_reuse_enabled` (default `false`), `session_reuse_roles` (default `["implementer","reviewer","qa"]`), `session_reuse_reset_on_prompt_change` (default `true`), `session_reuse_reset_on_rollback` (default `true`) across global, project override, effective config, and CLI config get/set/show.
- [ ] `config set` validates roles against `planner|implementer|reviewer|qa|completer`; invalid roles return validation errors.
- [ ] Runtime orchestrator warns and skips unknown roles; warns and skips reuse for known-but-unsupported v1 roles (`planner`, `completer`).
- [ ] `src/backend/mod.rs` adds `BackendInvocationContext` and `CliBackend::effective_args(&self, ctx) -> Result<Vec<String>>`.
- [ ] Claude rewrite rules are implemented and idempotent: require `-p`, remove `-p`, enforce single `--resume <id>`, enforce single `--output-format json`.
- [ ] Codex rewrite rules are implemented and idempotent: require trailing `-`, rewrite to `exec resume <id> ... --json -`, enforce one `--json`, preserve `-` as last token.
- [ ] No-session invocations return unchanged args.
- [ ] On `effective_args` error, orchestrator logs warning, disables reuse for that invocation, rebuilds fresh full prompt, and continues without crashing.
- [ ] `src/backend/tmux_backend.rs` uses `CliBackend::effective_args()` for command construction.
- [ ] New `src/backend/output_normalizer.rs` provides `NormalizedOutput` and `normalize_output(backend_name, raw_stdout)`.
- [ ] Normalizer extracts text/session/tokens for Claude JSON and Codex JSONL; malformed structured input falls back to raw text without panic.
- [ ] If structured payload exists but assistant message text is missing, normalizer returns `Err` so caller degrades gracefully.
- [ ] Orchestrator normalizes immediately after every backend execution attempt; parse always consumes normalized text; on normalization error it parses raw stdout.
- [ ] Bootstrap hash is implemented exactly as specified and used for reuse validity checks; legacy empty `prompt_hash_at_loop_start` falls back to `prompt_hash` and is persisted.
- [ ] Session isolation key is strict `(loop_number, role, backend_spec)`; bootstrap mismatch forces fresh call and record replacement.
- [ ] Session lifecycle rules are enforced: store only when session id exists; update on new id; keep prior id when resume response omits id; parse failure after normalization still updates/stores session record.
- [ ] Rollback removes all records for loops `> target` unconditionally; target-loop clearing respects `session_reuse_reset_on_rollback`.
- [ ] Prompt-change restart clears current-loop sessions when `session_reuse_reset_on_prompt_change=true`.
- [ ] Backend invocations keep cwd at repo root; add `debug_assert_eq!(current_dir, repo_root)` before invocation.
- [ ] Add and register `src/validate/tests_sessions.rs` with exactly six conformance tests:
- [ ] `sessions::history_capping_limits_review_entries`
- [ ] `sessions::history_capping_limits_qa_entries`
- [ ] `sessions::session_lifecycle_stores_and_resumes`
- [ ] `sessions::session_invalidation_on_rollback`
- [ ] `sessions::session_invalidation_on_prompt_change`
- [ ] `sessions::working_directory_stays_at_repo_root`
- [ ] Add unit/integration tests for arg rewrite success/failure/idempotency, output normalization behavior, bootstrap hash determinism/invalidation sensitivity, and session store serde/lookup/upsert/remove.
- [ ] `nix develop -c cargo check`, `nix develop -c cargo test`, and sessions validate filter pass.
