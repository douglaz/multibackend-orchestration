# Implementation Notes

## Decisions Made
- Added `PlannerStateInPrompt { FullJson, Summary }` and `PreviousSpecsInPrompt { None, Titles, FullText }` enums to `src/config/global.rs` with serde kebab-case renaming for TOML/JSON compatibility, matching the existing enum pattern (e.g. `CommitMessageStyle`).
- Used `#[serde(default)]` on the new `WorkflowConfig` fields so existing config files without these fields deserialize cleanly with default values (`Summary`, `Titles`, `Some(10)`).
- For `ProjectWorkflowOverrides`, used `Option<Option<usize>>` for `planner_max_prior_loops` to distinguish "not set (inherit)" (`None`) from "explicitly set to unlimited" (`Some(None)`) from "explicitly capped" (`Some(Some(n))`).
- Removed the now-unused `collect_previous_specs` function since `summarize_previous_specs_for_planner` with `FullText` mode provides the same behavior.
- Updated `build_completer_prompt` to take `project_dir: &Path` instead of `previous_specs: &str`, making it self-contained for spec resolution using the same config-driven modes as the planner.
- `summarize_state_for_planner` produces a compact one-line-per-loop bullet list with metadata (status, review count, QA round count, spec path, commit) while deliberately excluding raw feedback/report file content.
- Loop selection for both summary and specs uses ascending loop_number order with latest-N capping when `max_loops` is set.
- CLI parse semantics: `"none"` maps to unlimited for global config; for project overrides, `"null"` = inherit, `"none"` = override-to-unlimited, integer = capped.

- None. All acceptance criteria implemented as specified.
