# Feature: Planner/Completer Prompt Compression (B)

## Description
Loop 1 completed Prompt De-duplication (A). The next missing feature is deterministic planner/completer context compression so prompts stop embedding full state/spec history by default while preserving workflow behavior.  
Implement configurable, deterministic summarization for project state and prior specs, wire it into planner and completer prompt builders, and expose all controls through global + project config with correct override semantics.

## Acceptance Criteria
- [ ] Add `PlannerStateInPrompt { FullJson, Summary }` (default `Summary`) and `PreviousSpecsInPrompt { None, Titles, FullText }` (default `Titles`) in `src/config/global.rs` with serde-compatible parsing.
- [ ] Extend global `WorkflowConfig` with:
- [ ] `planner_state_in_prompt` default `Summary`
- [ ] `planner_previous_specs_in_prompt` default `Titles`
- [ ] `planner_max_prior_loops: Option<usize>` default `Some(10)`
- [ ] Extend `ProjectWorkflowOverrides` in `src/config/project.rs` with:
- [ ] `planner_state_in_prompt: Option<PlannerStateInPrompt>`
- [ ] `planner_previous_specs_in_prompt: Option<PreviousSpecsInPrompt>`
- [ ] `planner_max_prior_loops: Option<Option<usize>>` (supports inherit vs explicit unlimited)
- [ ] Extend `EffectiveWorkflowConfig` and `resolve_effective_config` in `src/config/mod.rs` to fully resolve the three new fields with correct precedence: CLI/run override behavior unchanged, project overrides global, defaults applied when unset.
- [ ] Add CLI config set/get support in `src/cli/config.rs` for all new keys, including parse semantics:
- [ ] integer for `planner_max_prior_loops` means capped mode
- [ ] `"none"` means unlimited (`None`)
- [ ] project override preserves inherit when key absent, but explicit `"none"` stores override-to-unlimited
- [ ] Add `summarize_state_for_planner(state: &ProjectState, max_loops: Option<usize>) -> String` in `src/workflow/orchestrator.rs` (or helper module) with deterministic loop ordering (ascending by loop number, then take latest N when capped).
- [ ] `summarize_state_for_planner` includes loop metadata needed for planning (status, iteration/verdict, artifact references like spec path) but excludes raw review feedback bodies and QA report bodies.
- [ ] Add `summarize_previous_specs_for_planner(state, project_dir, mode, max_specs)` with semantics:
- [ ] `None` => empty
- [ ] `Titles` => bullet list of prior spec titles only
- [ ] `FullText` => current behavior (full spec bodies)
- [ ] `max_specs=None` unlimited, `Some(0)` include none, and deterministic latest-N selection.
- [ ] Update `build_planner_prompt` and `build_completer_prompt` to honor `planner_state_in_prompt`, `planner_previous_specs_in_prompt`, and `planner_max_prior_loops`.
- [ ] Backward compatibility maintained for existing state/config files (deserialization defaults preserve old installations).
- [ ] Unit tests cover:
- [ ] state summary includes expected metadata and excludes feedback/report bodies
- [ ] `Titles` mode returns titles-only bullets
- [ ] `Some(0)` and `None` cap semantics for both summary and prior specs
- [ ] global/project merge precedence for all three new fields
- [ ] CLI parsing for numeric vs `"none"` and project override semantics.

## Files to Modify/Create
- `src/config/global.rs` - add new enums, defaults, and workflow fields.
- `src/config/project.rs` - add project workflow override fields for planner compression controls.
- `src/config/mod.rs` - extend `EffectiveWorkflowConfig` and merge resolution logic + precedence tests.
- `src/cli/config.rs` - add key handling and parse helpers for new workflow settings.
- `src/workflow/orchestrator.rs` - implement summarization helpers and integrate into planner/completer prompt construction.
- `src/workflow/orchestrator.rs` - add/extend unit tests for summary/spec modes and deterministic capping behavior.
