# Review: SUGGESTIONS

## Required Changes
1. **Planner state summary metadata (`src/workflow/orchestrator.rs`)**: `summarize_state_for_planner` does not consistently include a loop verdict field.
Current: Loop lines include `status`, `iterations`, and `spec`, and only conditionally print `approval` when present.
Expected: Include a deterministic verdict value for each loop summary entry (for example, approved/pending/failed mapping), so summary output always contains status/iteration/verdict/spec-path metadata.
Reference: Feature Spec B acceptance criterion: summary must include loop metadata `(status/iteration/verdict/spec path)`.

2. **State payload formatting contract in planner/completer prompts (`src/workflow/orchestrator.rs`, `src/prompts/templates.rs`)**: `FullJson` mode now sets `state_json` to a pre-fenced markdown block.
Current: `state_text` for `FullJson` is built as ```` ```json ... ``` ````, but default templates already wrap `{{state_json}}` in fenced JSON blocks, causing nested fences; summary mode is also injected into a JSON fence.
Expected: Keep `state_json` as raw JSON string for template variables, and only apply fencing in fallback-appended sections when needed. This preserves prompt shape and avoids markdown nesting regressions.
Reference: Goal constraint in prompt: reduce tokens “without changing workflow semantics”; Acceptance criterion requiring `build_planner_prompt` and `build_completer_prompt` to honor modes cleanly.

## Recommended Improvements
1. Add explicit tests that assert planner/completer rendered output has no nested code fences in `FullJson` mode and includes a stable verdict token in summary mode.
