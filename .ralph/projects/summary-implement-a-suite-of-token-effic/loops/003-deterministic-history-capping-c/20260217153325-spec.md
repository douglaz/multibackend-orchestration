# Feature: Deterministic History Capping (C)

## Description
Add configurable caps to the existing `collect_review_history` and `collect_qa_history` functions so they return only the N most recent exchanges (by iteration number ascending, capped to the last N). Add three new config fields across all four config layers (global, project, effective, CLI) to control maximum review history entries, maximum QA history entries, and whether to include history when session reuse is active for a given invocation. The history collection functions currently iterate all exchanges unbounded; this feature adds deterministic sorting-and-slicing so that prompt token usage scales predictably regardless of how many review/QA iterations a loop accumulates.

## Acceptance Criteria
- [ ] `collect_review_history(state, project_dir, max_entries)` accepts a `max_entries: usize` parameter, sorts exchanges by `iteration` ascending, and returns only the last `max_entries` exchanges formatted as before.
- [ ] `collect_qa_history(state, project_dir, max_entries)` accepts a `max_entries: usize` parameter with the same sort-then-cap semantics.
- [ ] `max_entries = 0` causes both functions to return an empty string immediately.
- [ ] All call sites of `collect_review_history` and `collect_qa_history` in the orchestrator pass the resolved effective config value for the cap.
- [ ] `WorkflowConfig` in `src/config/global.rs` gains three new fields with defaults: `max_review_history_entries_in_prompt: usize` (default `3`), `max_qa_history_entries_in_prompt: usize` (default `2`), `include_history_when_session_reuse_enabled: bool` (default `false`).
- [ ] `ProjectWorkflowOverrides` in `src/config/project.rs` gains three corresponding `Option<...>` fields: `max_review_history_entries_in_prompt: Option<usize>`, `max_qa_history_entries_in_prompt: Option<usize>`, `include_history_when_session_reuse_enabled: Option<bool>`.
- [ ] `EffectiveWorkflowConfig` in `src/config/mod.rs` gains three resolved (non-Option) fields and the merge logic applies project-over-global precedence.
- [ ] `src/cli/config.rs` handles `ralph config set --global` and `ralph config set --project` for all three new keys, with integer parsing for the two cap fields and bool parsing for the session-history field.
- [ ] Serde attributes ensure backward compatibility: missing keys in existing config files deserialize to defaults without error.
- [ ] Unit test: sequential iteration numbers (1,2,3,4,5) with `max_entries=3` returns iterations 3,4,5.
- [ ] Unit test: non-sequential iteration numbers (1,3,7,2,5) with `max_entries=2` returns iterations 5,7 (the two highest).
- [ ] Unit test: `max_entries=0` returns empty string for both review and QA history.
- [ ] Unit test: global/project merge precedence for all three new C fields — project override wins when present, global default used when absent.
- [ ] Unit test: `include_history_when_session_reuse_enabled=false` with `session_reused_this_call=true` causes history to be omitted (empty). Note: the actual per-invocation gating logic at call sites can use a simple conditional; the full session reuse machinery (Feature D) is not required — just the config field and the conditional check at the call site accepting a `session_reused_this_call: bool` parameter or equivalent.
- [ ] Unit test: when resume arg rewriting fails and call falls back to fresh prompt, history is included using configured caps (not forced empty), even if session reuse is enabled globally.
- [ ] `cargo check` and `cargo test` pass with all new and existing tests.
