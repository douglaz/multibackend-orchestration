## Notes

The `log_parse_retry_token_metrics` function exhaustively matches all 8 combinations of `Option<u64>` for the three token fields. This is verbose (about 100 lines of near-identical arms) but functionally correct and avoids any runtime cost for conditional field emission. A macro could reduce this, but it's not a blocking concern and the spec didn't call for style optimization.

The correction prompt helper was placed in `orchestrator.rs` rather than a separate `prompts.rs` file. The impl-notes explicitly note this deviation to avoid Nix source filtering churn. This is a reasonable pragmatic decision — the function is small (8 lines) and tightly coupled to the retry pipeline.

All call sites correctly thread the two new parameters (`loop_number`, `initial_session_id`) — planner/completer pass `None` for session (as expected for unsupported-reuse roles), while implementer/reviewer/qa pass their respective session IDs. The prompt_reviewer uses `loop_number=0` which is appropriate for a pre-loop phase.
