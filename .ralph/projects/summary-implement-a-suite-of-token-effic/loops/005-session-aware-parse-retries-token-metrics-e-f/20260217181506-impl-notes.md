# Implementation Notes

## Decisions Made
- Refactored `execute_with_parse_retries` in `src/workflow/orchestrator.rs` to a session-aware pipeline:
- Attempt 1: initial call, normalize, parse.
- Attempt 2: conditional in-session correction retry (only when a session is active after attempt 1 normalization), normalize, parse.
- Attempt 3: opposite-backend reformatter, normalize, parse.
- Attempt 4: forced fresh full-prompt retry on original backend (`session_id=None`), normalize, parse.
- Added per-attempt token metrics logging after every normalization via `tracing::info!` with fields: `role`, `phase`, `loop_number`, `attempt`, `backend`, `session_reused`, `tokens_in`, `tokens_out`, `cached_in`, using `tracing::field::Empty` when token values are unavailable.
- Added `BackendRegistry::override_session_id` in `src/backend/mod.rs` so retry stages can force resume/fresh behavior per attempt without changing the Backend trait.
- Added unit tests in `src/workflow/orchestrator.rs` covering:
- `ParseRetriesExhausted.attempts == 3` without session.
- `ParseRetriesExhausted.attempts == 4` with session follow-up.
- Attempt numbering/session flags in token metrics logs, including attempt 2 showing `session_reused=true` when session ID comes from attempt 1 normalization.

## Spec Deviations
- Kept the short session correction prompt helper inside `src/workflow/orchestrator.rs` (`session_retry_correction_prompt`) rather than adding a separate `src/workflow/prompts.rs` module, to keep Nix source filtering/build behavior stable. Functional behavior matches the spec intent.
