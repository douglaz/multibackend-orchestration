# Feature: Append-Only Retry Attribution Logging

## Description
Loop 1 added deterministic path and sanitization utilities, but execution paths still do not use them. This feature integrates append-only backend attempt logging into orchestrator execution so each role writes to one deterministic log file and every retry/fallback attempt is explicitly attributed with a stable separator.

## Acceptance Criteria
- [ ] Orchestrator uses canonical log roles for execution logging: `planner`, `implementer`, `qa`, `reviewer`, and `prompt-reviewer` (prompt review uses `loop_number = None`).
- [ ] Every log path is derived exclusively through `log_path_for_role(project_dir, loop_number, role)`; no filename derivation from `loop_slug` or backend name.
- [ ] Log files are opened in `create(true) + append(true)` mode and are never truncated.
- [ ] Before each backend attempt, a separator is appended with: attempt number, sanitized backend label, fallback flag, and timestamp.
- [ ] Timeout retries and parse-retry/reformatter fallback attempts append to the same file for the same `(loop_number, role)`.
- [ ] Logging is best-effort: open/write/flush failures emit `tracing::warn!`, disable further log writes for that run, and do not change backend/orchestrator result semantics.
- [ ] Unit tests cover separator formatting, attempt numbering across retry paths, and log-writer failure resilience.
- [ ] Conformance tests include `retry_append_behavior` and `prompt_reviewer_path` and are registered in validate discovery.
- [ ] `cargo test` passes and validate passes for the new streaming-log conformance cases.

## Files to Modify/Create
- `src/output_log.rs` - add append-mode log writer helpers (open, separator write, graceful disable-on-error) and unit tests.
- `src/workflow/orchestrator.rs` - thread logging context through backend execution helpers and increment/log attempt metadata across all retry/fallback branches.
- `src/validate/tests_streaming.rs` - add conformance tests for retry append behavior and prompt-reviewer root-level log path.
- `src/validate/mod.rs` - register `tests_streaming::tests()`.

## Dependencies
- Requires: Deterministic Log Paths and Path Safety Utilities (Loop 1)
- Blocks: Byte-preserving chunked streaming capture, timeout kill/reap cleanup, and remaining streaming conformance coverage (`mid_execution_visibility`, `timeout_cleanup`)
