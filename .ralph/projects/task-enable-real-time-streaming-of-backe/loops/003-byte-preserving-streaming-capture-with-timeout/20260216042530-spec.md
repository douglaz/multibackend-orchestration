# Feature: Byte-Preserving Streaming Capture with Timeout Cleanup

## Description
Replace the monolithic `child.wait_with_output()` execution in `CliBackend` with incremental chunk-based streaming that preserves raw bytes, writes them to the `LogWriter` in real-time, and properly kills/reaps child processes on timeout or fatal I/O errors. This is the final functional feature that addresses prompt requirements 3 (Streaming semantics) and 4 (Timeout and process cleanup), and adds the remaining conformance tests (`mid_execution_visibility`, `timeout_cleanup`) plus required unit tests.

Currently, `CliBackend::execute` calls `child.wait_with_output()` wrapped in `tokio::time::timeout`. This has three problems: (a) no bytes are visible until the process exits, (b) on timeout the child is dropped without explicit `kill()`+`wait()`, leaving potential zombies, and (c) `String::from_utf8_lossy` is applied to the entire buffer rather than only at the final return point. The `LogWriter` already supports `write_bytes(&[u8])` from Loop 2 but is only called post-hoc in the orchestrator.

This feature restructures execution to: spawn the child, take the stdout handle, loop with `tokio::io::AsyncReadExt::read_buf` into a `BytesMut` buffer reading chunks as they arrive, append each chunk to both an in-memory `Vec<u8>` accumulator and the `LogWriter` sink, apply `String::from_utf8_lossy` only once at the end when returning the final `Result<String>`, and on timeout (or fatal stream I/O error) explicitly call `child.kill()` then `child.wait()` before writing a timeout footer to the log and returning `BackendTimeout`.

## Acceptance Criteria
- [ ] `CliBackend::execute` (or a new internal streaming method it delegates to) uses `child.stdout.take()` with `AsyncReadExt::read_buf` into a `BytesMut` chunk buffer instead of `child.wait_with_output()`.
- [ ] Raw bytes (including `\r`, partial lines, binary data) are appended to an in-memory `Vec<u8>` accumulator as each chunk arrives — no per-chunk string conversion.
- [ ] Each chunk of raw bytes is simultaneously written to the `LogWriter` via `write_bytes()` as it is read, enabling real-time log visibility.
- [ ] `String::from_utf8_lossy()` is called exactly once on the accumulated `Vec<u8>` only at the final return point of successful execution.
- [ ] The `Backend` trait or `CliBackend::execute` signature is extended to accept an optional `&mut LogWriter` (or equivalent mechanism) so the backend can stream bytes to the log during execution.
- [ ] On timeout: `child.kill().await` followed by `child.wait().await` is called explicitly before returning the error.
- [ ] On timeout: a footer line (e.g., `\n--- timeout ts=<ISO8601> ---\n`) is written to the `LogWriter` before returning `BackendTimeout`.
- [ ] On fatal stdout read I/O error: the same `kill()`+`wait()` cleanup is applied to the child process.
- [ ] Any partial output captured before timeout/error is still written to the log (the in-memory buffer up to that point).
- [ ] No zombie child processes remain after timeout or I/O error paths — verified by `child.wait()` completing.
- [ ] `execute_with_timeout_retries` passes the `LogWriter` through to the backend execution so streaming writes occur during execution, not after.
- [ ] The existing `LogWriter` best-effort failure policy is preserved: if log writes fail during streaming, a `tracing::warn!` is emitted, further writes are disabled, but execution continues unaffected.
- [ ] Unit tests cover: (a) CR and partial-line byte preservation through chunked reads, (b) exact byte-match between process-emitted bytes and captured buffer, (c) `child.kill()`+`child.wait()` is called on timeout, (d) timeout footer appears in log output.
- [ ] Conformance test `streaming::mid_execution_visibility` is added: spawns a slow-output mock script, checks that the log file grows while the process is still running.
- [ ] Conformance test `streaming::timeout_cleanup` is added: spawns a hanging mock script with a short timeout, verifies timeout footer in log, partial output preserved, and child process is dead.
- [ ] All conformance tests registered in `src/validate/mod.rs` (existing registration of `tests_streaming` covers this).
- [ ] `cargo test` passes including all new and existing tests.
- [ ] `cargo check` has no new warnings.
