# Feature: Deterministic Log Paths and Path Safety Utilities

## Description
Add the foundational utility layer for deterministic, role-based log path derivation and filename sanitization. This introduces a new `output_log` module with two core functions: `log_path_for_role()` which derives deterministic log file paths from `(project_dir, loop_number, role)` tuples following the specified naming convention, and `sanitize_for_filename()` which strips unsafe characters from backend labels for use in log separators/headers. These are pure, stateless functions that form the base layer for all subsequent streaming, append, and retry-attribution work.

## Acceptance Criteria
- [ ] A new module `src/output_log.rs` exists and is registered in `src/lib.rs`
- [ ] `log_path_for_role(project_dir, loop_number: Option<u32>, role: &str) -> PathBuf` returns `{project_dir}/loops/{loop_number:03}/agent-output-{role}.log` when `loop_number` is `Some`
- [ ] `log_path_for_role(project_dir, None, "prompt-reviewer")` returns `{project_dir}/agent-output-prompt-reviewer.log`
- [ ] `log_path_for_role` does NOT use `loop_slug` or backend name in derived paths
- [ ] `ensure_log_parent(path)` creates parent directories if they don't exist, returns `io::Result<()>`
- [ ] `sanitize_for_filename(label: &str) -> String` replaces non-alphanumeric/non-hyphen/non-underscore characters with `_`, collapses consecutive underscores, and trims leading/trailing underscores
- [ ] `sanitize_for_filename` handles empty input, unicode, path separators, shell metacharacters
- [ ] Unit tests cover: normal loop+role paths, prompt-reviewer root path, edge cases (loop 0, loop 999), sanitization of unsafe chars (`../`, `; rm -rf`, spaces, unicode), empty string handling
