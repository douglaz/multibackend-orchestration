Now I have a thorough understanding of the codebase. Let me analyze what needs to change:

1. **`GlobalConfig` (global.rs)**: Currently, `GlobalConfig` struct does NOT have `#[serde(default)]` on any of its top-level fields (`workspace`, `backends`, `workflow`, `templates`, `git`), nor does it have a `#[serde(default)]` on the struct itself. Similarly, the nested types (`WorkspaceConfig`, `BackendConfigs`, `BackendConfig`, `WorkflowConfig`, `TemplateConfig`, `GitConfig`) don't have `Default` impls and many required fields lack `#[serde(default = ...)]`. This means `toml::from_str::<GlobalConfig>("")` would fail.

2. **`init.rs`**: Template writing logic is inline in `execute()` — needs extraction to `create_workspace()`.

3. **`auto.rs`**: Uses `Workspace::discover()?` directly at line 129 — needs `ensure_workspace()` wrapper.

This is all one cohesive feature since the config defaults and auto-init are both part of the same deliverable. Here's the spec:

# Feature: Config Defaults and Auto-Init for `ralph auto`

## Description
Implement two interrelated capabilities: (1) make `GlobalConfig` deserializable from empty or partial TOML by adding serde defaults and `Default` impls to all nested config types, and (2) add auto-workspace-initialization to the `ralph auto` command so it creates `.ralph` when no workspace exists. This also refactors `init.rs` to extract a reusable `create_workspace()` function.

## Acceptance Criteria
- [ ] `toml::from_str::<GlobalConfig>("")` succeeds and equals `GlobalConfig::default()`
- [ ] Whitespace-only TOML (`"   \n  "`) deserializes to `GlobalConfig::default()`
- [ ] Missing top-level sections (`workspace`, `backends`, `workflow`, `templates`, `git`) default correctly
- [ ] Missing fields inside present sections default correctly
- [ ] Missing backend blocks (`claude` or `codex` absent) use backend-specific defaults matching `GlobalConfig::default()`
- [ ] `GlobalConfig::load()` still errors when the TOML file does not exist (no behavior change)
- [ ] `init.rs` exposes `pub(crate) fn create_workspace(root: &Path) -> Result<Workspace>` that calls `Workspace::init`, writes all templates + legacy symlinks, and returns the workspace
- [ ] `init::execute()` delegates to `create_workspace()` (behavior unchanged)
- [ ] `auto.rs` adds `ensure_workspace() -> Result<Workspace>` that catches `WorkspaceNotFound` from `discover()` and auto-creates `.ralph` in the current directory via `init::create_workspace`
- [ ] Auto-init prints exactly `initialized workspace at .ralph` to stderr
- [ ] Non-`WorkspaceNotFound` errors from `discover()` propagate unchanged
- [ ] Other commands (`run`, `project`, `init`, etc.) still fail with `WorkspaceNotFound` when no workspace exists
- [ ] Auto-init on an existing workspace where `ralph.toml` is missing still errors (from `Workspace::load`)
- [ ] Unit test: `empty_toml_deserializes_to_defaults`
- [ ] Unit test: `whitespace_toml_deserializes_to_defaults`
- [ ] Unit test: `partial_sections_default_correctly`
- [ ] Unit test: `missing_single_backend_uses_backend_specific_default`
- [ ] Unit test: `ensure_workspace_creates_workspace_when_missing`
- [ ] Unit test: `create_workspace_writes_all_templates`
- [ ] Validate test: `auto_initializes_workspace_when_missing`

- [ ] Validate test: `auto_does_not_change_other_commands_workspace_not_found_behavior`
- [ ] Validate test: `auto_on_existing_workspace_with_missing_ralph_toml_still_errors`
- [ ] Validate test: `init_behavior_unchanged_for_non_empty_target`
