# Feature: Interactive PRD Debug Logging

## Description
Add always-on debug logging to the interactive PRD workflow so every backend call preserves raw output for diagnosis. This instruments all `run_backend_sync()` calls in `interactive_prd.rs` and all reviewer retry attempts in `prd/quick.rs` with structured log entries containing prompt summaries, backend identity, raw output, and outcome markers (execution, validation, parse). Logs are written to `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/logs/issue-{N}-{role}.log` using the existing best-effort `LogWriter` infrastructure.

## Acceptance Criteria
- [ ] Helper `prd_log_dir(data_dir, owner, repo) -> PathBuf` returns `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/logs/`
- [ ] UTF-8-safe prompt truncation helper truncates at 500 characters (not bytes), reports original byte length, never panics on multibyte input
- [ ] `PrdLogContext` struct bundles `log_dir`, `issue_number`, `writer_backend_spec`, `reviewer_backend_spec` to avoid parameter explosion
- [ ] Every `run_backend_sync()` call in interactive PRD writes a log entry (attempt separator, `backend_spec=...`, prompt summary, raw output, outcome markers) before validation/parsing
- [ ] Every reviewer retry attempt in `run_review_with_retry()` logs attempt separator, backend spec, prompt summary, raw output (or execution failure marker), and parse result
- [ ] `check_spec_sections()` callers log `validation: pass` or `validation: fail missing=[...]` after raw output
- [ ] Question-generation and synthesis calls log `validation: n/a`
- [ ] Timeout paths log `--- execution: timeout ---`; error paths log `--- execution: error <message> ---`; success logs `--- execution: ok ---`
- [ ] Logs use canonical path `{data_dir}/{owner}/{repo}/.ralph/interactive-prd/logs/issue-{N}-{role}.log` with roles: `questions-a`, `questions-b`, `synthesis`, `writer`, `reviewer`
- [ ] Logging failures never fail the PRD workflow (best-effort semantics preserved)
- [ ] `quick-prd` callers remain compatible by passing `None` for optional logging parameters
- [ ] Raw output is logged even when section validation subsequently fails and discards the output
- [ ] No duplicate raw-output writes when streaming logging is in use
