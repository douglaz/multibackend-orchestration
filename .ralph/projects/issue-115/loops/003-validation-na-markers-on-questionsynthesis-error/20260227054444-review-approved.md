## Notes
The core fix is elegant: `run_backend_with_validation_na()` wraps `run_backend_sync()` and calls `log_validation_na()` unconditionally before returning the result. Because Rust evaluates `log_validation_na(Some(log_writer))` before the return/propagation, the marker is guaranteed to be written to the log file regardless of whether `run_backend_sync` returned Ok or Err. The `?` at each call site then propagates the error after the log write is complete.

The deduplication of `truncate_prompt_for_log` from `quick.rs` is clean — the function was already `pub` in `interactive_prd.rs`, and the import in `quick.rs` and `tests_interactive_prd.rs` both resolve correctly.

The new conformance test covers two distinct failure modes (timeout via `sleep 2` with 1-second limit, and execution error via exit code 1 on the second call) and verifies both execution and validation markers in separate log files.
