# Feature: Validation-NA Markers on Question/Synthesis Error Paths

## Description
Ensure that `--- validation: n/a ---` is always written to question-generation and synthesis log files, even when the backend call fails with a timeout or error. Currently, the `?` operator on `run_backend_sync()` in `generate_questions_with_timeout()` causes early return before `log_validation_na()` is reached. This violates the prompt requirement that "Calls without section validation (question generation, synthesis, reviewer parsing attempts) must log `--- validation: n/a ---`." Additionally, deduplicate the `truncate_prompt_for_log()` helper that was copied into `prd/quick.rs`.

## Acceptance Criteria
- [ ] `questions-a` log contains `--- validation: n/a ---` when backend A times out or errors
- [ ] `questions-b` log contains `--- validation: n/a ---` when backend B times out or errors
- [ ] `synthesis` log contains `--- validation: n/a ---` when synthesis backend times out or errors
- [ ] Execution markers (`execution: timeout` or `execution: error`) remain present alongside `validation: n/a`
- [ ] Successful question/synthesis calls continue to log `--- validation: n/a ---` (no regression)
- [ ] `truncate_prompt_for_log()` in `quick.rs` is replaced with an import from `interactive_prd`
- [ ] A new conformance test verifies `validation: n/a` is present in the same log file as `execution: timeout` or `execution: error` for question/synthesis roles
- [ ] Existing tests continue to pass

## Files to Modify/Create
- `src/daemon/interactive_prd.rs` - Refactor `generate_questions_with_timeout()` to log `validation: n/a` in both success and error branches for all three backend calls (questions-a, questions-b, synthesis). Change `?` early-return pattern to match-based error handling that writes `log_validation_na()` before propagating the error.
- `src/prd/quick.rs` - Remove duplicated `truncate_prompt_for_log()` and `LOG_PROMPT_PREVIEW_CHARS` constant; import the public version from `interactive_prd` instead.

- `src/validate/mod.rs` - Register the new test if not auto-registered via the existing `tests()` function.
