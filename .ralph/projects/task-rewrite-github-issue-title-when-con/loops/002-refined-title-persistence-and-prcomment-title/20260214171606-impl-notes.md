# Implementation Notes

## Decisions Made
- Added `refined_title: Option<String>` field to `DaemonTask` with `#[serde(default)]` for backward compatibility with legacy JSON that omits this field.
- `extract_original_title` splits on `\n\n` to get the title segment before the body, matching the `compose_raw_idea` format (`"{title}\n\n{body}"`).
- Refined title persistence uses `store.update_task()` in a separate best-effort call after refinement succeeds; errors are logged as warnings and do not abort dispatch.
- PR title precedence is implemented as a chained `Option` expression: `refined_title.or_else(extract_original_title).unwrap_or_else(fallback)`.
- Comment formatting uses `**{title}**\n\n{body}` when a refined title exists; otherwise just the body.
- The `refined_title` is captured from `RefinedPrompt.title` in the destructured return of the refinement call, alongside the body.
- New tasks created in `poll_and_claim` explicitly initialize `refined_title: None`.

## Spec Deviations
- None. All acceptance criteria are implemented as specified.

## Testing
- **Unit tests in `src/daemon/mod.rs`**: 2 new tests verify legacy deserialization without `refined_title` yields `None`, and round-trip serialization preserves `refined_title: Some(...)`.
- **Unit tests in `src/daemon/runtime.rs`**: 4 new tests cover all required `extract_original_title` cases: with body, no body, empty string, and body-only (empty title).
- **Conformance tests in `src/validate/tests_daemon.rs`**: 5 new tests:
  - `refinement_title_in_pr`: refined title used as PR title, persisted in store.
  - `refinement_disabled_pr_uses_original_title`: falls back to original title from raw_idea.
  - `refinement_failure_pr_uses_original_title`: falls back to original title on refine error.
  - `legacy_task_without_raw_idea_pr_uses_fallback`: falls back to `ralph: {task_id}`.
  - `refined_prompt_comment_includes_title`: bold title header appears in comment body.
- All 542 tests pass (`cargo test` — 0 failures, 0 errors).
