# Feature: Activity-Aware Idle Timeout for CliBackend Execution

## Description
Replace the fixed global timeout in `CliBackend::execute_streaming` with an idle timeout that resets whenever stdout or stderr receives a data chunk. This uses a `tokio::sync::Notify` to signal activity from the stdout/stderr read loops to a watchdog task, which uses a `biased` `tokio::select!` loop to prioritize cancellation and activity signals over timeout expiry. The existing real-time log streaming, output normalization, and process-group kill semantics remain unchanged.

## Acceptance Criteria
- [ ] Real-time log streaming for `CliBackend` remains intact (`agent-output-*.log` grows in real time).
- [ ] Idle timeout is activity-based: every stdout or stderr chunk resets the timer.
- [ ] Stalled backends are terminated after the configured inactivity window with the same process-group kill semantics as the current timeout path.
- [ ] Output normalization (`String::from_utf8_lossy`) and `captured_stdout` accumulation are preserved.
- [ ] No duplicate log writes appear.
- [ ] Watchdog task is reliably cancelled after process/read-loop completion.
- [ ] Existing unit tests pass: `cli_backend_streaming_preserves_exact_bytes_in_log`, `cli_backend_timeout_kills_and_reaps_child_and_writes_footer`.
- [ ] Existing streaming validate tests pass.
- [ ] New unit test `cli_backend_idle_timeout_resets_on_activity` is added and passing (slow-but-active process survives beyond nominal timeout).
- [ ] Existing timeout test is strengthened or a new test confirms idle timeout fires on stall (initial output then silence beyond timeout).
- [ ] Validate conformance coverage for idle-timeout reset behavior in streaming path is added/updated and passing.
- [ ] Timing tests use generous margins and are CI-stable.

## Files to Modify/Create
- `src/backend/mod.rs` — Introduce `tokio::sync::Notify` for activity signaling; refactor watchdog task from fixed `tokio::time::sleep` to a `biased` `tokio::select!` loop over cancellation, `Notify::notified()`, and timeout expiry; notify from both stdout and stderr chunk-read paths; keep all other streaming/logging/kill logic unchanged.
- `src/backend/mod.rs` (test section or `#[cfg(test)]` module) — Add `cli_backend_idle_timeout_resets_on_activity` test; strengthen existing timeout test to confirm idle-stall termination.
- `src/validate/tests_streaming.rs` (or equivalent existing streaming validate module) — Add or extend conformance test covering idle-timeout reset behavior during streaming execution.
- `src/validate/mod.rs` — Only if new test module registration is needed for the conformance test.
