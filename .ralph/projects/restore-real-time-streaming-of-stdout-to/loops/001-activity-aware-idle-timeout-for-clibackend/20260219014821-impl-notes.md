# Implementation Notes

## Decisions Made
- Replaced fixed global timeout in `CliBackend::execute_streaming` with an idle-timeout watchdog using `tokio::sync::Notify` + `oneshot` cancellation in `src/backend/mod.rs:329`.
- Added activity signals from both stdout and stderr chunk paths (`notify_one()` on each chunk) so either stream resets idle timeout (`src/backend/mod.rs:350`, `src/backend/mod.rs:416`).
- Implemented watchdog loop with `tokio::select! { biased; ... }` prioritizing cancellation/activity over sleep expiry, then preserved existing timeout cleanup path (kill/reap + timeout footer + `BackendTimeout`) (`src/backend/mod.rs:363`).
- Preserved existing streaming/logging/normalization behavior: stdout still accumulates in `captured_stdout`, log writes remain real-time, and final output still uses `String::from_utf8_lossy` (`src/backend/mod.rs:468`).
