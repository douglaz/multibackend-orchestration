# Feature: Cleaned GitHub Issue Body from Refinement

## Description
Extend the daemon's refinement pipeline to produce an optional third artifact — `cleaned_body` — which is a lightly edited version of the original GitHub issue body. When present and valid, the daemon updates the GitHub issue body via `gh issue edit --body`. The feature adds a new output section to the refinement prompt, updates the parser and data model, adds a new GitHub helper function, integrates the body update into the runtime dispatch flow, and provides comprehensive unit and conformance test coverage. All existing behavior (title extraction, strict body validation, comment posting, `--idea` dispatch) remains unchanged.

## Acceptance Criteria
- [ ] Refinement system prompt in `refine.rs` defines the three-section output format (`TITLE: ...\n---\n<body>\n=== CLEANED BODY ===\n<cleaned body>`) and explicitly instructs the model that cleaned body must exclude the title, preserve structure, and only fix typos/grammar/readability.
- [ ] `RefinedPrompt` struct includes `cleaned_body: Option<String>`.
- [ ] `parse_refined_output` uses standalone line-level matching (`line.trim() == "=== CLEANED BODY ==="`) to find the delimiter; splits only on the first occurrence.
- [ ] `body` remains strict-validated via existing `validate_output`; invalid body still fails refinement.
- [ ] `cleaned_body` validation is best-effort: missing, empty, whitespace-only, or too-short (`MIN_OUTPUT_LENGTH`) yields `None` without failing refinement. Debug logging for dropped content is permitted.
- [ ] `github.rs` exposes `update_issue_body(owner, repo, issue_number, body) -> Result<()>` mirroring `update_issue_title` but using `gh issue edit --body`.
- [ ] `runtime.rs` destructures `cleaned_body` from refinement result and performs best-effort body update (log warning on failure, never abort dispatch).
- [ ] Existing `refined-prompt` comment uses title + structured `body` only (no `cleaned_body`).
- [ ] Existing `--idea` dispatch receives structured `body` only (no `cleaned_body`).
- [ ] Missing `cleaned_body` section (two-section output) skips `gh issue edit --body` call entirely.
- [ ] Unit tests added in `refine.rs`: `parse_refined_output_three_section_success`, `parse_refined_output_no_cleaned_body_fallback`, `parse_refined_output_empty_cleaned_body_degraded`, `parse_refined_output_cleaned_body_preserves_structure`, `parse_refined_output_delimiter_in_content_not_split`, and one explicit multi-delimiter test.
- [ ] Conformance tests added in `tests_daemon.rs`: `daemon::refinement_cleaned_body_dispatched`, `daemon::refinement_no_cleaned_body_skips_edit`, `daemon::refinement_cleaned_body_failure_non_blocking`.
- [ ] Conformance assertions verify: `--body` called only when valid cleaned body exists; `--idea` always uses structured body; `refined-prompt` comment excludes cleaned body; `--body` edit failure is non-blocking (stable substring match for warning).

## Files to Modify/Create
- `src/daemon/refine.rs` — (1) Update `REFINEMENT_SYSTEM_PROMPT` to define three-section output format with cleaned-body instructions. (2) Add `cleaned_body: Option<String>` to `RefinedPrompt`. (3) Update `parse_refined_output` to find standalone `=== CLEANED BODY ===` delimiter, split body vs cleaned_body, validate cleaned_body best-effort. (4) Add 6 unit tests for new parsing behavior.
- `src/daemon/github.rs` — Add `update_issue_body(owner, repo, issue_number, body) -> Result<()>` function mirroring `update_issue_title` but passing `--body` to `gh issue edit`.
- `src/daemon/runtime.rs` — (1) Update refinement result destructuring to extract `cleaned_body`. (2) After existing title update block, add best-effort `update_issue_body` call when `cleaned_body.is_some()`. (3) Ensure `cleaned_body` is not passed to comment or `--idea` dispatch.
- `src/validate/tests_daemon.rs` — Add 3 conformance tests: `refinement_cleaned_body_dispatched` (verifies `--body` called with valid cleaned body, `--idea` uses structured body, comment excludes cleaned body), `refinement_no_cleaned_body_skips_edit` (verifies no `--body` call for two-section output), `refinement_cleaned_body_failure_non_blocking` (verifies `--body` failure logs warning but dispatch continues).
