# Feature: Project Delete Command

## Description
Add a `ralph project delete <id>` CLI subcommand that removes a project's directory tree (`.ralph/projects/<id>/`) after validating the project ID format, confirming the project exists, verifying it is not the currently active project, and acquiring its file lock to prevent concurrent operations. Includes four conformance tests exercising the happy path, active-project refusal, nonexistent-project error, and the no-active-project scenario.

## Acceptance Criteria
- [ ] `ralph project delete my-proj` removes `.ralph/projects/my-proj/` and prints `project 'my-proj' deleted`
- [ ] If the project does not exist (no `state.json`), the command exits with code 2 and prints a `ProjectNotFound` error
- [ ] If the project is the currently active project, the command exits with code 2 and prints a `Validation` error: `"cannot delete the active project 'my-proj'; run \`ralph project use <other-id>\` first"`
- [ ] If no project is currently active, the delete command proceeds normally (no active-project guard fires)
- [ ] If the project ID contains characters outside `[a-zA-Z0-9_-]` or is empty, the command exits with code 2 and prints a `Validation` error before any filesystem access
- [ ] If the project's `.lock` file is held by another process, the command exits with code 3 and prints a `StateLocked` error
- [ ] Conformance test `project::delete_removes_directory` passes under `ralph validate`
- [ ] Conformance test `project::delete_refuses_active` passes under `ralph validate`
- [ ] Conformance test `project::delete_nonexistent_fails` passes under `ralph validate`
- [ ] Conformance test `project::delete_no_active_project` passes under `ralph validate`

## Files to Modify/Create
- `src/cli/mod.rs` — Add `Delete(ProjectDeleteArgs)` variant to the `ProjectCommand` enum; add `ProjectDeleteArgs` struct with a `project_id: String` positional argument (mirroring `ProjectUseArgs`)
- `src/cli/project.rs` — Add `ProjectCommand::Delete` match arm: validate project ID via `validate_project_id()`, discover workspace, check project exists (`workspace.project_exists()`), check not active (`workspace.active_project_id()`), acquire project lock (`ProjectLock::acquire()`), drop the lock, call `fs::remove_dir_all()` on the project directory, print confirmation
- `src/project/lifecycle.rs` — Change `validate_project_id` visibility from `fn` (private) to `pub(crate) fn` so the delete handler can reuse it; no logic changes
- `src/validate/tests_project.rs` — Add four `ConformanceTest` entries and their test functions: `delete_removes_directory` (create two projects, switch active, delete the non-active one, verify removal), `delete_refuses_active` (attempt to delete the active project, expect exit code 2 and directory preserved), `delete_nonexistent_fails` (delete a non-existent ID, expect exit code 2), `delete_no_active_project` (clear the active-project file, delete a project, verify success)
