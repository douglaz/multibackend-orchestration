# Feature: Deterministic branch cleanup in remove_worktree and restart reconciliation tests

## Description
Fix `remove_worktree()` to always perform `git worktree prune` and branch cleanup (`git show-ref --verify` + `git branch -D`) regardless of whether the worktree directory exists on disk. Update the function signature to accept the branch name and return `Result<()>` with contextual errors instead of silently ignoring failures. Update all call sites to pass the branch name. Add the `runtime_restart_in_progress_with_stale_branch` integration test and update the existing restart retry test to assert branch cleanup via `git show-ref --verify` exit code.

## Acceptance Criteria
- [ ] `remove_worktree()` accepts a `branch` parameter (the `refs/heads/...` short name, e.g. `ralph/daemon/{task_id}`)
- [ ] `remove_worktree()` executes cleanup in this exact order: (1) if worktree path exists: `git worktree remove --force <path>`, (2) always: `git worktree prune`, (3) always: `git show-ref --verify refs/heads/<branch>` to check branch existence, (4) if branch exists: `git branch -D <branch>`
- [ ] If the worktree path does not exist, only step 1 is skipped; steps 2-4 still run
- [ ] Branch existence is checked exclusively with `git show-ref --verify refs/heads/<branch>` — never `git branch --list`
- [ ] "Branch not found" from `show-ref --verify` (non-zero exit) is non-fatal and means skip the `branch -D` step
- [ ] Failures in `worktree remove`, `worktree prune`, or `branch -D` (other than missing branch) return contextual `RalphError` errors that include the git command and target path/branch
- [ ] `remove_worktree()` returns `Result<()>` instead of being silent/best-effort (callers that want best-effort can `let _ =` or log the error)
- [ ] All existing call sites in `runtime.rs` (`cleanup_worktree`, `dispatch_task` terminal-race, `reconcile_worktrees`) and `worktree.rs` (`reconcile_worktrees`) are updated to pass the branch name
- [ ] `reconcile_worktrees()` does NOT implement a separate orphan-branch cleanup pass — it relies entirely on `remove_worktree()` for branch cleanup
- [ ] The `reconcile_worktrees` function in `worktree.rs` receives branch information for each task being removed (either via a map parameter or by deriving the branch name from the task_id convention `ralph/daemon/{task_id}`)
- [ ] Existing restart/reconciliation test (`runtime_reconciliation_on_startup` or equivalent restart retry test) is updated to assert branch cleanup using `git show-ref --verify refs/heads/<branch>` exit code
- [ ] New test `runtime_restart_in_progress_with_stale_branch` is added that: (a) seeds an `in_progress` task with fake PID/PGID in `tasks.json`, (b) creates a pre-existing local branch `ralph/daemon/{task_id}` without a worktree directory, (c) starts the daemon in single-iteration mode to trigger restart reconciliation, (d) asserts reconcile -> redispatch -> terminal state flow completes, (e) asserts redispatch success using the stderr signal/message used by current tests (`dispatched task`), (f) asserts the branch is gone using `git show-ref --verify refs/heads/ralph/daemon/{task_id}` returning non-zero exit code
- [ ] No test asserts on worktree directory existence (only uses `git show-ref --verify` for branch assertions)
- [ ] Tests assert all three required signals: dispatch success, terminal task state in `tasks.json`, branch ref cleanup via `show-ref --verify`
