# Review: APPROVED

## Acceptance Criteria Checklist
- [x] `remove_worktree()` accepts a `branch` parameter (the `refs/heads/...` short name, e.g. `ralph/daemon/{task_id}`) — signature is now `remove_worktree(repo_root, workspace_root, task_id, branch: &str) -> Result<()>`
- [x] `remove_worktree()` executes cleanup in this exact order: (1) if worktree path exists: `git worktree remove --force <path>`, (2) always: `git worktree prune`, (3) always: `git show-ref --verify refs/heads/<branch>`, (4) if branch exists: `git branch -D <branch>` — verified in `worktree.rs` diff, steps are sequential and unconditional (except step 1 gated on `wt_path.exists()`)
- [x] If the worktree path does not exist, only step 1 is skipped; steps 2-4 still run — the old early `return` is replaced with an `if wt_path.exists()` block; prune/show-ref/branch-D always execute
- [x] Branch existence is checked exclusively with `git show-ref --verify refs/heads/<branch>` — no `git branch --list` anywhere in the diff or remaining code
- [x] "Branch not found" from `show-ref --verify` (non-zero exit) is non-fatal and means skip the `branch -D` step — `if !show_ref_output.status.success() { return Ok(()); }`
- [x] Failures in `worktree remove`, `worktree prune`, or `branch -D` return contextual `RalphError::Orchestration` errors that include the git command and target path/branch — all four git commands have `.map_err` with descriptive messages and non-success status checks
- [x] `remove_worktree()` returns `Result<()>` instead of being silent/best-effort — signature confirmed
- [x] All existing call sites updated: `cleanup_worktree` (now takes `Option<String>` branch), `dispatch_task` terminal-race cleanup, `reconcile_worktrees` in `runtime.rs` — all pass branch to `worktree::remove_worktree`
- [x] `reconcile_worktrees()` does NOT implement a separate orphan-branch cleanup pass — it delegates entirely to `remove_worktree()` for both on-disk stale worktrees and active tasks with missing worktree dirs
- [x] `reconcile_worktrees` receives branch information via `task_branches: &HashMap<String, String>` parameter, with fallback to `daemon_branch_name()`
- [x] Existing `runtime_reconciliation_on_startup` test updated with branch seeding (`create_local_branch`), precondition asserts via `git_show_ref_verify_status`, and post-reconciliation branch cleanup assertions
- [x] New test `runtime_restart_in_progress_with_stale_branch` added: (a) seeds `in_progress` task with fake PID 42424, (b) creates branch without worktree dir, (c) runs `--single-iteration`, (d) asserts dispatch signal `dispatched task acme-widgets-210`, (e) asserts terminal state, (f) asserts branch gone via `show-ref --verify`
- [x] No test asserts on worktree directory existence — only `git show-ref --verify` is used for branch assertions
- [x] Tests assert all three signals: dispatch success (`dispatched task`), terminal task state in `tasks.json`, branch ref cleanup via `show-ref --verify`

## Notes
The implementation is clean and precisely matches the spec. Key observations:

1. The `reconcile_worktrees` enhancement to handle active tasks with no on-disk worktree directory (the stale-branch-without-worktree case) is well-designed — it collects on-disk task IDs in a `HashSet`, then iterates active tasks not found on disk, calling `remove_worktree` which will skip step 1 (no dir) but still prune and clean the branch.

2. The `complete_task` call site correctly passes `task.branch.clone()` so the actual branch (which may differ from the daemon convention after a branch switch) is used for cleanup.
