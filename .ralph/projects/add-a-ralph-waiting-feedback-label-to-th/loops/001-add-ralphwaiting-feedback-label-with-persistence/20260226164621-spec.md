# Feature: Add `ralph:waiting-feedback` label with persistence-safe lifecycle and reconciliation

## Description
Add a new informational GitHub label, `ralph:waiting-feedback`, as the 6th PRD label to reflect when an interactive PRD issue is in a waiting state (`AwaitingAnswers` or `AwaitingFeedback`). The label is added after successful state persistence into waiting states, removed after successful persistence into terminal states (`Done`, `Failed`), and reconciled at the end of every per-issue tick to correct drift caused by external label deletion or transient GitHub failures. Stale labels on `Pending` issues are also cleaned up by reconciliation. All label operations are best-effort and must never block workflow progress.

## Acceptance Criteria
- [ ] `ralph:waiting-feedback` is registered as the 6th entry in `PRD_LABELS` (with color and description) and in `PRD_LABEL_NAMES`.
- [ ] `ralph:waiting-feedback` is **not** included in `IN_PROGRESS_PRD_LABEL_NAMES`.
- [ ] `has_prd_label` recognizes `ralph:waiting-feedback` (automatically, since it iterates `PRD_LABEL_NAMES`).
- [ ] On `Pending -> AwaitingAnswers` transition, after successful state save, best-effort add `ralph:waiting-feedback`.
- [ ] On `AwaitingAnswers -> AwaitingFeedback` transition, after successful state save, best-effort add `ralph:waiting-feedback` (or leave present).
- [ ] On `AwaitingFeedback -> AwaitingFeedback` revision loop, after successful save, best-effort add `ralph:waiting-feedback` if missing (no-op if already present).
- [ ] On terminal transitions (`Done`, `Failed`), after successful state save, best-effort remove `ralph:waiting-feedback`.
- [ ] End-of-tick reconciliation runs after every per-issue dispatch path (success, error, panic recovery).
- [ ] Reconciliation: if persisted post-tick state is waiting and label is missing, best-effort add it.
- [ ] Reconciliation: if persisted post-tick state is `Pending` and label is present, best-effort remove stale label.
- [ ] Reconciliation: if persisted post-tick state is terminal, reconciliation does nothing for this label.
- [ ] No-op waiting tick with label already present must not call add/remove for `ralph:waiting-feedback`.
- [ ] All label operations are best-effort and never block workflow progress.
- [ ] Existing PRD label count assertions updated from 5 to 6.
- [ ] Conformance tests in `src/validate/tests_interactive_prd.rs` cover: add on AwaitingAnswers, add on AwaitingFeedback, persistence through revision loops, remove on Done, remove on Failed, reconciliation add on missing label during waiting no-op, reconciliation no-op when label present, reconciliation add after failed dispatch with waiting state, reconciliation removal of stale label on Pending, terminal removal failure is non-blocking, and persistence-safe ordering validation (no label add if save fails).
