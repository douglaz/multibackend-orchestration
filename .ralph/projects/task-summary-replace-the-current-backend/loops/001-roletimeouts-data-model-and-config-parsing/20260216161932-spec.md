# Feature: RoleTimeouts Data Model and Config Parsing

## Description
Add the `RoleTimeouts` struct to `src/config/global.rs` with per-role timeout fields (`planner`, `implementer`, `reviewer`, `qa`, `completer`, `reformatter`), wire it into `BackendConfig` alongside the existing `timeout_seconds` field, and ensure TOML deserialization supports partial `[backends.<backend>.timeouts]` blocks with defaults for missing roles. Emit deprecation warnings when `timeout_seconds` is present on config load or set via CLI. Update CLI `config set`/`config get`/`config show` and MCP `config_show` to expose the new `timeouts.*` keys. This is the foundational layer that all subsequent features (backend registry API, orchestrator migration, validate tests) depend on.

## Acceptance Criteria
- [ ] `RoleTimeouts` struct exists in `src/config/global.rs` with fields `planner: u64`, `implementer: u64`, `reviewer: u64`, `qa: u64`, `completer: u64`, `reformatter: u64`, all defaulting to `7200`.
- [ ] `RoleTimeouts` implements `Default`, `Debug`, `Clone`, `Serialize`, `Deserialize`, `PartialEq`, `Eq`.
- [ ] `RoleTimeouts::for_role(&self, role: &str) -> Option<u64>` returns `Some(value)` for the six known roles and `None` for unknown strings.
- [ ] `BackendConfig` gains `timeouts: RoleTimeouts` field with `#[serde(default)]`.
- [ ] `BackendConfig` keeps `timeout_seconds: u64` as `#[serde(default = "default_backend_timeout_seconds", skip_serializing_if = "Option::is_none")]` — changed to `Option<u64>` so it serializes only when explicitly set.
- [ ] TOML deserialization of a partial `[backends.claude.timeouts]` block (e.g., only `planner = 300`) fills remaining roles with `7200`.
- [ ] A TOML file with no `[backends.claude.timeouts]` section at all still produces `RoleTimeouts::default()` (all `7200`).
- [ ] `GlobalConfig::load` emits `warning: backends.claude.timeout_seconds is deprecated and ignored at runtime; use backends.claude.timeouts.<role>` to stderr when `timeout_seconds` is present in the TOML for claude (and similarly for codex).
- [ ] `src/cli/config.rs`: `config set backends.claude.timeouts.planner 300` (and all six roles, for both claude and codex) correctly modifies the in-memory config and persists.
- [ ] `src/cli/config.rs`: `config get backends.claude.timeouts.planner` returns the current value.
- [ ] `src/cli/config.rs`: `config set backends.claude.timeout_seconds 600` persists and emits the deprecation warning to stderr.
- [ ] `config show` (CLI and MCP `config_show`) output includes the `timeouts` object with all six role fields under each backend.
- [ ] Unit tests in `src/config/global.rs` verify: defaults, partial timeout table parsing, deprecated key parsing/persistence, `for_role` helper.
- [ ] `tests/init_command.rs` asserts default role timeout structure exists (all six fields = 7200 for both backends).
- [ ] `src/cli/config.rs` tests for setting/getting new timeout keys and deprecated warning behavior.
- [ ] `cargo check` and `cargo test` pass with no new warnings (except the intentional deprecation warnings during test execution).
