# Feature: Role-Aware Backend Registry Timeout Resolution

## Description
Loop 1 completed the config/data-model layer (`RoleTimeouts`, parsing, and deprecated key compatibility). The next logical step is wiring runtime backend creation to those role-specific timeout values by adding a role-aware registry API and timeout-aware backend constructors. This enables orchestration roles to consume the new config without changing non-orchestrator behavior yet.

## Acceptance Criteria
- [ ] `src/backend/mod.rs` adds `get_or_create_for_role(&mut self, spec: &str, role: &str) -> Result<Arc<dyn Backend>>` and keeps `get_or_create_for_spec(&str)` unchanged.
- [ ] `get_or_create_for_role` parses backend specs with the same logic/path as `get_or_create_for_spec` (same validation, same model parsing semantics).
- [ ] Role timeout resolution uses `backends.<backend>.timeouts.<role>` and falls back to `7200` for unknown roles.
- [ ] Role-aware caching is implemented so the same backend spec can be cached separately per role timeout context.
- [ ] Repeated `get_or_create_for_role` calls with the same `(spec, role)` return the same cached instance; different roles for the same spec do not collide.
- [ ] `get_or_create_for_spec` continues using non-role cache behavior and default timeout behavior for non-orchestrator callsites.
- [ ] Backend construction paths in `src/backend/claude.rs` and `src/backend/codex.rs` accept explicit timeout values while preserving existing model/args behavior.
- [ ] Deprecated `backends.<backend>.timeout_seconds` is not used for runtime timeout selection in either role-aware or non-role-aware registry paths.
- [ ] `tests/backend.rs` verifies role timeout selection, role cache separation, unknown-role fallback to `7200`, and unchanged non-role acquisition behavior.

## Files to Modify/Create
- `src/backend/mod.rs` - add role-aware acquisition API, timeout resolution by role, and role-aware cache keys.
- `src/backend/claude.rs` - accept explicit timeout input in backend construction path.
- `src/backend/codex.rs` - accept explicit timeout input in backend construction path.
- `tests/backend.rs` - add regression coverage for role-based timeout selection and cache key behavior.

## Dependencies
- Requires: RoleTimeouts Data Model and Config Parsing (Loop 1)
- Blocks: Orchestrator callsite migration to `get_or_create_for_role`, validate/conformance timeout migration
