# QA: FAIL

## Failures

1. **`nix build -L` fails**: 2 conformance tests fail (213 passed, 2 failed):
   - **`streaming::timeout_cleanup`**: The test sets `backends.claude.timeout_seconds=1` and `backends.codex.timeout_seconds=1` (deprecated keys), then expects the planner to timeout quickly and produce a `--- timeout ts=` footer in the log. Since the implementation correctly ignores `timeout_seconds` at runtime, the backends get the default 7200s timeout from `RoleTimeouts`, so the expected quick-timeout behavior never triggers. The planner log shows output without a timeout footer.
   - **`e2e_conformance::backend_timeout_exhausted_fails_task`**: The test sets `backends.claude.timeout_seconds=2` and `backends.codex.timeout_seconds=2` (deprecated keys), then expects a `BackendTimeoutExhausted` error in stderr. Instead it gets `parse retries exhausted for role planner` because the deprecated key doesn't affect runtime timeout resolution — the 7200s default is used instead, so the mock finishes before any timeout occurs.

2. **Root cause**: Both failing tests still configure timeouts via the deprecated `timeout_seconds` key, which this loop's implementation correctly ignores at runtime (per spec). The tests need to be migrated to use the new `backends.<backend>.timeouts.<role>` keys, but that migration is listed in the master prompt as a future conformance task dependent on orchestrator callsite migration.
