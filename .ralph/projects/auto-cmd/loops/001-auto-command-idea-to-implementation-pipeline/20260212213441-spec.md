# Feature: auto command — idea-to-implementation pipeline

## Description
Add a `ralph auto` CLI subcommand that chains three existing operations into a single workflow: (1) generate an engineering spec via the quick-prd pipeline, (2) create a new ralph project from the spec, and (3) run the project until complete. This includes the `AutoArgs` clap struct, the `slugify_idea()` helper, the three-phase `execute()` function, CLI registration in the `Commands` enum, and all required unit tests.

## Acceptance Criteria
- [ ] `src/cli/auto.rs` exists with `AutoArgs` struct deriving `Debug, Args` from clap
- [ ] `AutoArgs` includes all specified flags: `--idea` (required, validated non-empty), `--spec-writer` (default "claude"), `--spec-reviewer` (default "codex"), `--max-spec-revisions` (default 2), `--project-id` (optional), `--backend` (optional), `--planner-backend`, `--implementer-backend`, `--reviewer-backend`, `--qa-backend`, `--completer-backend` (all optional), `--skip-commit` (bool), `--tmux`/`--no-tmux` (conflicting optional bools), `--dry-run` (bool)
- [ ] `fn slugify_idea(idea: &str) -> String` lowercases, replaces non-alphanumeric/non-hyphen runs with single `-`, trims leading/trailing dashes, truncates to 40 chars, trims trailing dash after truncation
- [ ] `pub async fn execute(args: AutoArgs) -> Result<()>` implements three sequential phases: quick-prd spec generation, project creation via `create_project()`, and orchestrated run via `Orchestrator::run()` with `until_complete: true`
- [ ] Phase 1 creates `BackendRegistry` with tmux disabled, validates/creates writer+reviewer backends, health-checks both, builds `QuickPrdOptions`, runs `QuickPrdPipeline`, and prints summary
- [ ] Phase 2 calls `create_project()` with slugified or explicit project ID, idea truncated to 60 chars as name, `PromptSource::File(result.spec_path)`, and optional starting backend
- [ ] Phase 3 re-discovers workspace via `Workspace::discover()`, creates `Orchestrator`, and calls `run()` with `RunOptions` passing through all role-override backends, `skip_commit`, `tmux`, and `until_complete: true`
- [ ] `--dry-run` short-circuits after phase 1 (prints spec, does not create project or run)
- [ ] `Commands::Auto(auto::AutoArgs)` variant added to `Commands` enum in `src/cli/mod.rs`
- [ ] Dispatch arm `Commands::Auto(args) => auto::execute(args).await` added to `run()` in `src/cli/mod.rs`
- [ ] `mod auto;` declaration added to `src/cli/mod.rs`
- [ ] Unit test `test_slugify_idea_basic`: "add retry logic" → "add-retry-logic"
- [ ] Unit test `test_slugify_idea_special_chars`: "fix bug #123 (urgent!)" → "fix-bug-123-urgent"
- [ ] Unit test `test_slugify_idea_truncation`: long idea truncated to 40 chars with no trailing dash
- [ ] Unit test `test_slugify_idea_consecutive_dashes`: "hello   world---test" → "hello-world-test"
- [ ] Unit test `parses_auto_command_with_defaults`: clap parsing verifies default values for `--spec-writer`, `--spec-reviewer`, `--max-spec-revisions`, and boolean flags
- [ ] Unit test `parses_auto_command_with_all_args`: clap parsing with every flag explicitly set verifies correct values
- [ ] Unit test `rejects_auto_with_empty_idea`: `--idea ""` is rejected (non-empty validation)
- [ ] `cargo check` compiles with zero errors
- [ ] `cargo test` passes all existing and new tests
