# Implementation Notes

## Decisions Made
- **Priority parsing via manual match rather than `clap::ValueEnum`**: The `AmendmentPriority` enum lives in `src/project/amendments.rs` with serde derives. Rather than adding clap as a dependency to the data model or modifying the existing enum, the CLI accepts priority as a `String` and validates it in `amend::execute()` via `parse_priority()`. This keeps the data model decoupled from CLI concerns and matches the project's pattern (e.g. `cfg_parse_prompt_change_action` in config).
- **`--body` as a required `String` arg**: The `@path` prefix convention is handled at execution time in `resolve_body()`, not at the clap parsing level. This keeps arg definitions simple and matches how the spec describes the behavior.
- **Default ID generation uses `EXT-<YYYYMMDDHHMMSS>`**: Reuses the existing `format_timestamp_yyyymmddhhmmss` utility from `src/util/time.rs`.
- **Synchronous command execution**: `amend::execute()` is sync (returns `Result<()>`, not async), since it only does filesystem operations. The dispatch in `run()` calls it directly without `.await`.
- **Conformance tests use the `run_case` pattern**: Following the convention established in `tests_validate_flags.rs` with `catch_unwind` for panic-safe test execution.

## Spec Deviations
- None. All acceptance criteria from the feature spec are implemented as specified.
