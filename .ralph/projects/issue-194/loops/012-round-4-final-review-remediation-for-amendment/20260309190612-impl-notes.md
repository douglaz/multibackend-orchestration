# Implementation Notes

## Decisions Made
- Introduced `InflightReadOutcome` enum to cleanly separate I/O read failures from content parse/validation failures in `read_and_parse_inflight`, replacing the former `parse_inflight_request` which conflated both error types into a single `Result`. This enables the drain loop to route I/O errors to rollback and content errors to quarantine without relying on error downcasting.
- Added `has_iso_basic_timestamp_prefix` as a local helper in `commit.rs` rather than extending `parse_artifact_filename_timestamp` in `artifacts.rs`, because the canonical 14-digit format is the project-wide standard and ISO-basic is only relevant for stray-artifact cleanup of files leaked by external backends.
- Used `#[cfg(unix)]` guard plus a runtime root-detection check (attempt to read the 0o000 file) for the I/O-fatal drain test, ensuring it skips gracefully on non-Unix platforms and in root-privileged CI environments.

## Spec Deviations
- None. All three amendments (FR-20260309-001, FR-20260309-002, STRAY-ROOT-FILES-001) are implemented exactly as specified.
