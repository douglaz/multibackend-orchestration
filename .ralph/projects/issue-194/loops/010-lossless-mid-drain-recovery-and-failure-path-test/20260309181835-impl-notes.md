# Implementation Notes

## Decisions Made
- **Rollback integrated directly into `drain_amendment_queue_with_hook`**: Rather than requiring callers to handle partial-drain errors, the drain function itself performs best-effort rollback via the existing `re_enqueue_amendments` helper. This keeps the rollback as close to the failure point as possible and prevents callers from needing to distinguish between "all-lost" and "partially-lost" errors.
- **New `rollback_mid_drain` private helper**: Extracted a dedicated function that mirrors the public `rollback_drained_amendments` but is scoped to drain-internal use. It handles both full and partial rollback, including the error message augmentation with unrestored IDs.
- **All `?` operators in the drain loop replaced with explicit error handling**: Every IO error point that could lose already-drained items (`remove_file_if_exists`, `before_json_claim`, `claim_file_without_overwrite`, `fs::remove_file`) now routes through `rollback_mid_drain` before returning `Err`.
- **Directory listing phase left as-is**: The `fs::read_dir`/`entry?`/`file_type?` calls happen before any items are drained, so `drained` is empty and no rollback is needed.
- **Existing `before_json_claim` hook reused for test injection**: The hook fires per-`.json` file before the claim rename, making it ideal for injecting a fatal error after N successful drains. No new hook parameter was needed.
- **Checkpoint failure test strengthened with exit-code assertion**: Added `!output.status.success()` and non-empty stderr checks to prove the failure path was actually exercised, not just that the pending count happened to be zero.

## Spec Deviations
- None. All acceptance criteria are implemented as specified.

## Testing
- **`drain_rolls_back_already_drained_items_on_mid_drain_fatal_error`**: Enqueues 3 items, injects a fatal error on the 3rd claim. Verifies all 3 are recoverable (2 via rollback + 1 untouched), then a fresh drain returns all 3.
- **`drain_rollback_preserves_original_amendment_fields`**: Verifies rolled-back items retain all original fields (`id`, `body`, `priority`, `source`, `source_detail`, `created_at`).
- **`drain_malformed_files_do_not_trigger_rollback`**: Verifies malformed files are quarantined independently and do not trigger the rollback path.
- **`quick_dev_checkpoint_failure_no_rollback_after_durable_success`** (strengthened): Now asserts non-zero exit code and non-empty stderr as evidence the checkpoint-failure path was exercised, in addition to the existing pending=0 assertion.
- All 22 unit tests in `project::amendments::tests` pass. `cargo check` succeeds.
