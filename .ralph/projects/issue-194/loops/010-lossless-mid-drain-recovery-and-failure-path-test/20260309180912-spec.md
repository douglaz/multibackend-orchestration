# Feature: Lossless Mid-Drain Recovery and Failure-Path Test Hardening

## Description
Core amendment-queue functionality is already in place (model, CLI intake, planning/quick-dev drain/injection, completion guards, and phase-failure re-enqueue).  
The next gap is a fatal mid-drain error path where already-processed items can be lost because `drain_amendment_queue` returns `Err` without exposing partial progress. This feature makes drain failures non-lossy and tightens conformance coverage for the quick-dev checkpoint-failure path so the test proves the intended behavior.

## Acceptance Criteria
- [ ] `drain_amendment_queue` tracks amendments successfully parsed/deleted during the current drain pass.
- [ ] If a fatal IO error occurs after one or more successful drains, the function performs best-effort rollback by re-enqueuing those drained items before returning `Err`.
- [ ] State invariant: when rollback succeeds, all previously drained items are back in the queue with original fields (`id`, `body`, `priority`, `source`, `source_detail`, `created_at`), and unprocessed files remain untouched.
- [ ] State invariant: when rollback is partial, return an error that includes unrestored amendment IDs; successfully restored IDs remain queued.
- [ ] Malformed-file handling remains independent: malformed entries are quarantined with warnings and do not trigger fatal rollback behavior.
- [ ] Add a deterministic unit test that injects a mid-drain fatal failure and verifies no amendment disappearance.
- [ ] `quick_dev_checkpoint_failure_no_rollback_after_durable_success` is strengthened to assert the failure path actually occurred (non-zero exit + checkpoint-failure evidence), or split into renamed semantics + deterministic failure-path test.

## Files to Modify/Create

- `src/validate/tests_amendments.rs` - make quick-dev checkpoint-failure conformance assertions prove the intended path.
