# Feature: Standard Orchestrator Amendment Integration

## Description
Wire the amendment queue into the standard orchestrator's planning phase and the quick-dev orchestrator's `PlanAndImplement` phase. This connects the data model and CLI intake (loops 1-2) to actual orchestration behavior: draining queued amendments at phase boundaries, injecting their content into planner/implementer prompts, and blocking premature completion requests when amendments are still pending.

## Acceptance Criteria
- [ ] Standard orchestrator drains the amendment queue at the start of `Phase::Planning`, before invoking the planner backend.
- [ ] Drained amendments (excluding `source == FinalReview` when `unify_final_review` is true) are formatted via `format_external_amendments_for_prompt` and passed into `build_planner_prompt` as a new `external_amendments` parameter.
- [ ] `build_planner_prompt` inserts `external_amendments` as a template variable and uses `append_section_if_missing` with heading `## External Amendments` as fallback when the template lacks the placeholder and content is non-empty.
- [ ] Before honoring `PlannerDecision::CompletionRequest`, the orchestrator calls `pending_amendment_count(&project_dir)` and returns `RalphError::Orchestration` with a message including the count if `count > 0`. This guard does NOT drain or re-enqueue.
- [ ] Quick-dev orchestrator drains the amendment queue inside `QuickDevPhase::PlanAndImplement`, after pre-commit feedback injection but before the backend call, and appends a `## External Amendments` section to the implementer prompt if non-empty.
- [ ] Both orchestrators reuse `format_external_amendments_for_prompt` from `src/project/amendments.rs` (no duplicated formatting logic).
- [ ] Missing queue directory (no amendments ever submitted) is handled gracefully — returns empty vec/zero count, no errors.
- [ ] Conformance tests in `src/validate/tests_amendments.rs` cover: (a) standard planner prompt injection, (b) quick-dev prompt injection, (c) completion guard rejection with pending queue.

### State Invariants
- **After drain:** All `.json` files in the queue dir have been renamed to `.inflight`, parsed, and deleted. Any parse failures are quarantined. The queue dir may still exist but contains no `.json` or `.inflight` files.
- **Completion guard failure:** No side effects on the queue. The pending files remain untouched for the next planning iteration to drain.
- **Missing queue dir:** Both `drain_amendment_queue` and `pending_amendment_count` return `Ok(vec![])` / `Ok(0)` respectively — no directory creation, no error.
