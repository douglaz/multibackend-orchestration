# Implementation Notes

## Decisions Made
- Added `AmendmentsConfig` as a new top-level struct in `GlobalConfig` (alongside `workspace`, `backends`, `workflow`, `templates`, `git`) rather than nesting under `WorkflowConfig`. This matches the spec's `[amendments]` TOML section and keeps amendment-specific config cleanly separated.
- Added `ProjectAmendmentsOverrides` with `Option<bool>` for `unify_final_review` on `ProjectConfig`, following the same pattern as all other project overrides (e.g., `ProjectWorkflowOverrides`).
- Created `EffectiveAmendmentsConfig` struct and added it to `EffectiveConfig`, resolved via the standard project-overrides-global merge pattern in `resolve_effective_config()`.
- Replaced the ad-hoc `unify_final_review_enabled()` / `read_unify_final_review_value()` functions (which did raw TOML probing) with a single `effective.amendments.unify_final_review` access, eliminating redundant file I/O during orchestration.
- Final-review mirroring uses warn-and-continue semantics: if `enqueue_amendment` fails for one accepted amendment, it logs a warning and continues the restart flow. This satisfies the failure invariant in the spec.
- For the dedupe conformance test, created a mock script that asserts CLI amendments appear in the planner prompt but final-review amendments do not (via `grep -q` negative assertion).

## Spec Deviations
- The spec says "invalid `amendments.unify_final_review` config types fail config loading before orchestration starts." This is inherently handled by serde deserialization — if `unify_final_review` is not a bool in TOML, `GlobalConfig::load()` or `ProjectConfig::load()` returns an error before any orchestration starts. No additional validation code was needed.
- The spec mentions `amendments.unify_final_review` in `config show` — for global scope, this is automatically included because `GlobalConfig` is serialized via `serde_json::to_value`. For project scope, the effective value is explicitly included in the JSON output alongside other effective config sections.

## Testing
- Three new conformance tests added to `src/validate/tests_amendments.rs`:
  1. `unify_config_default_off` — verifies default is `false`, set/get works at both global and project scopes, and project overrides global.
  2. `unify_planner_dedupe_excludes_final_review` — runs a full orchestration loop with unify enabled, verifying that CLI amendments appear in the planner prompt but final-review-sourced amendments are excluded (dedupe).
  3. `unify_mirroring_enqueues_final_review_amendments` — verifies that `AmendmentRequest` with `source=FinalReview` round-trips correctly through enqueue/drain, validating the data model integration that the orchestrator mirroring depends on.
- Verification: `cargo check` passes with zero warnings and zero errors.
