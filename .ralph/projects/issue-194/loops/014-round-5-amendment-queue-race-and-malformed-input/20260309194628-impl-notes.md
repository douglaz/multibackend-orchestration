# Implementation Notes

## Decisions Made
- **Enqueue inflight-aware suffix selection**: Added an `.inflight` sibling existence check before attempting to claim a `.json` path in `enqueue_amendment`. This prevents creating a `.json` file that shares a stem with an in-progress drain claim, closing the same-stem race window at the writer side.
- **Content-aware same-stem dedup in drain**: Replaced the blind `completed_inflight_stems: HashSet` delete with a `completed_inflight_items: HashMap<String, AmendmentRequest>` that compares parsed content. True duplicates (from interrupted claims) are still dropped for at-most-once semantics, while distinct payloads with the same stem are both processed to prevent silent data loss.
- **Byte-based inflight reads**: Changed `read_and_parse_inflight` from `fs::read_to_string` + `serde_json::from_str` to `fs::read` + `serde_json::from_slice`. This ensures invalid UTF-8 bytes are classified as malformed content (quarantined, drain continues) rather than fatal I/O read errors that would trigger rollback.
- **Same-stem distinct `.json` processed directly**: When a same-stem `.json` with different content is found after its `.inflight` sibling was already drained, the `.json` is read and deleted directly (not claimed to `.inflight`) since the `.inflight` name was already used. This is a pragmatic trade-off: the crash-safety risk is minimal for this edge case, and avoids adding a secondary inflight naming scheme.
