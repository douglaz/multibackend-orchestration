# Implementation Notes

## Decisions Made
- Added `re_enqueue_amendments` as a best-effort function returning failed IDs rather than `Result`, since partial success (some items re-enqueued) is preferable to total failure. Successfully re-enqueued items remain queued even when later items fail.
- Added `rollback_drained_amendments` as a convenience that wraps the re-enqueue logic with error composition: on full success it returns the original phase error; on partial failure it returns a combined `RalphError::Orchestration` including both the original error and the list of unrestored IDs.
- Used `.map_err(|e| rollback_drained_amendments(...))` at each failable `?` point between drain and durable state commit rather than async blocks or helper closures, keeping the code change minimal and readable.
- Cloned `drained_amendments` into `drained_for_rollback` immediately after drain to preserve the original vec even when `into_iter()` consumes it for the unify-final-review filter path.
- The durable success boundary for Feature is `state.register_feature_loop()`; for CompletionRequest it is `state.register_completion_attempt()`. All failable operations before these points are wrapped with rollback.
- Re-enqueued amendments get new filenames (current timestamp) but preserve all original JSON fields including `created_at`, which satisfies the at-least-once guarantee without requiring exact filename restoration.

## Spec Deviations
- None. All six acceptance criteria are addressed: Planning rollback, QuickDev rollback, success-path invariant (no rollback after durable commit), failure-path invariant (all IDs re-enqueued), partial-rollback invariant (fail hard with combined error), and conformance test coverage.

## Testing
- Two new unit tests in `src/project/amendments.rs`: `re_enqueue_restores_items_to_queue` and `re_enqueue_preserves_original_fields` verify the core re-enqueue function.
- Two new conformance tests in `src/validate/tests_amendments.rs`: `planning_failure_preserves_drained_amendments` (standard orchestrator with a planner that exits 1) and `quick_dev_failure_preserves_drained_amendments` (quick-dev with an implementer that exits 1). Both enqueue an amendment, run the failing orchestration, then assert the amendment is still pending and drainable with original fields.
- All 19 amendment unit tests pass. `cargo check` succeeds clean.
