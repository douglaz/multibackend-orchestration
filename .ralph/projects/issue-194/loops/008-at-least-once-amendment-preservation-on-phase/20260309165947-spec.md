# Feature: At-Least-Once Amendment Preservation on Phase Failure

## Description
Completed loops already cover the amendment model/queue, `ralph amend`, planner and quick-dev prompt injection, final-review unification, and completion guards (Loops 1, 2, 3, 4, 6; completion attempts 5 and 7).  
The next missing feature is failure safety: drained external amendments can still be lost if planning or quick-dev fails after drain but before a durable phase success. Implement rollback-style re-enqueue to guarantee at-least-once handling across these failure paths.

## Acceptance Criteria
- [ ] `Phase::Planning` keeps drained amendments in memory and re-enqueues them with original fields (`id`, `body`, `priority`, `source`, `source_detail`, `created_at`) on any error after drain and before durable planner success state is committed.
- [ ] `QuickDevPhase::PlanAndImplement` applies the same behavior: on any post-drain/pre-transition failure, drained amendments are re-enqueued with original fields.
- [ ] Success-path invariant: if the phase reaches durable success, drained amendments are not re-enqueued (no duplicate replay).
- [ ] Failure-path invariant: if downstream work fails and rollback succeeds, all drained amendment IDs are present in queue again for retry.
- [ ] Partial-rollback invariant: if re-enqueue fails for any item, orchestration fails hard and error output includes both the original phase error and the IDs that were not restored; successfully restored items remain queued.
- [ ] Conformance coverage is added in `src/validate/` for both standard and quick-dev flows by forcing failures immediately after drain and asserting amendments are preserved.

## Files to Modify/Create

- `src/workflow/quick_dev_orchestrator.rs` - add rollback/re-enqueue handling for `PlanAndImplement`.
- `src/validate/tests_amendments.rs` - add regression conformance tests for drain-then-fail preservation in both orchestration paths.
