# Implementation Notes

## Decisions Made
- Placed the late guard at line 2797 in `orchestrator.rs`, the single canonical `ProjectStatus::Completed` return path that all completion flows converge through (including completer-approved, acceptance-QA-passed, final-review-approved, and force-complete paths). This avoids duplicating the guard in each individual completion setter.
- Used a distinct error message (`"completion blocked: N amendment(s) arrived in the queue during completing/final-review"`) to differentiate the late guard from the existing planning-phase guard (`"planner requested completion but N amendment(s) are still pending in the queue"`). This makes diagnostics clearer.
- The late-guard conformance test mock has the **completer** (not the planner) inject the amendment into the queue, so the planning-phase guard passes (queue is empty at that point) and only the late guard catches the late-arriving amendment.
- For `amend_cli_multiple_amendments_drain_in_order`, replaced membership-only `contains` assertions with a strict `assert_eq!` on the exact ID sequence, enforcing that drain returns amendments in lexicographic filename order (which preserves enqueue order due to timestamp-prefixed filenames).

## Spec Deviations
- None. All six acceptance criteria are addressed exactly as specified.

## Testing
- `cargo check` and `cargo test --test amend_cli --no-run` both pass cleanly.
- **Late guard** (`orchestrator.rs:2797`): `pending_amendment_count` is called immediately before the successful completion return. If count > 0, returns `RalphError::Orchestration`. The guard does not drain, rename, or delete queue files. If `pending_amendment_count` fails (I/O error), the `?` operator propagates the error, preventing a successful completion result.
- **Conformance test** (`tests_amendments.rs`): `late_guard_blocks_completion_after_completing_phase_amendment` injects an amendment during the completer call (after the planner's CompletionRequest), verifies exit code 1, checks the error message contains the late-guard text, and confirms pending count > 0 (queue unmodified).
- **Drain order test** (`amend_cli.rs`): `amend_cli_multiple_amendments_drain_in_order` now asserts `ids == ["EXT-MULTI-0", "EXT-MULTI-1", "EXT-MULTI-2"]` in exact sequence.
