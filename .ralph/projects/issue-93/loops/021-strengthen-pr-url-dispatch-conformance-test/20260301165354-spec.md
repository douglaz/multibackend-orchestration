# Feature: Strengthen PR URL Dispatch Conformance Test

## Description
The conformance test for requirement #11 (`pr_url_plumbed_through_child_args`) currently validates only CLI argument parsing via `clap::Parser` — it confirms `--pr-url` is accepted by `RunArgs` and `AutoArgs`. However, the requirement specifies: "`--pr-url` is plumbed through child args **and timing is correct**." The test does not cover the runtime dispatch path where:
1. PR URL is resolved by exact head-branch match (via `find_existing_pr` using `gh pr list --head {branch}`) when multiple PRs may exist.
2. The resolved PR URL is forwarded into the spawned child process arguments.
3. PR URL resolution happens **before** the child process is spawned (timing/order assertion).

This feature strengthens the existing conformance test to cover the full dispatch path using mock `gh` scripts that simulate multiple PRs and log-marker ordering assertions, matching the pattern already established by other runtime conformance tests (e.g., `draft_watcher_pushes_before_create`).
