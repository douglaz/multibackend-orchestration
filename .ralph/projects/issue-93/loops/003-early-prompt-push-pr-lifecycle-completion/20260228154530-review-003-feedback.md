# Review: SUGGESTIONS

## Required Changes

1. **Early Prompt Push — function missing**: `commit_and_push_initial_prompt()` does not exist in `src/git/commit.rs`.
   - Current: No such function exists anywhere in the codebase.
   - Expected: A public function `commit_and_push_initial_prompt(repo_root, project_id, branch)` that (a) resolves the HEAD branch and returns `RalphError::BranchMismatch` on mismatch, (b) stages only the three prompt-input files (`.ralph/projects/<id>/prompt.md`, `state.json`, `config.toml`), (c) returns `Ok(())` on empty staged diff, (d) commits and pushes on non-empty diff.
   - Reference: Spec acceptance criteria 1–5.

2. **Orchestrator call-site missing**: `orchestrator.rs` does not call `commit_and_push_initial_prompt` after branch checkout.
   - Current: After `checkout_branch` (line ~260) and `merge_base_branch` (line ~261), the orchestrator proceeds directly to the loop without committing prompt files.
   - Expected: Insert a call to `commit_and_push_initial_prompt` between branch checkout and the first loop iteration.
   - Reference: Spec acceptance criterion 6.

3. **PR lifecycle — draft→ready promotion missing**: `handle_pr_flow` in `src/daemon/runtime.rs` does not check `is_pr_draft()` or call `mark_pr_ready()`.
   - Current: When an existing PR is found (line ~2258), it edits the PR title/body but never inspects draft status or promotes it. The `is_pr_draft` and `mark_pr_ready` functions exist in `github.rs` (lines 615, 638) but are unused by `handle_pr_flow`.
   - Expected: When an existing PR is found and the task completed successfully, check `is_pr_draft()` and call `mark_pr_ready()` if true.
   - Reference: Spec acceptance criterion 7.

4. **PR lifecycle — no-diff draft closure missing**: `handle_pr_flow` detects no-diff (line ~2135) but does not close the PR or clear the stored URL.
   - Current: Posts a no-diff comment and returns early (lines ~2135–2148).
   - Expected: When a draft PR exists and has no diff against base, call `close_pr()` and clear the PR URL via `save_task_metadata`.
   - Reference: Spec acceptance criterion 8.

5. **`complete_task` retry logic missing**: `complete_task` in `src/daemon/runtime.rs` (lines ~1530–1593) has no retry loop.
   - Current: Each operation is attempted once; errors are logged and execution continues.
   - Expected: Max 3 total attempts, 30-second delay between attempts, retry only transient failures.
   - Reference: Spec acceptance criteria 9–10.

6. **Error classification missing**: `src/error.rs` has no `is_transient()` method on `RalphError`.
   - Current: Only `is_quota_error()` (line 143) and `exit_code()` (line 156) exist.
   - Expected: An `is_transient()` method classifying network/transport/rate-limit/subprocess errors as transient and validation/branch/config errors as terminal.
   - Reference: Spec acceptance criterion 11.

   - Current: File contains `.ralph/**/*.log`, `.ralph/quick-prd/`, and `/SPEC.md` but not `.ralph/task_metadata/`.
   - Expected: Add `.ralph/task_metadata/` to `.gitignore`.
   - Reference: Spec acceptance criterion 12.

8. **Git pollution prevention — unstage in `commit_and_push_phase_transition` missing**: The function at `src/git/commit.rs:139–174` runs `git add -A` (line 162) without unstaging generated artifacts.
