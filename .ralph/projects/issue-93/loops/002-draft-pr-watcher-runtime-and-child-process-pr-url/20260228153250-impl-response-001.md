# Implementation Response (Iteration 1)

## Changes Made

### 1. PR URL orchestrator integration (Required #1 & #3)

**Files**: `src/workflow/orchestrator.rs`, `src/project/state.rs`

Added `pr_url: Option<String>` field to `ProjectState` (with `#[serde(default)]` for backward compatibility) so the PR URL is durably persisted across orchestration phases. In `Orchestrator::run()`, the incoming `options.pr_url` is propagated into `state.pr_url` early in the method (after state reconstruction, before dry-run check), making it available to completion, final review, and PR update phases. The field is initialized to `None` in `ProjectState::new()`.

### 2. PR URL persistence across daemon restarts (Required #2)

**File**: `src/daemon/runtime.rs`

Introduced durable task metadata stored at `.ralph/daemon/tasks/{task_id}.json`:
- New public types: `TaskMetadata` struct, `load_task_metadata()`, `save_task_metadata()` functions
- `task_metadata_path()` helper returns the file path
- In `dispatch_task()`, persisted metadata is loaded first; if a PR URL exists on disk, it is used instead of re-querying GitHub via API. This ensures daemon restarts don't lose track of existing draft PRs
- In `draft_pr_watcher()`, the PR URL is persisted to disk immediately after successful PR creation (and after successful race-condition recovery)

### 3. Race condition handling on PR creation (Required #4)

**File**: `src/daemon/runtime.rs`

After a `create_pr` failure in `draft_pr_watcher()`, the watcher now re-queries `github::find_existing_pr()` to check if another process created the PR concurrently. If an existing PR is found, it is treated as success: `pr_created` is set to true and the PR URL is persisted to durable storage. This prevents the task from losing its PR URL reference when another daemon instance wins the creation race.

### 4. Observability logging for PR URL propagation (Recommended #1)

**File**: `src/daemon/runtime.rs`

Added diagnostic `eprintln!` logging at key PR URL decision points:
- When recovering a persisted PR URL from task metadata
- When resolving the final PR URL (whether from persistence, API, or None)
- When spawning child processes (both `ralph run` and `ralph auto` paths include the PR URL in the log line)

### 5. Fixed misleading RunOptions.pr_url comment (Recommended #2)

**File**: `src/workflow/orchestrator.rs`

Updated the doc comment on `RunOptions.pr_url` from "PR URL passed from the daemon's draft-PR watcher" to accurately describe that the URL is resolved before child spawn (from existing PR lookup or CLI `--pr-url`), and that `None` triggers the draft-PR watcher.

### 6. PR URL persistence conformance test (Recommended #3)

**File**: `src/validate/tests_pr_runtime.rs`

Added `pr_url_persisted_across_restarts` test that exercises the `save_task_metadata` / `load_task_metadata` round-trip:
- Verifies fresh load returns `None`
- Persists a PR URL, reloads, verifies recovery
- Overwrites with `None`, reloads, verifies clearing

### 7. ChildHandle.pr_url field (Recommended #4)

**File**: `src/daemon/mod.rs`, `src/daemon/runtime.rs`

Added `pub pr_url: Option<String>` to `ChildHandle`. The field is populated at spawn time from the resolved PR URL. In `auto_rebase_phase()`, the cached `pr_url` from the handle is used first, falling back to a GitHub API query only when the cached value is `None`. When the API returns a URL, it is back-filled into the handle for future cycles.
