# Implementation Notes

## Decisions Made
- Extended `src/daemon/github.rs` with foundational draft-PR lifecycle APIs:
  - `has_commits_ahead_of_base(worktree_path, base_branch) -> Result<bool>` using `git rev-list --count <base>..HEAD`.
  - `mark_pr_ready(owner, repo, pr_number) -> Result<()>` via `gh pr ready`.
  - `is_pr_draft(owner, repo, pr_number) -> Result<bool>` via `gh pr view --json isDraft`.
  - `close_pr(owner, repo, pr_number) -> Result<()>` via `gh pr close`.
- Added `draft: bool` support to both PR creation paths in `github.rs`:
  - `create_pr(...)`
  - `create_pr_with_body_file(...)`
  - Both now append `--draft` when `draft == true`.
- Updated the existing caller in `src/daemon/runtime.rs` (`handle_pr_flow`) to pass `draft: false`, preserving current behavior.
- Added a new typed error variant in `src/error.rs`:
  - `BranchMismatch { expected: String, actual: String }`
  - Includes a clear display message suitable for future branch-guard usage.
- Added unit tests:
  - `github.rs`: JSON parsing tests for `isDraft` true/false via `parse_pr_is_draft`.
  - `error.rs`: display/format test for `BranchMismatch`.
- Kept error propagation aligned with existing convention (`RalphError::Orchestration(...)`) for GitHub/git command failures and parsing failures.

## Spec Deviations
- None functionally.
- Minor note: the newly added `is_pr_draft` helper and parser are currently not called by runtime code yet (this is expected at this foundational step), so `cargo check` reports dead-code warnings. This does not affect correctness or test outcomes.
