# Review: SUGGESTIONS

## Required Changes

1. **Early Prompt Push — function missing**: `commit_and_push_initial_prompt()` does not exist in `src/git/commit.rs`.
   - Current: No such function exists anywhere in the codebase (confirmed via grep).
   - Expected: A function that stages only the three prompt-input files (`prompt.md`, `prompt-original.md`, `prompt-review.md`), enforces a branch guard via `RalphError::BranchMismatch`, skips commit on empty diff, and pushes on non-empty diff.
   - Reference: Spec AC #1–#5.

2. **Orchestrator call site missing**: `commit_and_push_initial_prompt` is never called from `src/workflow/orchestrator.rs`.
   - Current: After `checkout_branch` + `merge_base_branch` (line 260–261), the orchestrator proceeds directly to prompt review without pushing prompt files.
   - Expected: A call to `commit_and_push_initial_prompt` immediately after the checkout/merge block (line 261) and before the implementation loop.
   - Reference: Spec AC #6.

3. **`handle_pr_flow` lacks draft-status inspection**: The existing `handle_pr_flow` (runtime.rs:2104–2310) does not call `is_pr_draft`, `mark_pr_ready`, or `close_pr`.
   - Current: When an existing PR is found, it edits title/body only. When no existing PR is found, it creates one with `draft: false`. No draft→ready promotion or no-diff draft→close logic exists.
   - Expected: Check `is_pr_draft`; if draft and has diff, call `mark_pr_ready`; if draft and no diff, call `close_pr` and clear PR URL from task metadata.
   - Reference: Spec AC #7–#9.

4. **`complete_task` lacks retry logic**: `complete_task` (runtime.rs:1530–1593) runs its operations once with no retry.
   - Current: Single-pass execution; failures are logged as warnings and ignored.
   - Expected: Wrap core operations in a retry loop: max 3 total attempts, 30s delay, retry only transient errors.
   - Reference: Spec AC #10–#12.

5. **`is_transient()` error classifier missing**: `src/error.rs` has `is_quota_error()` but no `is_transient()` method or equivalent that classifies `RalphError` variants as transient (network/transport/rate-limit/subprocess) vs terminal (validation/branch/config).
   - Current: Only `is_quota_error()` exists, which is narrower than the needed transient classification.
   - Expected: An `is_transient()` method on `RalphError` (or free function) that matches the spec's retry semantics.
   - Reference: Spec AC #13.

6. **`.gitignore` missing `codex_output/` pattern**: `.gitignore` includes `/SPEC.md` but does not include `codex_output/` or other backend side-effect patterns.
   - Current: Only `/SPEC.md`, `.ralph/**/*.log`, `.ralph/quick-prd/` are present.
   - Expected: Add `codex_output/` and any other generated-artifact patterns.
   - Reference: Spec AC #14.

7. **`commit_and_push_phase_transition` lacks generated-artifact unstaging**: The function (commit.rs:139–174) does `git add -A` but does not unstage generated artifacts via `git rm --cached --ignore-unmatch`.
   - Current: `commit_feature_loop` unstages `.ralph/`, but `commit_and_push_phase_transition` does not unstage any generated artifacts (`codex_output/`, `SPEC.md`, etc.).
   - Expected: After `git add -A`, call `git rm --cached --ignore-unmatch` for each generated-artifact pattern before `git commit`.
   - Reference: Spec AC #15–#16.

8. **7 conformance tests missing**: `tests_pr_runtime.rs` has 6 tests from Loop 2 but none of the 7 required for Loop 3:
   - Current tests: `draft_watcher_creates_draft_when_branch_ahead`, `draft_watcher_pushes_before_create`, `draft_watcher_exits_cleanly_on_cancellation`, `pr_url_plumbed_through_child_args`, `e2e_draft_create_via_binary`, `pr_url_persisted_across_restarts`.
   - Missing tests: early prompt push stages only prompt files, early prompt push fails on branch mismatch, `create_pr` honors `draft: true`, draft PR marked ready in transition path, no-diff draft PR closed, `complete_task` retries transient failures (max 3), `complete_task` does not retry terminal errors.
   - Reference: Spec AC #17–#23.

## Recommended Improvements

1. The `handle_pr_flow` currently creates PRs with `draft: false` (line 2293). Since the draft PR watcher already creates draft PRs during execution, the completion-time `handle_pr_flow` should likely detect the existing draft and promote it rather than creating a new non-draft PR.
