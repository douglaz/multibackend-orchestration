# Implementation Response (Iteration 1)

## Changes Made
1. **Fixed draft PR lifecycle E2E timing to make watcher deterministic** (Required Change #1)
   - **Root cause:** The `e2e_draft_create_via_binary` test had a race condition where the mock child process exited after only 1 second (`sleep 1`), but the `draft_pr_watcher` uses a default 15-second poll interval. The watcher's first poll might miss the commit (child hasn't committed yet), and by the time it would poll again (15s later), the child has already exited and the watcher is cancelled in `collect_children`. This meant no draft PR was ever created, so `handle_pr_flow` fell through to the non-draft `create_pr` path.
   - **Fix in `src/validate/tests_pr_runtime.rs`:**
     - Added `("RALPH_DRAFT_PR_WATCH_POLL_SECS", "1")` to the E2E test's daemon env vars, reducing the watcher poll interval from 15s to 1s
     - Increased the mock ralph child script's `sleep` from 1s to 10s, providing ample time for the watcher to detect the commit, push, and create the draft PR before the child exits
   - The watcher now reliably creates the draft PR before the child exits, so `handle_pr_flow` finds the existing draft PR, confirms it's draft, and calls `mark_pr_ready` — producing the expected `create → ready` sequence
