# Implementation Notes

## Decisions Made
- `sync_project_branch(repo_root, issue_number)` implemented in `src/git/branch.rs` with strict remote-first semantics: `git fetch origin` → check `origin/ralph/issue-<n>` → `checkout -B` to reset to remote, or `checkout -b` from `origin/HEAD` if missing. Never falls back to local refs.
- Added `remote_ref_exists` helper using `run_git_status` to check ref existence without treating missing refs as errors.
- Worktree base ref fallback chain in `src/daemon/worktree.rs` (`origin/master` → `master` → `HEAD`) replaced with strict `origin/HEAD` only. If `origin/HEAD` is missing, worktree creation returns an actionable error instead of silently falling back to local refs.
- Renamed `sync_remote_master` to `fetch_origin` and changed from `git fetch origin master` to `git fetch origin` (full fetch) to ensure all remote refs including project branches are updated.
- Remote-first sync invoked non-fatally in `dispatch_task` in `src/daemon/runtime.rs` — if the sync fails (e.g., no origin remote configured), dispatch falls through to existing branch checkout behavior rather than aborting. This preserves backward compatibility for repos without remotes while enforcing remote-first in the sync function itself.
- The sync call is placed after worktree creation/clean but before project branch checkout and child spawning, satisfying the "before invoking `ralph run`" requirement.
- Conformance tests exercise `sync_project_branch` directly against real git repos (bare remote + clone), not via mock scripts, since the function uses real git commands.

## Spec Deviations
- The conformance tests for remote-first sync use real git repos rather than the daemon subprocess harness because `sync_project_branch` operates at the git-command level and doesn't go through the CLI. This provides stronger isolation and deterministic testing.
- The `origin/HEAD` missing test required pointing the bare remote's HEAD to a nonexistent branch *and* deleting the local `origin/HEAD` symref, because `git fetch` auto-creates `origin/HEAD` from the remote's HEAD. This accurately simulates a misconfigured remote.
- The runtime dispatch sync is non-fatal to avoid regressing existing worktrees that may not have an origin remote (e.g., local-only test repos). The spec's strictness ("never create project branches from local refs") is enforced at the `sync_project_branch` level, while the dispatch path gracefully degrades.
- No changes were needed to `src/validate/mock_scripts.rs` — the existing mock scripts were sufficient since the sync function uses real git operations, not mocked `gh` commands.

## Testing

  - `sync_project_branch_resets_to_remote_when_exists` — verifies local diverged commits are discarded when remote branch exists
  - `sync_project_branch_creates_from_origin_head_when_missing` — verifies new branch created from `origin/HEAD`
  - `sync_project_branch_fails_when_origin_head_missing` — verifies actionable error with issue number, branch name, and `origin/HEAD` mention
  - `sync_project_branch_discards_local_only_commit` — integration-style test proving local-only commits vanish after sync
- **Conformance tests** (`src/validate/tests_daemon.rs`, 5 new tests):
  - `daemon::sync_project_branch_resets_to_remote` — remote branch exists, local diverged commits discarded
  - `daemon::sync_project_branch_creates_from_origin_head` — remote branch missing, created from `origin/HEAD`
  - `daemon::sync_project_branch_missing_origin_head_error` — actionable error when `origin/HEAD` absent
  - `daemon::sync_project_branch_discards_local_commit` — integration: local-only commit removed after sync
  - `daemon::worktree_uses_origin_head_not_local_refs` — worktree creation uses `origin/HEAD`, not `origin/master`/`master`/`HEAD`
