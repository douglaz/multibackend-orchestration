# Feature: Final Contract Alignment for Checkpoint Defaults and Temporary Log Routing

## Description
Loops 1-6 already implemented the core redesign (structured checkpoint commits, remote-first branch sync, commit+push transitions, in-memory daemon state, lock enforcement, and state-free test migration). The remaining gaps are the completion-blocking mismatches: logs still written under project loop paths, no-checkpoint position still collapsed to loop `0` in reconstruction/status flows, and `parse_last_ralph_commit` validating older malformed commits instead of only the newest matching checkpoint. This feature closes those gaps.

## Acceptance Criteria
- [ ] `src/output_log.rs` routes all agent logs to `.ralph/tmp/logs` only (no `.ralph/projects/**` log writes).
- [ ] Log filenames are deterministic and collision-safe across project/loop/role combinations.
- [ ] Existing append/retry semantics of `LogWriter` are preserved (attempt separators, timeout footer, non-fatal write failures).
- [ ] `reconstruct_project_state(...)` uses checkpoint-derived position for `current_loop/current_phase` when git context exists, without artifact-based fallback for position.
- [ ] No-checkpoint default is consistently `loop=1`, `phase=planning`.
- [ ] `status` output no longer remaps loop `1` to loop `0`.
- [ ] `parse_last_ralph_commit(...)` validates only the newest matching remote Ralph checkpoint commit.
- [ ] If the newest matching checkpoint is malformed, parsing fails with actionable error including commit context.
- [ ] Older malformed Ralph commits do not fail derivation when a newer valid checkpoint exists.
- [ ] Unit tests cover no-checkpoint default, malformed-newest failure, and "newest valid + older malformed" success.
- [ ] Validate conformance tests assert tmp-log routing and no-checkpoint status/history defaults.
