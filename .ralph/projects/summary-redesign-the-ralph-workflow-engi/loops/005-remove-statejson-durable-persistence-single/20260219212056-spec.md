# Feature: Remove state.json Durable Persistence, Single Daemon Lock, and Git+Label CLI Derivation

## Description
This is the final integration loop. Three related gaps remain after Loops 1–4:

1. **state.json removal** — The orchestrator still calls `persist_state()` writing `state.json`, and `src/project/lifecycle.rs` still provides `load_project_state` / `save_project_state` file-based I/O. All durable reads/writes of `state.json` must be removed. In-memory `ProjectState` must be reconstructed on startup from `derive_position()` (git commit trailers on the remote branch) and loop artifact files on disk — never from a JSON state file.

2. **CLI status/history derivation** — `src/cli/status.rs` and `src/cli/history.rs` currently call `load_project_state()` (reading `state.json`). Both must be rewritten to derive workflow position from `derive_position()` (git commits on the remote project branch) and task lifecycle from GitHub labels. `src/cli/tail.rs` also reads `state.json` and needs the same treatment.

3. **Single daemon lock** — The spec requires a per-repo daemon lock at `/tmp/ralph-daemon-<sha256(canonical_repo_root)>.lock` using non-blocking `flock`. A second daemon instance for the same repo must exit immediately with a clear non-zero error. This is not yet implemented; the existing `ProjectLock` in `src/util/lock.rs` is per-project, not per-daemon.

4. **Conformance tests** — Validate tests for daemon lock contention, CLI `status`/`history` reading from git+labels, and crash-after-local-commit-before-push recovery.

## Acceptance Criteria
- [ ] No `state.json` or `tasks.json` read or write paths remain anywhere in the codebase (acceptance criterion #6 from master spec).
- [ ] `persist_state()` calls removed from `src/workflow/orchestrator.rs`; orchestrator uses `derive_position()` for workflow position on startup/resume.
- [ ] `load_project_state()` and `save_project_state()` file-based I/O removed from `src/project/lifecycle.rs`; in-memory `ProjectState` is reconstructed from git history and loop artifact metadata.
- [ ] `src/cli/status.rs` derives project state from `derive_position()` (git commit trailers on remote branch) and GitHub labels — not from `state.json`.
- [ ] `src/cli/history.rs` derives loop/phase history from commit trailers on the remote branch — not from `state.json`.
- [ ] `src/cli/tail.rs` state reads replaced with git+label derivation or removed where applicable.
- [ ] Other consumers (`src/cli/project.rs`, `src/cli/rollback.rs`, `src/cli/run.rs`, `src/mcp/handlers.rs`, `src/mcp/tail_events.rs`) updated to remove `load_project_state` / `save_project_state` calls.
- [ ] Single daemon lock acquired at `/tmp/ralph-daemon-<sha256(canonical_repo_root)>.lock` using non-blocking `flock` before `runtime::run()` in `execute_start()`.
- [ ] If daemon lock is unavailable, process exits immediately with non-zero status and clear error message.
- [ ] Lock is held for daemon lifetime and released on exit (file descriptor close).
- [ ] Validate conformance test: second daemon instance for same repo exits immediately with lock-contention error.
- [ ] Validate conformance test: `ralph status` output matches git+label derived state (not `state.json`).
- [ ] Validate conformance test: `ralph history` output matches commit-trailer derived history.
- [ ] Validate conformance test: crash after local commit but before push does not advance recovered state (remote-first checkout discards local-only commit on restart).
- [ ] Fresh clone restart resumes from last pushed checkpoint commit and current labels (master spec acceptance criterion #1).
