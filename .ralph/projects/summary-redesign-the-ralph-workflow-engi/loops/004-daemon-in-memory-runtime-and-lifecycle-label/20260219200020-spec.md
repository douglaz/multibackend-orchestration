# Feature: Daemon In-Memory Runtime and Lifecycle Label Reconciliation

## Description
Loops 1-3 are complete (`ralph_commit` parser/builder, remote-first branch sync, phase transition commit+push). The largest remaining gap is daemon durability: runtime still persists `tasks.json`/`TaskStore` and does not enforce lifecycle-label normalization/reconciliation semantics from the master spec.  
Implement a label-driven daemon runtime that keeps task state only in memory (`children: HashMap<u32, ChildHandle>`) and treats GitHub lifecycle labels as the only durable task lifecycle source of truth.

## Acceptance Criteria
- [ ] Remove durable daemon task persistence: no runtime reads/writes of `.ralph/**/tasks.json` remain in daemon execution paths.
- [ ] Replace `TaskStore`-driven orchestration with in-memory `children: HashMap<u32, ChildHandle>` keyed by `issue_number`.
- [ ] `ChildHandle` includes `pid`, `pgid`, `tokio::process::Child`, `branch`, and `log_file`.
- [ ] Startup reconciliation resets all open issues labeled `ralph:in-progress` back to `ralph:ready` before polling/dispatch.
- [ ] Lifecycle transitions are enforced via labels only: claim `ready -> in-progress`, success `in-progress -> completed`, failure `in-progress -> failed`.
- [ ] Multi-lifecycle-label issues are normalized to only `ralph:failed` and skipped for that poll cycle.
- [ ] Label mutations use retry-on-conflict and retry-on-transient-failure behavior with bounded attempts and actionable errors.
- [ ] Runtime fetches issue metadata from GitHub on demand; no persisted daemon metadata fields are used as durable truth.
- [ ] `daemon` CLI paths that currently depend on `TaskStore` (`status`/`abort`/`retrigger`) are updated to label-driven behavior and no longer require `tasks.json`.
- [ ] Validate conformance coverage is added/updated for startup reconciliation, multi-label normalization, retry behavior, and "no durable tasks.json writes".

## Files to Modify/Create
- `src/daemon/mod.rs` - remove `TaskStore`/`DaemonTask` durable persistence model and task-file helpers.
- `src/daemon/runtime.rs` - refactor runtime loop to in-memory child tracking and label-driven lifecycle transitions.
- `src/daemon/github.rs` - add lifecycle-label classification/normalization and robust label swap APIs with retry policy.
- `src/cli/daemon.rs` - remove task-store scanning and migrate daemon subcommands to label-derived state.
- `src/validate/tests_daemon.rs` - replace persistence-oriented assertions with label-truth reconciliation assertions.
- `src/validate/mock_scripts.rs` - add mock `gh` behaviors for conflicts/transient failures and normalization scenarios.
- `src/validate/harness.rs` - adjust helper APIs that currently assume `tasks.json` exists.

## Dependencies
- Requires: Loop 1 (Ralph Structured Commit Parser and Builder), Loop 2 (Remote-First Project Branch Sync), Loop 3 (Phase Transition Commit-and-Push Checkpointing)
- Blocks: Single-daemon lock enforcement, `.ralph/tmp` startup cleanup/log routing, final `state.json` read/write removal, and end-to-end completion criteria for label-only lifecycle truth
