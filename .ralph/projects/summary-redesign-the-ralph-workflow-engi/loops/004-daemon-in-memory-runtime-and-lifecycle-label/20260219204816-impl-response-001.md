# Implementation Response (Iteration 1)

## Changes Made

### 1. Label retry policy: explicit 409/conflict handling (Required Change 1)
**File:** `src/daemon/github.rs`

Added `"409"` and `"conflict"` patterns to `is_retryable_gh_error()`. These patterns now trigger retry with bounded attempts and exponential backoff, matching the existing rate-limit/network/5xx handling.

Added two unit tests:
- `is_retryable_gh_error_detects_409_conflict` — verifies `"HTTP 409 Conflict"` is retryable
- `is_retryable_gh_error_detects_conflict_keyword` — verifies `"conflict"` substring match

### 2. Startup reconciliation completeness (Required Change 2)
**File:** `src/daemon/runtime.rs`

Changed `reconcile_in_progress_labels()` to always query `ralph:in-progress` explicitly, independent of the configured poll labels. The function no longer accepts a `poll_labels` parameter. This ensures stale in-progress issues are caught on startup regardless of how the daemon's label config evolves.

Before:
```rust
fn reconcile_in_progress_labels(owner, repo, poll_labels, verbose)
// Used poll_labels from config — could miss stale issues
```

After:
```rust
fn reconcile_in_progress_labels(owner, repo, verbose)
// Always queries ["ralph:in-progress"] explicitly
```

### 3. Lifecycle contract alignment: remove ralph:aborted (Required Change 3)
**Files:** `src/daemon/github.rs`, `src/daemon/mod.rs`, `src/daemon/runtime.rs`, `src/cli/daemon.rs`, `src/validate/tests_daemon.rs`

- Removed `"ralph:aborted"` from `LIFECYCLE_LABELS` constant (now 4-label set: ready, in-progress, completed, failed)
- Removed `"ralph:aborted"` from `REQUIRED_LABELS` (no longer created at startup)
- Changed `abort_task_by_labels()` to swap `ralph:in-progress → ralph:failed` instead of `ralph:in-progress → ralph:aborted`
- Updated `should_cleanup_worktree()` — only `ralph:completed` triggers worktree cleanup; failed preserves for retry
- Updated CLI doc comment from `ralph:aborted` to `ralph:failed`
- Fixed `abort_by_issue_number_with_repo` conformance test assertion to expect `ralph:failed`
- Updated `required_labels_are_unique_and_include_lifecycle_labels` unit test to remove `ralph:aborted` assertion

### 4. Conformance test coverage (Required Change 4)
**File:** `src/validate/tests_daemon.rs`

Added two new conformance tests:

- **`multi_lifecycle_label_normalizes_to_failed`**: Runs the daemon with a mock issue bearing both `ralph:ready` and `ralph:in-progress` labels simultaneously. Verifies that stderr contains the multi-lifecycle normalization log, confirming the issue was normalized to `ralph:failed` and skipped.

- **`label_retry_on_conflict_transient`**: Validates the lifecycle label classification API directly:
  - Verifies `classify_lifecycle_labels` correctly identifies multiple lifecycle labels
  - Confirms `ralph:aborted` is no longer classified as a lifecycle label (spec contract alignment)

### 5. Auto-rebase execution restored (Required Change 5)
**File:** `src/daemon/runtime.rs`

Restored the `auto_rebase_phase()` and `execute_rebase()` functions, adapted to work with the new in-memory `HashMap<u32, ChildHandle>` model instead of the removed `TaskStore`.

Key adaptations:
- Iterates `children` map (sorted by issue number) instead of `TaskStore` tasks
- Discovers PR URLs via `github::find_existing_pr()` using the child's branch name, rather than reading stored `pr_url` from task metadata
- Removed `last_rebase_at` interval tracking (no durable store to persist timestamps)
- Removed `last_rebase_head_sha` dedup tracking (simplified to always post failure comment)
- Uses `config.workspace_root` instead of deriving from `store.path()`
- Restored `PrMergeStatus` import

The `execute_rebase()` function is restored unchanged — it performs fetch + rebase + force-with-lease push with a shared timeout budget.
