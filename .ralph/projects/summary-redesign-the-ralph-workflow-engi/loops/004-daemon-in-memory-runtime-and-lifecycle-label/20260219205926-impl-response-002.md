### Required Change 1: Daemon status label query semantics

**File**: `src/cli/daemon.rs` (lines 260–280)

**Problem**: `execute_status()` called `poll_issues` with both `ralph:ready` and `ralph:in-progress` in a single query. Because `gh issue list --label` uses AND semantics (repeated `--label` flags require ALL labels to match), this only returned issues having *both* labels simultaneously — never normal single-label issues.

**Fix**: Replaced the single multi-label query with a loop that issues one `poll_issues` call per lifecycle label (`ralph:ready`, `ralph:in-progress`). Results are de-duplicated via `HashSet<u32>` on issue number. Each query uses OR-per-call semantics (separate calls) to correctly return issues with either label.

```rust
let mut issues: Vec<github::GhIssue> = Vec::new();
let mut seen: std::collections::HashSet<u32> = std::collections::HashSet::new();
for label in &["ralph:ready", "ralph:in-progress"] {
    let query_labels = vec![label.to_string()];
    match github::poll_issues(&owner, &repo_name, &query_labels) {
        Ok((batch, _overflow)) => {
            for issue in batch {
                if seen.insert(issue.number) {
                    issues.push(issue);
                }
            }
        }
        Err(err) => {
            eprintln!("warning: failed to query {label} issues for {slug}: {err}");
        }
    }
}
```
