# Review: SUGGESTIONS

## Required Changes
1. **Daemon status label query semantics are incorrect**
   - Current: `src/cli/daemon.rs:261` calls `poll_issues` with both `ralph:ready` and `ralph:in-progress`, while `poll_issues` explicitly uses repeated `--label` with AND semantics (`src/daemon/github.rs:85`). This only returns issues that have both labels, not normal ready/in-progress issues.
   - Expected: Query lifecycle states in a way that reflects label-truth status (for example, separate queries per lifecycle label or an unfiltered query with local lifecycle classification).
   - Reference: Feature spec acceptance criterion: daemon `status` is label-driven and should not depend on `tasks.json`.

2. **Validate conformance suite is still tied to removed `tasks.json` behavior**
   - Current: Registered conformance tests still seed/assert `.ralph/daemon/tasks.json` (`src/validate/tests_daemon.rs:1183`, `src/validate/tests_daemon.rs:1577`, `src/validate/tests_daemon.rs:1641`) and helpers still read/write it (`src/validate/tests_daemon.rs:2537`, `src/validate/tests_daemon.rs:2551`).
   - Expected: Registered daemon validate tests should be rewritten to assert label-driven/in-memory behavior (GitHub labels + child lifecycle), not TaskStore file transitions.
   - Reference: Feature spec acceptance criteria: remove durable daemon task persistence and update validate coverage for the new runtime model.

3. **Retry conformance coverage does not test retry behavior**
   - Current: `label_retry_on_conflict_transient` (`src/validate/tests_daemon.rs:3123`) only checks `classify_lifecycle_labels`; it does not exercise `add_label_with_retry` / `remove_label_with_retry` / `swap_lifecycle_label` retry paths.
   - Expected: Add a validate test that simulates retryable failures (409/conflict/transient), verifies bounded retry attempts, and confirms success/failure behavior and error surfacing.
   - Reference: Feature spec acceptance criteria: retry-on-conflict and retry-on-transient-failure, plus validate coverage explicitly including retry behavior.
