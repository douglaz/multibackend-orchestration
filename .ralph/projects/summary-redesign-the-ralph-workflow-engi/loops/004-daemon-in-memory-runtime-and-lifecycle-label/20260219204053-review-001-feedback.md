# Review: SUGGESTIONS

## Required Changes
1. **Label retry policy**: conflict retries are not fully implemented.
   - Current: `src/daemon/github.rs` retries on rate-limit/network/5xx patterns, but does not clearly treat conflict errors (for example `409`/`conflict`) as retryable.
   - Expected: implement explicit retry-on-conflict handling with bounded attempts and actionable terminal errors.
   - Reference: Feature spec acceptance criterion: retry-on-conflict and retry-on-transient-failure.

2. **Startup reconciliation completeness**: stale `in-progress` issues can be missed.
   - Current: `reconcile_in_progress_labels` in `src/daemon/runtime.rs` uses configured poll labels; if config omits `ralph:in-progress`, orphaned in-progress issues are not reset.
   - Expected: startup reconciliation must always query/reset all `ralph:in-progress` issues before normal polling.
   - Reference: Feature spec acceptance criterion: startup resets all `ralph:in-progress` to `ralph:ready`.

3. **Lifecycle contract mismatch**: an extra lifecycle label is introduced.
   - Current: `src/daemon/github.rs` includes `ralph:aborted` in `LIFECYCLE_LABELS`, and abort flow swaps to it.
   - Expected: conform to the declared lifecycle set (`ready`, `in-progress`, `completed`, `failed`) or update the spec/contract explicitly.
   - Reference: Master prompt lifecycle-label definitions and transition rules.

4. **Validate coverage gaps**: required conformance tests are incomplete.
   - Current: `src/validate/tests_daemon.rs` adds coverage for startup reset and no `tasks.json`, but not for multi-label normalization and retry behavior.
   - Expected: add validate tests for multi-lifecycle normalization (`>1 -> failed + skip`) and retry-on-conflict/transient label mutation behavior.
   - Reference: Feature spec acceptance criterion for validate coverage additions.

5. **Scope regression**: unrelated runtime behavior was removed.
   - Current: `src/daemon/runtime.rs` removes auto-rebase execution entirely.
   - Expected: preserve existing non-target behavior unless explicitly removed by the spec.
   - Reference: Loop scope is daemon durability/lifecycle truth; auto-rebase removal is outside stated acceptance scope.

## Recommended Improvements
1. Add targeted unit tests in `src/daemon/github.rs` for retry classification (`409 conflict`, transient network, rate-limit variants) to lock behavior.
