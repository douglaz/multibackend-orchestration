# Implementation Response: Review Iteration 2

## Required Change 1: Resolve validate conformance regressions

### Root Cause
After restoring strict `issue-<number>` project-id validation in the checkpoint
commit parser, all conformance tests that used arbitrary project IDs (e.g.
`run-single`, `qa-disabled`, `session-lifecycle`, `pr-stable-model`) failed
because checkpoint commits with non-compliant IDs were rejected during state
reconstruction via `reconstruct_project_state`.

### Fix Applied
Updated **66 project IDs** across **9 test files** to use `issue-<number>`
format with non-overlapping numeric ranges per module:

| File | ID Range |
|---|---|
| tests_tail.rs | issue-101 – issue-103 |
| tests_run.rs | issue-201 – issue-219 |
| tests_qa.rs | issue-301 – issue-313 |
| tests_sessions.rs | issue-401 – issue-406 |
| tests_commands.rs | issue-501 – issue-506 |
| tests_streaming.rs | issue-601 – issue-609 |
| tests_prompt_review.rs | issue-701 – issue-708 |
| tests_e2e_conformance.rs | issue-801 – issue-803 |
| tests_daemon.rs | (unchanged, already used issue-N) |

Additional fixes discovered during validation:

- **`run::completion_artifacts_committed`**: Updated assertion to check for
  `"completing"` (checkpoint format) instead of `"completion"` (old tag format).
- **`prompt_review::stable_mock_with_modeled_backend`**: Changed project ID from
  `pr-stable-model` to `issue-708`.
- **`commands::rollback_hard`**: The `--hard` rollback code used tag-based ref
  resolution which no longer works since tags are not created. Added
  `find_checkpoint_commit()` in `src/cli/rollback.rs` to look up ralph
  checkpoint commit hashes on the remote project branch when tags are absent.
- **`e2e_conformance::pr_metadata_verification`**: Mock `gh pr list` returned
  `[]` which the daemon's jq query (`.[0].url`) treated as a non-empty PR URL,
  routing to the `edit existing PR` path instead of `create new PR`. Fixed by
  returning empty string for `pr list` in the mock.

## Required Change 2: Restore issue-<number> project-id validation

Already applied in the previous iteration's impl-response-001. The
`is_valid_project_id` function in `src/git/ralph_commit.rs` enforces
`issue-<number>` format by stripping the `"issue-"` prefix and validating
remaining characters are ASCII digits.

## Recommended Improvement: Checkpoint reconstruction conformance test

Added `daemon::reconstruct_position_from_real_remote_checkpoint` conformance
test in `src/validate/tests_daemon.rs`. This test:

1. Creates a real bare remote + clone via `setup_remote_clone()`.
2. Creates `ralph/issue-55` branch and pushes it.
3. Calls `commit_and_push_phase_transition()` for loop 1 (planning →
   implementing) and verifies `derive_position()` returns `(1, Implementing)`.
4. Calls `commit_and_push_phase_transition()` for loop 2 (implementing →
   reviewing) and verifies `derive_position()` returns `(2, Reviewing)`.

This locks in the git-derived position reconstruction path end-to-end using
real remote commits (not `update-ref` shortcuts).
