# Feature: Phase Transition Commit-and-Push Checkpointing

## Description
Replace the orchestrator's durable `state.json` phase-persistence with a `commit_and_push_phase_transition` function that stages all artifacts, commits with the structured Ralph commit format (from Loop 1), and pushes to `origin/<project_branch>`. The in-memory phase only advances after a successful push. This eliminates `save_project_state()` calls at phase boundaries and ensures crash-after-commit-before-push leaves no remote state change (startup sync from Loop 2 will discard the local-only commit). Tag-based loop checkpointing is also removed.

## Acceptance Criteria
- [ ] New function `commit_and_push_phase_transition(repo_root, project_id, loop_number, from_phase, to_phase)` in `src/git/commit.rs` that: (a) runs `git add -A`, (b) builds a structured commit message via `build_ralph_commit_message`, (c) commits, (d) pushes to `origin <project_branch>`, and (e) returns `Ok(())` only after successful push.
- [ ] Orchestrator phase-boundary logic in `src/workflow/orchestrator.rs` calls `commit_and_push_phase_transition` instead of `save_project_state()` for each phase transition (planning→implementing, implementing→qa, qa→reviewing, reviewing→committing, committing→completing, and loop restart transitions).
- [ ] In-memory `ProjectState` phase field is updated only after `commit_and_push_phase_transition` returns `Ok`; on push failure, the phase is not advanced and the error is propagated.
- [ ] Remove loop-tag checkpointing logic (any `git tag` calls used for loop transition markers) from `src/git/commit.rs` and `src/workflow/orchestrator.rs`.
- [ ] `commit_feature_loop` in `src/git/commit.rs` is refactored or replaced so the orchestrator's commit phase uses the structured format rather than freeform messages.
- [ ] Unit tests: round-trip test that `commit_and_push_phase_transition` creates exactly one commit on the remote with correct subject and trailers; verify push failure leaves local commit but no remote advance.
- [ ] Integration test: simulate crash-after-commit-before-push by committing without pushing, then running `sync_project_branch` (Loop 2) to confirm the local-only commit is discarded and position reverts to the last pushed checkpoint.
