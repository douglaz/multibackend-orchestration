# Feature: Ralph Structured Commit Parser and Builder

## Description
Create `src/git/ralph_commit.rs` — a new module that provides structured commit message building and parsing for Ralph checkpoint commits. This is the foundational data layer that all other features in the specification depend on. It defines the canonical commit format with subject line `ralph(issue-<number>): loop <N> <from_phase> -> <to_phase>` and required trailers (`Ralph-Project`, `Ralph-Loop`, `Ralph-Phase`), and provides functions to build these commit messages, parse them from raw git log output, and validate consistency between subject and trailers. Register the module in `src/git/mod.rs`.

## Acceptance Criteria
- [ ] New file `src/git/ralph_commit.rs` exists and is registered as `pub mod ralph_commit` in `src/git/mod.rs`
- [ ] `RalphCommitInfo` struct defined with fields: `project_id: String` (e.g. `issue-42`), `loop_number: u32`, `phase: Phase`, `from_phase: Phase`, `commit_hash: Option<String>`
- [ ] `build_ralph_commit_message(project_id, loop_number, from_phase, to_phase) -> String` produces correctly formatted subject + blank line + trailers matching the spec format: subject `ralph(issue-<N>): loop <loop> <from> -> <to>`, trailers `Ralph-Project: issue-<N>`, `Ralph-Loop: <u32>`, `Ralph-Phase: <to_phase>`
- [ ] `parse_ralph_commit(raw_subject: &str, raw_body: &str, commit_hash: Option<&str>) -> Result<RalphCommitInfo>` parses a single commit's subject+body into `RalphCommitInfo`, returning a descriptive error on malformed input
- [ ] `parse_last_ralph_commit(repo_root: &Path, branch: &str) -> Result<Option<RalphCommitInfo>>` walks `origin/<branch>` log to find the newest matching Ralph checkpoint commit. Returns `Ok(None)` when no matching commit exists. Returns an error when the newest Ralph-patterned commit is malformed (subject/trailer mismatch, missing trailers, etc.)
- [ ] `derive_position(repo_root: &Path, branch: &str) -> Result<(u32, Phase)>` calls `parse_last_ralph_commit` and returns `(loop_number, phase)` or defaults to `(1, Phase::Planning)` when no commit is found. Propagates malformed-commit errors
- [ ] Parser rejects commits where subject project-id disagrees with `Ralph-Project` trailer
- [ ] Parser rejects commits where subject loop number disagrees with `Ralph-Loop` trailer
- [ ] Parser rejects commits with missing required trailers (`Ralph-Project`, `Ralph-Loop`, `Ralph-Phase`)
- [ ] Phase serialization in commit messages uses lowercase snake_case matching the existing `Phase` serde representation (e.g. `planning`, `implementing`, `qa`, `reviewing`, `committing`, `completing`)
- [ ] Unit tests cover: build/parse round-trip, rejection of malformed subject, rejection of missing trailers, rejection of subject/trailer disagreement, `derive_position` default when no commits exist
- [ ] The module compiles and all tests pass (`cargo test`)
