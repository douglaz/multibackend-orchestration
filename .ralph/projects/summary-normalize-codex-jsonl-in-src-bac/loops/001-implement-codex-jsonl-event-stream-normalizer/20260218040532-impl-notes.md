# Implementation Notes

## Decisions Made

- Added new module `src/backend/output_normalizer.rs` with:
  - `NormalizedOutput` struct with exact required fields (`text`, `session_id`, `tokens_in`, `tokens_out`, `cached_in`).
  - `normalize_output()` backend dispatcher: `codex` routes to JSONL normalizer, `claude` passthrough, unknown backend returns `Err`.
  - `normalize_codex_jsonl()` line-by-line JSONL parsing that skips malformed lines without panicking.
- Implemented explicit type-scoped event parsing:
  - `thread.started` only for `session_id` (`src/backend/output_normalizer.rs:78`).
  - `item.completed` + `item.type == "agent_message"` only for assistant text (`src/backend/output_normalizer.rs:83`).
  - `turn.completed` only for usage fields (`src/backend/output_normalizer.rs:93`), with `cached_input_tokens` falling back to `cache_read_input_tokens`.
- Implemented legacy flat fallback only when `type` field is absent (`src/backend/output_normalizer.rs:112`), with precedence `event_text` over `flat_text` (`src/backend/output_normalizer.rs:147`).
- Non-JSON lines are skipped silently; if no JSON objects are seen at all, raw output is returned as-is.
- Registered module in `src/backend/mod.rs:4` (`pub mod output_normalizer;`).
