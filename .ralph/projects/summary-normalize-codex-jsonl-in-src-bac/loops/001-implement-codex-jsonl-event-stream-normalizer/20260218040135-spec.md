# Feature: Implement Codex JSONL event-stream normalizer with explicit scoping and precedence

## Description
Create the `src/backend/output_normalizer.rs` module that parses Codex `exec --json` JSONL event streams into a structured `NormalizedOutput`. The function `normalize_codex_jsonl` must correctly extract assistant text from `item.completed` events with `agent_message` items, session IDs from `thread.started` events, and usage from `turn.completed` events — all scoped to their exact `type` field. A flat-format fallback is preserved for legacy JSON objects that lack a `type` field. Event-based text always takes precedence over flat-format text. A top-level `normalize_output` dispatcher routes by backend name. The module is registered in `src/backend/mod.rs`.

## Acceptance Criteria
- [ ] New file `src/backend/output_normalizer.rs` exists with `NormalizedOutput` struct (fields: `text: String`, `session_id: Option<String>`, `tokens_in: Option<u64>`, `tokens_out: Option<u64>`, `cached_in: Option<u64>`) and public functions `normalize_output` and `normalize_codex_jsonl`.
- [ ] `normalize_codex_jsonl` parses JSONL line-by-line, silently skipping malformed lines (no panic).
- [ ] `session_id` is extracted only from `{"type":"thread.started","thread_id":"..."}`.
- [ ] Assistant text is extracted only from `{"type":"item.completed","item":{"type":"agent_message","text":"..."}}`.
- [ ] When multiple `agent_message` events exist, the last one wins.
- [ ] Flat-format text is extracted from `{"role":"assistant","content":"..."}` and `{"message":{"role":"assistant","content":"..."}}` only when the object has no `type` field.
- [ ] Event-based text (`agent_message`) overrides flat-format text when both are present.
- [ ] Usage is extracted only from `{"type":"turn.completed","usage":{...}}` with mapping: `input_tokens→tokens_in`, `output_tokens→tokens_out`, `cached_input_tokens→cached_in` (falling back to `cache_read_input_tokens→cached_in`).
- [ ] Flat fallback for `session_id` and `usage` is applied only when the JSON object has no `type` field.
- [ ] `normalize_output("codex", raw)` dispatches to `normalize_codex_jsonl`; `normalize_output("claude", raw)` returns text as-is; unknown backends return `Err`.
- [ ] Empty or whitespace-only input returns `Err`.
- [ ] Non-JSON raw input is returned as-is (raw text fallback) for codex backend.
- [ ] `src/backend/mod.rs` declares `pub mod output_normalizer;`.
- [ ] Test `codex_real_jsonl_extracts_text_and_session` passes — verifies text, session_id, tokens_in, tokens_out, cached_in from a realistic event stream.
- [ ] Test `codex_last_agent_message_wins` passes — two agent_message events, final text is from the second.
- [ ] Test `codex_event_text_precedes_flat_text` passes — both flat and event text present, event text wins.
- [ ] Test `codex_thread_and_usage_are_type_scoped` passes — objects with `thread_id`/`usage` under wrong `type` values are ignored.
- [ ] Existing-style tests pass: `codex_jsonl_extracts_text_and_session` (flat format), `codex_jsonl_missing_assistant_returns_err`, `codex_non_json_returns_raw`, `malformed_json_does_not_panic`.
- [ ] `cargo test output_normalizer` succeeds with zero failures.
- [ ] `cargo test` full suite has no regressions.
