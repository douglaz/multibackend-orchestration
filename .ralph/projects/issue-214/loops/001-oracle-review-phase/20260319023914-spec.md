# Feature: Oracle Review Phase

## Description
Add a new daemon phase `oracle_review_phase` that automatically reviews open, non-draft pull requests using the `oracle` CLI (`@steipete/oracle`) and posts idempotent top-level PR comments. The phase integrates into the daemon poll loop after `pr_review_phase`, is disabled by default, and tracks reviewed `(pr_number, head_sha)` pairs in a persisted JSON state file to avoid duplicate reviews. It supports author allowlisting, per-cycle caps, comment truncation, and self-healing state reconciliation from existing bot-authored marker comments.

## Acceptance Criteria
- [ ] **Config fields added**: `daemon_oracle_review_enabled` (bool, default false), `daemon_oracle_review_timeout_secs` (u64, default 900), `daemon_oracle_review_authors` (Vec<String>, default []), `daemon_oracle_review_max_per_cycle` (u32, default 3) wired through `WorkspaceConfig`, `EffectiveDaemonConfig`, `DaemonRuntimeConfig`, `set_global_config_value`, `config get`, and `config show`
- [ ] **Bounds validation**: `timeout_secs` must be > 0, `max_per_cycle` must be > 0; rejected at `set_global_config_value` time
- [ ] **GitHub PR listing**: `list_open_non_draft_prs` calls `gh pr list --state open --json number,headRefOid,isDraft,author --limit 100`, with a pure `parse_open_prs` helper that filters drafts and returns `Vec<OpenPrInfo>` plus overflow flag
- [ ] **PR diff fetching**: `fetch_pr_diff` calls `gh pr diff {pr_number} --repo {owner}/{repo}` and returns the diff text
- [ ] **Phase in poll loop**: `oracle_review_phase` is called in the main loop after `pr_review_phase` and before later phases; errors are logged as warnings and do not break the loop
- [ ] **Disabled by default**: Phase returns immediately when `oracle_review_enabled` is false
- [ ] **Draft PR exclusion**: Draft PRs are filtered out during parsing and never reach phase logic
- [ ] **Author allowlist**: When `daemon_oracle_review_authors` is non-empty, only PRs whose author matches case-insensitively are eligible; when empty, all non-draft PRs are eligible
- [ ] **Dedup state persistence**: `OracleReviewState` (HashMap<String, String> keyed by PR number → head SHA) persists at `{workspace_root}/daemon/oracle-review-state/state.json` with atomic write, auto-created parent dirs, default on missing file, and error on corrupt JSON
- [ ] **SHA-based dedup**: PRs whose head SHA matches state are skipped; changed SHA triggers fresh review
- [ ] **Marker-based idempotency**: Comments start with `<!-- ralph:oracle-review:{pr_number}:{head_sha} -->`; existing bot-authored marker comments skip oracle invocation and reconcile state
- [ ] **Oracle invocation**: Diff written to temp file under `{workspace_root}/daemon/oracle-review-state/`, passed as argument to `oracle` via `process::run_command_with_timeout`, temp file cleaned up after completion or failure
- [ ] **System prompt**: Exact text: `You are a senior code reviewer. Review this PR diff for bugs, security issues, performance problems, and code quality. Be concise and actionable. Focus on substantive issues, not style nits.`
- [ ] **Timeout from config**: Oracle timeout uses `daemon_oracle_review_timeout_secs`
- [ ] **Comment posting**: Uses `post_bot_comment_with_marker_with_gh_bin` with configured `gh_bin` and resolved `bot_login`
- [ ] **Comment truncation**: Review body truncated via shared `truncate_for_github` helper (made `pub(crate)`) accounting for marker + newline + body within `GITHUB_COMMENT_LIMIT` (65536)
- [ ] **Per-cycle cap**: At most `daemon_oracle_review_max_per_cycle` successful reviews per cycle; skipped/filtered PRs do not count
- [ ] **Failure isolation**: Oracle timeout, non-zero exit, spawn failure, diff fetch failure, or comment post failure logs warning for that PR and continues processing remaining eligible PRs without updating state
- [ ] **State saved per-PR**: State persisted immediately after each successful review, not batched at end of cycle
- [ ] **100-PR overflow warning**: Exact string `warning: oracle review: gh pr list returned 100 PRs, results may be truncated`
- [ ] **Truncation helpers exposed**: `truncate_for_github` and `GITHUB_COMMENT_LIMIT` changed to `pub(crate)` in `runtime.rs`
- [ ] **Conformance tests**: Full test suite in `src/validate/tests_daemon_oracle_review.rs` covering all required scenarios (config defaults, set/get roundtrips, bounds rejection, config show, disabled no-op, eligible PR reviewed, draft skip, dedup by SHA, SHA change re-review, author allowlist, case-insensitive matching, per-cycle max, existing bot marker skip, oracle timeout/exit/spawn failures, comment-post failure, 100-PR overflow warning)
- [ ] **Unit tests**: `parse_open_prs`, state load/save, corrupt state, dedup for same SHA vs changed SHA
