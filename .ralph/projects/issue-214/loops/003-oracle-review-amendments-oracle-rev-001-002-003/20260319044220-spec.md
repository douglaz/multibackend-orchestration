# Feature: Oracle Review Amendments (ORACLE-REV-001, -002, -003)

## Description
Address three final review amendments for the oracle review phase:
1. **ORACLE-REV-001**: Remove dependency on private `@steipete/oracle` internals. The current code monkey-patches `commander` via a Node.js wrapper script and always passes the undocumented `--system` flag. Replace with a supported invocation: fold the system prompt into the `--prompt` text and invoke `oracle` directly without the wrapper/entrypoint detection logic.
2. **ORACLE-REV-002**: Fix race condition in `OracleReviewState::save()` which uses a fixed temp path `state.json.tmp`. Use a unique temp file per save (PID + timestamp suffix or `tempfile` crate) in the same directory before atomic rename.
3. **ORACLE-REV-003**: The `oracle_spawn_failure_isolated` test is a false positive — it starts a real process that exits 7 with stderr text "oracle spawn:", so the classifier matches on text rather than exercising the actual spawn-failure code path. Fix by pointing the oracle binary at a nonexistent path for the first PR to trigger a real `failed to spawn command` error from `run_command_with_timeout`.

## Acceptance Criteria
- [ ] `ORACLE_SYSTEM_WRAPPER` constant and all wrapper/entrypoint-detection code (`resolve_oracle_cli_entrypoint`, `resolve_executable_in_path`, `oracle_wrapper_temp_path`) are removed
- [ ] Oracle is invoked as `oracle --prompt <combined_prompt> --file <diff_path> --write-output <output_path>` using only documented flags (no `--system`)
- [ ] The system prompt text is folded into the `--prompt` argument (e.g. `"{ORACLE_SYSTEM_PROMPT}\n\n{ORACLE_USER_PROMPT}"`)
- [ ] The `ORACLE_USER_PROMPT` constant is removed; its content is merged into the combined prompt
- [ ] `OracleReviewState::save()` writes to a unique temp file (e.g. `state.json.tmp.{pid}.{nanos}`) before atomic rename, not a fixed `state.json.tmp` path
- [ ] A unit test verifies that concurrent or repeated saves do not collide on temp file names
- [ ] `oracle_spawn_failure_isolated` test triggers an actual spawn failure for the first PR by making the oracle binary unresolvable (e.g. set PATH to exclude oracle for the first invocation, or use a nonexistent binary name)
- [ ] The test verifies `run_command_with_timeout` returns `failed to spawn command` for the first PR
- [ ] The test still verifies the second PR is processed successfully despite the first PR's spawn failure
- [ ] The mock oracle `spawn` mode is removed since it is no longer needed
- [ ] `eligible_pr_reviewed` test still validates the exact system prompt content is passed (now via `--prompt` instead of `--system`)
- [ ] All existing validate conformance tests continue to pass
