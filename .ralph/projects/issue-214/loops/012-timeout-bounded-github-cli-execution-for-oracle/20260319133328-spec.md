# Feature: Timeout-Bounded GitHub CLI Execution for Oracle Review

## Description
The core `oracle_review_phase` work is already complete across loops 1, 3, 5, 7, and 9: the phase exists, config wiring/defaults are in place, exact-marker dedup works, Oracle invocation uses the supported CLI surface, atomic state persistence is fixed, and post-success/readback-failure accounting is already correct. The remaining accepted gap is final-review amendment `ORACLE-REV-FR-002`: every `gh` subprocess used by the oracle-review flow still runs without a deadline, so a hung `gh pr list`, `gh pr diff`, comment lookup, login lookup, or comment post/readback can wedge the phase and stall the repo’s poll loop.

This feature should add timeout-bounded execution for all `gh` commands used by oracle review, reusing the existing process-group kill behavior from `process::run_command_with_timeout` or an equivalent helper. Scope this to the oracle-review path only, preserve existing phase semantics, and keep the current state invariants: no state update and no per-cycle count increment on pre-post failures or timed-out post attempts; if the GitHub post itself succeeds and only the follow-up readback times out, treat the review as successfully posted and advance state/count exactly once.

## Acceptance Criteria
- [ ] All `gh` subprocesses used by the oracle-review path run with a deadline instead of bare `Command::output().await`.
- [ ] The implementation reuses `daemon_oracle_review_timeout_secs` as the timeout budget for these oracle-review `gh` calls; no new config fields or project-level overrides are introduced.
- [ ] `list_open_non_draft_prs` timeout/failure is reported as an `oracle review` warning, leaves `OracleReviewState` unchanged, and returns control to the poll loop without aborting the daemon.
- [ ] Authenticated bot-login lookup timeout/failure is reported as an `oracle review` warning, leaves state unchanged, and returns control to the poll loop without aborting the daemon.
- [ ] Per-PR marker lookup/comment-fetch timeout is treated as a warning for that PR, does not update state, does not increment `daemon_oracle_review_max_per_cycle`, and processing continues to later eligible PRs in the same cycle.
- [ ] Per-PR diff-fetch timeout is treated as a warning for that PR, does not update state, does not increment the per-cycle count, and processing continues to later eligible PRs.
- [ ] `gh issue comment` timeout/spawn failure/non-zero exit is classified as comment-post failure for that PR, does not update state, does not increment the per-cycle count, and does not abort the cycle.
- [ ] If `gh issue comment` succeeds but the follow-up bot-comment readback times out or otherwise fails, the helper still reports `Posted`, `oracle_review_phase` advances state immediately for `(pr_number, head_sha)`, and the successful post counts toward `daemon_oracle_review_max_per_cycle`.
- [ ] Existing behaviors remain unchanged: exact first-line marker matching, bot-only dedup, author allowlist filtering, per-cycle cap semantics, immediate state persistence after success, and non-fatal runtime integration after `pr_review_phase`.
- [ ] Add conformance coverage for at least: hung `gh pr list`, hung bot-login lookup, hung marker/comment lookup on one PR while a later PR still succeeds, hung `gh pr diff` on one PR while a later PR still succeeds, timed-out `gh issue comment` not advancing state, and timed-out readback-after-success still advancing state/count.
