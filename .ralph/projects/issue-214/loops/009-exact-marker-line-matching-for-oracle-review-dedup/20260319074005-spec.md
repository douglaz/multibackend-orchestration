# Feature: Exact Marker Line Matching for Oracle Review Dedup

## Description
Tighten the oracle review marker dedup check from substring-based matching (`body.contains(marker)`) to exact-marker-line matching (body must start with `{marker}\n` or equal the marker exactly). Currently, `find_bot_comment_with_marker_with_gh_bin` in `src/daemon/github.rs:2142` uses `.contains(marker)`, which means any bot-authored comment that embeds the marker string anywhere in its body — not just as the leading marker line — will falsely suppress oracle execution and advance dedup state. This is amendment ORACLE-REV-FINAL-001 from the Round 3 final review.

The fix adds a specialized exact-marker-line finder for the oracle review phase, leaving the existing `contains`-based helper unchanged for other callers (e.g., `pr_review_phase`, `interactive_prd`). The oracle phase's pre-oracle existence check and the `post_bot_comment_with_marker_outcome_with_gh_bin` function's both pre-check and post-readback calls must use starts-with semantics for oracle markers.

## Acceptance Criteria
- [ ] A new helper function `find_bot_comment_with_marker_exact_with_gh_bin` is added to `src/daemon/github.rs` that matches only bot-authored comments whose body starts with `{marker}\n` or equals the marker exactly
- [ ] The oracle review phase's pre-oracle existence check (`oracle_review.rs:160`) uses the exact-marker-line helper instead of the substring-based one
- [ ] `post_bot_comment_with_marker_outcome_with_gh_bin` uses the exact-marker-line helper for both its pre-check (line 2182) and post-readback (line 2229) lookups, since it is only called by the oracle review phase and already constructs bodies with the marker as the first line
- [ ] A bot-authored comment that contains the marker text embedded later in the body (not at the start) does NOT suppress oracle invocation
- [ ] A bot-authored comment with the marker as the first line correctly suppresses oracle invocation and self-heals state
- [ ] Validate conformance test added: bot comment with embedded marker does not falsely skip oracle
- [ ] Unit test added for the exact-marker-line matching logic
- [ ] All existing oracle review tests continue to pass

## Files to Modify/Create
- `src/daemon/github.rs` - Add `find_bot_comment_with_marker_exact_with_gh_bin` that uses starts-with semantics (`body.starts_with(&format!("{marker}\n")) || body == marker`). Update `post_bot_comment_with_marker_outcome_with_gh_bin` to use this helper at lines 2182 and 2229 instead of the substring-based `find_bot_comment_with_marker_with_gh_bin`.
- `src/daemon/oracle_review.rs` - Change the pre-oracle marker check at line 160 to call `find_bot_comment_with_marker_exact_with_gh_bin` instead of `find_bot_comment_with_marker_with_gh_bin`.
- `src/validate/tests_daemon_oracle_review.rs` - Add a conformance test `embedded_marker_does_not_suppress_oracle` that sets up a bot-authored comment containing the marker text mid-body (e.g., `"some preamble\n<!-- ralph:oracle-review:11:sha-11 -->\nstuff"`) and verifies oracle IS invoked and the PR IS reviewed. Also verify the existing `existing_bot_marker_skips_oracle` test still passes (marker at start of body).
