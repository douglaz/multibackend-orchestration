I now have full clarity on the issue. The acceptance failure from `codex(gpt-5.3-codex-xhigh)` identified a real bug: the dispatch gate is too permissive. When `task.project_id` is `None` (fresh task), the code still runs project discovery and routes to `spawn_ralph_run` if a project is found. This violates Required Behavior #3 which says: "if `task.project_id` is `Some(id)`, spawn `ralph run`; otherwise use the existing fresh-dispatch path."

The fix is clear: the dispatch decision should be based solely on `task.project_id`, not on discovery. Discovery should only be used for persistence (so the project_id is available on future retries), not for routing.

Here is the spec:

# Feature: Fix Fresh-Dispatch Regression — Gate on task.project_id Only

## Description
Fix the dispatch gate in `dispatch_task()` so that the routing decision between `spawn_ralph_run` (resume path) and `spawn_ralph_auto` (fresh-dispatch path) is based **solely** on `task.project_id`, not on a discovered project ID. The current code runs project ID discovery for fresh tasks (`project_id = None`) and uses the discovered value to route through the resume path, which violates Required Behavior #3 ("if `task.project_id` is `Some(id)`, spawn `ralph run`; otherwise use the existing fresh-dispatch path") and Acceptance Criterion #1 ("Fresh task dispatch behavior does not regress").

Project discovery should still run for fresh tasks, but only to **persist** the discovered `project_id` to the task store after CAS activation — so that if the task later fails and is retried, it will have `project_id` set and correctly take the resume path. The dispatch routing itself must only check `task.project_id`.

## Acceptance Criteria
- [ ] In `dispatch_task()`, the branch between `spawn_ralph_run` vs `spawn_ralph_auto` is gated on `task.project_id.is_some()`, **not** on `effective_project_id`.
- [ ] Project discovery still runs for fresh tasks (when `task.project_id.is_none()`) and the discovered value is still persisted to the task store after CAS activation.
- [ ] A pending task with `project_id: None` always dispatches via `spawn_ralph_auto` even when exactly one project exists under `.ralph/projects/`.
- [ ] A pending task with `project_id: Some(id)` always dispatches via `spawn_ralph_run`.
- [ ] New conformance test: pending task with `project_id: null` and exactly one workspace project dispatches via `ralph auto --idea`, not `ralph run --project`.
- [ ] All existing conformance tests continue to pass (including all 5 required resume/retry tests from Loop 1).
- [ ] All verification commands pass: `cargo check`, `cargo test`, `nix build -L`, `ralph validate --filter daemon`.

## Files to Modify/Create
- `src/daemon/runtime.rs` — Change the dispatch branch at line ~433 from `if let Some(project_id) = effective_project_id.as_deref()` to `if let Some(project_id) = task.project_id.as_deref()`. Keep the `effective_project_id` computation (lines 417-424) and its persistence to the task store (lines 536-537) unchanged, since discovery-for-persistence is correct behavior.
- `src/validate/tests_daemon.rs` — Add a new conformance test `runtime_fresh_dispatch_ignores_discovered_project` that creates a workspace with exactly one project under `.ralph/projects/`, enqueues a task with `project_id: null`, runs a single daemon iteration, and asserts the spawned command uses `ralph auto --idea` arguments (not `ralph run --project`).
