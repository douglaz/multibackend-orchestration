# Feature: Fast Validate Harness Foundations (Shared Global Config Mutator + Fast Setup Helpers)

## Description
Establish the performance foundation for validate-suite speedups by moving global config mutation into a shared production helper and adding non-CLI fast harness setup methods. This enables later test migrations (`tests_streaming.rs`, `tests_e2e_conformance.rs`) to avoid repeated subprocess overhead while preserving behavior.

## Acceptance Criteria
- [ ] Add a shared `pub(crate)` global config mutator near `GlobalConfig` (for example `set_global_config_value(config, key, raw_value)`), with the same key coverage and validation behavior currently used by `ralph config set --global`.
- [ ] Refactor `cli config set` global path to call the shared mutator instead of local duplicated mutation logic.
- [ ] Keep `cli::config` internals private; no new public exposure of `cli::config` module internals.
- [ ] Preserve existing CLI behavior for global config writes (same success/error outcomes for supported and unsupported keys).
- [ ] Add `RalphHarness::init_workspace_fast` that initializes workspace using production Rust APIs (not spawning `ralph init`).
- [ ] Add `RalphHarness::create_project_fast` that creates projects via production Rust APIs (not spawning `ralph project new`), preserving project metadata/prompt semantics.
- [ ] Add `RalphHarness::set_config_fast` for global scope only, using the shared global config mutator and writing `.ralph/ralph.toml`.
- [ ] Add `RalphHarness::setup_mock_backends_fast` that configures Claude/Codex command paths and disables Gemini via `set_config_fast`.
- [ ] Add a command helper supporting explicit child env removals (for example `ralph_env_with_removals(args, env_vars, env_removals)`), where removed keys are absent in the child even if present in parent process env.
- [ ] Keep existing harness subprocess helpers (`init_workspace`, `create_project`, `setup_mock_backends`) intact for suites that intentionally validate CLI paths.
- [ ] Add/adjust tests to verify shared mutator parity and env-removal behavior, and ensure existing config/harness tests continue to pass without behavioral regressions.

## Files to Modify/Create
- `src/config/global.rs` - Add shared global config mutation helper (and supporting parsing/validation helpers as needed).
- `src/config/mod.rs` - Re-export shared mutator as `pub(crate)` for internal crate use.
- `src/cli/config.rs` - Delegate global `config set` path to shared mutator and remove duplicated local mutation path.
- `src/validate/harness.rs` - Add `init_workspace_fast`, `create_project_fast`, `set_config_fast`, `setup_mock_backends_fast`, and env-removal command helper.
- `src/validate/harness.rs` (tests section) and/or `src/cli/config.rs` tests - Add parity and env-removal coverage for new helpers.

- Blocks: Migration of `tests_streaming.rs` and `tests_e2e_conformance.rs` to fast helpers, plus retry-override conformance cases requiring deterministic env-unset execution
