# Feature: RALPH_MAX_BACKEND_RETRIES override in execute_with_timeout_retries

## Description
Add a configurable retry-count override for backend timeout retries in the orchestrator. A new helper function `max_backend_retries() -> u8` reads the `RALPH_MAX_BACKEND_RETRIES` environment variable and applies validation/clamping rules. The hardcoded retry limit of `3` in `execute_with_timeout_retries` is replaced with the computed value. Unit tests cover the full parsing/clamping matrix.

## Acceptance Criteria
- [ ] A `max_backend_retries() -> u8` helper function exists in `src/workflow/orchestrator.rs` (or a nearby private helper scope).
- [ ] The helper reads `RALPH_MAX_BACKEND_RETRIES` from the environment exactly once per call.
- [ ] Behavior table is implemented:
  - Env var unset → returns `3`
  - Env var is a valid integer in `1..=10` → returns that exact value as `u8`
  - Env var is `0` → rejects, returns default `3`
  - Env var is a non-numeric string (e.g. `"abc"`) → returns default `3`
  - Env var is a numeric value `> 10` (e.g. `11`, `256`) → clamps to `10`
- [ ] The env var is parsed using an integer type wider than `u8` (e.g. `u32` or `i64`) so that values like `256` are parsed as numeric and clamped rather than treated as parse failures.
- [ ] `execute_with_timeout_retries` calls `max_backend_retries()` once at the start of the function and stores the result.
- [ ] The `for attempt in 1..=3_u8` loop bound is replaced with `1..=max_retries` using the stored value.
- [ ] The exhaustion check (currently `attempt >= 3`) is replaced with `attempt >= max_retries`.
- [ ] No other behavioral changes to `execute_with_timeout_retries` (backoff strategy, error propagation, logging remain the same).
- [ ] Unit tests in the orchestrator `#[cfg(test)] mod tests` block cover the full parsing/clamping matrix:
  - Unset → `3`
  - `"1"` → `1`
  - `"5"` → `5`
  - `"10"` → `10`
  - `"0"` → `3`
  - `"abc"` → `3`
  - `""` (empty string) → `3`
  - `"11"` → `10`
  - `"256"` → `10`
- [ ] Unit tests use `std::env::set_var` / `std::env::remove_var` (or a testable abstraction) and run with `#[serial]` or equivalent to avoid env-var races.
