# Feature: Daemon dispatch project-ID normalization

## Description
Normalize daemon dispatch so that every daemon-managed task uses `project_id = "issue-{n}"` exclusively. This involves three interconnected changes: (1) update `spawn_ralph_auto` and its command builder to accept an optional `project_id` parameter and append `--project-id <id>` when present, (2) in `dispatch_task`, compute `project_id` as `format!("issue-{issue_number}")` once per dispatch and determine resume vs. fresh by checking whether `worktree/.ralph/projects/issue-{n}/prompt.md` exists (after `sync_project_branch` completes), and (3) remove all slug-based discovery calls (`discover_project_ids`, `discover_project_from_remote_branches`, `prior_project_id` extraction) from the dispatch path, along with the extra project-branch checkout block that follows discovery.

## Acceptance Criteria
- [ ] `spawn_ralph_auto` and `build_ralph_auto_command` accept `project_id: Option<&str>` parameter
- [ ] When `project_id` is `Some`, `--project-id <id>` is appended to the `ralph auto` command args
- [ ] When `project_id` is `None`, command args are unchanged (preserves manual `ralph auto --idea` behavior)
- [ ] `dispatch_task` computes `project_id = format!("issue-{issue_number}")` once before any dispatch decision
- [ ] Resume decision is: `wt_path.join(".ralph/projects/{project_id}/prompt.md").is_file()` evaluated after `sync_project_branch`
- [ ] If resume is true, dispatch calls `spawn_ralph_run(&ralph_bin, &wt, &project_id, &log_path)`
- [ ] If resume is false, dispatch calls `spawn_ralph_auto(&ralph_bin, &wt, &idea, &log_path, Some(&project_id))`
- [ ] Calls to `discover_project_ids` and `discover_project_from_remote_branches` are removed from `dispatch_task`
- [ ] The `prior_project_id` return value from `create_worktree` is no longer used for dispatch decisions (signature change deferred)
- [ ] The extra `checkout_branch_in_worktree` block after discovery (lines ~1059-1077) is removed; `sync_project_branch` already checks out `ralph/issue-{n}`
- [ ] `create_worktree` return type changes from `Result<(PathBuf, Option<String>)>` to `Result<PathBuf>`
- [ ] `verify_worktree_branch` return type changes from `Result<Option<String>>` to `Result<()>` with `prior_project_id` extraction logic removed
- [ ] Existing unit test `spawn_command_uses_long_idea_flag` updated to pass `None` for project_id and assert unchanged args
- [ ] New unit test: `spawn_auto_command_includes_project_id` asserts `Some("issue-42")` adds `--project-id issue-42`
- [ ] Fresh dispatch for issue 42 invokes `ralph auto --idea ... --project-id issue-42`
- [ ] Resume dispatch for issue 42 invokes `ralph run --project issue-42` when `.ralph/projects/issue-42/prompt.md` exists
- [ ] No slug-based fallback influences dispatch decisions
