# Review: SUGGESTIONS

## Required Changes

1. **Deadline enforcement is incomplete in rebase-agent loop**: timeout budget is not applied to all subprocess-based steps.
   - Current: `git::conflicting_files()` and `git::has_conflicts()` are called without timeout budgeting in `src/daemon/rebase_agent.rs:249`, `src/daemon/rebase_agent.rs:276`, and `src/daemon/rebase_agent.rs:292` (they run `git status` internally without bounded timeout).
   - Expected: every subprocess step in the agent loop must consume the shared remaining deadline and fail immediately when budget is exhausted.
   - Reference: Master Prompt Functional Requirements `4` ("Before each subprocess call, compute remaining duration… No step may run without bounded timeout.").

2. **Success condition can return early while rebase is still in progress**.
   - Current: `run_rebase_continue()` returns `Ok(())` even when `is_rebase_in_progress(worktree_path)` is still true (if no conflicts), and caller exits success (`src/daemon/rebase_agent.rs:327`, `src/daemon/rebase_agent.rs:340`, `src/daemon/rebase_agent.rs:288`).
   - Expected: only return success once rebase is actually complete (not in progress) and conflicts are clear; otherwise continue looping.
   - Reference: Feature Spec Acceptance Criteria ("Success is returned only when `git rebase --continue` succeeds and no conflicts remain.").

3. **Integration test suite is not passing and is race-prone**.
   - Current: `cargo test -q --test daemon_rebase_agent` fails (3/5 failed). Tests mutate global `PATH` (`tests/daemon_rebase_agent.rs:137`, `tests/daemon_rebase_agent.rs:145`), which is unsafe under parallel test execution.
   - Expected: make integration tests deterministic and passing (serialize or avoid global env races), and keep all required scenarios green.
   - Reference: Master Prompt Testing Requirements `2` (integration-style scenarios must be covered).

4. **Validate conformance coverage does not exercise daemon runtime behavior for required paths**.
   - Current: new validate cases mostly assert parsing/prompt text (`src/validate/tests_daemon_rebase.rs:94`, `src/validate/tests_daemon_rebase.rs:131`) rather than executing daemon auto-rebase enabled/disabled/failure runtime flows.
   - Expected: conformance tests should validate actual daemon behavior for agent-enabled recovery, `"none"` fallback, and agent-failure fallback.
   - Reference: Master Prompt Testing Requirements `3` and Feature Spec Acceptance Criteria for `src/validate/tests_daemon_rebase.rs`.

## Recommended Improvements

1. Include agent stderr/stdout context in non-zero exit errors to improve diagnosability (`src/daemon/rebase_agent.rs:270`).
