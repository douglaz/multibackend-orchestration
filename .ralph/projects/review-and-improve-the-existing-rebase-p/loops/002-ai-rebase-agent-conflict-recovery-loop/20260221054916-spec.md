# Feature: AI Rebase Agent Conflict Recovery Loop

## Description
Loop 1 already delivered config plumbing, backend parsing, and conflict classification. This feature adds the missing runtime behavior: when daemon auto-rebase hits a classified merge conflict, run an AI rebase agent in the worktree to resolve/stage conflicts and advance `git rebase --continue` iteratively under one shared timeout budget, while preserving existing failure behavior for non-conflict errors and disabled mode.

## Acceptance Criteria
- [ ] `src/daemon/rebase_agent.rs` exposes `resolve_rebase_conflicts(worktree_path, rebase_target, agent_backend, deadline) -> Result<(), RalphError>` with an internal error enum mapped to clear `RalphError` messages.
- [ ] Rebase-agent loop uses a hard cap of `10` iterations and is deterministic.
- [ ] Each iteration performs, in order: `git::conflicting_files()`, prompt rendering, agent command execution, `git::has_conflicts()` verification, and `git rebase --continue`.
- [ ] The prompt template is fixed and includes rebase target, explicit conflicting file list, required `git add` staging, prohibition of `git rebase --continue`/`git rebase --abort`, and prohibition on unrelated file edits.
- [ ] Success is returned only when `git rebase --continue` succeeds and no conflicts remain.
- [ ] If `git rebase --continue` introduces new conflicts, the loop repeats until resolved or iteration cap is reached.
- [ ] One shared deadline is enforced across initial rebase, agent invocations, and all `--continue` attempts; each subprocess call uses remaining time and fails immediately when budget is exhausted.
- [ ] On any agent-path failure (spawn error, timeout, non-zero exit, unresolved conflicts, iteration cap), rebase is aborted if in progress and an error is returned.
- [ ] `execute_rebase` in `src/daemon/runtime.rs` invokes `resolve_rebase_conflicts` only for classified conflict failures and only when backend is enabled.
- [ ] `execute_rebase` keeps existing non-conflict failure behavior unchanged.
- [ ] Backend value `"none"` preserves prior fail/abort path with no agent attempt.
- [ ] Unit tests cover prompt rendering contract, timeout accounting, loop-cap failure, unresolved-conflict failure, and abort-on-failure behavior.
- [ ] `tests/daemon_rebase_agent.rs` covers successful recovery, multi-commit conflict loops, agent non-zero exit, agent success-without-resolution, and timeout.
- [ ] `src/validate/tests_daemon_rebase.rs` adds conformance tests for agent-enabled recovery, agent-disabled fallback, and agent-failure fallback.

## Files to Modify/Create
- `src/daemon/rebase_agent.rs` - Implement resolver entrypoint, internal error model, prompt builder, deadline accounting, agent/continue loop, and unit tests.
- `src/daemon/runtime.rs` - Integrate conflict-only resolver invocation, shared deadline plumbing, and fallback semantics.
- `src/git/mod.rs` - Add helper(s) only if needed to detect rebase-in-progress safely before abort.
- `tests/daemon_rebase_agent.rs` - Add integration-style conflict recovery scenarios with mock `claude`.
- `src/validate/tests_daemon_rebase.rs` - Extend conformance coverage to runtime conflict-recovery behaviors.
- `src/validate/mod.rs` - Register any new daemon rebase conformance cases if module wiring changes.
