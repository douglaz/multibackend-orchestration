# Feature: Config Plumbing, Backend Parsing, and Conflict Classification

## Description
Lay the groundational infrastructure for AI-assisted conflict recovery by adding the `daemon_rebase_agent_backend` configuration key (global + project override), implementing backend string parsing with validation, and introducing a conflict-vs-non-conflict failure classifier for `execute_rebase`. This loop does NOT invoke an agent or modify runtime control flow beyond extracting the classifier and wiring config — it prepares all the pieces that the agent loop (next loop) will depend on.

## Acceptance Criteria
- [ ] `WorkspaceConfig` in `src/config/global.rs` includes `daemon_rebase_agent_backend: String` with serde default `"claude(opus)"`.
- [ ] `ProjectDaemonOverrides` in `src/config/project.rs` includes `rebase_agent_backend: Option<String>`.
- [ ] `DaemonRuntimeConfig` in `src/cli/daemon.rs` (or wherever it lives) carries the resolved `rebase_agent_backend` field, with project override taking precedence over global default.
- [ ] A `parse_rebase_agent_backend` function exists that accepts a `&str` and returns a typed enum: `RebaseAgentBackend::None`, `RebaseAgentBackend::Claude { model: String }`, or an error for unsupported values.
- [ ] Parsing handles: `"none"` -> disabled, `"claude"` -> Claude with default model `"opus"`, `"claude(sonnet)"` -> Claude with model `"sonnet"`, `"claude(opus)"` -> Claude with model `"opus"`, any other string -> clear error.
- [ ] A `classify_rebase_failure` function exists (in `runtime.rs` or `rebase_agent.rs`) that takes exit code, stderr bytes, and worktree path, and returns `RebaseFailureKind::Conflict` or `RebaseFailureKind::Other`.
- [ ] Classification logic: conflict only when exit code == 1, stderr contains `"CONFLICT"` or `"could not apply"`, AND `git::has_conflicts(worktree_path)` is true; otherwise `Other`.
- [ ] New `src/daemon/rebase_agent.rs` module is created and exported from `src/daemon/mod.rs`, containing the backend enum, parser, and classifier.
- [ ] Backward compatibility: missing `daemon_rebase_agent_backend` in config file deserializes to default `"claude(opus)"`.
- [ ] Unit tests cover backend parsing for all cases: `none`, `claude`, `claude(opus)`, `claude(sonnet)`, empty string, unknown string.
- [ ] Unit tests cover conflict classifier: conflict case (exit 1 + CONFLICT in stderr + has_conflicts true), non-conflict exit codes, missing conflict indicators in stderr, has_conflicts returning false.
- [ ] Validate conformance tests cover: config default value, config backward compatibility (missing key), agent-disabled (`"none"`) produces `RebaseAgentBackend::None`.
