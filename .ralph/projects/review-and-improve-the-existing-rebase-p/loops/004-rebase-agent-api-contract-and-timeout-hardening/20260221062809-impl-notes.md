# Implementation Notes

## Decisions Made
- **String-based public entrypoint**: Changed `resolve_rebase_conflicts` to accept `agent_backend: &str` instead of `&RebaseAgentBackend`. The typed enum is kept internal to the module. Backend parsing happens inside `resolve_rebase_conflicts`, which means invalid backend strings are caught at the entrypoint boundary with clear `RalphError` messages.
- **"none" handling in the entrypoint**: When `agent_backend` is `"none"`, the function immediately aborts any in-progress rebase and returns an `Orchestration` error with a message indicating resolution was skipped. This lets the runtime caller handle it via the existing failure-comment flow.
- **Typed helper preserved**: Renamed the original implementation to `resolve_rebase_conflicts_typed` (private) so the typed `RebaseAgentBackend` enum is still used internally for command construction. This avoids double-parsing in the loop.
- **Timeout-bounded abort**: Replaced all unbounded `Command::new("git").args(["rebase", "--abort"]).output()` calls with `process::run_command_with_timeout`-backed variants. In `rebase_agent.rs`, `abort_rebase_if_in_progress` now accepts a deadline and computes remaining budget (with a 5-second minimum floor). In `runtime.rs`, a `bounded_abort` closure computes the same timeout from the shared deadline.
- **Error propagation**: Removed both `.unwrap_or(false)` patterns in the resolve loop (lines for post-continue and post-failure conflict checks). These now use `.map_err(|e| AgentError::SpawnFailed(...))` to propagate timeout/spawn errors upward, which ultimately surface as `RalphError::Orchestration` to the runtime.
- **Runtime config type change**: `DaemonRuntimeConfig.rebase_agent_backend` changed from `RebaseAgentBackend` to `String`. CLI startup still validates the string via `parse_rebase_agent_backend` for early error detection, but stores the raw string for runtime use.
