## Implementation Notes

### Harness addition (`harness.rs`)
Add `ralph_with_stdin<I, S>(&self, args: I, input: &str) -> Result<Output>` following the exact pattern of existing `ralph()` method but with `Stdio::piped()` for all three streams, writing `input` to stdin, dropping stdin handle, then calling `child.wait_with_output()`.

### Test module patterns (`tests_mcp.rs`)
Follow exact patterns from `tests_commands.rs` and `tests_tail.rs`:
- Own `run_case()` via `catch_unwind` + `panic_message()`
- Own `setup_with_project()` for tests needing workspace+project
- Test names prefixed `"mcp::"`
- Each test function signature: `fn(h: &RalphHarness) -> TestResult`
- JSON-RPC protocol: `"2.0"`, MCP protocol version `"2025-06-18"`
- Server info: `name="ralph"`, version is non-empty string
- 9 tool names: `project_new`, `project_list`, `project_show`, `run`, `status`, `history`, `tail`, `quick_prd`, `config_show`
- Parse error code: `-32700`, method not found: `-32601`
- Tool-level errors use `isError: true` in `CallToolResult`, not protocol-level error codes
- Transport is newline-delimited JSON (one JSON object per line)
- `init_handshake()` sends: initialize request (id=1) + `notifications/initialized` notification (no id)
- `mcp_exchange()` pipes input to `ralph mcp serve`, asserts exit code 0, splits stdout by newlines, parses each non-empty line as JSON `Value`
