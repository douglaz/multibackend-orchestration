# Feature: TmuxBackend execution wrapper

## Description
Loop 1 already completed the tmux primitives (`ensure_session`, `create_window`, `wait_for_exit`, `kill_window`) and tmux availability checks. The next logical feature is implementing `TmuxBackend`, a `Backend` implementation that wraps `CliBackend` and runs backend commands inside tmux windows while still returning stdout for orchestration parsing. This delivers the core tmux execution path before config/CLI toggle wiring.

## Acceptance Criteria
- [ ] Add a `TmuxBackend` struct that wraps `CliBackend` and implements the existing `Backend` trait without changing trait signatures.
- [ ] `TmuxBackend::execute` writes prompt/input, stdout/output, and exit-code temp files with unique names per invocation.
- [ ] `TmuxBackend::execute` calls tmux helpers from `src/backend/tmux.rs` in order: `ensure_session` -> `create_window` -> `wait_for_exit` -> `kill_window` (best-effort cleanup).
- [ ] The tmux window command captures only stdout to file and leaves stderr visible in tmux (no `2>&1` in the generated command).
- [ ] Backend command path/args/env from `CliBackend` are preserved in tmux mode (including proper shell escaping/quoting).
- [ ] Timeout behavior matches existing backend semantics by using the backend timeout when waiting for the exit file.
- [ ] Non-zero exit codes return `RalphError::BackendCommandFailed` with backend name and actionable details.
- [ ] Temp files are cleaned up on success, failure, and timeout (RAII/finally-style cleanup).
- [ ] `health_check` for `TmuxBackend` validates both tmux availability and wrapped backend availability.
- [ ] Add tests (mock tmux runner, no real tmux dependency) covering success, non-zero exit, timeout, command construction, and cleanup behavior.
- [ ] Existing non-tmux `CliBackend` execution behavior remains unchanged.

## Files to Modify/Create
- `src/backend/tmux_backend.rs` - add `TmuxBackend` implementation, command construction, temp file lifecycle, and unit tests with mocked tmux runner.
- `src/backend/mod.rs` - expose new module/type and add minimal `CliBackend` accessors needed by the wrapper (command, args, env, timeout, resolved path).
- `tests/backend_tmux.rs` - add integration-style tests for wrapper behavior using mocks/stubs (no tmux binary required).

## Dependencies
- Requires: tmux session and window management (Loop 1)
- Blocks: configuration and CLI wiring; window labeling and UX polish
