# Implementation Notes

## Decisions Made
- Used a generic `TmuxBackend<R: TmuxCommandRunner>` with a default type parameter (`RealTmuxRunner`) so tests can inject a mock runner while production code uses the real one without specifying the type parameter.
- Temp file uniqueness uses a global `AtomicU64` counter combined with the PID and session name, avoiding any filesystem-based temp file creation overhead.
- Shell escaping uses the standard single-quote wrapping trick (`'...'` with embedded `'` escaped as `'\''`), which is safe for all POSIX shells.
- Environment variables are exported via `export KEY=VALUE;` prefix in the shell command rather than using tmux's `set-environment`, keeping the tmux session clean for other windows.
- The `TempFileGuard` uses synchronous `std::fs::remove_file` in its `Drop` impl since async `Drop` isn't available in Rust; this is acceptable because temp file removal is fast I/O.
- `wait_for_exit` timeout is remapped from the generic `backend: "tmux"` to `backend: "<actual-backend-name>"` so error messages are actionable.
- Tests use a file-watcher pattern (spawned tokio task that polls for the prompt file then writes output/exit files) to simulate the tmux command completing, avoiding any real tmux dependency.
- Made `CliBackend::resolved_command_path()` public (was private) rather than duplicating the logic — this is the minimal visibility change needed.

- `cargo test backend_tmux` — runs integration tests in `tests/backend_tmux.rs`
- `cargo test` — runs all tests including existing ones (no regressions)
- `cargo check` — verifies compilation
