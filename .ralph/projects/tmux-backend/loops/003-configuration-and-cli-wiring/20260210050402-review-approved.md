# Review: APPROVED

## Acceptance Criteria Checklist
- [x] `WorkspaceConfig` in `src/config/global.rs` gains two new optional fields: `tmux` (`bool`, default `false`) and `tmux_session` (`String`, default `"ralph"`), both annotated with `#[serde(default)]` so existing `ralph.toml` files parse without changes
- [x] `GlobalConfig::default()` sets `tmux: false` and `tmux_session: "ralph".to_owned()`
- [x] `RunArgs` in `src/cli/mod.rs` gains `--tmux` (sets tmux=true) and `--no-tmux` (sets tmux=false) flags, declared as `Option<bool>` with `conflicts_with` so they are mutually exclusive; both default to `None` (defer to config)
- [x] `RunOptions` in `src/workflow/orchestrator.rs` gains a `tmux: Option<bool>` field, threaded from `RunArgs`
- [x] The orchestrator resolves the effective tmux mode: CLI flag overrides config value, config value overrides the default (`false`)
- [x] When tmux mode is active and `dry_run` is false, the orchestrator calls `tmux::check_tmux_available()` early (before health checks) and fails with `RalphError::TmuxUnavailable` if tmux is not installed
- [x] `BackendRegistry::new` accepts a new parameter conveying tmux settings (enabled + session name); when enabled, it wraps each `CliBackend` in `TmuxBackend<RealTmuxRunner>` before inserting into the registry
- [x] When tmux mode is disabled (the default), `BackendRegistry::new` behaves identically to the current implementation — no `TmuxBackend` wrapping, no tmux checks
- [x] `EffectiveConfig` (or `RunOptions`) carries the resolved tmux settings so the orchestrator can pass them to `BackendRegistry::new`
- [x] Existing tests pass without modification; new unit tests cover: config deserialization with/without tmux fields, CLI flag parsing (--tmux, --no-tmux, neither), registry construction with tmux wrapping, and the early tmux-availability check
- [x] The `Backend` trait is not changed

## Notes

The implementation is clean and comprehensive. All acceptance criteria are met with evidence in the diff:

- **Config fields**: `src/config/global.rs` adds `tmux: bool` with `#[serde(default)]` and `tmux_session: String` with `#[serde(default = "default_tmux_session")]`. The custom default function for `tmux_session` is a justified deviation from the spec — using plain `#[serde(default)]` on `String` would default to `""`, not `"ralph"`.

- **CLI flags**: `src/cli/mod.rs` adds both flags with `conflicts_with` for mutual exclusion, properly typed as `Option<bool>`. The `num_args = 0..=1` pattern allows `--tmux` to work as a bare flag (defaulting to `true`) or with an explicit value.

- **Threading**: `src/cli/run.rs` merges the two flags via `args.tmux.or(args.no_tmux)` into `RunOptions.tmux`.

- **Resolution & preflight**: `resolve_tmux_settings()` implements the CLI > config > default precedence. `validate_tmux_preflight()` is cleanly separated and testable via a generic `FnOnce` parameter. Preflight runs before `health_check_all()` as specified.

- **Registry wrapping**: `BackendRegistryTmuxConfig` is a clean public struct. `backend_with_optional_tmux()` conditionally wraps `CliBackend` in `TmuxBackend<RealTmuxRunner>`. When disabled, identical to the prior behavior.

- **Test coverage**: Thorough — config deserialization (3 tests), CLI parsing (4 tests), orchestrator resolution/preflight (4 unit tests + 2 integration tests), and registry wrapping behavior (2 integration tests with mock scripts). The `PathGuard` + `PATH_LOCK` pattern safely isolates tests that manipulate `PATH`.

- **Formatting changes** in `tmux_backend.rs` and `backend_tmux.rs` are `rustfmt` normalization only — no behavioral changes.

- **`src/cli/config.rs`** bonus: `set_global_value` supports the new `workspace.tmux` and `workspace.tmux_session` keys for `ralph config set`.
