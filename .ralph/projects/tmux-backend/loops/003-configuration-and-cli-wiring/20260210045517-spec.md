# Feature: Configuration and CLI wiring

## Description

Wire the existing `TmuxBackend` implementation into the configuration system, CLI flags, and orchestrator so that users can enable tmux mode via `ralph.toml` or `--tmux`/`--no-tmux` CLI flags. When tmux mode is active, the orchestrator wraps each `CliBackend` in a `TmuxBackend` at registry construction time. When disabled (the default), behavior is identical to today. This feature also performs an early-exit validation: if tmux mode is requested but tmux is not installed, ralph fails immediately with a clear error before any backend work begins.

## Acceptance Criteria

- [ ] `WorkspaceConfig` in `src/config/global.rs` gains two new optional fields: `tmux` (`bool`, default `false`) and `tmux_session` (`String`, default `"ralph"`), both annotated with `#[serde(default)]` so existing `ralph.toml` files parse without changes
- [ ] `GlobalConfig::default()` sets `tmux: false` and `tmux_session: "ralph".to_owned()`
- [ ] `RunArgs` in `src/cli/mod.rs` gains `--tmux` (sets tmux=true) and `--no-tmux` (sets tmux=false) flags, declared as `Option<bool>` with `conflicts_with` so they are mutually exclusive; both default to `None` (defer to config)
- [ ] `RunOptions` in `src/workflow/orchestrator.rs` gains a `tmux: Option<bool>` field, threaded from `RunArgs`
- [ ] The orchestrator resolves the effective tmux mode: CLI flag overrides config value, config value overrides the default (`false`)
- [ ] When tmux mode is active and `dry_run` is false, the orchestrator calls `tmux::check_tmux_available()` early (before health checks) and fails with `RalphError::TmuxUnavailable` if tmux is not installed
- [ ] `BackendRegistry::new` accepts a new parameter conveying tmux settings (enabled + session name); when enabled, it wraps each `CliBackend` in `TmuxBackend<RealTmuxRunner>` before inserting into the registry
- [ ] When tmux mode is disabled (the default), `BackendRegistry::new` behaves identically to the current implementation — no `TmuxBackend` wrapping, no tmux checks
- [ ] `EffectiveConfig` (or `RunOptions`) carries the resolved tmux settings so the orchestrator can pass them to `BackendRegistry::new`
- [ ] Existing tests pass without modification; new unit tests cover: config deserialization with/without tmux fields, CLI flag parsing (--tmux, --no-tmux, neither), registry construction with tmux wrapping, and the early tmux-availability check
- [ ] The `Backend` trait is not changed

## Files to Modify/Create

- `src/config/global.rs` — Add `tmux: bool` and `tmux_session: String` to `WorkspaceConfig`, update `Default`, ensure `#[serde(default)]` for backward compatibility
- `src/cli/mod.rs` — Add `--tmux` / `--no-tmux` flags to `RunArgs`
- `src/cli/run.rs` — Thread the new tmux flag into `RunOptions`
- `src/workflow/orchestrator.rs` — Add `tmux` field to `RunOptions`, resolve effective tmux mode, call `check_tmux_available()` when enabled, pass tmux settings to `BackendRegistry::new`
- `src/backend/mod.rs` — Update `BackendRegistry::new` signature to accept tmux config; conditionally wrap backends in `TmuxBackend`
- `src/config/mod.rs` — Optionally add tmux fields to `EffectiveConfig` or `EffectiveWorkflowConfig` if needed for cleaner plumbing

- Blocks: Window labeling and UX polish (Feature 4)
