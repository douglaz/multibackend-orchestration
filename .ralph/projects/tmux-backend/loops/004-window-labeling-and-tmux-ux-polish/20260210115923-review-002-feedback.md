# Review: SUGGESTIONS

## Required Changes
1. **Completed-window retention is not reliably effective in default tmux behavior**: `window_keep_seconds` sleeps before cleanup, but completed command windows are launched as direct `new-window` command processes and can close immediately on process exit.
   - Current: `src/backend/tmux.rs:83` creates windows with `tmux new-window ... <shell_command>` and `src/backend/tmux_backend.rs:195` sleeps before kill; there is no `remain-on-exit` handling, so completed windows may not remain inspectable.
   - Expected: ensure completed windows actually stay visible for the configured retention period (for example by enabling `remain-on-exit` for Ralph-managed windows/session, or equivalent command strategy), then clean them up.
   - Reference: Master prompt “Completed windows are kept briefly for inspection, then cleaned up”; spec acceptance criterion on retention behavior.

2. **Window-disappearance handling only checks session existence, not window existence**: a disappeared window in a still-alive session is currently treated as timeout instead of actionable command failure.
   - Current: timeout path in `src/backend/tmux_backend.rs:219` uses `tmux::has_session(...)` (`src/backend/tmux.rs:159`) and returns `BackendTimeout` when the session exists, even if the specific window was externally closed.
   - Expected: detect missing window (not just missing session) and return `BackendCommandFailed` with actionable diagnostics when execution cannot complete because that window vanished before writing the exit file.
   - Reference: Spec acceptance criterion: “If execution cannot complete because the tmux window disappears before an exit file is written, return `BackendCommandFailed` with actionable diagnostics.”

## Recommended Improvements
1. Add a focused test for “session exists but target window disappeared before exit-file write” to lock in the required diagnostic behavior, alongside current missing-session timeout coverage.
