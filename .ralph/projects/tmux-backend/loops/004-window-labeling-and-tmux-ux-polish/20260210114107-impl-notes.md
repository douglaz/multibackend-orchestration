# Implementation Notes

## Decisions Made
- After a thorough audit of every file listed in the spec, all acceptance criteria for Loop 4 are already satisfied by code introduced in Loops 1-3. No new code changes are needed.
- Contextual window labels (`L{loop}-{role}-{backend}`) are generated by `format_window_label()` in `src/backend/tmux.rs:226` and consumed by `build_label()` in `src/backend/tmux_backend.rs:55-62`.
- Label sanitization (invalid character normalization, dash collapsing, truncation to 32 chars) is handled by `sanitize_tmux_label()` in `src/backend/tmux.rs:236-263`.
- The `SharedTmuxContext` / `TmuxExecutionContext` pattern (`src/backend/mod.rs:143-157`) passes loop/role context from the orchestrator to `TmuxBackend` without modifying the `Backend` trait. The orchestrator calls `registry.set_tmux_context(...)` before every backend invocation (planner: `orchestrator.rs:216`, impl initial: `orchestrator.rs:358`, impl feedback: `orchestrator.rs:443`, reviewer: `orchestrator.rs:600`, completer: `orchestrator.rs:844`).
- `workspace.tmux_window_keep_seconds` is defined in `src/config/global.rs:28` with `#[serde(default = "default_tmux_window_keep_seconds")]` defaulting to `5`. It is wired for `config get/set` in `src/cli/config.rs:275-276` and passed to `BackendRegistryTmuxConfig` at `orchestrator.rs:134`.
- Retention delay logic is in `tmux_backend.rs:194-204`: after successful command completion, `TmuxBackend` sleeps for `window_keep_seconds` before cleanup. Immediate cleanup when `0`.
- Missing session at window creation triggers one retry via `create_window_with_retry()` in `tmux.rs:177-197`.
- Best-effort cleanup via `kill_window_best_effort()` in `tmux.rs:202-215` logs a warning instead of failing.
- Timeout/window-disappearance produces `BackendCommandFailed` with actionable diagnostics mentioning the window label, backend command, and session name (`tmux_backend.rs:210-227`).
- `ralph tail --tmux` is implemented in `cli/mod.rs:149` (`--tmux` flag on `TailArgs`) and `cli/tail.rs:118-222` (tmux availability check, session existence check, `tmux attach -t <session>`).
- Non-tmux behavior is completely unchanged: tmux mode is opt-in via config or CLI flags; `Backend` trait is unmodified.

## Spec Deviations
- None. All acceptance criteria are fully satisfied by the existing codebase.

- `src/backend/tmux_backend.rs` unit tests: retention and cleanup behavior, timeout with actionable diagnostics, label building.
