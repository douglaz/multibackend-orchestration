# Implementation Response (Iteration 3)

## Changes Made

1. **Reordered timeout classification before window cleanup** (Required Change 1):
   In `src/backend/tmux_backend.rs`, moved the `has_window()` classification check to occur **before** `kill_window_best_effort()` in the timeout path. Previously (lines 222-237), `kill_window_best_effort` was called at step 6 and `has_window` at step 7; now `has_window` is called at step 5 (immediately after `wait_for_exit` returns `BackendTimeout`) and `kill_window_best_effort` follows at the same step after classification is complete. This ensures that in real tmux, a successful `kill-window` cannot cause `has_window` to falsely report the window as missing, which would misclassify genuine timeouts as `BackendCommandFailed`. The retention delay (step 6) and final cleanup (step 7) now only apply to the success path, since the timeout branch returns early after its own cleanup.

   Updated all mock response sequences in both test files to reflect the new ordering (`has_window` before `kill_window` in timeout paths):
   - `src/backend/tmux_backend.rs`: `execute_genuine_timeout_returns_backend_timeout` and `execute_window_disappeared_returns_actionable_error`
   - `tests/backend_tmux.rs`: `tmux_backend_genuine_timeout_returns_backend_timeout`, `tmux_backend_timeout_with_missing_session_returns_actionable_error`, `tmux_backend_keep_seconds_skipped_on_failure`, `tmux_backend_session_alive_but_window_gone_returns_command_failed`, and `tmux_backend_returns_actionable_error_on_window_disappearance`

   All seven timeout-related tests now model realistic semantics: classification occurs while the window is still in its pre-cleanup state, so `has_window` results are trustworthy.
