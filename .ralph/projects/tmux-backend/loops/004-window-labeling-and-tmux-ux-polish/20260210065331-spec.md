# Feature: Window labeling and tmux UX polish

## Description
Loops 1-3 already delivered tmux session management, `TmuxBackend` execution, and config/CLI enablement. The next missing feature is UX polish: generate contextual tmux window names (`L{loop}-{role}-{backend}`), keep completed windows briefly before cleanup, handle external tmux/session/window interruptions gracefully, and add an explicit tmux attach flow for users (`ralph tail --tmux`).

## Acceptance Criteria
- [ ] In tmux mode, every backend invocation uses a contextual window label in the format `L{loop}-{role}-{backend}` (example: `L3-impl-codex`) instead of the current generic label.
- [ ] Label generation is deterministic and tmux-safe (invalid characters normalized; overly long labels truncated predictably).
- [ ] Orchestrator passes loop/role execution context to `TmuxBackend` without changing the `Backend` trait signature.
- [ ] A new workspace config field controls completed-window retention (for example `workspace.tmux_window_keep_seconds`, default non-zero “brief” duration).
- [ ] After command completion, `TmuxBackend` waits for the configured retention duration before killing the tmux window; `0` means immediate cleanup.
- [ ] If tmux session/window is removed externally during execution, behavior is explicit and recoverable:
- [ ] Missing session at window creation triggers one re-ensure/retry path before failing.
- [ ] Missing session/window during cleanup is treated as best-effort cleanup (warn/log, no hard failure).
- [ ] If execution cannot complete because the tmux window disappears before an exit file is written, return `BackendCommandFailed` with actionable diagnostics (not a silent/ambiguous timeout).
- [ ] `ralph tail --tmux` attaches to the configured tmux session (`tmux attach -t <session>`) and returns a clear error when tmux/session is unavailable.
- [ ] Existing non-tmux and existing artifact-tail behavior remain unchanged when `--tmux` is not used.
- [ ] Tests cover label formatting, retention timing behavior, interruption edge cases, and `tail --tmux` command behavior without requiring real tmux in CI.

## Files to Modify/Create
- `src/backend/tmux_backend.rs` - add contextual label usage, retention-delay cleanup, and robust error handling for external tmux/window loss.
- `src/backend/tmux.rs` - add helper(s) for session/window existence checks and retry-friendly error classification.
- `src/workflow/orchestrator.rs` - provide per-invocation loop/role context to backend execution path.
- `src/config/global.rs` - add `workspace.tmux_window_keep_seconds` with backward-compatible defaulting.
- `src/cli/config.rs` - wire new config key for `config get/set`.
- `src/cli/mod.rs` - add `--tmux` mode to `tail` arguments.
- `src/cli/tail.rs` - implement tmux attach flow while preserving existing artifact-tail functionality.
- `tests/backend_tmux.rs` - add/extend tests for labels, retention, and edge-case handling.
- `tests/orchestrator.rs` - add coverage for context propagation into tmux execution labels.
- `tests/tail.rs` (or new `tests/tail_tmux.rs`) - add tests for `ralph tail --tmux` behavior and failure modes.
