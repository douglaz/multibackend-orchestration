# Implementation Notes

## Decisions Made
- After thorough review of the codebase, all acceptance criteria for Loop 4 were already satisfied by implementations delivered in Loops 1-3. The prior implementers proactively built contextual labels, retention, error handling, and the `tail --tmux` flow alongside the core features.
- No new code changes are required. Each criterion is addressed below with evidence.

## Acceptance Criteria Evidence

### 1. Contextual window labels `L{loop}-{role}-{backend}`
- **Implemented in**: `src/backend/tmux.rs:22-25` — `window_label()` generates the format `L{loop_number}-{role}-{backend}`.
- **Used in**: `src/backend/tmux_backend.rs:176-179` — `execute()` calls `tmux::window_label()` when `TmuxExecContext` is set.

### 2. Label sanitization and truncation
- **Implemented in**: `src/backend/tmux.rs:16,29-45` — `MAX_LABEL_LEN = 32`, `sanitize_label()` replaces non-`[A-Za-z0-9_-]` with `_` and truncates.
- **Tests**: `tmux.rs::tests::window_label_normalizes_invalid_chars`, `window_label_truncates_long_labels`, `sanitize_label_preserves_alnum_dash_underscore`, `sanitize_label_replaces_dots_and_spaces`.

### 3. Orchestrator passes loop/role context without changing Backend trait
- **Implemented in**: `src/backend/mod.rs:32-33` — `Backend` trait has a default no-op `set_tmux_exec_context()`.
- **Orchestrator calls**: `src/workflow/orchestrator.rs` lines 215-218 (planner), 355-358 and 435-438 (implementer), 590-593 (reviewer), 831-834 (completer).
- **TmuxBackend overrides**: `src/backend/tmux_backend.rs:264-266`.
- **CliBackend is unaffected**: uses the trait default no-op.

### 4. `workspace.tmux_window_keep_seconds` config field
- **Implemented in**: `src/config/global.rs:27-28` with `#[serde(default = "default_tmux_window_keep_seconds")]` and default value of `5` (line 97, 144-146).
- **Wired in config CLI**: `src/cli/config.rs:275-277` — `set_global_value` handles `workspace.tmux_window_keep_seconds`.
- **Tests**: `global.rs::tests::default_workspace_tmux_settings_match_expected_values`, `deserializes_workspace_tmux_defaults_when_fields_are_missing`.

### 5. Retention delay before killing window; `0` means immediate
- **Implemented in**: `src/backend/tmux_backend.rs:203-205` — after successful `wait_result`, sleeps for `window_keep_seconds` if non-zero.
- **Builder**: `with_keep_seconds()` at line 48-51; wired through `BackendRegistryTmuxConfig` at `mod.rs:155,243`.
- **Orchestrator passes config value**: `orchestrator.rs:134`.

### 6. Missing session at window creation triggers re-ensure/retry
- **Implemented in**: `src/backend/tmux.rs:220-240` — `create_window_with_retry()` catches session-missing errors from `create_window()`, calls `ensure_session()`, and retries once.
- **Used in**: `src/backend/tmux_backend.rs:190-196`.
- **Tests**: `tmux.rs::tests::create_window_with_retry_retries_on_missing_session`, `create_window_with_retry_propagates_non_session_errors`; integration test `tests/backend_tmux.rs::tmux_backend_retries_window_creation_on_session_loss`.

### 7. Missing session/window during cleanup is best-effort
- **Implemented in**: `src/backend/tmux.rs:189-202` — `kill_window_best_effort()` warns on failure instead of returning error.
- **Used in**: `src/backend/tmux_backend.rs:206`.
- **Tests**: `tmux.rs::tests::kill_window_best_effort_does_not_fail_on_error`; integration test `tests/backend_tmux.rs::tmux_backend_cleanup_ignores_missing_window`.

### 8. Window disappearance returns `BackendCommandFailed` with diagnostics
- **Implemented in**: `src/backend/tmux_backend.rs:210-233` — after timeout, checks `has_session()`; if session is gone and no exit file, returns `BackendCommandFailed` with message mentioning "disappeared" and "Re-run the command to retry".
- **Tests**: `tests/backend_tmux.rs::tmux_backend_window_disappeared_gives_actionable_error`.

### 9. `ralph tail --tmux` attaches to tmux session
- **CLI flag**: `src/cli/mod.rs:148-149` — `--tmux` boolean on `TailArgs`.
- **Implementation**: `src/cli/tail.rs:119-121` (early return for tmux path), `tail.rs:177-213` (`execute_tmux_attach()`) — checks tmux availability, verifies session exists, runs `tmux attach -t <session>`.
- **Tests**: `tests/tail_tmux.rs` — argument parsing tests for `--tmux` with/without other flags.

### 10. Non-tmux behavior unchanged
- The `--tmux` flag on `tail` defaults to `false` (line 149). Without it, `execute()` falls through to existing artifact-tail logic (line 123+).
- `CliBackend::set_tmux_exec_context` is a no-op default (mod.rs:33), so non-tmux backends are unaffected.

### 11. Test coverage
- **Label tests**: `tmux.rs::tests` — 6 tests covering basic format, normalization, truncation, determinism.
- **Retention**: `tmux_backend.rs::tests` and integration tests cover `with_keep_seconds` builder. The delay path is exercised; `0` means the sleep is skipped.
- **Interruption edge cases**: `tests/backend_tmux.rs` — retry on session loss, best-effort cleanup, window disappeared detection.
- **Tail --tmux**: `tests/tail_tmux.rs` — 5 parsing tests.
- **Context propagation**: `tests/backend_tmux.rs::tmux_backend_uses_contextual_label_when_context_set`, `set_tmux_exec_context_via_trait`, `tmux_backend_falls_back_to_generic_label_without_context`.
- **Orchestrator tmux tests**: `tests/orchestrator.rs::tmux_mode_fails_early_when_tmux_is_unavailable`, `tmux_mode_dry_run_skips_tmux_availability_check`.
