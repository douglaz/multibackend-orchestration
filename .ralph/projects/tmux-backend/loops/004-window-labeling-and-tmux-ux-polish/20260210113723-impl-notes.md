# Implementation Notes

## Decisions Made

1. **SharedTmuxContext via Arc<Mutex>**: To pass loop/role context from the orchestrator to TmuxBackend without modifying the `Backend` trait signature, we introduced `SharedTmuxContext` (an `Arc<Mutex<TmuxExecutionContext>>` wrapper) shared between `BackendRegistry` and all `TmuxBackend` instances. The orchestrator calls `registry.set_tmux_context(...)` before each backend invocation, and `TmuxBackend::execute()` consumes the context with `take()`.

2. **Window label format**: Labels use the format `L{loop}-{role}-{backend}` (e.g., `L3-impl-codex`). The `sanitize_tmux_label()` function replaces any non-alphanumeric, non-dash, non-underscore character with a dash, avoids consecutive replacement dashes, strips trailing dashes, and truncates to 32 characters. When no context is available, the label falls back to `ralph-{backend_name}`.

3. **Retention delay placement**: The `tmux_window_keep_seconds` delay is applied only on successful execution (exit file written), and only when the value is non-zero. This avoids blocking on failures or timeouts. The delay occurs between reading the exit file and the best-effort cleanup.

4. **Timeout mapped to actionable error**: `BackendTimeout` from `wait_for_exit()` is mapped to `BackendCommandFailed` with a message explaining the tmux window may have been closed externally, including the session name and command for debugging. This is more actionable than a generic timeout.

5. **Best-effort window cleanup**: `kill_window_best_effort()` logs a `warn!` on failure instead of returning an error. This ensures that externally-removed windows never cause a hard failure during cleanup.

6. **Window creation retry**: `create_window_with_retry()` catches "session missing" errors on the first `create_window()` attempt, re-ensures the session, and retries once. This handles the race condition where a session disappears between `ensure_session()` and `create_window()`.

7. **Role labels in orchestrator**: The orchestrator uses these role labels for `set_tmux_context()`: `"planner"`, `"impl"` (for implementer), `"reviewer"`, `"completer"`. The `"impl"` abbreviation keeps labels short and tmux-friendly.

8. **Default `tmux_window_keep_seconds`**: Set to `5` seconds. This gives users a brief window to inspect completed tmux windows before cleanup, while not blocking the orchestrator for too long. A value of `0` means immediate cleanup.

9. **`ralph tail --tmux` implementation**: The `--tmux` flag on `tail` does an early return before any project/artifact logic. It discovers the workspace config, checks tmux availability, verifies the session exists, and runs `tmux attach -t <session>` as a blocking child process. Clear error messages guide the user when tmux is not installed or the session doesn't exist yet.

## Spec Deviations

1. **No separate `has_window()` function**: The spec mentioned "session/window existence checks". We implemented `has_session()` but did not add a dedicated `has_window()` function since window existence is implicitly checked during `create_window_with_retry()` and `kill_window_best_effort()`. Adding it would be unused overhead.

2. **Dash collapsing in sanitizer**: The `sanitize_tmux_label()` function collapses consecutive dashes that are *produced by replacements* (i.e., prevents a replacement dash from being added if the previous character was already a dash). However, it does **not** collapse consecutive dashes that already exist in the original input (e.g., `"a--b"` stays as `"a--b"`). This is a minor difference from a strict "collapse all dashes" interpretation but preserves intentional input patterns.

3. **`execute_tmux_attach()` uses `std::process::Command`**: The spec mentioned `tmux attach`. We use a synchronous `std::process::Command` (not `tokio::process::Command`) for the final `tmux attach` call because it needs to inherit the terminal's stdin/stdout/stderr for interactive use. The session existence check still uses async `tokio::process::Command`.
