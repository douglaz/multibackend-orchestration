# Review: SUGGESTIONS

## Required Changes
1. **Contextual tmux labels are not preserved across retry invocations**: retries can fall back to generic labels instead of `L{loop}-{role}-{backend}`.
Current: `TmuxBackend` consumes context via `take()` (`src/backend/tmux_backend.rs:160`, `src/backend/mod.rs:154`), while orchestrator sets context once before `execute_with_parse_retries` (`src/workflow/orchestrator.rs:215`, `src/workflow/orchestrator.rs:1513`), which may call backend execution multiple times.
Expected: preserve or reapply loop/role context for every backend execution attempt in tmux mode (including parse/timeout retries), so labels remain contextual on all invocations.
Reference: Feature spec acceptance criteria “every backend invocation uses contextual window label” and “orchestrator passes loop/role context without changing Backend trait”.

2. **`BackendRegistryTmuxConfig` update breaks existing test constructors**: integration tests still construct the old struct shape.
Current: new required field `window_keep_seconds` exists (`src/backend/mod.rs:166`), but struct literals in `tests/backend.rs:15` and `tests/backend.rs:224` omit it.
Expected: update test helpers to include `window_keep_seconds` (and keep existing behavior expectations).
Reference: Master prompt constraint “All existing tests must continue to pass without modification.”

3. **Acceptance-required test coverage is incomplete**: retention timing and `tail --tmux` runtime behavior are not covered.
Current: tmux backend tests pass `window_keep_seconds = 0` and do not assert keep-delay behavior (`src/backend/tmux_backend.rs:311` onward), and `tests/tail_tmux.rs:1` only validates CLI parsing (no attach/error-path behavior).
Expected: add tests for keep-delay (`>0`) vs immediate cleanup (`0`), plus `tail --tmux` behavior/failure modes (tmux unavailable, missing session, attach failure) using stubs/mocks.
Reference: Feature spec acceptance criteria final test bullet.

4. **One new sanitizer test is inconsistent with implementation behavior**.
Current: `sanitize_tmux_label_collapses_dashes` expects `"a--b---c"` to collapse (`src/backend/tmux.rs:535`), but the sanitizer preserves existing hyphens and only normalizes invalid-character runs (`src/backend/tmux.rs:248`).
Expected: align test expectation with actual intended behavior (or adjust sanitizer/docs so behavior and tests are consistent).
Reference: Feature spec acceptance criteria on deterministic/tmux-safe label formatting.

## Recommended Improvements
1. Distinguish true backend timeout vs external tmux/window disappearance. Right now all `BackendTimeout` from wait are remapped to `BackendCommandFailed` (`src/backend/tmux_backend.rs:210`), which bypasses orchestrator timeout-retry logic (`src/workflow/orchestrator.rs:1574`).
