# Feature: Deterministic tmux preflight test isolation

## Description
Loops 1-4 delivered the functional tmux backend behavior (session/window management, `TmuxBackend`, config/CLI wiring, and UX polish). The remaining blocker is completion-gate reliability: `tests/orchestrator.rs` currently simulates missing tmux by mutating process-wide `PATH`, which races with parallel tests that invoke `git` and causes intermittent failures (for example `dry_run_does_not_checkout_project_branch`).  
This feature adds a testability seam for tmux availability checks and refactors orchestrator integration tests to stop mutating global environment state, while keeping runtime behavior unchanged.

## Acceptance Criteria
- [ ] `Orchestrator::new` continues to use real `tmux::check_tmux_available` in production (no behavior change for users).
- [ ] Orchestrator exposes a test-friendly injection path for tmux preflight checking (e.g., constructor or setter) so tests can force `Ok`/`Err(TmuxUnavailable)` without touching `PATH`.
- [ ] `tests/orchestrator.rs` tmux preflight tests are rewritten to use injected checkers instead of `PathGuard::set("")`.
- [ ] The preflight integration tests still verify both behaviors: tmux-enabled non-dry-run fails early with `RalphError::TmuxUnavailable`, and dry-run skips tmux preflight.
- [ ] Process-wide `PATH` mutation is removed from orchestrator tests (or fully isolated behind serialization that covers all path-sensitive tests in that binary).
- [ ] Running `cargo test --test orchestrator -- --test-threads=16` is stable across repeated runs in the Nix dev shell.
- [ ] `nix build` passes after the refactor, satisfying the prompt constraint that existing tests continue to pass.

## Files to Modify/Create
- `src/workflow/orchestrator.rs` - add tmux preflight checker injection mechanism with default real checker path.
- `tests/orchestrator.rs` - replace PATH-mutation tmux tests with injected-checker tests; remove obsolete PATH race scaffolding.
- `tests/backend.rs` - align any shared PATH-test helper usage if needed to keep test approach consistent and race-free.
- `flake.nix` - update check/stress command wiring if needed to codify parallel orchestrator test verification.
