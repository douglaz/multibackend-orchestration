# Feature: Extend LogWriter with prompt-hash separator and validation footer

## Description
Add the missing `output_log.rs` primitives that all downstream wiring depends on: a prompt-hash-aware attempt separator (`write_attempt_separator_with_prompt`), a validation footer formatter/writer (`format_validation_footer` / `write_validation_footer`), and a prompt SHA-256 helper. These extend `LogWriter` in a backward-compatible way — the existing `write_attempt_separator` (no hash) continues to work unchanged for callers that don't supply a prompt.

## Acceptance Criteria
- [ ] `format_attempt_separator` accepts an optional `prompt_sha256: Option<&str>` parameter and, when `Some`, appends `prompt_sha256=<hex>` to the separator line
- [ ] Existing `format_attempt_separator` calls (4 args, no hash) continue to compile unchanged — backward compatibility preserved via a new `format_attempt_separator_with_prompt` function or by adding the optional param to the existing function with a default
- [ ] `LogWriter::write_attempt_separator_with_prompt(&mut self, backend_label: &str, is_fallback: bool, prompt: &str)` computes SHA-256 of the prompt's UTF-8 bytes (lowercase hex) and writes a separator including `prompt_sha256=<hash>`
- [ ] `LogWriter::write_attempt_separator` (existing) continues to work identically (no hash in output)
- [ ] `format_validation_footer(passed: bool, missing: &[String]) -> String` returns exactly `\n--- validation=pass missing=[] ---\n` on pass, or `\n--- validation=fail missing=[section1,section2] ---\n` on fail (comma-separated, no spaces, deterministic)
- [ ] `LogWriter::write_validation_footer(&mut self, passed: bool, missing: &[String])` appends the formatted footer to the log
- [ ] `compute_prompt_sha256(prompt: &str) -> String` utility returns lowercase hex SHA-256 of prompt's UTF-8 bytes
- [ ] Unit test: separator includes `prompt_sha256=<expected_hex>` when prompt is provided
- [ ] Unit test: legacy separator (no hash) unchanged — exact existing format preserved
- [ ] Unit test: validation footer pass produces exact string `--- validation=pass missing=[] ---`
- [ ] Unit test: validation footer fail with `["Milestones", "Requirements"]` produces exact string `--- validation=fail missing=[Milestones,Requirements] ---`
- [ ] Unit test: `compute_prompt_sha256("hello")` returns the known SHA-256 of `"hello"` (`2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824`)
- [ ] Unit test: `LogWriter::write_validation_footer` appends to log file correctly
- [ ] All existing `output_log` tests pass without modification

## Files to Modify/Create
- `src/output_log.rs` — Add `compute_prompt_sha256`, `format_attempt_separator_with_prompt`, `format_validation_footer`, `LogWriter::write_attempt_separator_with_prompt`, `LogWriter::write_validation_footer`; add corresponding unit tests to the existing `#[cfg(test)] mod tests` block

- Blocks: Interactive PRD wiring (log creation in `interactive_prd.rs`), reviewer retry logging (`prd/quick.rs`), conformance tests (`validate/tests_interactive_prd_logging.rs`)
