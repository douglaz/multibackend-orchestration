# Feature: Interactive PRD Runtime Logging Wiring and Reviewer Retry Integration

## Description
Loop 1 completed the `output_log.rs` primitives. The next feature is wiring those primitives into live interactive PRD execution: create per-issue PRD log files, log every questions/draft/revision backend call, and update reviewer retry logic so every internal retry attempt is logged (including parse-failure retries), while keeping `None`-writer behavior unchanged for existing Quick PRD callers.

## Acceptance Criteria
- [ ] Add a single interactive-PRD log directory source of truth in `interactive_prd.rs`: `config.repo_clone_path().join(".ralph").join("tmp").join("logs")`.
- [ ] Thread `issue_number: u32` through interactive generation helpers so log file names are deterministic and issue-scoped.
- [ ] Questions phase logs raw outputs to:
- [ ] `prd-{issue}-questions-a.log`
- [ ] `prd-{issue}-questions-b.log`
- [ ] `prd-{issue}-questions-synth.log`
- [ ] Draft/revision phases log raw outputs to:
- [ ] `prd-{issue}-draft-writer.log`
- [ ] `prd-{issue}-draft-reviewer.log`
- [ ] `prd-{issue}-revision-writer.log`
- [ ] `prd-{issue}-revision-reviewer.log`
- [ ] All interactive backend attempts write separators with `write_attempt_separator_with_prompt(...)` so `prompt_sha256` is present.

- [ ] Unit tests in `interactive_prd.rs` cover success logging, section-failure retry logging + fail footer, pass footer, timeout footer, expected filenames, and logging I/O failure tolerance.
