# Implementation Notes

## Decisions Made
- Extended `TmuxExecutionContext` with `loop_dir: Option<PathBuf>` and threaded it through all orchestrator `set_tmux_context` callsites, using `None` for prompt reviewer/planner and loop-scoped `Some(...)` paths for implementer/QA/reviewer/completer/acceptance QA.
- Added `CLI_OUTPUT_COUNTER: AtomicU64` in `src/backend/mod.rs` and implemented shared helpers to build `{YYYYMMDDHHMMSS}-agent-output-{role}-{counter}.log` filenames and persist log artifacts with metadata + stdout/stderr sections.
- Wired artifact persistence directly into backend execution points:
  - `CliBackend::execute`: immediately after `wait_with_output()` and before status interpretation.
  - `TmuxBackend::execute`: after reading captured output and before exit-code interpretation.
- Kept persistence best-effort by design: write failures log `warn!` and never change backend return behavior; intentional skips (`loop_dir: None`, timeout without output, spawn failure) emit `debug!`; successful writes emit `info!` with full path/backend/role.
- Added unit coverage in `src/backend/mod.rs` for success, non-zero exit, `loop_dir: None`, filename format, counter uniqueness, timeout, and spawn-failure behavior.
- Added validate conformance tests in `src/validate/tests_run.rs`:
  - `run::agent_output_artifacts`
  - `run::planner_no_agent_output`
- Preserved unrelated existing worktree changes outside this feature scope.
