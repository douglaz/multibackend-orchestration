# Feature: Persist Backend CLI Output Logs as Loop Artifacts

## Description
Add a post-mortem debug artifact system that writes one `.log` file per backend CLI invocation when loop-scoped context is available. Each artifact captures raw stdout, stderr, and metadata (backend name, role, exit status) so that operators can diagnose malformed responses, parse retries, and fast retry sequences from the loop directory. The feature uses a process-scoped atomic counter for filename uniqueness and is entirely best-effort — write failures never alter orchestration behavior.

## Implementation Notes

### Architecture Decision: Where to Write Artifacts
The artifact write must happen inside `CliBackend::execute()` and `TmuxBackend::execute()` (not in the orchestrator), because:
1. The prompt requires writing "immediately after `wait_with_output()` returns and before backend result is interpreted"
2. `CliBackend::execute()` currently discards stderr on success (only returns stdout) and discards stdout on failure (only returns stderr in the error). The raw `Output` struct with both streams is only available inside `execute()`.
3. Both `CliBackend` and `TmuxBackend` need artifact writing since either may be the active backend.

### Accessing Context from CliBackend
`CliBackend` currently has no access to the `SharedTmuxContext`. To read `loop_dir` and `role`:
- Add a new `SharedOutputContext` (or rename/extend `SharedTmuxContext` to `SharedExecutionContext`) containing `loop_dir: Option<PathBuf>` and `role: Option<String>`.
- Pass this shared context to both `CliBackend` and `TmuxBackend` at construction time in `BackendRegistry::new()` and `backend_with_optional_tmux()`.
- The orchestrator sets context before each invocation (already does this for tmux context).

**Alternatively** (simpler): Rename `SharedTmuxContext`/`TmuxExecutionContext` to `SharedExecutionContext`/`ExecutionContext`, add `loop_dir` to it, and thread it through `CliBackend` as well. This avoids a second shared-context type while keeping the existing pattern.

### File Content Format
```
=== Backend Output Log ===
backend: claude
role: implementer
exit_status: 0

=== STDOUT ===
<raw stdout as lossy UTF-8>

=== STDERR ===
<raw stderr as lossy UTF-8>
```

### Counter Pattern
```rust
static CLI_OUTPUT_COUNTER: AtomicU64 = AtomicU64::new(0);
```
Reuses the same `AtomicU64 + Relaxed` pattern from `INVOCATION_COUNTER` in `tmux_backend.rs`.
