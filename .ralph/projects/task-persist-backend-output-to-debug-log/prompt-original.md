The revised specification has been written to `draft.md`. Here's how each review issue was addressed:

**Issue 1 (tail -f and log visibility):** Removed the contradictory claim that operators can `tail -f` during execution. The summary now explicitly states output files are "post-mortem debug artifacts" written after `wait_with_output()` returns. Streaming is listed in Out of Scope. Log level changed from `debug!` to `info!` so paths appear in normal operator logs. The AC item now says "logged at `info!` level when files are written" rather than "before invocation starts."

**Issue 2 (Path resolution / planner slug unavailability):** Replaced the `project_dir` + `loop_slug` context shape with a single `loop_dir: Option<PathBuf>` field. The orchestrator sets `loop_dir: None` for the planner callsite (where slug doesn't exist yet) and `loop_dir: Some(...)` for all post-planning callsites where the directory is already known. A callsite-by-callsite table documents which gets `None` vs `Some`. Planner output capture is explicitly called out in Out of Scope with rationale.

**Issue 3 (Filename collisions):** Added a `static CLI_OUTPUT_COUNTER: AtomicU64` (reusing the existing pattern from `tmux_backend.rs:14`). The counter value is appended to every filename: `{timestamp}-agent-output-{role}-{counter}.log`. This guarantees uniqueness across same-second retries (parse retries, QA iterations, timeout retries with fast backoff). A dedicated unit test (#5) validates uniqueness across rapid invocations.

**Issue 4 (Timeout/spawn failure coverage):** Added a new Technical Approach section (§5) explicitly covering both paths. Timeout: no output available from `wait_with_output()`, so no files written, `debug!` log emitted. Spawn failure: no process output exists, no files written. Two new AC items codify this. Unit test #7 validates the timeout case.

**Issue 5 (Timestamp prefix vs suffix):** Aligned with the existing artifact convention — filenames now use timestamp as **prefix**: `{YYYYMMDDHHMMSS}-agent-output-{role}-{N}.log`, matching `{YYYYMMDDHHMMSS}-spec.md`, `{YYYYMMDDHHMMSS}-impl-notes.md`, etc. AC item #3 explicitly states this consistency requirement.

**Issue 6 (Testing completeness):** Added conformance tests in `src/validate/tests_run.rs` per the project guideline ("Every new feature should add coverage in `src/validate/`"). Test #9 validates output files are created end-to-end. Test #10 validates the planner no-slug path produces no files. Unit tests now cover collision/uniqueness (#5), timeout behavior (#7), timestamp-prefix format (#6), and the absent-context path (#3, #4). AC includes a conformance test requirement.
