# Implementation Notes

## Decisions Made
- `is_retryable_push_error` extracts stderr by parsing the canonical `"git push failed for branch {branch}: {stderr}"` format from the `RalphError`'s display string, splitting on `: ` after the branch name segment. This ensures the branch name (which may contain numeric codes like `403` or `500`) is excluded from classification.
- Kept `is_retryable_push_stderr` as the internal classification engine and had `is_retryable_push_error` delegate to it after extraction. This avoids duplicating pattern lists and keeps the existing direct-stderr tests valid.
- Non-push `RalphError` variants and malformed push error messages (missing `"git push failed for branch "` prefix or `": "` separator) return `false` (non-retryable), matching the spec's "non-push/unknown error fallback to non-retryable" requirement.
- `push_branch_with_retry_impl` now constructs the `RalphError::Orchestration` immediately on push failure, then passes it to `is_retryable_push_error` for the retry decision. The error is returned directly if non-retryable or attempts are exhausted, avoiding reconstruction.

## Spec Deviations
- The spec requests the signature `is_retryable_push_error(err: &RalphError) -> bool` with a non-`self` function. The implementation matches this exactly as `pub fn is_retryable_push_error(err: &RalphError) -> bool` (free function, not a method on `RalphError`).

## Testing
- 4 new unit tests added covering all spec requirements:
  - `is_retryable_push_error_classifies_transient_and_permanent` — HTTP 5xx, timeout, connection reset (retryable) vs permission denied, non-fast-forward, GH013, HTTP 403 (non-retryable)
  - `is_retryable_push_error_branch_name_collision_safety` — branch `fix/issue-403` with transient stderr is retryable; branch `feature/500-errors` with permanent stderr is non-retryable
  - `is_retryable_push_error_non_push_error_fallback` — non-push `Orchestration` errors, `Validation` errors, and malformed messages all return `false`
  - `is_retryable_push_error_unknown_stderr_is_non_retryable` — unknown/unparseable stderr defaults to non-retryable
- All 5 existing `push_branch_with_retry_impl` tests continue to pass (they now exercise the `is_retryable_push_error` path implicitly)
- Full suite: 876 tests pass, 0 failures
