# Feature: Daemon Resilience Hardening (Log Preservation, Push Retry, Watcher Timeout)

## Description
Implement three independent resilience fixes for the Ralph daemon: (1) preserve log output across retriggers by switching to append mode with timestamped separators, (2) add retry logic with backoff for transient git push failures and propagate final failures instead of swallowing them, (3) bound watcher teardown time so stuck watchers cannot block task completion indefinitely.

## Acceptance Criteria
- [ ] `build_ralph_auto_command()` and `build_ralph_run_command()` in `process.rs` open log files in append mode (`OpenOptions::new().create(true).append(true)`) instead of `File::create()`
- [ ] When an existing log file has content, a separator `--- retrigger at <YYYY-MM-DDTHH:MM:SSZ> ---` is written on its own line with blank lines around it before new output begins
- [ ] Separator write failure emits a warning to stderr (including file path and error) but does not fail command construction
- [ ] `is_retryable_push_error(err: &RalphError) -> bool` in `github.rs` correctly classifies transient errors (HTTP 5xx, timeout, connection/network/DNS) as retryable and permanent errors (auth denied, non-fast-forward, protected-branch) as non-retryable
- [ ] `push_branch_with_retry(worktree_path, branch)` and `push_branch_with_retry_impl(git_bin, worktree_path, branch, delays_secs)` are added in `github.rs` with deterministic backoff `[10, 20, 40]` (4 total attempts)
- [ ] Existing `push_branch()` is preserved for backward compatibility
- [ ] `handle_pr_flow()` in `runtime.rs` uses `push_branch_with_retry` and propagates failure via `?` (no longer returns `Ok(())` on push failure)
- [ ] `draft_pr_watcher_with_sleep()` in `runtime.rs` uses `push_branch_with_retry`; gating behavior unchanged (no PR creation when push fails)
- [ ] After retry exhaustion, caller of `handle_pr_flow()` logs best-effort warning and still performs lifecycle label swap (`ralph:in-progress` → `ralph:failed`)
- [ ] `WATCHER_TEARDOWN_TIMEOUT` constant (`Duration::from_secs(30)`) added in `runtime.rs`
- [ ] `await_watcher_with_timeout(join_handle, watcher_name, task_id)` helper added: uses `tokio::time::timeout`, logs warning on join error, aborts task and logs warning on timeout

## Implementation Notes

### process.rs: Log Append Mode
- Extract a helper (e.g., `open_log_file_append`) that handles: open in append mode, check file length > 0, write separator if non-empty, return file handle
- Separator format: `\n--- retrigger at 2026-03-04T02:15:00Z ---\n\n` (blank line before separator, blank line after)
- Use `chrono::Utc::now().format("%Y-%m-%dT%H:%M:%SZ")` or `std::time::SystemTime` with manual formatting if chrono is not available
- On separator write failure: `eprintln!("warning: failed to write retrigger separator to {path}: {err}")` then continue
- The `file.try_clone()` pattern for stdout/stderr redirect is preserved unchanged

### github.rs: Push Retry
- `is_retryable_push_error` inspects `RalphError`'s string message (since errors come from git stderr). Match patterns:
  - Retryable: `"500"`, `"502"`, `"503"`, `"504"`, `"timeout"`, `"timed out"`, `"connection refused"`, `"connection reset"`, `"network"`, `"dns"`, `"resolve host"`, `"Could not resolve"`, `"unable to access"` (transient access failures)
  - Non-retryable: `"permission denied"`, `"authentication"`, `"non-fast-forward"`, `"protected branch"`, `"denied"`, `"forbidden"`
  - Default: retryable (fail-safe: retry unknown errors)
- `push_branch_with_retry_impl` takes `delays_secs: &[u64]` so tests can pass `&[0, 0, 0]` for instant retry
- Use `std::thread::sleep` for delays (this runs in blocking context via `spawn_blocking_op`)
- `push_branch_with_retry` calls `push_branch_with_retry_impl("git", path, branch, &[10, 20, 40])`
- Log each retry attempt number and delay to stderr

### runtime.rs: Watcher Timeout
- `await_watcher_with_timeout` signature: `async fn await_watcher_with_timeout(handle: tokio::task::JoinHandle<()>, watcher_name: &str, task_id: &str)`
- On `Ok(Ok(()))`: silent success
- On `Ok(Err(join_err))`: `eprintln!("warning: {watcher_name} join failed for {task_id}: {join_err}")`
- On `Err(_elapsed)`: `handle.abort(); eprintln!("warning: {watcher_name} teardown timed out for {task_id}, aborted")`
- Apply to all 4 watcher join points (2 in `collect_children`, 2 in `kill_aborted_children`)

### runtime.rs: Push Failure Propagation
- In `handle_pr_flow()`, change the push match block from `Err(err) => { eprintln!(...); return Ok(()); }` to `Err(err) => { return Err(err); }`
- The caller of `handle_pr_flow()` must catch this error, log it as a warning, and still proceed with lifecycle label swap

### State Invariants
- **Log separator failure**: Command construction succeeds; file handle is valid for stdout/stderr redirect regardless of separator write outcome
- **Push retry exhaustion in `handle_pr_flow()`**: Returns `Err`; caller logs warning and proceeds with `ralph:in-progress` → `ralph:failed` label swap. PR creation is skipped but lifecycle transition is not blocked.
- **Push retry exhaustion in `draft_pr_watcher_with_sleep()`**: `push_ok` is `false`; PR creation is skipped; watcher continues polling on next interval (existing gating behavior preserved)
- **Watcher timeout**: Task is aborted via `handle.abort()`; warning is logged; `collect_children()`/`kill_aborted_children()` proceed to next child without blocking. Label transitions still occur.
- **Watcher join error (non-timeout)**: Warning logged; execution continues normally
