# Feature: Context-Aware Git Push Retry Classification

## Description
Completed loops already delivered append-mode log preservation, retry-capable push flow, error propagation, and bounded watcher teardown. The remaining gap is the accepted final-review amendment `DAEMON-PUSH-RETRY-CLASSIFIER-001`: harden `git push` retry classification in `src/daemon/github.rs` so retryability is determined from explicit HTTP/error context in stderr, not raw numeric substring collisions (for example `403`/`500` inside repo URLs), while preserving existing retry/backoff behavior.

## Acceptance Criteria
- [ ] Update push stderr classification to parse HTTP codes only from explicit transport-error context (for example `http 503`, `returned error: 503`, similar bounded forms), not from arbitrary numeric substrings in stderr.
- [ ] Classify auth/permission/policy failures as non-retryable, including explicit HTTP `401` and `403`, plus existing permanent patterns (`permission denied`, `non-fast-forward`, `protected branch`, `GH013`, `repository rule violation`, `repository not found`).
- [ ] Keep transient failures retryable (`5xx`, timeout/timed out, connection reset/refused, DNS/resolve host/network errors), even when stderr contains URLs/paths with digits like `403` or `500`.
- [ ] Failure-mode invariants: permanent classification returns failure on the first attempt (no retry sleep); transient classification uses the existing deterministic schedule `[10, 20, 40]` and only fails after retry exhaustion.
- [ ] Add regression tests for: DNS error with URL containing `403` (retryable), explicit HTTP `401` (non-retryable), explicit HTTP `503` (retryable), explicit HTTP `403` (non-retryable), and URL containing `500` plus HTTP `401` (non-retryable).
- [ ] Preserve public API/behavior contracts (`is_retryable_push_error`, `push_branch_with_retry`, `push_branch_with_retry_impl`) and keep existing tests green.

## Files to Modify/Create
