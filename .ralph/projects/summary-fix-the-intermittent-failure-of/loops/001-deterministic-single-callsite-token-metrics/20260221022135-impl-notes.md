# Implementation Notes

## Decisions Made
- Replaced the 8-arm `match` in `log_parse_retry_token_metrics` with exactly one `info!()` callsite that always logs `tokens_in`, `tokens_out`, `cached_in` as `u64` (default `0`) plus `tokens_in_present`, `tokens_out_present`, `cached_in_present` as `bool`, while preserving existing context fields and message text `"parse-retry normalization metrics"`.
- Updated parse-retry metrics capture test types in `src/workflow/orchestrator.rs`:
  - `ParseRetryMetricsEvent` now stores numeric token values and `*_present` booleans (replacing `*_seen`).
  - `MetricsVisitor` now captures numeric values in `record_u64`/`record_i64`, presence/session flags in `record_bool`, removes `mark_token_field`, and no longer depends on `record_debug` for token detection.
  - Updated `MetricsCaptureLayer::on_event` mapping to populate new event fields from visitor state.
- Updated `parse_retry_attempts_four_with_session_followup_and_token_metrics` assertions to verify:
  - exactly 4 events,
  - attempts `[1, 2, 3, 4]`,
  - `session_reused` `[false, true, false, false]`,
  - attempt 1 presence flags `true/true/true` with values `11/22/33`,
  - attempts 2-4 presence flags `false/false/false` with values `0/0/0`.
- Added a small test-only tracing init helper (`ensure_test_tracing_subscriber`) used by the two parse-retry tests and a `tracing::callsite::rebuild_interest_cache()` call in the capture test to keep capture deterministic under parallel test execution.
