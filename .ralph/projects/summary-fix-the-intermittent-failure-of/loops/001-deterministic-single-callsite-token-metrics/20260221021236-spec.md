# Feature: Deterministic single-callsite token-metrics logging

## Description
Refactor `log_parse_retry_token_metrics` to emit exactly one `info!()` tracing callsite for all token-presence combinations, replacing the current 8-way `match` that creates 8 separate callsites. The root cause of the intermittent test failure is that different `info!()` macro invocations create distinct tracing callsites with potentially different field orderings. Under glibc vs musl, the `tracing` subscriber visitor may encounter fields in different orders or skip `Empty`-valued fields inconsistently, causing the `MetricsVisitor` to sometimes miss fields that are actually present.

The fix collapses all branches into a single `info!()` that always emits: numeric `tokens_in`, `tokens_out`, `cached_in` (using `0` when the `Option` is `None`) and boolean `tokens_in_present`, `tokens_out_present`, `cached_in_present` flags. The `ParseRetryMetricsEvent` and `MetricsVisitor` structs are updated to capture both the numeric values and the boolean presence flags via `record_bool`. The test is updated to assert on the new deterministic field structure.
