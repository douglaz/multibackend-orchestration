# Feature: Durable Session Store Persistence

## Description
Persist the in-memory `SessionStore` to `<project_dir>/session-store.json` so that session reuse survives process restarts and cross-process commands like `ralph rollback`. Every mutation to the session store is followed by an immediate write to disk. During project-state reconstruction, the persisted file is loaded if present and valid, with graceful fallback to an empty store on missing or corrupt files. Rollback and prompt-change invalidation flows also persist their resulting state.

## Acceptance Criteria
- [ ] A constant `SESSION_STORE_FILE = "session-store.json"` is defined in `src/project/lifecycle.rs`.
- [ ] A public function `persist_session_store(project_dir: &Path, store: &SessionStore) -> Result<()>` writes the store as pretty-printed JSON to `<project_dir>/session-store.json`, returning `Err` on write failure.
- [ ] `reconstruct_project_state_internal` loads and parses `session-store.json` into `state.session_store` when the file exists and is valid JSON.
- [ ] Missing `session-store.json` during reconstruction silently yields an empty `SessionStore` (no log, no crash).
- [ ] Corrupt/invalid JSON in `session-store.json` during reconstruction yields an empty `SessionStore` with a `warn`-level log message, no crash.
- [ ] In `src/workflow/orchestrator.rs`, every call site of `upsert_session_after_execution(...)` is followed by an immediate `persist_session_store` call.
- [ ] In `src/workflow/orchestrator.rs`, `handle_prompt_change` persists the session store after the final clear/preserve decision is made.
- [ ] In `src/cli/rollback.rs`, rollback-driven session invalidation is followed by an immediate `persist_session_store` call.
- [ ] Write failures from `persist_session_store` propagate as `Err` (never silently swallowed).
- [ ] With `session_reuse_reset_on_rollback=true`, rollback removing loop N leaves zero records for loop N in the persisted file.
- [ ] With `session_reuse_reset_on_prompt_change=true`, prompt-change restart clears affected loop records and persists.
- [ ] With `session_reuse_reset_on_prompt_change=false`, prompt-change restart preserves records and persists.
- [ ] Per-project isolation: one project's session-store writes never affect another project's file.
- [ ] Unit test `persist_and_load_session_store_roundtrip` passes: persist then load, assert equality.
- [ ] Unit test `missing_session_store_file_yields_empty_store` passes: reconstruct without file, assert empty records.
- [ ] Unit test `corrupt_session_store_file_yields_empty_store` passes: write invalid JSON, reconstruct, assert empty records and no crash.
- [ ] Validate conformance test `session_persistence_survives_restart` passes: run once capturing persisted records, run again on same project, assert reuse deterministically.
- [ ] Validate conformance test `session_persistence_invalidated_by_rollback` passes: enable rollback reset, create sessions, rollback to target loop N, assert persisted file has no loop N records.
- [ ] Validate conformance test `session_persistence_invalidated_by_prompt_change_enabled` passes: assert persisted file matches cleared behavior.
- [ ] Validate conformance test `session_persistence_preserved_on_prompt_change_disabled` passes: assert persisted file matches preserved behavior.
- [ ] All new unit tests and validate conformance tests pass.
