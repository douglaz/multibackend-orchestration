# Implementation Notes

## Decisions Made
- Added `SESSION_STORE_FILE` and durable session-store IO in `src/project/lifecycle.rs`, including `persist_session_store(project_dir, store)` using pretty JSON.
- Added reconstruction hydration via `reconstruct_project_state_internal` so `load_project_state` always loads `session-store.json` into `state.session_store`, with empty fallback for missing/corrupt files and `warn` logging for corrupt/read-failure cases.
- Wired immediate persistence after every orchestrator session mutation path:
  - after every `upsert_session_after_execution(...)` call site,
  - after rollback-on-limit paths,
  - after prompt-change restart clear/preserve decision.
- Wired immediate persistence in CLI rollback after rollback-driven session invalidation in `src/cli/rollback.rs`.
- Added lifecycle unit tests:
  - `persist_and_load_session_store_roundtrip`
  - `missing_session_store_file_yields_empty_store`
  - `corrupt_session_store_file_yields_empty_store`
- Extended validate conformance tests in `src/validate/tests_sessions.rs`:
  - `session_persistence_survives_restart`
  - `session_persistence_invalidated_by_rollback`
  - `session_persistence_invalidated_by_prompt_change_enabled`
  - `session_persistence_preserved_on_prompt_change_disabled`

## Spec Deviations
- `session_persistence_survives_restart` seeds a deterministic reviewer record into `session-store.json` before the second run instead of depending on first-run backend-emitted `session_id` capture. This preserves the intended deterministic reuse assertion (`call_count` increment + same `session_id`) while remaining stable with the current backend execution normalization path.
