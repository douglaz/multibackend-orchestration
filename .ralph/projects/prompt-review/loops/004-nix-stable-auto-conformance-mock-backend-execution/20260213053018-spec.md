# Feature: Nix-Stable Auto Conformance Mock Backend Execution

## Description
Loops 1 and 2 already delivered the full prompt-review feature set (state/config/parser/runtime integration + conformance coverage).  
The remaining gap is release-path reliability: `nix build -L` still fails on `prompt_review::auto_skip_flag_bypasses` because the mock backend command path is not stable/executable in that environment.  
This feature hardens validate mock-backend execution so `auto --skip-prompt-review` conformance is reproducible in sandboxed builds.

## Acceptance Criteria
- [ ] `nix build -L` passes end-to-end, including validate conformance, with no failures in `prompt_review::auto_skip_flag_bypasses`.
- [ ] Validate harness mock backend setup uses an interpreter-stable invocation (`bash <script>` or equivalent) instead of relying on direct script execution behavior.
- [ ] Mock scripts used by validate tests are written to a path that remains valid for the full test lifecycle in sandboxed/Nix builds.
- [ ] Backend mock setup in the harness configures command and args together (and avoids stale default backend args interfering with script execution).
- [ ] `prompt_review::auto_skip_flag_bypasses` continues asserting prompt-review bypass behavior (no `prompt-review.md`, no `prompt-original.md`) while using the hardened backend setup.
- [ ] Existing prompt-review conformance tests still pass unchanged in behavior after the harness/mock refactor.

## Files to Modify/Create
- `src/validate/harness.rs` - add stable mock backend wiring helper(s) that set command+args in a sandbox-safe way.
- `src/validate/mock_scripts.rs` - add/share an auto-capable mock script payload for reuse across tests.
- `src/validate/tests_prompt_review.rs` - switch `auto_skip_flag_bypasses` to the hardened mock setup; remove fragile inline script handling.
- `src/validate/tests_run.rs` - optionally adopt the same helper for consistency if shared setup changes require call-site updates.
