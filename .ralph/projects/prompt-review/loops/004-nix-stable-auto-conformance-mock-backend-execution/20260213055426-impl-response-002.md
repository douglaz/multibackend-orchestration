# Implementation Response (Iteration 2)

## Changes Made
1. **Rewrote `setup_mock_backends_stable` to use a `/bin/sh` wrapper that ignores model flags** — The root cause was that `claude::backend_from_config` and `codex::backend_from_config` unconditionally prepend `--model <name>` flags to the args array when resolving modeled specs like `claude(opus)`. With `command = "bash"` and `args = [script]`, this produced `bash --model opus script.sh`, which fails because bash interprets `--model` as its own option. The fix creates a thin `/bin/sh` wrapper script (`mock-wrapper.sh`) that execs `bash <real-script>` without passing through `"$@"`. The wrapper is set as the backend command with `args = []`. When model flags get injected, they become positional args to the wrapper but are silently ignored since the wrapper doesn't use them. `/bin/sh` is available in Nix sandboxes (unlike `/usr/bin/env`), so this is stable across build environments.

2. **Added `backends.{claude,codex}.models.*` config set support** — Added `set_backend_model()` helper in `src/cli/config.rs` with match arms for `backends.claude.models.<role>` and `backends.codex.models.<role>` keys. Supports all six roles (planner, implementer, reviewer, qa, completer, reformatter) and `null` to clear. While not strictly required for the wrapper approach, this enables future test flexibility and was part of the reviewer's recommendation for making the mock setup robust against modeled backends.

3. **Added `prompt_review::stable_mock_with_modeled_backend` regression test** — New conformance test in `src/validate/tests_prompt_review.rs` that exercises `setup_mock_backends_stable` with a full `ralph run --loops 1` (which invokes backends with modeled specs like `claude(opus)` for the planner role). This catches the specific failure class (`bash --model opus script.sh`) before a full `nix build`, satisfying the reviewer's recommended improvement.
