# Implementation Notes

## Decisions Made
- Refactored `src/cli/rollback.rs` to make non-`--hard` rollback strictly soft: no reset/push, artifact/session/state rollback still runs, and `.rollback-target` is written.
- Added explicit hard rollback flow in `src/cli/rollback.rs`: resolve target ref, capture `original_head`, hard reset, attempt force-push, recover on push failure by resetting back to `original_head`, then apply rollback cleanup/state updates.
- Added marker lifecycle helpers in `src/project/lifecycle.rs`:
  - `write_rollback_target_marker`
  - `remove_rollback_target_marker`
  - marker-aware reconstruction clamp during `load_project_state`
- Implemented reconstruction boundary behavior in `src/project/lifecycle.rs`: when `.rollback-target` contains valid `m < checkpoint_loop`, loops/session records are clamped to `<= m`, phase is reset to planning, malformed marker is ignored with warning.
- Updated recovery persistence in `src/project/lifecycle.rs` to save the reconstructed/clamped state object (not raw git JSON) after corruption recovery.
- Updated orchestrator commit checkpoint behavior in `src/workflow/orchestrator.rs` to remove `.rollback-target` only after successful checkpoint commit.
- Added/updated tests:
  - `tests/rollback_command.rs` (soft marker + no git mutation, hard marker delete, push-failure fallback, dry-run side effects/messaging, marker cleanup on successful commit, marker retention on failed commit).
  - `tests/recovery.rs` (marker clamp, no-marker unchanged behavior, malformed marker ignored).
  - `src/validate/tests_commands.rs` (soft rollback marker/no-HEAD mutation assertion, hard rollback marker deletion + remote push assertion, reconstruction marker boundary conformance case).

## Spec Deviations
- Hard rollback force-push is skipped (not failed) when no upstream tracking branch is configured.  
  Rationale: preserves behavior for local-only repos while still force-pushing when upstream exists.
