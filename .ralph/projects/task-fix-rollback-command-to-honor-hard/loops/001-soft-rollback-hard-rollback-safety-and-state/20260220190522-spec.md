# Feature: Soft Rollback, Hard Rollback Safety, and State Reconstruction Marker

## Description
Fix `ralph rollback <loop>` so that the default (non-`--hard`) path performs a **soft rollback** — cleaning up artifacts, invalidating sessions, and updating state without any git-history mutation — and writes a `.rollback-target` marker file. Preserve destructive git behavior only behind `--hard`, adding push-failure recovery (revert to `original_head`, degrade to soft-rollback semantics). Teach `reconstruct_project_state_internal` to honor the marker boundary, and have the orchestrator's `checkpoint_phase_transition` remove a stale marker after a successful new checkpoint. Ensure dry-run mode is mutation-free with mode-specific messaging.

## Acceptance Criteria
- [ ] `ralph rollback <loop>` (no `--hard`) does **not** run `git reset --hard`, `git push --force`, or any history-rewriting git command.
- [ ] Soft rollback still performs artifact cleanup (loops > target), session invalidation, and state file updates.
- [ ] Soft rollback writes `<project_dir>/.rollback-target` containing the target loop as a plain integer.
- [ ] `ralph rollback <loop> --hard` performs local hard reset to target ref **and** force-pushes remote, same as current destructive behavior.
- [ ] Hard rollback deletes `.rollback-target` on full success (if file exists).
- [ ] Hard rollback captures `original_head` before reset; on push failure, reverts local HEAD to `original_head`.
- [ ] On push failure with successful revert: writes `.rollback-target` (soft-fallback), runs cleanup, exits non-zero with message about soft fallback.
- [ ] On push failure with failed revert: runs cleanup best-effort, exits non-zero with inconsistency warning.
- [ ] `reconstruct_project_state_internal` reads `.rollback-target`; if valid integer `m < checkpoint_loop`, clamps loop to `m`, sets phase to `Phase::Planning`, ignores checkpoint commits with loop > `m`.
- [ ] Malformed marker is ignored with a trace/warning log (no crash).
- [ ] Absent marker leaves reconstruction unchanged.
- [ ] `checkpoint_phase_transition` removes `.rollback-target` only after a successful new checkpoint commit.
- [ ] Failed checkpoint attempt does **not** remove the marker.
- [ ] Dry-run mode performs zero mutations (no git ops, no marker writes/deletes, no artifact/session/state writes).
- [ ] Dry-run output for soft mode mentions "no git reset/push" and marker write intent.
- [ ] Dry-run output for hard mode mentions hard reset and force push intent.
- [ ] `rollback_current_loop` behavior is unchanged (artifact/in-memory only).
- [ ] All existing rollback-related tests continue to pass.
- [ ] New unit/integration tests cover: soft rollback writes marker without git mutation; hard rollback deletes marker on success; hard rollback push-failure reverts HEAD and writes marker fallback; reconstruction clamping with/without marker; dry-run zero side-effects and mode-specific messaging.
- [ ] Conformance tests added in `src/validate/` covering soft rollback path, hard rollback path, and reconstruction with marker boundary.

## Files to Modify/Create
- `src/cli/rollback.rs` — Gate git-reset/force-push behind `--hard`; add `original_head` capture and push-failure recovery logic; write/delete `.rollback-target` marker per mode; update dry-run output to be mode-specific.
- `src/project/lifecycle.rs` — In `reconstruct_project_state_internal`, read `.rollback-target` marker; clamp loop and phase when marker is valid and below checkpoint loop; warn on malformed marker.
- `src/workflow/orchestrator.rs` — In `checkpoint_phase_transition`, remove `.rollback-target` after successful checkpoint commit only.
- `tests/` (unit/integration test files) — Add tests for soft rollback marker write, hard rollback marker delete, push-failure fallback, reconstruction clamping, dry-run behavior.
- `src/validate/` (new or existing conformance test files) — Add conformance tests for soft path, hard path, and reconstruction marker boundary.
