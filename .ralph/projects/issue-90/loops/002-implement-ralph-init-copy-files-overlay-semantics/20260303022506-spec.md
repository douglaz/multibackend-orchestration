# Feature: Implement `ralph init --copy-files` overlay semantics and strict workspace validation

## Description
Implement the missing `init --copy-files` behaviors on top of the already-completed minimal default `init` path. The feature adds three explicit execution modes for `--copy-files`:
- full scaffold on new/empty targets,
- strict overlay on existing valid workspaces (`ralph.toml` present and parseable),
- explicit failure modes for non-workspace or malformed-workspace inputs.

The feature also updates dry-run planning so copy-mode reports template/config actions, while preserving the current minimal default init behavior and keeping bootstrap callers on the minimal path unchanged.

## Acceptance Criteria
- [ ] `ralph init --copy-files` on an empty or non-existent target creates a full scaffold (projects dir + templates dir + 11 template files + full config).
- [ ] `ralph init --copy-files` on an existing workspace (`ROOT/ralph.toml` exists and parses as `GlobalConfig`) performs overlay:
  - creates `ROOT/templates/` if missing,
  - creates only missing template files,
  - never overwrites any existing template file.
- [ ] Overlay config merge uses existing `GlobalConfig`-parseable TOML as base and inserts missing keys from full-default reference without overwriting present values, preserving unknown user keys.
- [ ] Overlay config merge preserves formatting/comments where possible via `toml_edit::DocumentMut`.
- [ ] `ralph init --copy-files` on an existing **non-empty** directory without `ROOT/ralph.toml` exits with code `2` and exact message `directory exists but is not a ralph workspace (no ralph.toml found)`.
- [ ] `ralph init --copy-files` on an existing workspace with malformed `ralph.toml` exits with code `1` and message containing `failed to parse ralph.toml`.
- [ ] `ralph init --dry-run` continues to emit only minimal actions; `ralph init --copy-files --dry-run` emits full overlay/full-scaffold actions including template actions and overlay plan.
- [ ] Dry-run mode performs no filesystem writes in all branches.
- [ ] Failure invariants:
  - In the non-workspace/non-empty error case, no workspace files are added or modified.
  - In malformed-TOML workspace case, no template/file writes are performed; the existing `ralph.toml` and existing templates remain unchanged.
  - In overlay path, existing template/config keys and user values are unchanged; only missing keys/files are added.
- [ ] `auto` and daemon bootstrap paths remain on minimal init behavior (no template creation).
