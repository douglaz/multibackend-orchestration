# Implementation Response (Iteration 1)

## Changes Made

1. **`src/config/global.rs`: Added `save_sparse` API for targeted config persistence (Required Change #1)**
   - Added `save_sparse(path, canonical_key, config)` function that uses `toml_edit::DocumentMut` to patch only the targeted key in-place
   - Preserves existing formatting, comments, and unknown user keys
   - Creates missing intermediate tables when needed
   - Deletes keys on clearable-null values (when the key is absent from full serialization)
   - Falls back to full save when the config file doesn't yet exist
   - Added `sparse_key_segments()` helper that correctly handles `backends.<backend>.env.<rest>` as a single literal key (even if `<rest>` contains dots), while `models` and `role_timeouts` split normally by dot segments

2. **`src/cli/config.rs`: Routed global set through sparse save path (Required Change #2)**
   - Changed `ConfigScope::Global` branch in `execute_set` from `workspace.save_config()` (full-file serialization) to `crate::config::save_sparse(&config_path, key, &workspace.config)`
   - Uses the already-resolved canonical key from `resolve_config_alias()` for consistent key path handling

3. **`src/config/global.rs`: Implemented dotted-key split behavior for env vs models/role_timeouts (Required Change #3)**
   - `sparse_key_segments()` detects the `backends.<backend>.env.<rest>` pattern and treats `<rest>` as one literal map key
   - `backends.<backend>.models.<role>` and `backends.<backend>.role_timeouts.<role>` split normally

4. **`src/config/global.rs`: Clear semantics for optional keys (Required Change #4)**
   - When `save_sparse` finds the target key absent in the full serialization (meaning the in-memory value is `None` for optional fields), it removes the key from disk
   - Non-optional fields always get written explicitly since they appear in full serialization

5. **`src/config/global.rs` + `src/validate/tests_commands.rs`: Unit and conformance tests (Required Change #5)**
   - Added 10 unit tests for `save_sparse`:
     - `save_sparse_preserves_comments_and_unrelated_formatting` 
     - `save_sparse_creates_intermediate_tables`
     - `save_sparse_removes_optional_key_on_null`
     - `save_sparse_handles_env_dotted_literal_keys`
     - `save_sparse_handles_models_role_clear`
     - `save_sparse_handles_role_timeouts_clear`
     - `save_sparse_falls_back_to_full_save_on_missing_file`
     - `sparse_key_segments_splits_normal_keys`
     - `sparse_key_segments_treats_env_rest_as_literal`
     - `sparse_key_segments_splits_models_and_timeouts_normally`
   - Added 3 conformance tests:
     - `config_set_global_preserves_comments` — verifies TOML comments survive `config set`
     - `config_set_global_preserves_unknown_keys` — verifies user-added custom TOML sections survive
     - `config_set_global_clears_optional_key` — verifies setting to `null` removes the key from disk

6. **`src/config/mod.rs` + `src/cli/config.rs`: Canonical key path and alias consistency (Required Change #6)**
   - `save_sparse` receives the already-resolved canonical key from `execute_set`, which calls `resolve_config_alias()` before both `set_global_config_value()` and `save_sparse()`
   - Rejections for `workspace.daemon_prd_*` and other unsupported keys remain intact in `set_global_config_value()` — `save_sparse` is only called after successful in-memory mutation
