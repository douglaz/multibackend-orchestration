# Implementation Notes

## Decisions Made
- Added an acceptance QA gate in `src/workflow/orchestrator.rs` inside `Phase::Completing` when completer returns `COMPLETE` and `qa_enabled` is true, using `execute_with_parse_retries()` + `parse_qa_output` (same QA path as feature-loop QA).
- Implemented `build_acceptance_prompt()` to include master prompt, completed feature-loop summary, git diff against base branch, and explicit project-wide acceptance instruction.
- Added acceptance result persistence:
  - PASS writes `ArtifactKind::AcceptancePass`, sets `CompletionLoopArtifacts.acceptance_result`, `acceptance_passed = Some(true)`, keeps `ProjectStatus::Completed`.
  - FAIL writes `ArtifactKind::AcceptanceFail`, sets `acceptance_result`, `acceptance_passed = Some(false)`, forces `completion.verdict = Some(Continue)`, sets `ProjectStatus::InProgress`, routes to `Phase::Planning`.
- Added planner feedback injection in `build_planner_prompt()`:
  - when latest completion attempt has acceptance failure, appends `## Completion Feedback` with both completer verdict artifact content and acceptance-fail artifact content.
- Added acceptance-gate integration tests in `tests/orchestrator.rs`:
  - `acceptance_gate_pass_keeps_completed`
  - `acceptance_gate_fail_overrides_complete_to_continue`
  - `planner_receives_acceptance_failure_context`
- Added acceptance-specific mock backend helpers and setup that stores counters under `.ralph/` to avoid dirty-tree false failures during planning re-entry.
