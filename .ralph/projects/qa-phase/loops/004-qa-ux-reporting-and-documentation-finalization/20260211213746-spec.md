# Feature: QA UX Reporting and Documentation Finalization

## Description
Loops 1-3 completed the core QA implementation (schema/config plumbing, runtime QA gate, and completion acceptance gate). The remaining gap from the master plan is Phase 4 polish: expose QA outcomes clearly in CLI UX (`status`, `history`) and document the QA workflow/config surface in `PLAN.md` so behavior is discoverable and consistent.

## Acceptance Criteria
- [ ] `ralph status` shows latest QA result summary for the active feature loop when `qa_results` is non-empty, including iteration, PASS/FAIL, and report artifact path.
- [ ] `ralph status` extracts up to 3 concise summary lines from the latest QA artifact body (`## Verification Summary` for pass, `## Failures` for fail), with graceful fallback if sections are missing.
- [ ] `ralph status` preserves current behavior when no QA attempts exist (no QA summary shown, existing review feedback behavior unchanged).
- [ ] `ralph history --verbose` includes QA metadata per feature loop: attempt count, last QA verdict (pass/fail), and last QA report artifact path (or `none`).
- [ ] `ralph history` non-verbose and JSON outputs remain backward-compatible (no schema change/regression).
- [ ] Legacy state compatibility is preserved: loops deserialized from older state files do not panic or render invalid output when QA fields are empty/defaulted.
- [ ] `PLAN.md` documents QA workflow additions: `Planning -> Implementing -> QA -> Reviewing`, completion acceptance gate behavior, QA artifact names, and planner feedback path after acceptance fail.
- [ ] `PLAN.md` documents QA configuration/CLI surface: `workflow.qa_enabled`, `workflow.max_qa_iterations`, `workflow.qa_backend`, `models.qa`, `templates.qa`, and `--qa-backend`.
- [ ] Tests cover status/history QA rendering for: zero attempts, latest pass, latest fail, and malformed/missing QA sections.
- [ ] Test suite passes with QA enabled and disabled paths unchanged.

## Files to Modify/Create
- `src/cli/status.rs` - add QA-aware latest-result summary selection and section-based summary extraction.
- `src/cli/history.rs` - add verbose QA attempt count, last verdict, and last report path output.
- `PLAN.md` - add QA workflow, acceptance-gate, config keys, and CLI/docs updates.
- `tests/status_history.rs` - new integration tests for `status`/`history` QA output behavior (or equivalent coverage in existing CLI tests).

## Dependencies
- Requires: QA Acceptance Gate for Completion Phase (Loop 3)
- Blocks: Project Completion Request
