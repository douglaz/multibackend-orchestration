# Implementation Notes

## Decisions Made
- **QA parser follows existing parser patterns**: `parse_qa_output()` uses the same `strip_frontmatter` → `first_h1_line` → `validate_required_section` pattern as all other parsers (planner, implementer, reviewer, completer). This ensures consistent error messages and parse-retry behavior.
- **QA feedback reuses implementer response contract**: When QA fails, the QA fail report is passed to the implementer as `review_feedback_content` in the existing implementer template. This reuses the `# Implementation Response (Iteration N)` output format, avoiding a new parser type. The artifact is stored as `ArtifactKind::ImplQaResponse` to distinguish it from review responses.
- **QA iteration counter uses `phase_iteration`**: As specified in the master prompt, `phase_iteration` is the single runtime counter. It starts at 1 when entering QA after initial implementation, increments after each QA fail→implementer response cycle, and resets to 1 when transitioning to Reviewing after QA pass.
- **QA limit check is self-contained in `Phase::QA` arm**: Unlike the review limit which uses a post-match handler, the QA limit is checked and handled entirely within the `Phase::QA` match arm. This is simpler and avoids introducing another mutable flag variable (`qa_limit_hit`) that persists across the match.
- **Pending QA feedback check uses `else if` branch**: The Implementing phase now has three branches: (1) no impl-notes → initial implementation, (2) pending QA feedback → QA failure response, (3) else → review feedback response. The QA feedback path is checked before the review feedback path to ensure QA failures are handled first.
- **`dry_run_summary` conditionally shows QA backend**: Only includes QA backend in the dry-run output when `qa_enabled=true`, preserving existing output for non-QA projects.

## Spec Deviations
- **Could not verify compilation**: The build environment did not allow running `cargo check` or `cargo test`. All code was written following existing patterns and manually reviewed for correctness.
- **`resume_from_phase_qa` test exercises full flow**: Instead of manually injecting state at `Phase::QA`, the test runs a full flow with `--until-review` to naturally reach the commit phase (passing through QA), then resumes. This verifies the full QA path end-to-end while also testing resume behavior.
