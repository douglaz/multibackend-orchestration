# Implementation Response (Iteration 3)

## Changes Made
1. **Fixed `resume_from_phase_qa` test to avoid git tag conflict on resume**: The root cause was that the initial full run creates a git tag `ralph/01-poc/loop-1` during commit. When state is rewritten back to `Phase::QA` and the orchestrator resumes, the commit phase tries to create the same tag again, which fails with a git error. The fix adds `git_ok(repo_root, &["tag", "-d", "ralph/01-poc/loop-1"])` after the initial run completes and before rewriting state. This deletes the pre-existing tag so the resumed run can re-create it during its own commit phase. The `repo_root` is derived from `workspace_root.parent()` since `workspace_root` points to `.ralph` inside the repo. The test now correctly validates the full QA->Review->Commit resume path without tag conflicts.
