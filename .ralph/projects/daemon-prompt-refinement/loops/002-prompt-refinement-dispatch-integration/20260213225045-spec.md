# Feature: Prompt Refinement Dispatch Integration

## Description
Loop 1 is complete (issue body + `raw_idea` data path, refinement config fields, and `--idea` argv fix).  
This feature implements the remaining behavior: actually refine the prompt before dispatch, post the refined prompt comment best-effort, and enforce the required pre-spawn ordering in the daemon runtime.

## Acceptance Criteria
- [ ] Add `src/daemon/refine.rs` with `refine_prompt(raw_idea, backend_spec, global_config) -> Result<String>` and a daemon-specific refinement system prompt constant.
- [ ] `refine_prompt` parses backend specs via `parse_backend_spec`, supports `claude`/`codex` with model overrides, and returns a validation error for unknown backends.
- [ ] Backend execution in `refine_prompt` uses `tokio::runtime::Handle::current().block_on(...)` (no nested runtime creation).
- [ ] Refinement output is validated (`trim()` non-empty and meaningful length); invalid/empty output returns `Err` to trigger fallback.
- [ ] `dispatch_task()` enforces this exact order: `create_worktree` -> resolve raw idea -> refine (if enabled) -> post `"refined-prompt"` comment -> spawn child -> CAS transition to `InProgress`.
- [ ] If `refinement_enabled = false`, no refinement backend call is made and raw idea is used directly.
- [ ] If refinement fails (backend error/timeout/invalid output), a warning is logged and raw idea is used.
- [ ] The pre-spawn comment uses `post_idempotent_comment(..., "refined-prompt", &idea)` where `idea` is the refined or fallback text.
- [ ] Comment-post failures never abort dispatch; daemon logs warning and still spawns `ralph auto`.
- [ ] Existing legacy-task hydration behavior is preserved: tasks with missing `raw_idea` are hydrated from GitHub and never use `"Implement task {task_id}"`.
- [ ] Add daemon conformance tests for: strict ordering, refinement happy path, refinement failure fallback, comment failure non-blocking behavior, refinement-disabled behavior, and retry idempotency.
- [ ] Add unit tests in `refine.rs` for prompt construction and output validation boundaries.

## Files to Modify/Create
- `src/daemon/refine.rs` - new refinement module (backend selection, prompt construction, async execution bridge, output validation, unit tests).
- `src/daemon/mod.rs` - export `pub mod refine;`.
- `src/daemon/runtime.rs` - integrate refinement/fallback/comment flow into `dispatch_task()` with strict ordering and warning-only failure handling.
- `src/validate/tests_daemon.rs` - add conformance tests for refinement dispatch scenarios and ordering assertions.
- `src/validate/mock_scripts.rs` - add reusable mock backend/ordering scripts if needed by new daemon validate cases.

- Requires: Data Layer, Configuration, and Argv Foundation
- Blocks: Project completion request for daemon prompt refinement
