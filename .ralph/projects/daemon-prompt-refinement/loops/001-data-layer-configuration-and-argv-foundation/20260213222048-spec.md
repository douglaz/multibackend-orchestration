# Feature: Data Layer, Configuration, and Argv Foundation

## Description
Establish the foundational data model changes, configuration plumbing, and argument-passing fix that all subsequent refinement work depends on. This includes: extending `GhIssue`/`RawGhIssue` with a `body` field, adding `raw_idea` to `DaemonTask`, adding `fetch_issue_body()` for restart recovery, wiring two new daemon configuration fields (`daemon_refinement_enabled`, `daemon_refinement_backend`) through the three-tier config system, and fixing the `spawn_ralph_auto()` argv to use `["auto", "--idea", idea]` instead of the incorrect positional `["auto", idea]`.

## Acceptance Criteria
- [ ] `RawGhIssue` gains `body: Option<String>` and `GhIssue` gains `body: Option<String>`. `poll_issues()` requests `"number,title,labels,body"` from `gh issue list --json`.
- [ ] `DaemonTask` gains `raw_idea: Option<String>` with `#[serde(default)]` for backwards compatibility. Existing `tasks.json` files without the field deserialize correctly (field defaults to `None`).
- [ ] After claiming an issue in `poll_and_claim()`, `raw_idea` is composed as `format!("{}\n\n{}", issue.title, issue.body.unwrap_or_default())` and stored on the `DaemonTask` before persisting.
- [ ] A new `fetch_issue_body(owner, repo, issue_number) -> Result<(String, Option<String>)>` function in `github.rs` calls `gh issue view <number> --repo owner/repo --json title,body` and returns `(title, body)`.
- [ ] `adopt_pending_tasks()` checks each pending task's `raw_idea`: if `None`, calls `fetch_issue_body()` to retrieve the title+body, composes the raw idea, and updates the task in the store. Never falls back to the synthetic `"Implement task {task_id}"` string.
- [ ] `dispatch_task()` uses `task.raw_idea` (or the freshly-fetched value) as the idea string instead of the current `format!("Implement task {}", task.task_id)`.
- [ ] `spawn_ralph_auto()` in `process.rs` uses `cmd.args(["auto", "--idea", idea])` instead of `cmd.args(["auto", idea])`.
- [ ] Two new fields added to `WorkspaceConfig`: `daemon_refinement_enabled: bool` (default `true`) and `daemon_refinement_backend: String` (default `"claude(sonnet)"`), with `#[serde(default = "...")]` annotations.
- [ ] Two new fields added to `ProjectDaemonOverrides`: `refinement_enabled: Option<bool>` and `refinement_backend: Option<String>`.
- [ ] Two new fields added to `EffectiveDaemonConfig`: `refinement_enabled: bool` and `refinement_backend: String`. `resolve_daemon_config()` wires them with project-override-or-workspace-default precedence.
- [ ] `DaemonRuntimeConfig` gains `refinement_enabled: bool`, `refinement_backend: String`, and `global_config: GlobalConfig`. These are populated in `cli/daemon.rs`'s `execute_start()`.
- [ ] Unit test: `DaemonTask` round-trips with and without `raw_idea` field (backwards compatibility).
- [ ] Unit test: `GhIssue` deserialization handles `body` present, `body: null`, and `body` absent.
- [ ] Unit test: Config deserialization with and without `daemon_refinement_enabled`/`daemon_refinement_backend` fields, verifying defaults.
- [ ] Unit test: `resolve_daemon_config` correctly applies project-level overrides for refinement fields.
- [ ] Unit test or assertion: `spawn_ralph_auto` produces argv `["auto", "--idea", <idea_string>]`.
