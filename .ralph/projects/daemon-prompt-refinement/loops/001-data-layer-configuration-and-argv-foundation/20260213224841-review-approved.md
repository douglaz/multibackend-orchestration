## Notes

**Metadata fallback behavior is sound but subtly different from spec AC 5 wording.** The spec says `adopt_pending_tasks` should skip the task on hydration failure (`continue`). The implementation does have that `continue` path (runtime.rs:154), but it's only reachable when `store.update_task()` fails, not when GitHub fetch fails — because `fetch_and_persist_raw_idea` applies a metadata fallback internally and returns `Ok`. The test `runtime_adopt_pending_fetch_failure_uses_metadata_fallback` correctly validates this: when `gh issue view` returns empty/malformed output, the metadata fallback idea is used and dispatch proceeds. This is actually more resilient than pure skip-and-retry, and the "never use `Implement task {task_id}`" constraint is fully satisfied.

**Formatting changes are cosmetic.** Several hunks in `github.rs`, `daemon.rs`, and `tests_daemon.rs` are `rustfmt` reformatting of existing code (e.g., collapsing `.args()` arrays, reformatting multi-line expressions). These don't affect behavior.

**Existing tests updated for new fields.** Tests that create `DaemonRuntimeConfig` or `DaemonTask` have been updated to include the new fields. Several existing runtime conformance tests now inject `RALPH_DAEMON_BIN` for the mock ralph binary — this is correct since `dispatch_task` now passes real issue content to `spawn_ralph_auto` rather than a hardcoded string, and the mock needs to accept `--idea` argv.
