# Implementation Notes

## Decisions Made
- Extended daemon issue/task data models to carry issue body content end-to-end: added `body: Option<String>` to `RawGhIssue`/`GhIssue`, added `raw_idea: Option<String>` (with `#[serde(default)]`) to `DaemonTask`, and stored `raw_idea` at claim time as `"{title}\n\n{body}"`.
- Added `github::fetch_issue_body(owner, repo, issue_number) -> Result<(String, Option<String>)>` using `gh issue view --json title,body`, then used it in restart adoption and dispatch for legacy pending tasks missing `raw_idea` (never using synthetic `"Implement task {task_id}"`).
- Fixed daemon child argv construction by changing spawn args to `["auto", "--idea", idea]` and introduced a unit-tested command builder to assert exact argv shape.
- Added daemon refinement config plumbing across all config layers:
  - `WorkspaceConfig`: `daemon_refinement_enabled` (default `true`), `daemon_refinement_backend` (default `"claude(sonnet)"`)
  - `ProjectDaemonOverrides`: `refinement_enabled`, `refinement_backend`
  - `EffectiveDaemonConfig`: `refinement_enabled`, `refinement_backend`
  - `DaemonRuntimeConfig`: `refinement_enabled`, `refinement_backend`, `global_config`
- Extended CLI config handling so new refinement daemon keys are available via `config get/set/show` in both workspace and project scope.
- Added validate conformance coverage for restart hydration + argv correctness (`daemon::runtime_adopt_pending_fetches_raw_idea_and_uses_idea_flag`) and expanded daemon config conformance assertions for new refinement fields.
