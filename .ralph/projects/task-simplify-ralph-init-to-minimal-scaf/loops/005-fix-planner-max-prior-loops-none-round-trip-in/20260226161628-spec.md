# Feature: Fix planner_max_prior_loops "none" round-trip in sparse config saves

## Description
When a user runs `ralph config set --global workflow.planner_max_prior_loops none`, the sparse save path removes the key entirely from `ralph.toml` (via `key_becomes_none`). On next load, the absent key deserializes to the default `Some(10)`, silently discarding the user's intent to set unlimited prior loops. This feature adds custom serde for `planner_max_prior_loops` so that `None` (unlimited) is persisted as an explicit value in TOML rather than being removed, and tightens the table-driven sparse test to prevent similar lossy round-trips from being masked.

## Acceptance Criteria
- [ ] `save_config_sparse(path, "workflow.planner_max_prior_loops", "none")` writes an explicit sentinel value to the TOML file (not key removal).
- [ ] After sparse save of `"none"`, `GlobalConfig::load` returns `planner_max_prior_loops == None` (unlimited).
- [ ] `save_config_sparse(path, "workflow.planner_max_prior_loops", "5")` still writes `planner_max_prior_loops = 5` and reloads as `Some(5)`.
- [ ] The `key_becomes_none` function no longer matches `"workflow.planner_max_prior_loops"` with value `"none"`.
- [ ] Custom serde (de)serializer for `WorkflowConfig::planner_max_prior_loops` that: deserializes `"none"` string → `None`, deserializes integer → `Some(n)`, deserializes absent key → `Some(10)` (default), serializes `None` → `"none"` string.
- [ ] Unit test: sparse save of `("workflow.planner_max_prior_loops", "none")` followed by `GlobalConfig::load` yields `planner_max_prior_loops == None`.
- [ ] Unit test: sparse save of `("workflow.planner_max_prior_loops", "12")` followed by `GlobalConfig::load` yields `planner_max_prior_loops == Some(12)`.
- [ ] The table-driven sparse key coverage test (`test_sparse_save_all_keys_match_set_global_config_value`) is tightened so the expected config is not normalized through `save/load` before comparison — instead, the expected state is obtained by applying `set_global_config_value` only, without a save+reload cycle that would mask lossy round-trips.
- [ ] Conformance test added in `tests_commands.rs`: `ralph config set --global workflow.planner_max_prior_loops none` followed by `ralph config get --global workflow.planner_max_prior_loops` returns the unlimited sentinel (not `10`).
- [ ] All existing tests continue to pass (`cargo test`).
- [ ] `cargo check` passes.
