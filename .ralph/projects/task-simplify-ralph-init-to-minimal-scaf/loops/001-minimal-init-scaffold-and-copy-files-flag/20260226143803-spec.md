# Feature: Minimal init scaffold and --copy-files flag

## Description
Change `ralph init` default behavior to create a **minimal workspace** (only `projects/` directory and a minimal `ralph.toml`) instead of the current full scaffold. Add a `--copy-files` flag that preserves the current full-scaffold behavior (templates directory, all 11 template files, full `ralph.toml` via `GlobalConfig::default().save()`). Update `create_workspace` to accept a `copy_files` parameter and propagate `false` through `auto` bootstrap, daemon bootstrap, and validate harness callers. Update dry-run output labels to distinguish between modes.

## Acceptance Criteria
- [ ] `InitArgs` gains a `copy_files: bool` field (`--copy-files` CLI flag, defaults to `false`).
- [ ] `ralph init` (no flag) creates only `.ralph/projects/` and `.ralph/ralph.toml` with minimal content; does **not** create `templates/` or any template files.
- [ ] Minimal `ralph.toml` parses via `toml::from_str::<GlobalConfig>()` and the parsed value equals `GlobalConfig::default()`. The workspace version is derived from `GlobalConfig::default().workspace.version` (not hardcoded).
- [ ] `ralph init --copy-files` creates the full scaffold: `projects/`, `templates/`, all 11 template files, and full `ralph.toml` via `GlobalConfig::default().save()`.
- [ ] `ralph init --dry-run` prints only minimal actions (`create-dir projects/`, `write-config ralph.toml`).
- [ ] `ralph init --copy-files --dry-run` prints full action set (directories, config, all templates).
- [ ] `create_workspace(root, copy_files)` signature updated; all existing callers compile.
- [ ] `auto` bootstrap (`ensure_workspace`) calls `create_workspace(..., false)`.
- [ ] daemon bootstrap (`ensure_workspace_initialized`) calls `create_workspace(..., false)`.
- [ ] validate harness calls `create_workspace(..., false)` where applicable.
- [ ] `ralph init` (no flag) still rejects non-empty non-workspace target directories.
- [ ] `Workspace::load` succeeds on a minimal workspace (only `projects/` and minimal config present).
- [ ] `Workspace::init` signature/behavior unchanged.
- [ ] `GlobalConfig::save()` retained and behaviorally unchanged for full-serialization paths.
- [ ] Template fallback to compiled defaults still works when template files are absent.
- [ ] New `InitAction::WriteMinimalConfig` variant (or equivalent) writes the minimal TOML content.
- [ ] Unit tests for: minimal vs copy-files action plans, filesystem results after each mode, dry-run output for both modes, minimal config parses to default equivalence.

## Files to Modify/Create
- `src/cli/mod.rs` - Add `copy_files: bool` field to `InitArgs`; add CLI arg parsing test.
- `src/cli/init.rs` - Add `WriteMinimalConfig` action variant; split `plan_actions` into `plan_actions_minimal` / `plan_actions_full` (or parameterize); update `create_workspace(root, copy_files)` signature; write minimal TOML content in `execute_actions`; update `execute()` to pass `args.copy_files`; add/update unit tests.
- `src/cli/auto.rs` - Update `create_workspace` call to `create_workspace(&path, false)`.
- `src/daemon/bootstrap.rs` - Update `create_workspace` call to `create_workspace(&workspace_root, false)`.
- `src/validate/harness.rs` - Update any `create_workspace` calls to pass `false`.

## Dependencies
- Requires: none (this is the foundational feature)
- Blocks: overlay validation for `--copy-files`, sparse global config writes (both depend on the minimal/full init distinction being in place)
