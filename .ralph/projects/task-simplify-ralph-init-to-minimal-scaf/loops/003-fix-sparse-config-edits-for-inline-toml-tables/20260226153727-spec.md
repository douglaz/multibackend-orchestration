# Feature: Fix sparse config edits for inline TOML tables

## Description
The sparse global config write functions (`ensure_table_path` and `remove_from_table`) incorrectly handle TOML inline tables. When a user's `ralph.toml` contains inline table syntax (e.g. `workflow = { auto_commit = true, planner_backend = "codex" }`), setting a key within that table replaces the entire inline table with a new standard table containing only the newly-set key, silently dropping all sibling keys. Similarly, removing a key (setting to `null`/`none`) inside an inline table is a silent no-op because `remove_from_table` only traverses via `Item::as_table_mut()`, which does not match inline tables. This fix updates both path-traversal and removal logic to support inline tables without data loss, and adds test coverage for these scenarios.

## Acceptance Criteria
- [ ] `ensure_table_path` descends into existing `InlineTable` entries without replacing them, preserving all sibling keys.
- [ ] `set_document_key` correctly sets a key inside an inline table while leaving other keys intact.
- [ ] `remove_from_table` can remove a key from within an inline table (e.g. setting an optional field to `null` inside `workflow = { ... }` actually removes it).
- [ ] New unit test: setting a key inside an inline-table config preserves all sibling keys in that inline table.
- [ ] New unit test: removing (nulling) an optional key inside an inline-table config actually removes the key.
- [ ] Existing sparse-save tests continue to pass (standard table configs are unaffected).
- [ ] `cargo check` and `cargo test` pass.

## Files to Modify/Create

Update `remove_from_table` to also traverse into inline tables (via `Item::as_inline_table_mut()`). Add two new test functions: `sparse_save_inline_table_preserves_siblings` and `sparse_save_inline_table_removes_optional_key`.
