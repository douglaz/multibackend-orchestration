# Feature: Acceptance Gate QA Conformance Tests

## Description
Loop 1 already covered the foundational QA conformance paths (`qa::disabled_skips_phase`, `qa::enabled_pass_proceeds_to_review`, `qa::fail_retries_then_passes`, `qa::iteration_limit_rolls_back`, `qa::config_get_set`). The next missing, high-impact coverage is completion-time acceptance gating. This feature adds conformance tests for acceptance QA pass/fail behavior so project completion is validated end-to-end when QA is enabled.

## Acceptance Criteria
- [ ] `src/validate/tests_qa.rs` registers two new tests: `qa::acceptance_gate_pass` and `qa::acceptance_gate_fail_forces_continue`.
- [ ] `qa::acceptance_gate_pass` sets `workflow.qa_enabled=true`, runs `ralph run` with `RALPH_COMPLETE=yes`, and exits with code 0.
- [ ] In `qa::acceptance_gate_pass`, `state.json` has `status: "completed"`, one completion attempt, and `completion_attempts[0].artifacts.acceptance_passed == true`.
- [ ] In `qa::acceptance_gate_pass`, the artifact at `completion_attempts[0].artifacts.acceptance_result` exists and is a QA PASS report.
- [ ] `qa::acceptance_gate_fail_forces_continue` uses a deterministic mock (counter/state-file driven) where acceptance QA fails on first completion attempt and passes on a later attempt.
- [ ] `qa::acceptance_gate_fail_forces_continue` runs with `workflow.qa_enabled=true` using `ralph run --until-complete` and exits with code 0.
- [ ] In `qa::acceptance_gate_fail_forces_continue`, the first completion attempt records `acceptance_passed == false` and writes an acceptance-fail artifact.
- [ ] In `qa::acceptance_gate_fail_forces_continue`, acceptance failure forces continuation (`verdict` persisted as continue behavior) and results in at least 2 completed feature loops.
- [ ] In `qa::acceptance_gate_fail_forces_continue`, a later completion attempt records `acceptance_passed == true` and final project `status == "completed"`.
- [ ] `nix build` passes with these additions and existing conformance tests remain green.
