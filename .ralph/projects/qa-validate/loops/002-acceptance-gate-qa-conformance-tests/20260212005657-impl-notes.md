# Implementation Notes

## Decisions Made
- **`acceptance_gate_pass` test uses `RALPH_COMPLETE=yes` env var** (via `ralph_env`): This matches the existing `completion_flow` test pattern in `tests_run.rs` and avoids needing a counter-based planner. The `qa_pass_mock_script()` already handles both feature QA and acceptance QA with PASS responses.
- **`acceptance_gate_fail_forces_continue` uses `--until-complete` CLI flag**: This flag tells the orchestrator to keep looping until the project reaches `completed` status, which is the correct mechanism for testing acceptance failure → forced continue → retry flow.
- **Planner counter alternates Feature/CompletionRequest (odd/even)**: The mock script uses modular arithmetic (`PCOUNT % 2`) so that odd calls (1, 3, ...) produce Feature specs and even calls (2, 4, ...) produce CompletionRequest. This guarantees at least 2 completed feature loops and 2 completion attempts in the flow.
- **Separate counter files for planner and acceptance QA**: The `acceptance_fail_then_pass_mock_script` takes two `Path` arguments for counter files, keeping state-tracking isolated and deterministic.
- **Completer always returns COMPLETE in the fail-then-pass mock**: Unlike the `mock_script_with_qa_branch` template (which checks `RALPH_COMPLETE` env var), the standalone mock script for acceptance-gate-fail always returns `# Verdict: COMPLETE` because the completer is only invoked during completion attempts (where we always want COMPLETE).
- **No changes needed to `mod.rs`**: The new tests are added to the `tests()` function in `tests_qa.rs`, which is already called by `register_tests()` in `mod.rs:80`.

## Spec Deviations
- None. All acceptance criteria are addressed directly.

## Testing
- `qa::acceptance_gate_pass`: Sets `workflow.qa_enabled=true`, runs `ralph run` with `RALPH_COMPLETE=yes`, verifies exit 0, `status: "completed"`, `completion_attempts[0].artifacts.acceptance_passed == true`, and that the acceptance result artifact exists containing `# QA: PASS`.
- `qa::acceptance_gate_fail_forces_continue`: Sets `workflow.qa_enabled=true`, runs `ralph run --until-complete` with a counter-driven mock where acceptance QA fails first then passes. Verifies exit 0, first attempt has `acceptance_passed == false` with `verdict == "continue"`, at least 2 feature loops exist, final attempt has `acceptance_passed == true`, and final `status == "completed"`.
- Both tests can be run with: `ralph validate --bin <path> --filter qa::acceptance_gate`
- Full suite: `nix build` (runs all conformance tests)
