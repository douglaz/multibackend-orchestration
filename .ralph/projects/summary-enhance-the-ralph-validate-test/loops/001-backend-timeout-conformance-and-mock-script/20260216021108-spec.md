# Feature: Backend Timeout Conformance and Mock Script Foundations

## Description
Add the foundational `e2e_mock_ralph_script()` and `e2e_mock_gh_logging_script()` helpers to the validate harness, then implement the `backend_timeout_exhausted_fails_task` conformance test. This establishes the new helper functions that later features (PR metadata verification, impl-response artifact test) depend on, while delivering the only entirely missing test category: backend timeout handling. The test verifies that a sleeping backend exceeding `timeout_seconds` surfaces `BackendTimeoutExhausted` and marks the orchestration as failed with non-zero exit.

## Acceptance Criteria
- [ ] `e2e_mock_ralph_script(ralph_bin: &Path) -> String` helper exists in `src/validate/mock_scripts.rs`, embeds absolute path at generation time, uses `exec /absolute/path/to/ralph auto "$@"` pattern, does not resolve `ralph` via `PATH`
- [ ] `e2e_mock_gh_logging_script() -> String` helper exists in `src/validate/mock_scripts.rs`, captures full `gh pr create` args and `--body-file` content to a log file for later assertion
- [ ] New test module `src/validate/tests_e2e_conformance.rs` is created and registered in `src/validate/mod.rs`
- [ ] Test `backend_timeout_exhausted_fails_task` exists and: uses a mock backend that sleeps 30s, sets `backends.<name>.timeout_seconds = 2`, asserts surfaced error contains `BackendTimeoutExhausted`, asserts non-zero exit code, asserts task/orchestration ends in failed state
- [ ] Test does not introduce any recursive mock `ralph` invocation (mock embeds absolute path)
- [ ] No reformatter path is triggered on backend timeout (the test confirms timeout → `BackendTimeoutExhausted`, not reformatter fallback)
- [ ] Existing tests continue to pass (`cargo test` and `ralph validate` green)
