# Feature: Codex Reasoning Effort Suffix Decomposition

## Description
Decompose suffixed codex model names (e.g., `gpt-5.3-codex-xhigh`) at backend construction time: strip known effort suffixes (`-low`, `-medium`, `-high`, `-xhigh`) from the model name and inject them as a separate `-c model_reasoning_effort="<level>"` CLI argument. This allows ralph's existing per-role model config with suffixed names to work transparently with ChatGPT accounts that only accept the base `gpt-5.3-codex` model name.

## Acceptance Criteria
- [ ] A `parse_codex_model_effort()` function is added to `src/backend/codex.rs` that correctly splits a model name into `(base_model, Option<effort>)` for all four known suffixes (`-low`, `-medium`, `-high`, `-xhigh`)
- [ ] The suffix list is ordered longest-first so `-xhigh` is matched before `-high`
- [ ] Model names without a known suffix pass through unchanged with `None` effort
- [ ] `backend_from_config()` in `src/backend/codex.rs` uses `parse_codex_model_effort()` to decompose the model name before building CLI args
- [ ] When an effort suffix is detected, the args include `-c model_reasoning_effort="<level>"` AND `--model <base_model>` (without the suffix)
- [ ] When no effort suffix is detected, only `--model <model_name>` is added (no `-c` arg injected)
- [ ] The backend display name preserves the original suffixed model name (e.g., `codex(gpt-5.3-codex-xhigh)`) for state.json and logs
- [ ] Unit tests cover all four suffixes, no-suffix passthrough, and unknown-suffix passthrough
- [ ] An integration test in `tests/backend.rs` verifies a codex backend created with a suffixed model spec produces correct CLI args at execution time
- [ ] `nix build` passes with no errors or warnings
- [ ] No changes are made to `claude.rs`, `BackendConfig`, `BackendRegistry`, `resolve_backend_for_role()`, `get_or_create_for_spec()`, the orchestrator, `parse_backend_spec()`, or `ralph.toml`

## Files to Modify/Create
- `src/backend/codex.rs` — Add `CODEX_EFFORT_SUFFIXES` constant and `parse_codex_model_effort()` function; modify `backend_from_config()` to call the parser and inject `-c model_reasoning_effort` when a suffix is found
- `tests/backend.rs` — Add integration test that creates a codex backend with a suffixed model spec, executes against a mock arg-printing script, and verifies the CLI args contain `--model gpt-5.3-codex` and `-c model_reasoning_effort="xhigh"` (not the suffixed model name)
