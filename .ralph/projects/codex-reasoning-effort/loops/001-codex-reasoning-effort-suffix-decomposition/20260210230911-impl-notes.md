# Implementation Notes

## Decisions Made
- Added `CODEX_EFFORT_SUFFIXES` (longest-first) and `parse_codex_model_effort()` in `src/backend/codex.rs` to split known suffixes (`-xhigh`, `-medium`, `-high`, `-low`) into `(base_model, effort)` and pass through unknown/no suffix unchanged.
- Updated `backend_from_config()` in `src/backend/codex.rs` to:
  - Preserve display name as the original spec (`codex(<original_model>)`)
  - Inject `--model <base_model>`
  - Inject `-c model_reasoning_effort="<level>"` only when a known suffix is detected.
- Added unit tests in `src/backend/codex.rs` for all four known suffixes, no-suffix passthrough, and unknown-suffix passthrough.
- Added integration test `get_or_create_for_spec_codex_suffix_injects_reasoning_effort_args` in `tests/backend.rs` to verify execution-time CLI args use base model plus reasoning effort and do not use the suffixed model in `--model`.
- Updated the codex reformat fixture assertion in `tests/orchestrator.rs` to match the new decomposed codex args used at runtime.

## Spec Deviations
- Modified `tests/orchestrator.rs` in addition to the two listed files so `nix build` remains green after codex arg decomposition changed the expected runtime argument shape in that fixture.
