# Implementation Notes

## Decisions Made
- Added `run_in(working_dir)` as a private helper alongside the public `run()` method. The public `run()` resolves `current_dir()` and delegates. This allows tests to pass an explicit temp directory without using `set_current_dir` (which causes race conditions in parallel tests).
- `QuickPrdLock` is a minimal private struct wrapping `fs2::FileExt` exclusive locking, following the same pattern as `PrdLock` in `src/prd/cache.rs` but scoped to quick-prd.
- The reformat prompt on review-parse failure is self-contained (doesn't depend on `StagePromptBuilder` or pipeline context), matching the spec's request for a "strict reformat prompt that requests a single fenced JSON block."
- Section retry uses `MAX_SECTION_RETRIES = 2` (same constant name and value as `src/prd/pipeline.rs`), applied as up to 2 additional re-executions of the writer backend for draft. If sections remain missing after retries, the pipeline proceeds best-effort with whatever output was returned.
- The `run_review_with_retry` function returns `RalphError::QuickPrdFailed` after 3 parse failures (no silent fallback), differing from the full PRD's `run_llm_gap_analysis` which falls back to `GapReport::default()`. This matches the spec requirement.

## Spec Deviations
- The `run()` method uses an internal `run_in(working_dir)` split for testability. The public API is unchanged (`run(self) -> Result<QuickPrdResult>`).
- The `QuickPrdLock` struct is private rather than public since it's purely an implementation detail.

## Testing
- `test_review_parse_retry_success` — verifies that a malformed first response is retried and the second valid response succeeds (2 backend calls).
- `test_review_parse_retry_exhaustion` — verifies that 3 consecutive malformed responses produce `QuickPrdFailed` error (3 backend calls).
- `test_empty_issues_auto_approval` — verifies `approved: false` with empty issues is treated as approved, revision_count = 0.
- `test_revision_artifact_writing` — full pipeline with 1 rejection then approval; verifies `draft.md`, `review-1.json`, `revision-1.md`, `review-2.json`, `SPEC.md`, and `meta.json` all exist.
- `test_section_retry_limit` — writer returns incomplete spec 3 times; verifies writer called 3 times (1 + 2 retries) and pipeline proceeds best-effort.
- All 14 tests in `prd::quick` pass. Full suite of 222+ tests passes with 0 failures.
