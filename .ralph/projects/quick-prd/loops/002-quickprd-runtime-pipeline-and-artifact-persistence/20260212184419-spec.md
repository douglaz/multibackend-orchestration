# Feature: QuickPrd Runtime Pipeline and Artifact Persistence

## Description
Loop 1 already delivered the quick-prd foundations (`QuickPrd*` data types, prompts, helper functions, and helper unit tests). The next logical feature is the missing execution layer in `src/prd/quick.rs`: implement the async draft→review→revise pipeline, structured review retry parsing, cache locking/artifact persistence, and final `SPEC.md`/`meta.json` output. This closes the core runtime gap before CLI wiring.

## Acceptance Criteria
- [ ] `src/prd/quick.rs` defines `QuickPrdPipeline` with fields `writer`, `reviewer`, `options`, plus `QuickPrdPipeline::new(...)` and `QuickPrdPipeline::run(self) -> Result<QuickPrdResult>`.
- [ ] `run_review_with_retry(backend, prompt)` is implemented with 3 parse attempts, using `parse_review_feedback`; retries use a strict reformat prompt that requests a single fenced JSON block.
- [ ] If all 3 review-parse attempts fail, `run_review_with_retry` returns an error (no silent fallback).
- [ ] `QuickPrdPipeline::run` creates `.ralph/quick-prd/{idea_hash}/`, creates/acquires `.lock` with `fs2::FileExt` exclusive locking, and holds it for the full run.
- [ ] Draft step renders `DRAFT_PROMPT`, executes writer backend, section-checks with `check_spec_sections`, retries missing sections up to the same 2-retry pattern used in PRD pipeline, and writes cleaned output to `draft.md`.
- [ ] Review loop runs up to `max_revisions`; each review is timed, parsed via `run_review_with_retry`, and cached as `review-{N}.json`.
- [ ] Edge case is handled: `approved: false` with empty `issues` is treated as approved and exits revision loop.
- [ ] When issues exist, revision prompt uses the latest spec and `format_issues(issues)`; revised output is section-checked, cached as `revision-{N}.md`, and becomes the next review input.
- [ ] Finalization writes `SPEC.md` in cwd, writes `meta.json` with timing/approval/revision fields from `QuickPrdMeta`, and returns `QuickPrdResult` with correct paths/count/approved/summary.
- [ ] If max revisions are exhausted without approval, pipeline still writes final `SPEC.md` and returns `approved = false` with warning text in summary.
- [ ] Backend failures (including timeout) propagate immediately and preserve already-written cache artifacts.
- [ ] Add async tests in `src/prd/quick.rs` for: review parse retry success, review parse retry exhaustion, empty-issues auto-approval behavior, revision artifact writing, and section-retry limit handling.

## Files to Modify/Create
- `src/prd/quick.rs` - add `run_review_with_retry`, `QuickPrdPipeline` runtime loop, cache/lock/finalize logic, and new async unit tests.

## Dependencies
- Requires: Core types, prompts, helper functions, and unit tests for quick-prd pipeline (completed Loop 1)
- Blocks: `quick-prd` CLI integration (`src/cli/quick_prd.rs`, `src/cli/mod.rs` command wiring, and CLI parsing tests)
