# Feature: Complete Daemon Runtime Concurrency and PRD Lifecycle Separation

## Description
Issue 105 still has partial implementation from Loop 1 (`Git Semaphore and dispatch_task Decoupling`): the semaphore existed and `dispatch_task` now returns `Result<ChildHandle>`, but the full objective is not finished.  
The next feature is to finish the remaining runtime refactor while preserving single-iteration behavior and phase ordering, by implementing concurrent I/O in phase substeps and adding proper continuous-mode PRD task lifecycle control with bounded shutdown.

This feature should deliver:
- Concurrency where required (`kill_aborted_children`, `auto_rebase_phase`, `poll_and_claim`, `collect_children`) without changing `children` ownership model.
- PRD background execution only in continuous mode (single-iteration stays inline once).
- Correct, deterministic lock discipline for repo-root git operations via existing semaphore.
- Behaviorally verified coverage in `validate` for concurrency, partial-failure safety, and PRD lifecycle.

## Acceptance Criteria
- [ ] Main loop phase sequence remains exactly: `kill_aborted_children` -> `collect_children` -> `auto_rebase_phase` -> `poll_and_claim` -> `collect_children`.
- [ ] `children` remains `&mut HashMap<u32, ChildHandle>` throughout runtime orchestration.
- [ ] In single-iteration mode with PRD enabled, exactly one inline PRD tick runs and no PRD background task is spawned.
- [ ] In continuous mode with PRD enabled:
  - PRD task is started via `tokio::spawn`.
  - It performs one immediate tick at startup.
  - It sleeps for `poll_seconds` between ticks.
  - It observes a shared `CancellationToken` and does not start new ticks after shutdown begins.
- [ ] PRD shutdown behavior is exactly:
  - cancel token,
  - await PRD task with timeout `prd_shutdown_timeout_secs`,
  - call `handle.abort()` if timeout expires,
  - emit warning log and continue daemon shutdown.
- [ ] `kill_aborted_children` performs label fetches concurrently using `JoinSet` with cap `max(1, config.max_concurrent)`.
- [ ] On concurrent label-fetch failure for an issue in `kill_aborted_children`, runtime logs the error and skips processing that issue for the cycle; other issues continue.
- [ ] `auto_rebase_phase` keeps:
  - candidate discovery and merge-metadata lookups strictly sequential,
  - break-on-first merge-metadata failure behavior unchanged,
  - while executing rebase operations concurrently, capped by `config.max_rebases_per_cycle`.
- [ ] `auto_rebase_phase` applies resulting child-state mutations sequentially after concurrent rebase execution.
- [ ] `poll_and_claim` keeps claim/label-swap/idea-extraction sequential per issue.
- [ ] After claim stage, dispatches for claimed issues run concurrently up to available `slots`.
- [ ] `poll_and_claim` no longer mutates `children` inside `dispatch_task`; caller inserts only successful `ChildHandle`.
- [ ] On dispatch failure in a multi-issue batch, rollback remains per-issue: each failed issue must have `ralph:in-progress` swapped back to `ralph:failed` independently.
- [ ] Invariant (failure safety): one failed dispatch does not rollback/suppress siblings already claimed or dispatched.
- [ ] `collect_children` keeps child status scan sequential.
- [ ] For each finished child, teardown order remains:
  - `watcher_cancel` -> `watcher_join` -> `draft_pr_cancel` -> `draft_pr_join`.
- [ ] `collect_children` keeps `print_log_tail` behavior for failed children.
- [ ] `complete_task` execution for finished children is concurrent via `JoinSet`.
- [ ] Panic/error in one `complete_task` path is logged and does not abort completion for other children.
- [ ] Repo-root-only git operations obtain the shared semaphore permit before execution and release after:
  - fetch at repo root,
  - worktree add/remove/prune,
  - project-branch sync operations,
  - repo readiness checks.
- [ ] Long worktree-local operations (`git rebase`, `git push` in worktrees) do not hold repo-root semaphore permit.
- [ ] All existing tests pass, and new tests are added/updated for:
  - concurrent dispatch of 2+ claimed issues,
  - partial rollback when one claim dispatch fails,
  - single-iteration PRD determinism (inline only),
  - concurrent rebase + dispatch without git lock contention failures.
- [ ] New/adjusted daemon conformance tests are registered in `src/validate/mod.rs`.
