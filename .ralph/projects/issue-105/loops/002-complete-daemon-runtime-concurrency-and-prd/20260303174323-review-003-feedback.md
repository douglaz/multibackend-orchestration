# Review: SUGGESTIONS

## Required Changes
1. **[src/validate/tests_daemon_concurrency.rs] tighten `single_iteration_prd_inline_only` so one inline tick is proven, not inferred**
   - Current: the test allows `tick_count == 0 || tick_count == 2`, and infers background safety from warning markers. This can pass if inline PRD is skipped while the run is still technically configured for PRD.
   - Expected: assert a deterministic inline PRD invocation (exactly one tick) and explicitly fail on any second tick path. E.g. configure mock inputs so PRD poll is forced and assert `tick_count == 2`, and add a stronger invariant that no background-only PRD invocation occurs.
   - Reference: acceptance criteria — “single-iteration PRD runs exactly one inline tick and no background task” and `Single-iteration PRD determinism (inline, no background task)`.

2. **[src/validate/tests_daemon_concurrency.rs] make `concurrent_rebase_dispatch_no_lock_contention` actually execute rebase work in the same cycle as dispatch**
   - Current: in single-iteration mode, `auto_rebase_phase` runs before `poll_and_claim`; with an initially empty `children` map, no actual rebase is performed in-cycle, so the test currently validates command handling coverage, not rebase/dispatch overlap.
   - Expected: create a scenario where both a rebase candidate and claimable issue are handled in one runtime cycle (or equivalent deterministic dual-path invocation), then assert no `index.lock`/git-root serialization errors and successful completion for both paths.
   - Reference: acceptance criteria — `concurrent rebase + dispatch without git lock contention errors`, `Add/adjust integration coverage`.

3. **[src/validate/tests_daemon_concurrency.rs] remove permissive PRD-tick and rebase-overlap assertions that mask regressions**
   - Current: the test still tolerates edge conditions that hide missing behavior (`0 or 2` ticks and only unhandled-command checks for rebase-capable paths).
   - Expected: replace permissive checks with strict causality checks (exact tick count, and explicit path-execution assertions for both PRD + rebase+dispatch overlap).
   - Reference: acceptance criteria and testability requirements in the feature spec section.

## Recommended Improvements
1. Add a shared test helper (either in `mock_scripts` or `harness`) that records `poll_and_advance_prd` call count and distinguishes inline/background invocation, then reuse it across daemon PRD tests for stable assertions.
2. If continuous-mode test scaffolding is introduced, prefer a bounded-run harness pattern (spawn daemon, wait for two cycles, signal stop) over single-iteration mode for overlap tests; this makes the rebase+dispatch concurrency behavior directly observable.
