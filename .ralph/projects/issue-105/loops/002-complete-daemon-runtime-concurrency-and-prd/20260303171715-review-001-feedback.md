## Required Changes
1. **[tests_daemon_concurrency.rs](src/validate/tests_daemon_concurrency.rs): strengthen single-iteration PRD determinism assertions**
   - Current: the test only checks for absence of a `"PRD background task"` log marker, but runtime does not emit that marker, so this does not verify whether a background PRD task was spawned.
   - Expected: assert PRD behavior by instrumentation counters/timestamps in mock scripts (e.g., one PRD tick, no spawned background handle, and no `tokio::spawn`-driven PRD trace) and by checking no second tick after single-iteration completion.
   - Reference: Acceptance criteria — “Single-iteration mode runs exactly one inline PRD tick and no PRD background task is spawned.”

2. **[tests_daemon_concurrency.rs](src/validate/tests_daemon_concurrency.rs): harden `partial_dispatch_rollback`**
   - Current: the test does not explicitly prove one issue failed dispatch and that only that issue was rolled back to `ralph:failed` while siblings remained unaffected.
   - Expected: assert per-issue outcomes: failed issue has only `ralph:failed` rollback state and successful issue(s) keep their claimed/dispatch state and are not rolled back.
   - Reference: Acceptance criteria — “Dispatch failure rollback remains per-issue,” and “invariant: one failed dispatch does not rollback/suppress siblings.”

3. **[tests_daemon_concurrency.rs](src/validate/tests_daemon_concurrency.rs) + harness support in [src/validate/harness.rs](src/validate/harness.rs): actually exercise concurrent rebase + dispatch under root Git lock pressure**
   - Current: the lock-contention test sets up dispatch but does not reliably force an actual auto-rebase candidate execution path in the same cycle, so it may not validate the intended contention avoidance.
   - Expected: create a scenario with at least one claimed issue and one rebase candidate in the same cycle, then assert no repo-root lock contention errors and both operations complete.
   - Reference: Acceptance criteria — “concurrent rebase + dispatch without git lock contention errors.”

4. **[src/daemon/runtime.rs](src/daemon/runtime.rs): align PRD shutdown wording vs strict spec (if literal compliance is required)**
   - Current: timeout fallback uses `AbortHandle::abort()` captured before awaiting the `JoinHandle`.
   - Expected: either keep this behavior with a short inline rationale in-code/test to show equivalence, or use direct `JoinHandle::abort()` ownership flow where feasible.
   - Reference: “PRD shutdown: ... call `handle.abort()` if timeout expires.”
