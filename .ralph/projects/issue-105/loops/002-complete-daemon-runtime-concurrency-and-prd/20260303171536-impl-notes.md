# Implementation Notes

## Decisions Made
- **PRD lifecycle via abort_handle**: Used `JoinHandle::abort_handle()` to get an `AbortHandle` before passing the `JoinHandle` to `tokio::time::timeout`. This allows calling `abort()` on timeout without ownership conflicts.
- **Concurrent rebase split into stages**: Restructured `auto_rebase_phase` into 3 stages: (1) sequential discovery/metadata with break-on-first-failure, (2) concurrent rebase execution via `JoinSet`, (3) sequential mutation application sorted by issue number for determinism.
- **Concurrent dispatch split into stages**: Restructured `poll_and_claim` into 3 stages: (1) sequential claim/label-swap/idea-extraction, (2) concurrent dispatch via `JoinSet`, (3) sequential result collection with per-issue rollback.
- **RebaseCandidate/RebaseOutcome types**: Introduced these structs to decouple data flow from `children` ownership, enabling concurrent execution without shared mutable state.
- **kill_aborted_children bounded concurrency**: Used manual in-flight tracking with JoinSet to cap concurrent label fetches at `max(1, config.max_concurrent)`, matching the spec exactly.
- **No worktree.rs/bootstrap.rs changes**: Semaphore discipline was already correctly implemented — callers in runtime.rs acquire permits before calling worktree functions, and long worktree-local operations (rebase, push) don't hold permits. The `_repo_root_lock` parameters in worktree.rs serve as documentation/future extensibility.

- **worktree.rs/bootstrap.rs unchanged**: The spec asked to "verify/complete repo-root operation paths." After verification, all repo-root operations are already correctly serialized by the caller in runtime.rs. No changes were needed in these files.
