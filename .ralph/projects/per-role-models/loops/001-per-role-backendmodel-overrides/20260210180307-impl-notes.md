# Implementation Notes

## Decisions Made
- Added per-role override fields across all config layers:
`src/config/global.rs`, `src/config/project.rs`, `src/config/mod.rs`.
Rationale: enable resolved overrides to flow from global/project/CLI into runtime orchestration.
- Introduced `RunWorkflowOverrides` in `src/config/mod.rs` and updated `resolve_effective_config()` to apply precedence `CLI > project > global > None` for each role override.
Rationale: keep precedence logic explicit and centralized.
- Added CLI flags to `RunArgs` in `src/cli/mod.rs` and wired them through `src/cli/run.rs` into `RunOptions` and orchestrator resolution.
Rationale: expose per-role overrides directly on `ralph run`.
- Added `RoleOverrides` in `src/backend/mod.rs` and updated `assign_feature_backends()` / `assign_completion_backends()` to compute baseline alternation first, then override per role.
Rationale: preserves existing alternation for non-overridden roles.
- Updated orchestrator (`src/workflow/orchestrator.rs`) to:
construct `RoleOverrides` from effective config, pass overrides into both assignment functions, and preload override specs via `get_or_create_for_spec()` before `health_check_all()`.
Rationale: ensures health checks include override backends/models.
- Expanded tests:
`tests/backend.rs` now covers all/partial/no override combinations for feature/completion assignment, and `src/config/mod.rs` adds precedence + validation tests for per-role overrides.
