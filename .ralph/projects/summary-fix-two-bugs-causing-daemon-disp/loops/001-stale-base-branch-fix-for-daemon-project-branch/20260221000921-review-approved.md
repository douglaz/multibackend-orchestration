## Notes

The implementation adds a thoughtful worktree-aware fallback: when the base branch is checked out in the current worktree, it detaches HEAD first before running `git branch -f`. If `git branch -f` still fails with "cannot force update" (e.g., another worktree), it falls back to `git update-ref`. This is a sensible defensive measure for daemon-managed worktree environments beyond what the spec strictly required, but it doesn't change behavior for the happy path.

The integration tests in `tests/mcp_handlers.rs`, `tests/reconstruction.rs`, and `tests/recovery.rs` were updated to set up an `origin` remote, which is now required because `create_project` resolves `origin/{base_branch}`. This is a correct and necessary cascading fix.
