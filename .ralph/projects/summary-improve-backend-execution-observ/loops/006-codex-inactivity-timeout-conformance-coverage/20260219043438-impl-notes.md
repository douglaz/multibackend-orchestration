# Implementation Notes

## Decisions Made
- The two Codex-specific conformance tests (`codex_active_stream_no_timeout` and `codex_hanging_stall_timeout`) reuse the existing mock script generators (`active_streaming_planner_mock_script` and `hanging_after_partial_planner_mock_script`) since these are backend-agnostic shell scripts — the Codex-vs-Claude distinction is controlled by setting `workspace.default_backend` to `"codex"` via config, which causes the orchestrator to route the planner role through the Codex backend.
- No changes to `mock_scripts.rs` were needed because the existing mock scripts already handle both backends identically (they're mock shells that respond to role-detecting prompt patterns, not real backend binaries).
- The stall test asserts `elapsed < 20s` to ensure the idle timeout (1s) kills the mock promptly rather than waiting for the full 30s sleep, providing a timing-based correctness check on top of the semantic assertions.
- Both Codex tests set `workflow.prompt_review_enabled` to `false` to match the pattern of the non-Codex equivalents, keeping mock complexity low.
