# Implementation Notes

## Decisions Made
- Reused existing mock scripts (`active_streaming_planner_mock_script` and `hanging_after_partial_planner_mock_script`) for the Codex tests rather than creating new Codex-specific variants. The mock scripts are backend-agnostic (they detect role via stdin prompt fragments, not backend identity), so the same scripts work for both Claude and Codex paths. The Codex-specific behavior is achieved by setting `workspace.default_backend` to `codex` via config, which routes the planner role through the Codex backend in the backend registry.
- Used `workspace.default_backend` config key (not `workflow.planner_backend`) to force Codex as the starting backend. This causes loop 1 (odd) to use Codex for the planner role via the alternation algorithm, which is the most natural way to test the Codex planner path end-to-end.
- Backend metadata verification uses `h.load_state(project_id)` returning `serde_json::Value`, checking `state["loops"][0]["backends"]["planner"]` starts with `"codex"`. This matches the pattern used in existing integration tests (e.g., `tests/orchestrator.rs`) while being appropriately loose about the exact model suffix (e.g., `codex(gpt-5.3-codex-xhigh)`).
- No changes to `mock_scripts.rs` were needed since the existing mock scripts handle all roles correctly regardless of which backend invokes them.
- No changes to `src/validate/mod.rs` were needed since `tests_streaming::tests()` is already registered and the new tests are added to that vector.

## Spec Deviations
- None. All six acceptance criteria are addressed:
  1. `codex_active_stream_no_timeout` — Codex planner backend, active stream, success when output keeps arriving below idle threshold even if total runtime exceeds timeout.
  2. `codex_hanging_stall_timeout` — Codex planner backend, partial output then stall, timeout failure.
  3. Stall test asserts partial output retained and timeout footer marker present (`"--- timeout ts="`).
  4. Stall test verifies PID cleanup via `libc::kill(pid, 0)` returning `-1` with `ESRCH`.
  5. Both new tests assert `state["loops"][0]["backends"]["planner"]` starts with `"codex"` to prevent accidental Claude-path coverage.
  6. Existing streaming conformance tests are unchanged (only additive changes to the test vector).

## Testing
- Run `nix develop -c cargo check` — compiles cleanly (only pre-existing unrelated warning about unused import in `tests_auto_init.rs`).
- Run the new tests: `nix develop -c cargo run -- validate --filter streaming::codex` to execute both Codex-specific conformance tests.
- Run all streaming tests: `nix develop -c cargo run -- validate --filter streaming` to verify no regressions in existing tests.
- Run full validate suite: `nix develop -c cargo run -- validate` to confirm all conformance tests pass.
