# Feature: Claude stream-json arg normalization and NDJSON output parsing

## Description
Implement two coordinated capabilities that together enable Claude's streaming JSON output mode:

1. **Arg normalization**: Modify `src/backend/claude.rs` to always emit exactly one `--output-format stream-json` pair for both fresh and resumed Claude invocations. Strip all pre-existing `--output-format` variants (both `--output-format <value>` and `--output-format=<value>` syntaxes) before appending, ensuring idempotent behavior.

2. **Stream NDJSON output normalization**: Create `src/backend/output_normalizer.rs` with a `normalize_claude_stream_json(raw: &str) -> Result<NormalizedOutput>` function. Integrate it into a top-level `normalize_output` dispatcher that auto-detects whether raw output is NDJSON stream, single-object Claude JSON, or raw text, and routes accordingly. The NDJSON normalizer must concatenate `content_block_delta` text deltas in arrival order, extract `session_id` from `message_start`, extract usage fields (`tokens_in`, `tokens_out`, `cached_in`) from `message_delta`/summary events, and gracefully skip unknown event types and malformed lines.

## Acceptance Criteria
- [ ] `backend_from_config` in `claude.rs` strips all existing `--output-format` variants (both `--output-format value` and `--output-format=value` forms) from configured args before appending exactly one `--output-format stream-json` pair.
- [ ] Normalization is idempotent: running it twice still produces exactly one `--output-format stream-json`.
- [ ] A resumed-call arg path (`effective_args_claude` or equivalent) also produces exactly one `--output-format stream-json`.
- [ ] `normalize_claude_stream_json` concatenates multiple `content_block_delta` text entries in order (not last-wins).
- [ ] `session_id` is extracted from `message_start.message.id` when present.
- [ ] `tokens_in`, `tokens_out`, `cached_in` are extracted from usage/summary events when present.
- [ ] Detection logic in `normalize_output` correctly distinguishes NDJSON stream (first valid JSON object has `"type"` field) from single-object Claude JSON.
- [ ] Unknown event types are silently ignored (forward-compatible).
- [ ] Malformed/non-JSON lines are skipped without error.
- [ ] If JSON events exist but no text deltas accumulated, return `RalphError::ParseError`.
- [ ] If zero JSON events parsed, return raw text fallback (existing behavior preserved).
- [ ] Existing single-object JSON normalization behavior (if any on master) is preserved or replicated.
- [ ] Unit tests cover: delta concatenation, session_id extraction, usage extraction, empty-text error, unknown events, malformed lines, detection routing, idempotent arg stripping.

## Files to Modify/Create
