# Feature: Inactivity timeout semantics for CLI and tmux execution paths

## Description
Loop 1 completed the timeout error-model foundation (`TimeoutKind` + enriched `BackendTimeout` + retry log fields), but runtime behavior is still wall-clock based in both `CliBackend::execute_streaming` and tmux `wait_for_exit`.  
This feature switches both execution paths to true inactivity timeout semantics (`timeout_seconds` = max idle duration), emits `TimeoutKind::Idle` on new timeouts, and adds conformance coverage for active-stream and stall behavior.

## Acceptance Criteria
- [ ] Non-tmux backend no longer uses a wall-clock `timeout(...)` wrapper for total runtime; timeout checks are based on idle duration only.
- [ ] Non-tmux activity is updated on any successful stdout/stderr read with `>0` bytes.
- [ ] Non-tmux watchdog checks idle elapsed periodically (about 1s), and times out only when `idle_duration >= timeout_seconds`.
- [ ] On non-tmux idle timeout, process group cleanup still occurs, partial output is preserved, timeout footer is written, and returned error is `RalphError::BackendTimeout { timeout_kind: TimeoutKind::Idle, idle_seconds, ... }`.
- [ ] Watchdog cancellation is race-safe: normal process completion cannot be misreported as timeout.
- [ ] `tmux::wait_for_exit` accepts stdout and stderr capture paths in addition to exit-file path and tracks file-size growth on either stream as activity.
- [ ] Tmux timeout is based on inactivity since last observed growth (not total wait duration), and returns `TimeoutKind::Idle`.
- [ ] Tmux execution creates a dedicated stderr capture file, cleans it up with other temp files, and preserves existing stdout capture behavior for downstream parsing.
- [ ] Backend output artifact persistence in tmux path includes captured stderr content separately from stdout.
- [ ] Existing timeout behavior tests are updated from `Walltime` expectations to `Idle` where applicable.
- [ ] Conformance coverage includes: active streaming beyond `timeout_seconds` without timeout, hanging-after-partial-output timeout with cleanup and retained partial output, and regression preservation of timeout cleanup behavior.
- [ ] No new config keys are introduced and `timeout_seconds` remains unchanged in schema/name.

## Files to Modify/Create
- `src/backend/mod.rs` - Replace wall-clock timeout flow with inactivity tracking in `execute_streaming`, including stdout/stderr activity bookkeeping, timeout signaling, and `TimeoutKind::Idle`.
- `src/backend/tmux.rs` - Extend `wait_for_exit` signature and implement idle detection via stdout/stderr capture-file growth.
- `src/backend/tmux_backend.rs` - Add stderr capture-file wiring in tmux command execution, pass both capture paths to `wait_for_exit`, return `Idle` timeout kind, and persist stderr artifact content.
- `src/backend/mod.rs` - Update/add unit tests for inactivity semantics (active stream survives, stall times out with idle context).
- `src/backend/tmux.rs` - Update/add unit tests for growth-based inactivity logic across stdout/stderr files.
- `src/backend/tmux_backend.rs` - Update timeout-related tests to assert `TimeoutKind::Idle` and verify stderr capture handling.
- `tests/backend_tmux.rs` - Update integration expectations from wall-clock timeout kind to idle timeout kind and validate unchanged cleanup guarantees.
- `src/validate/tests_streaming.rs` - Add/adjust conformance tests for active-stream-no-timeout and hanging-stall-timeout under inactivity semantics.
- `src/validate/mock_scripts.rs` - Add any needed mock streaming/hanging scripts to support new conformance scenarios.
