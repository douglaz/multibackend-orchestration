# Review: SUGGESTIONS

## Required Changes
1. **Non-tmux idle timeout does not terminate promptly**: fix process termination on timeout so execution returns near the configured idle threshold.
Current: `src/backend/mod.rs:363` calls `libc::kill(-(pid as i32), SIGKILL)` without putting the child in its own process group first; in practice this misses the target group. Evidence: `cargo test cli_backend_stall_after_partial_output_times_out_idle -- --nocapture` finished in **30.01s** with a **200ms** timeout, meaning timeout was flagged but process cleanup did not happen at timeout.
Expected: ensure the spawned backend process is in a dedicated process group (or use a guaranteed kill path/fallback) and verify timeout returns shortly after idle threshold while preserving partial output/footer.
Reference: Feature spec AC “On non-tmux idle timeout, process group cleanup still occurs…” and “timeout based on idle duration only.”

2. **Timeout tests do not validate kill-at-timeout behavior**: add elapsed-time assertions to prove inactivity timeout enforcement, not just eventual failure.
Current: `src/backend/mod.rs:953` test and `src/validate/tests_streaming.rs:396` hanging test assert timeout/error/log content, but not that execution ends within a bounded duration; this allowed the 30s regression to pass.
Expected: assert runtime upper bounds (for example, around configured timeout + small buffer) in stall-timeout unit/conformance tests.
Reference: Feature spec AC for inactivity semantics and conformance “hanging… timeout with cleanup/kill.”
