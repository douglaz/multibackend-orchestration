# Feature: Fix waiting-label reconciliation ordering and dedup test regression

## Description
Two final review amendments remain unaddressed from rounds 1 and 2. First, the `dedup_invariant_issue_processed_at_most_once` integration test fails because the Pending→AwaitingAnswers path now makes 2 `gh issue edit` calls (remove `ralph:prd` + add `ralph:waiting-feedback`) but the test still expects a count of 1. Second, `ralph:waiting-feedback` reconciliation in waiting states is gated behind `get_or_fetch_bot_login(...)`, so if `gh api user` fails, the waiting label is never applied/reconciled. The reconciliation must be moved before the bot-login lookup in each waiting-state transition wrapper so it runs on no-op, processing, and retry/error paths. Both integration and conformance bot-login-failure tests must also assert that `--add-label ralph:waiting-feedback` is attempted.
