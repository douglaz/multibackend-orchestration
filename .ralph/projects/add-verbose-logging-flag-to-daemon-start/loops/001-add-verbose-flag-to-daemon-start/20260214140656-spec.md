# Feature: Add --verbose Flag to Daemon Start

## Description
Add a `--verbose` CLI flag to `ralph daemon start` that enables detailed daemon runtime diagnostics on `stderr` using guarded `eprintln!` calls. This includes adding the `verbose: bool` field to both `DaemonStartArgs` and `DaemonRuntimeConfig`, instrumenting the runtime event loop with verbose logging at all contract-specified event points (poll cycle, child collection, task transitions, operational context), and adding four conformance tests to validate correct CLI behavior and output presence/absence. All new verbose log lines are prefixed with `verbose:` and only emitted when the flag is set. Existing unconditional `eprintln!` messages remain unchanged.

## Acceptance Criteria
- [ ] `DaemonStartArgs` gains `#[arg(long)] pub verbose: bool` field
- [ ] `DaemonRuntimeConfig` gains `pub verbose: bool` field
- [ ] `execute_start` plumbs `args.verbose` into `DaemonRuntimeConfig`
- [ ] `ralph daemon start --verbose` is accepted (exit 0)
- [ ] `ralph daemon start` without `--verbose` behaves identically to today (no `verbose:` lines on stderr)
- [ ] `ralph daemon status --verbose` and `ralph daemon abort --verbose` are rejected by clap (non-zero exit, stderr references invalid/unexpected `--verbose`)
- [ ] Poll-cycle verbose log emits iteration number, active child count, available slot count, and planned sleep duration
- [ ] Child collection logs each terminal child event with task id, pid, and exit status
- [ ] Child collection logs one summary line with count of still-running children (only when count > 0)
- [ ] No per-child "still running" lines are emitted
- [ ] `dispatch_task` CAS success logs `pending -> in_progress` with task id and pid
- [ ] `complete_task` CAS success logs `in_progress -> terminal` with task id
- [ ] Dispatch CAS race (task already terminal) logs abort-race context and spawned pid
- [ ] Completion CAS race (task already terminal) logs preservation message
- [ ] `reconcile_tasks` logs per-task reset action when verbose
- [ ] `adopt_pending_tasks` logs per-task re-adoption action when verbose
- [ ] `reconcile_tasks` signature updated to accept `verbose: bool` (or config reference) and all call sites plumbed
- [ ] All new verbose logs are guarded by `if config.verbose` (or equivalent `if verbose`)
- [ ] All new verbose logs go to `stderr` via `eprintln!` and start with `verbose:`
- [ ] Conformance test `daemon::verbose_flag_accepted_by_start` passes
- [ ] Conformance test `daemon::verbose_flag_rejected_by_status_and_abort` passes
- [ ] Conformance test `daemon::verbose_output_present_when_enabled` passes (stderr has `^verbose:` lines including poll-cycle line)
- [ ] Conformance test `daemon::verbose_output_absent_when_disabled` passes (stderr has zero `^verbose:` lines)
- [ ] Tests registered in `tests()` vector in `tests_daemon.rs`
- [ ] No new dependencies added
- [ ] `nix develop -c cargo check` passes
- [ ] `nix develop -c cargo test` passes

- [ ] Existing daemon and broader validate tests continue to pass
