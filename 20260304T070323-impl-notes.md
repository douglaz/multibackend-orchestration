# Implementation Notes

## Decisions Made
- **Backend preflight in quick-dev-auto**: Added early resolution/validation before quick-PRD runs or project is created. Uses workspace-level config (no project overrides since project doesn't exist yet) with CLI args taking precedence, mirroring the orchestrator's resolution chain.
- **Exposed orchestrator helpers**: Made `resolve_implementer_backend`, `resolve_reviewer_backend`, and `validate_distinct_backends` `pub(crate)` so `quick-dev-auto` can reuse `validate_distinct_backends` directly for identical error messages.
- **Quick-dev marker detection in reconstruction**: Used presence of `quick_dev_review_iteration` or `quick_dev_final_review_attempts` in state.json (alongside `quick_dev_phase`) as a reliable marker that the file was written by the quick-dev orchestrator. This scopes all state.json overrides to quick-dev projects only — non-quick projects that lack these fields are unaffected even if a rogue state.json exists.
- **current_phase/phase_iteration restoration**: Restored from state.json whenever the file is identified as quick-dev-originated (has markers), not just when `quick_dev_phase` is `Some`. This handles the post-completion case where `quick_dev_phase` is cleared to `None` but `current_phase=completing` must still be visible to reconstruction.
