# Implementation Notes

## Decisions Made
- Replaced raw numeric substring matching (`"403"`, `"500"`, `"502"`, `"503"`, `"504"`) with context-aware HTTP status code extraction via two bounded patterns: `http <NNN>` and `returned error: <NNN>`. These are the two forms used by git/curl transport error messages.
- Added two private helper functions (`extract_http_status_codes`, `parse_bounded_3digit_code`) to parse HTTP codes only from explicit error context, preventing URL/path numeric collisions.
- HTTP 401 is now explicitly classified as non-retryable (previously only covered implicitly via the `"authentication"` text pattern).
- Classification precedence order: (1) text-based permanent patterns → non-retryable, (2) HTTP 401/403 from context → non-retryable, (3) HTTP 5xx from context → retryable, (4) text-based transient patterns → retryable, (5) unknown → non-retryable.
- Preserved all existing text-based patterns unchanged (removed only the raw numeric entries `"403"` from non-retryable and `"500"`/`"502"`/`"503"`/`"504"` from retryable).
- The 3-digit code parser rejects codes that are part of longer numeric tokens (e.g. `5031` is not matched as `503`).

## Spec Deviations
- None. All acceptance criteria are satisfied exactly as specified.

## Testing
- 7 new tests added covering all required regression cases:
  - `dns_error_with_url_containing_403_is_retryable` — DNS error with `403` in URL path (retryable)
  - `explicit_http_401_is_non_retryable` — HTTP 401 via `returned error: 401` (non-retryable)
  - `explicit_http_503_is_retryable` — HTTP 503 via `HTTP 503` prefix (retryable)
  - `explicit_http_403_is_non_retryable` — HTTP 403 via `returned error: 403` (non-retryable)
  - `url_containing_500_plus_http_401_is_non_retryable` — URL with `500` + actual HTTP 401 (non-retryable)
  - `extract_http_status_codes_bounded_context` — direct unit test of the extraction helper
- All 52 existing + new github.rs tests pass (`cargo test --lib daemon::github -- --test-threads=1`).
- `cargo check` passes with no new warnings.
- Public API contracts (`is_retryable_push_error`, `push_branch_with_retry`, `push_branch_with_retry_impl`) are unchanged.
- Existing mock-binary tests (`transient_then_success`, `permanent_failure`, `transient_exhaustion`, `unknown_failure`, `classifies_on_stderr_not_branch_name`) all continue to pass.
- Pre-existing flaky temp-file race in parallel test execution (not introduced by this change) occasionally fails one of the mock-binary tests; passes reliably with `--test-threads=1`.
