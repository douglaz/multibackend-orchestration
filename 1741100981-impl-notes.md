# Implementation Notes

## Decisions Made
- Created a centralized `persist_destination_and_checkpoint` helper that atomically writes destination phase/counters to `state.json` before attempting any checkpoint/commit. This ensures the invariant: if persistence fails, no checkpoint is attempted; if checkpoint fails after persistence, resume starts from the destination phase.
- Guard-at-entry checks are placed at the very beginning of `CodexReview` and `FinalReview` match arms, before any backend call or prompt construction. This guarantees zero backend invocations in guarded-entry scenarios.
- The FinalReview guard-at-entry writes a distinct force-complete artifact with "(Guard-at-Entry)" in the title and a different summary message to distinguish it from the in-loop force-complete path.
- For the `FinalReview -> PlanAndImplement` reloop transition, `review_iteration` is reset to 0 in the persisted destination state (matching the fresh cycle semantics), while `final_review_attempts` carries forward.
- All five non-terminal transitions now use the centralized helper, replacing the prior pattern of `checkpoint_if_enabled` without destination persistence.

## Spec Deviations
- None. All acceptance criteria are implemented as specified.
