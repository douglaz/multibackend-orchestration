### Key Implementation Details

1. **`draft_pr_watcher()`** — A cancellation-aware async loop that polls `has_commits_ahead_of_base` every 15 seconds. When the branch diverges, it pushes and creates a draft PR, then exits (single-flight). Uses `tokio::select!` with the `CancellationToken` for cooperative shutdown.

2. **PR URL resolution** — In `dispatch_task()`, before spawning the child process, we call `github::find_existing_pr()` with the exact head branch name. If a PR already exists, its URL is passed to the child via `--pr-url` and no watcher is started.

3. **Lifecycle teardown** — `draft_pr_cancel` is cancelled and `draft_pr_handle` is joined in all three exit paths: `collect_children()` (normal exit), `kill_aborted_children()` (abort), and `drain_all_children()` (daemon shutdown).

4. **Child process plumbing** — `spawn_ralph_auto` and `spawn_ralph_run` both accept `pr_url: Option<&str>` and append `["--pr-url", url]` to the command args when present.

## Decisions Made

1. **Poll interval of 15 seconds** — Chosen as a reasonable balance between responsiveness and API/git overhead. The constant `DRAFT_PR_WATCH_POLL_SECONDS` is defined at the top of `runtime.rs` for easy adjustment.

2. **Single-flight watcher** — The watcher creates one draft PR then returns, rather than continuing to poll. This avoids duplicate PR creation and keeps the task simple.

3. **No watcher when PR URL already known** — If `find_existing_pr()` returns a URL before spawning, we skip the watcher entirely and pass the URL directly to the child.

4. **`spawn_blocking` for git operations** — All blocking git/GitHub operations inside the watcher use `tokio::task::spawn_blocking` to avoid blocking the async runtime.

5. **Error logging, not propagation** — The watcher logs errors via `eprintln!` and continues polling rather than propagating errors upward. This matches the existing artifact-watcher pattern and prevents transient git failures from killing the task.
