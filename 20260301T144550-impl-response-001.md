# Implementation Response (Iteration 1)

## Changes Made
1. **Fixed draft PR lifecycle E2E timing to make watcher deterministic** (Required Change #1)
   - **Root cause:** The `e2e_draft_create_via_binary` test had a race condition where the mock child process exited after only 1 second (`sleep 1`), but the `draft_pr_watcher` uses a default 15-second poll interval (`DRAFT_PR_WATCH_POLL_SECS`). The watcher's first poll might miss the commit (child hasn't committed yet), and by the time it would poll again (15 seconds later), the child has already exited and the watcher is cancelled in `collect_children`. This meant no draft PR was ever created, so `handle_pr_flow` fell through to the non-draft `create_pr` path.
   - **Fix in `src/validate/tests_pr_runtime.rs`:**
     - Added `("RALPH_DRAFT_PR_WATCH_POLL_SECS", "1")` to the E2E test's `daemon_env` environment variables, reducing the watcher poll interval from 15 seconds to 1 second. This ensures the watcher detects the child's commit within its second poll cycle (first poll may race with child startup).
     - Increased the mock ralph child script's `sleep` from 1 second to 10 seconds, providing ample time for the watcher to detect the commit, push the branch, and create the draft PR before the child exits and the watcher is cancelled.
   - **Result:** The watcher now reliably creates the draft PR before the child exits, so when `handle_pr_flow` runs in `complete_task`, it finds the existing draft PR via `find_existing_pr`, checks `is_pr_draft` (returns true from mock), and calls `mark_pr_ready` — producing the expected `create → ready` sequence in the GH log.
