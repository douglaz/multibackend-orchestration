# Implementation Response (Iteration 1)

## Changes Made

1. **Done transition durability ordering** (Required Change 1)
   - Moved the durable `state.save()` call **inside** `do_approval_transition()` (`src/daemon/interactive_prd.rs:853-861`), so it executes BEFORE `ralph:prd-active` is removed.
   - If save fails, the in-memory state is reverted to `AwaitingFeedback` and an error is returned — `ralph:prd-active` removal is never reached, keeping the issue poll-visible.
   - The `ralph:prd-active` label removal now only occurs after the save succeeds (`src/daemon/interactive_prd.rs:864-871`).
   - `finish_transition` retains its save-failure revert logic as a safety net, but for Done transitions the critical save now happens inside the transition function itself.

2. **Status marker spoof hardening in transition_to_failed** (Required Change 2)
   - Added `bot_login: Option<&str>` parameter to `transition_to_failed()` (`src/daemon/interactive_prd.rs:1365`).
   - When `bot_login` is available, uses `github::post_bot_comment_with_marker()` for bot-scoped idempotency; falls back to generic `post_comment_with_marker()` when bot identity is unavailable (`src/daemon/interactive_prd.rs:1388-1400`).
   - Threaded `bot_login_cache: &mut Option<String>` through `finish_transition()` (`src/daemon/interactive_prd.rs:995`) so all callers provide bot identity to `transition_to_failed`.
   - Updated all three `finish_transition` call sites (`src/daemon/interactive_prd.rs:415,557,682`) to pass `bot_login_cache`.
   - All three transition functions (`transition_pending_to_awaiting_answers`, `transition_awaiting_answers_to_awaiting_feedback`, `transition_awaiting_feedback`) already had `bot_login_cache` available.
