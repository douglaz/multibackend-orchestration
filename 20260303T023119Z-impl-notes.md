# Implementation Notes

## Decisions Made
- **`CopyFilesTarget` enum for branching**: Introduced a `CopyFilesTarget` enum (`NewOrEmpty` / `ExistingWorkspace`) returned by `validate_copy_files_target()` to cleanly separate the three execution paths (full scaffold, overlay, error) before any planning or execution begins.
- **`OverlayConfig` action variant**: Added a new `InitAction::OverlayConfig` variant rather than reusing `WriteConfig`, so that dry-run output clearly distinguishes "overlay-config" from "write-config" in its action descriptions.
- **Recursive `merge_tables` for config overlay**: The config merge uses a recursive table-walking approach with `toml_edit::DocumentMut` to insert missing keys from the default reference into the existing document. This preserves comments, formatting, and unknown user keys. The borrow checker is satisfied because we only call `get_mut` once per key per level (consistent with the project's documented pattern for mutable table traversal).
- **Error variant selection**: Non-workspace errors use `RalphError::Validation` (exit code 2) for the "not a ralph workspace" case, and `RalphError::Orchestration` (exit code 1) for the "failed to parse ralph.toml" case. This matches the spec's exit code requirements exactly.
- **`plan_overlay_actions` checks filesystem at plan time**: For overlay mode, the plan function checks which directories and template files already exist so it can emit only the missing actions. This means the dry-run output accurately reflects what _would_ be created.
- **No changes to `cli/mod.rs`**: The `InitArgs.copy_files` field was already properly wired from Loop 1 and propagated into `execute()`. No modifications were needed.
- **No changes to `tests_auto_init.rs`**: The existing auto-init tests already assert `!workspace_root.join("templates").exists()`, confirming minimal bootstrap behavior. No updates were required.
