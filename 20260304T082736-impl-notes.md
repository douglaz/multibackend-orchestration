# Implementation Notes

## Decisions Made
- **Canonical backend equality via `parse_backend_spec`**: Added a local `canonicalize_backend_spec` helper in `quick_dev_orchestrator.rs` that parses the raw spec string through `parse_backend_spec` and reconstructs it in canonical form (`name` or `name(model)`). This strips the `?` optional prefix and trims whitespace, ensuring `" claude "`, `"?claude"`, and `"claude"` all canonicalize to `"claude"` before comparison. The same logic already exists privately in `config/mod.rs` and `workflow/orchestrator.rs`; a local copy avoids changing module visibility for a 5-line function.
- **Crash-durable counter persistence at mutation points**: Added `state.quick_dev_review_iteration = review_iteration; save_state_to_disk(state, project_dir)?;` immediately after `review_iteration += 1` in `CodexReview`, and `state.quick_dev_final_review_attempts = final_review_attempts; save_state_to_disk(state, project_dir)?;` immediately after `final_review_attempts += 1` in `FinalReview`. This ensures counters are durable before any guard check or transition side effect. The force-complete path now correctly persists the incremented attempt count since it inherits the already-written field value.
- **Integration test for `?`-prefix equality**: The `?`-prefix optional syntax is rejected upstream (before `validate_distinct_backends`) when used as an implementer/reviewer CLI override, so the integration test uses whitespace-padded `claude(opus)` instead. The unit test for `?`-prefix canonical equality is retained since it tests the function directly.
