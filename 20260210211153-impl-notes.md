# Implementation Notes

## Decisions Made

- **Validation as separate phase**: Implemented `ValidatePrd` as a distinct phase in the state machine that runs after all stage outputs are generated and gap-checked. This provides clear separation between stage generation and final PRD validation.

- **Validation retry pattern**: Used the same fenced-JSON extraction and parse retry pattern (up to 3 attempts) as gap analysis for consistency. On parse failure after 3 attempts, falls back to treating the PRD as valid (permissive default).

- **Stage hash persistence**: Added `stage_hashes.json` in the cache directory to persist stage input hashes across runs. This enables resume functionality to compare current inputs against previous runs, not just in-memory values.

- **Resume skip logic**: When `--resume` is enabled, `run_stage` checks if the cached output exists and the input hash matches. If both conditions are true, the stage is skipped and cached output is reused. If either condition fails (missing cache or hash mismatch), the stage executes normally.

- **Hash invalidation cascade**: When answers change during a rerun (via `ApplyAnswers`), the `maybe_rerun_phase` clears both stage outputs and stage input hashes from the rerun point forward. This ensures downstream stages are recomputed when inputs change.

- **Validation failure reporting**: On validation failure, writes a structured markdown report to `validation_report.md` in the cache directory with actionable next steps. Returns `RalphError::PrdValidationFailed` (exit code 11) with no auto-repair loop in v1.

- **Cache helper methods**: Added `write_validation_report`, `read_stage_hashes`, and `write_stage_hashes` to `CacheManager` for validation and resume functionality.

- **Validation types**: Added `ValidationResult` and `ValidationIssue` types to `gaps.rs` with `run_llm_validation` and `parse_validation_result` functions following the same pattern as gap analysis.

## Spec Deviations

None. All acceptance criteria are fully satisfied:
- Real `ValidatePrd` phase implementation with LLM validation
- Validation parse retry (3 attempts) with reformat prompt
- Valid → Done transition with finalization
- Invalid → exit 11 with validation report (no auto-repair in v1)
- Resume hydration from cache (stage outputs + hashes)
- Resume skip logic in `RunStage` when cache valid
- Missing/invalid/hash-mismatched stages recompute on resume
- Stage hash persistence via `stage_hashes.json`
- Resume idea guard enforced
- Integration tests cover all validation and resume scenarios

## Testing

Run integration tests to verify all acceptance criteria:

```bash
cargo test --test prd
```

Key test scenarios:
1. **Validation pass**: `validation_pass_writes_final_prd` - Verifies valid PRD generates `PRD.md`
2. **Validation fail**: `validation_fail_returns_exit_11_with_report` - Verifies exit code 11 and validation report creation
3. **Resume skip**: `resume_skips_cached_stages_with_matching_hashes` - Verifies reduced backend calls when hashes match
4. **Resume invalidation**: `resume_invalidates_stages_when_answers_change` - Verifies stages rerun when inputs change
5. **Resume idea mismatch**: `resume_idea_mismatch_returns_cache_mismatch_error` - Verifies exit code 2 on idea mismatch

All existing tests remain passing (gap analysis, interactive flow, max rounds, non-interactive, user quit, parse retries).

To manually test validation:
1. Run a PRD pipeline to completion: `ralph prd --idea "test idea" --backend codex`
2. Observe validation phase after PRD stage
3. If validation fails, check `.ralph/prd/<hash>/validation_report.md`

To manually test resume:
1. Run a PRD pipeline: `ralph prd --idea "test" --backend codex`
2. Resume without changes: `ralph prd --idea "test" --backend codex --resume` (should skip stages)
3. Modify `.ralph/prd/<hash>/answers.yaml` and resume (should rerun affected stages)
