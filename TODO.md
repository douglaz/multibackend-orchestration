# TODO

- When a new run is executed with `--project`, we should either set active project = None or override active project with the specified one
- **auto_branch race condition**: When `ralph run` creates a new branch via `auto_branch`, it branches from the current HEAD. If `ralph project new` was committed separately after the prompt commit, the branch point may be *before* the project files commit, causing "No such file or directory" on the new branch. Fix: either `auto_branch` should ensure it includes all commits up to and including the project state files, or `ralph project new` + prompt commit should be atomic, or `ralph run` should detect the missing state and merge the latest master commit before proceeding.
- `ralph tail` without `--project` shows stale output from last active project instead of the currently running project. Consider auto-detecting which project has an active run, or at least warn when showing a completed project.
- **tmux: show stdout in window too**: Currently tmux mode redirects stdout to a temp file for parsing, so users watching the tmux session only see stderr. Use `tee` to display stdout in the tmux pane while still capturing it to the output file. The shell command should change from `cmd > output` to `cmd | tee output` so the agent's actual response is visible alongside its stderr/thinking output.
- **codex model suffix per invocation**: The codex CLI model suffixes (`-high`, `-xhigh`, `-medium`) map to reasoning effort levels, but ChatGPT accounts don't support these suffixes — only the base `gpt-5.3-codex` model works (reasoning effort is set via `~/.codex/config.toml` `model_reasoning_effort`). Two fixes needed: (1) Change `ralph.toml` defaults to use the base model name since suffixed models don't work with ChatGPT accounts. (2) Allow configuring a reasoning-effort suffix or separate flag per role invocation, so different roles can use different effort levels without relying on model-name hacks. Could be a new `reasoning_effort` field per role in `BackendRoleModels`, passed as a CLI arg to codex.
